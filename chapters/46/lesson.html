Chapter 45 learned from scalar rewards produced during interaction. Feedback about language often arrives in a different form: for one prompt, a reviewer prefers response A to response B. Direct preference optimization turns those comparisons into a stable objective, while a separate experiment shows when an automatic checker can supply a reward directly.

The concrete goal

You will calculate one DPO pair by hand, train policy logits from four chosen/rejected pairs, verify a gradient with central differences, and optimize another policy against an arithmetic checker. The program executes both training procedures; neither is a stand-in printout.

1. From reward to preference

A scalar reward says how much one outcome is worth according to a rule. A preference pair says only that response yw, the chosen or winning answer, should rank above response yl, the rejected or losing answer, for the same prompt x. It need not say whether either answer is perfect.

This distinction matters. Suppose one answer is concise but omits a minor qualification and another is wrong. Choosing the first supplies an ordering. Assigning it reward one might falsely suggest complete correctness. Pairwise data is often easier to collect, but it can contain inconsistent judgments, presentation bias, and gaps in what was compared.

Our fixture has two prompts and three possible complete responses per prompt. A policy row contains three logits. Stable softmax converts them to probabilities. This categorical policy is intentionally smaller than the decoder from earlier chapters, but it performs the same probability operation that an autoregressive model performs at each token.

For an autoregressive response y=(y₁,…,yT), its log probability is a sum:

log π(y|x) = Σt=1..T log π(yt | x,y<t)

The prompt supplies context; response tokens contribute to the response likelihood. Padding must be masked. The one-choice fixture has T=1, so it tests preference arithmetic without introducing tokenization and masking. That scope is a limitation, not a claim that sequence details do not matter.

2. Work through the DPO objective

Direct preference optimization compares two changes in odds: the current policy's chosen-versus-rejected margin and the same margin under a frozen reference policy. Define

z = β[(log π(yw|x)−log π(yl|x)) − (log πref(yw|x)−log πref(yl|x))]

Here β is positive and controls the scale of the relative margin. The pair loss is −log σ(z), where σ is sigmoid. If policy and reference have identical margins, z=0, σ(0)=0.5, and loss is −log 0.5 = ln 2 ≈ 0.6931.

A pair that moved in the chosen direction

Suppose current log probabilities are −0.8 for chosen and −1.6 for rejected, so the policy margin is 0.8. Reference values are −1.0 and −1.4, so its margin is 0.4. With β=0.5, z=0.5(0.8−0.4)=0.2. Sigmoid(0.2)≈0.5498 and loss≈0.5981, below ln 2. The objective rewards improvement relative to the reference, not merely a positive raw margin.

The derivative of the loss with respect to z is σ(z)−1 = −σ(−z). It is strongly negative when the pair is ranked incorrectly and approaches zero when the chosen response already leads by a large relative margin. For a categorical row, the log-normalizers cancel inside log π(chosen) − log π(rejected). The chosen-logit slope is −βσ(−z), and the rejected-logit slope has the opposite sign.

Gradient descent therefore raises the chosen logit and lowers the rejected logit. The reference receives no update. In a batch, every pair's gradient must be evaluated at the same old policy, accumulated, averaged, and then applied. Updating the row between two pairs silently changes full-batch gradient descent into an order-dependent online procedure.

let margin = beta * ((current[chosen] - current[rejected])
    - (frozen[chosen] - frozen[rejected]));
let slope = -beta / (1.0 + margin.exp()) / pairs.len() as f64;
gradient[chosen] += slope;
gradient[rejected] -= slope;

3. Why the reference is part of the problem

The preference objective is derived from maximizing expected reward while penalizing departure from a reference with KL regularization. In the underlying objective J=Eπ[r]−β KL(π||πref), r is reward and the expectation averages over policy responses. The optimum satisfies π*(y|x) ∝ πref(y|x) exp(r(x,y)/β): larger β penalizes a departure more strongly for a fixed reward function. In the transformed DPO loss, β also multiplies the learned log-ratio margin, so increasing it changes both slope and saturation; it is not interchangeable with a learning rate. Rearranging that relationship turns a policy/reference log ratio into an implicit reward. In a chosen-minus-rejected difference, the prompt-only normalizer cancels.

This derivation explains why removing the reference changes the objective. A raw pair classifier asks only whether chosen beats rejected. DPO asks whether the new policy increases that relative preference compared with its starting anchor. The reference anchors the relative margins, but a finite preference dataset does not guarantee preservation of behavior elsewhere. On separable pairs, this unregularized categorical logistic loss can keep increasing margins as training continues; DPO’s derivation is not a hard bound on the final KL. The reference also does not certify the anchor’s quality.

Freeze means freeze.

If reference logits are aliases into policy storage, updating policy also moves the reference. The relative margin may stay near zero even as both distributions drift. The Rust function takes separate borrowed reference rows and mutable policy rows. train_dpo clones the starting values once, then updates only policy.

Numerical stability matters before model size does. Computing softmax, then taking ln, can underflow an extremely unlikely response to zero and produce negative infinity. The project computes log-softmax as (logit − maximum) − ln Σ exp(logits − maximum). Keeping the subtraction in this order also preserves ln 2 for two equal logits near 10¹⁶; adding the maximum back too early could round that normalization away. It computes −log σ(z) as stable softplus of −z: max(−z,0)+log(1+exp(−|z|)).

The implementation rejects empty pairs, nonpositive β or learning rate, invalid indices, mismatched row widths, identical chosen and rejected indices, and nonfinite logits. These checks sit at the training boundary because corrupted preference indices or nonfinite model state should not silently produce a plausible average.

4. When a checker can supply reward

Some tasks have a verifiable reward. A compiler can run tests, a theorem checker can validate a proof, and arithmetic can be recomputed. For the prompt “2 + 3,” the project parses both operands and evaluates candidates 4, 5, and 6. It returns reward one only for candidate 5.

This feedback supports a policy-gradient objective directly. Let rewards be r=[0,1,0] and probabilities p=softmax(θ). The expected reward is J=Σᵢpᵢrᵢ. Its exact logit gradient is

∂J/∂θᵢ = pᵢ(rᵢ − J)

The first exact reward step

At θ=[0,0,0], each probability is 1/3 and J=1/3. For the correct candidate, the gradient is (1/3)(1−1/3)=2/9. Each wrong candidate has gradient (1/3)(0−1/3)=−1/9. With ascent rate 0.5, the correct logit rises by 1/9 and each wrong logit falls by 1/18. The probabilities still sum to one because softmax performs the normalization.

After 200 exact-gradient steps, the printed policy is approximately [0.0036, 0.9928, 0.0036]. This is a small policy-gradient experiment whose reward comes from executing the checker. It is distinct from DPO training above. A sampled version would draw a candidate and use REINFORCE; exact expectation is available here because there are only three actions.

Automatic does not mean complete. A test suite may miss edge cases. A mathematical answer checker may reward a bare final number when a derivation is required. A model can learn shortcuts that satisfy a flawed verifier. Held-out problems, adversarial cases, and limits on tool access remain part of evaluation.

6. Practice, debug, and transfer

Exercise A · Implement the DPO pair loss

Open ch46_01.rs. Begin with the equal-margin check.

Hint 1 · Form one number

Subtract reference margin from policy margin, then multiply by beta.

Hint 2 · Stable identity

−log σ(z) equals log(1+exp(−z)). The tiny exercise uses moderate inputs; the project shows the overflow-safe form.

Worked solution
(1.0 + (-beta * (policy_margin - reference_margin)).exp()).ln()

When both margins are equal, the exponent is one and the answer is ln 2.

Exercise B · Build a two-pair batch

Complete projects/ch46/starter/src/main.rs. Then give one prompt three logits and two preferences with the same chosen response. Accumulate both pair gradients before changing any logit. Check that reversing the pair order yields identical parameters.

Hint 1 · Storage

Use one gradient vector initialized to zeros and add chosen/rejected contributions for each pair.

Stable scalar checkpoint

Let u=−β(policy_margin−reference_margin). Return u.max(0.0) + (-u.abs()).exp().ln_1p(). This agrees with the elementary formula while avoiding overflow for the starter’s extreme-margin test.

Hint 2 · Update

After the loop, subtract learning rate times every accumulated component.

Reference reasoning

The reference divides each pair contribution by pair count. Order independence follows because addition happens before mutation. Small floating-point differences can remain if summation order changes, so compare with a tolerance rather than bits.

Debugging · Loss becomes NaN on a confident model

A learner computes softmax(logits)[rejected].ln(). With a rejected logit near −1000, the probability rounds to zero. Diagnose and repair the layer responsible.

Answer

Probability-space softmax underflows before the logarithm. Compute log-softmax directly with maximum-subtracted log-sum-exp. Also use stable softplus for the DPO loss. Clamping the final NaN hides the source and destroys the intended gradient.

Independent variation · Conflicting preferences

Add one pair choosing response zero over response one for prompt zero, which conflicts with the two existing comparisons favoring response one. Predict how the final probability changes and inspect per-pair losses.

Worked answer

The new pair pushes the same logit difference in the opposite direction. Its loss cannot simultaneously approach zero with the original reversed preference. The optimum compromises according to pair counts, beta, and the shared comparison against reference. Aggregate loss may fall while neither direction reaches the confidence seen in consistent data. This is why a mean alone can hide annotation conflict.
