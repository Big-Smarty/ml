What information is present in a preference pair?

A scalar reward says how much one outcome is worth according to a rule. A preference pair says only that response yw, the chosen or winning answer, should rank above response yl, the rejected or losing answer, for the same prompt x. It need not say whether either answer is perfect.

This distinction matters. Suppose one answer is concise but omits a minor qualification and another is wrong. Choosing the first supplies an ordering. Assigning it reward one might falsely suggest complete correctness. Pairwise data is often easier to collect, but it can contain inconsistent judgments, presentation bias, and gaps in what was compared.

Our fixture has two prompts and three possible complete responses per prompt. A policy row contains three logits. Stable softmax converts them to probabilities. This categorical policy is intentionally smaller than the decoder from earlier chapters, but it performs the same probability operation that an autoregressive model performs at each token.

For an autoregressive response y=(y1,…,yT), its log probability is a sum:

logπ(y|x)=∑t=1Tlogπ(yt|x,y<t)

The prompt supplies context; response tokens contribute to the response likelihood. Padding must be masked. The one-choice fixture has T=1 response position, so it tests preference arithmetic without introducing tokenization and masking. That scope is a limitation, not a claim that sequence details do not matter.

Can a reward model learn what the comparisons actually distinguish?

A learned reward model maps a prompt/response to a scalar score. Pairwise training asks that the chosen response score exceed the rejected score. This differs from DPO: the reward model learns explicit score parameters, while DPO directly learns policy response odds relative to a reference. A full RLHF pipeline can first fit demonstrations, then fit a reward model from comparisons, then optimize a policy against that learned reward. This lab executes each small mechanism separately and does not claim to train a language decoder with RLHF.

Our response feature vector has two entries: checked correctness (zero or one) and normalized length. A linear score r=w0×correctness+w1×length has two weights. Given feature difference d=features(chosen)−features(rejected), the pair margin is w·d. Model the chance of a chosen win by sigmoid(w·d), and minimize −logsigmoid(w·d). This is the Bradley–Terry pair model applied to a linear reward score.

At w=[0,0], chosen [1,0.2] and rejected [0,0.8] give d=[1,−0.6] and margin zero. The loss is ln2, and the weight gradient is −0.5d=[−0.5,0.3]. Gradient descent at learning rate 0.2 gives w=[0.1,−0.06]. That single pair favors correctness and shorter length; it cannot tell which property caused the preference. A counterbalanced second pair [1,0.8] over [0,0.2] cancels the length gradient while reinforcing correctness.

InstructGPT is a source for the separate demonstration, reward-model and policy-optimization stages. Its end-to-end human evaluation does not establish the effect of SFT alone or the behavior of this two-weight fixture. Ouyang et al., Training language models to follow instructions with human feedback.

How do chosen and rejected odds form a DPO loss?

Direct preference optimization compares two log ratios. The policy_logratio is the current policy's chosen log probability minus its rejected log probability. The reference_logratio is the same difference under a frozen reference policy. Define

z=β[(logπ(yw|x)−logπ(yl|x))−(logπref(yw|x)−logπref(yl|x))]

Here β is positive and controls the scale of the relative log-ratio margin. The pair loss is −logσ(z), where σ is sigmoid. If policy and reference have identical log ratios, z=0, σ(0)=0.5, and loss is −log0.5=ln2≈0.6931.

A pair that moved in the chosen direction

Suppose current log probabilities are −0.8 for chosen and −1.6 for rejected, so the policy margin is 0.8. Reference values are −1.0 and −1.4, so its margin is 0.4. With β=0.5, z=0.5(0.8−0.4)=0.2. sigmoid(0.2)≈0.5498 and loss≈0.5981, below ln2. The objective rewards improvement relative to the reference, not merely a positive raw margin.

The derivative of the loss with respect to z is σ(z)−1=−σ(−z). It is strongly negative when the pair is ranked incorrectly and approaches zero when the chosen response already leads by a large relative margin. For a categorical row, the log-normalizers cancel inside logπ(chosen)−logπ(rejected). The chosen-logit slope is −βσ(−z), and the rejected-logit slope has the opposite sign.

Gradient descent therefore raises the chosen logit and lowers the rejected logit. The reference receives no update. In a batch, every pair's gradient must be evaluated at the same old policy, accumulated, averaged, and then applied. Updating the row between two pairs silently changes one optimizer step on a full-batch mean into an order-dependent online procedure. Inside loss_and_gradient, the code names both log ratios and divides each contribution by the number of supplied pairs:

let policy_logratio =
    policy_log_probabilities[pair.chosen] - policy_log_probabilities[pair.rejected];
let reference_logratio = reference_log_probabilities[pair.chosen]
    - reference_log_probabilities[pair.rejected];
let margin = beta * (policy_logratio - reference_logratio);
total_loss += dpo_pair_loss(policy_logratio, reference_logratio, beta);
let loss_slope = -beta / (1.0 + margin.exp()) / data.len() as f64;
gradient.logits[pair.prompt][pair.chosen] += loss_slope;
gradient.logits[pair.prompt][pair.rejected] -= loss_slope;

The derivative storage has the same nested-vector shape as the policy logits, but it is not a second model:

#[derive(Debug)]
struct Gradient {
    logits: Vec<Vec<f64>>,
}

Why must the reference stay fixed?

The preference objective is derived from maximizing expected reward while penalizing departure from a reference with KL regularization. In the underlying objective J=Eπ[r]−βKL(π∥πref), r is reward and the expectation averages over policy responses. The optimum satisfies π*(y|x)∝πref(y|x)exp(r(x,y)β): larger β penalizes a departure more strongly for a fixed reward function. In the transformed DPO loss, β also multiplies the learned log-ratio margin, so increasing it changes both slope and saturation; it is not interchangeable with a learning rate. Rearranging that relationship turns a policy/reference log ratio into an implicit reward. In a chosen-minus-rejected difference, the prompt-only normalizer cancels.

This derivation explains why removing the reference changes the objective. A raw pair classifier asks only whether chosen beats rejected. DPO asks whether the new policy increases that relative preference compared with its starting anchor. The reference anchors the relative margins, but a finite preference dataset does not guarantee preservation of behavior elsewhere. On separable pairs, this unregularized categorical logistic loss can keep increasing margins as training continues; DPO’s derivation is not a hard bound on the final KL. The reference also does not certify the anchor’s quality.

Freeze means freeze.

If reference logits are aliases into policy storage, updating policy also moves the reference. The relative margin may stay near zero even as both distributions drift. Policy::loss_and_gradient borrows separate policy and reference values, while Policy::step mutates only the policy. train_dpo clones the starting values once, then updates only that clone.

Numerical stability matters before model size does. Computing softmax, then taking ln, can underflow an extremely unlikely response to zero and produce negative infinity. The project computes log-softmax as (logit−maximum)−ln∑exp(logits−maximum). Keeping the subtraction in this order also preserves ln2 for two equal logits near 1016; adding the maximum back too early could round that normalization away. It computes −logσ(z) as stable softplus of −z: max(−z,0)+log(1+exp(−|z|)).

The implementation rejects empty pairs, nonpositive β or learning rate, invalid indices, mismatched row widths, identical chosen and rejected indices, and nonfinite logits. These checks sit at the training boundary because corrupted preference indices or nonfinite model state should not silently produce a plausible average.

fn dpo_pair_loss(policy_logratio: f64, reference_logratio: f64, beta: f64) -> f64 {
    let negative_margin = -beta * (policy_logratio - reference_logratio);
    negative_margin.max(0.0) + (-negative_margin.abs()).exp().ln_1p()
}

When can an automatic checker supply reward?

Some tasks have a verifiable reward. A compiler can run tests, a theorem checker can validate a proof, and arithmetic can be recomputed. For the prompt 2+3, the project parses both operands and evaluates candidates 4, 5, and 6. It returns reward one only for candidate 5.

This feedback supports a policy-gradient objective directly. Let rewards be r=[0,1,0] and probabilities p=softmax(θ). The expected reward is J=∑ipiri. Its exact logit gradient is

∂J∂θi=pi(ri−J)

This J is a probability-weighted sum over the three candidates for one prompt, not an arithmetic mean over candidates. There is no prompt-batch reduction in this fixture. A multi-prompt version would need to state whether and how it averages those per-prompt expectations.

The first exact reward optimizer step

At θ=[0,0,0], each probability is 13 and J=13. For the correct candidate, the gradient is 13(1−13)=29. Each wrong candidate has gradient 13(0−13)=−19. With learning_rate = 0.5, the correct logit rises by 19 and each wrong logit falls by 118. The probabilities still sum to one because softmax performs the normalization.

After 200 exact-gradient optimizer steps, the printed policy is approximately [0.0036,0.9928,0.0036]. This is a small policy-gradient experiment whose reward comes from executing the checker. It is distinct from DPO training above and has no environment transition. A sampled version would draw a candidate and use REINFORCE; exact expectation is available here because there are only three actions.

Automatic does not mean complete. A test suite may miss edge cases. A mathematical answer checker may reward a bare final number when a derivation is required. A model can learn shortcuts that satisfy a flawed verifier. Held-out problems, adversarial cases, and limits on tool access remain part of evaluation.
