A line with one input can answer “how does one measurement relate to the target?” Most predictions depend on several measurements at once. This chapter turns one number into a feature vector, extends the gradient without hiding it behind a tensor library, and shows why units can make correct optimization behave badly.

Your goal

You will fit a three-input linear regression model to synthetic measurements, standardize each feature using training statistics, and make a prediction through a checked dot product.

1. One measurement leaves information unused

Imagine estimating an apartment's monthly energy use. Floor area matters, but so do occupant count and building age. Two apartments with the same area can have different targets. A one-input model must give them the same prediction because it cannot see the distinguishing measurements. Adding features gives the model evidence it previously lacked.

For one example, collect the measurements in a vector x = [x₁,x₂,x₃]. In our course-authored fixture, the positions mean area, occupants, and age. The ordering is part of the data contract. The model has a matching weight vector w = [w₁,w₂,w₃] and one bias b.

Trace a three-feature prediction

Let x = [60,2,10], w = [2,5,−1], and b = 7. Corresponding products are 120, 10, and −10. Their sum is 120; adding the bias gives ŷ = 127. The second weight means one additional occupant contributes five target units when other features are fixed. The negative age weight subtracts one unit per year in this invented model.

Changing the order to [occupants, area, age] without changing w gives 4+300−10+7 = 301. The arithmetic succeeds but the meaning is broken. Shapes catch length mismatches; only a documented schema catches order mismatches.

The sum of corresponding products is a dot product, written w·x. The complete prediction is ŷ = w·x+b. Both vectors must have dimension D. A batch of N examples contains N such vectors, but we still handle one fixed-size array at a time; a general tensor abstraction arrives only after the scalar and vector rules are familiar.

2. Linear regression reuses the learning loop

Linear regression predicts a numeric target with a weighted sum. “Linear” refers to how parameters enter the equation. The same weights apply to every row. With N examples and D features, mean squared error remains L = (1/N)Σᵢ(ŷᵢ−yᵢ)².

Chapter 2's chain rule gives one derivative per feature. For weight j, the inner prediction derivative is xᵢⱼ:

∂L/∂wⱼ = (2/N) Σᵢ (w·xᵢ+b−yᵢ)xᵢⱼ

The index i selects an example and j selects a feature. xᵢⱼ is one number: feature j of example i. The bias derivative is still (2/N)Σᵢeᵢ. The output gradient has D weight components plus one bias component, matching the parameter shapes.

One update with two features

Use one example x = [2,3], y = 7 and a zero model. Error is −7. The ordinary-MSE weight contributions are 2(−7)[2,3] = [−28,−42], and the bias contribution is −14. With rate 0.01, the updated parameters are [0.28,0.42] and b = 0.14. Its new prediction is 0.56+1.26+0.14 = 1.96, closer to seven.

One example cannot identify a unique pair of weights: many combinations predict seven for that vector. Multiple varied examples constrain a shared solution. Low training loss alone still does not make coefficients causal; correlated inputs can trade weight between each other.

for (dw, value) in gradient.weights.iter_mut().zip(features) {
    *dw += 2.0 * error * value / n;
}

The Rust zip mirrors corresponding multiplication. The reference uses [f64; 3] for both vectors, so unequal dimensions cannot enter this internal calculation. The Rustlings exercise uses slices and explicitly rejects unequal lengths, making the invariant observable.

3. Put unlike units on workable coordinates

Our raw features have very different ranges: area is tens or hundreds, occupants are one to five, and age is one to twelve. In a gradient, each error is multiplied by its feature. The area component can therefore be far larger solely because area uses larger units. One learning rate may barely move the occupant weight yet make the area weight overshoot.

Feature scaling changes coordinates before training. For each feature j, compute its training mean μⱼ and population standard deviation σⱼ, then transform xⱼ to zⱼ = (xⱼ−μⱼ)/σⱼ. The transformed training feature has mean zero and average squared deviation one.

Standardize one feature by hand

Suppose training occupant counts are [1,2,3]. Their mean is μ = 2. Deviations are [−1,0,1]; squared deviations average to 2/3, so σ = √(2/3) ≈ 0.8165. The count 3 becomes (3−2)/0.8165 ≈ 1.2247. A future count 4 becomes about 2.4495 using the same μ and σ.

Do not recompute μ and σ after seeing that future example. The transformation is part of the fitted model. Validation, test, and production inputs must use training statistics, even when their transformed mean is not zero.

A constant training feature has σ = 0 and cannot be divided safely. The project rejects it. In a larger pipeline you might remove the feature, but silently replacing zero with one would conceal the fact that the training data contains no information about its effect.

Scaling does not make a nonlinear relationship linear and does not fix incorrect labels. It improves the numerical geometry of gradient descent. Coefficients now act on standard-deviation units, so compare them only with that fact stated. To deploy the model, save μ and σ alongside weights and bias.

4. Run the multifeature project

The reference source fits a Scaler to eight training rows, transforms the rows, trains three weights, then transforms one new vector with the stored statistics. Both data and algorithm are deliberately small enough to inspect.

cargo test --manifest-path projects/ch03/Cargo.toml
cargo run --release --manifest-path projects/ch03/Cargo.toml

The tests verify that every transformed training feature is centered, that constant features fail clearly, that MSE drops below 2.1, and that the held-out prediction for [100,3,6] lies between 240 and 260. The range is a deterministic implementation check, not an uncertainty interval. The synthetic targets were designed to be nearly linear with small deviations.

Follow one row through the program. Scaler::transform produces three standardized values in the documented order. predict multiplies them with three weights and sums before adding the bias. loss_and_gradient computes a single error, contributes it to every weight component, and averages over rows. train applies all components after the gradient is complete.

Try a controlled comparison: reduce training to 20 steps and record MSE; then bypass scaling while keeping rate 0.05. Raw area values usually make updates nonfinite or unstable. A much smaller rate may train the raw model, but other coordinates then move slowly. This is an optimization effect, not evidence that standardized features are inherently more predictive.

5. Practice, debug, and vary

Exercise A · A checked dot product

Complete ch03_01.rs. Return None when the slice lengths differ; otherwise sum matching products.

Hint 1 · Validate first

Compare weights.len() and features.len(). A truncated zip would silently ignore extra entries.

Hint 2 · Express the reduction

Use weights.iter().zip(features).map(...).sum() inside then or an explicit branch.

Worked solution
(weights.len() == features.len()).then(|| {
    weights.iter().zip(features).map(|(w, x)| w * x).sum()
})

Validation must happen before zip because zip intentionally stops at the shorter iterator.

Debugging · Great validation numbers from the wrong scaler

A learner concatenates training and validation rows, computes means and scales, then splits them again. Why is this a bug even though no target entered the scaler?

Answer

The validation feature distribution influenced a fitted preprocessing parameter, so development has information about held-out inputs it would not have before deployment. Fit on training rows only, then reuse those statistics. Target-free preprocessing can still leak.

Independent variation · Add an interaction

Create targets y = 2x₁ + 3x₂ + 4x₁x₂ from varied pairs. First fit only [x₁,x₂], then add x₁x₂ as a third feature. Predict at [2,3].

Worked answer

The true target is 4+9+24 = 37. A plain two-feature linear model cannot represent the changing joint effect across varied data. Adding the product as a feature lets an otherwise linear parameter model represent it with raw-feature weights [2,3,4] and bias zero. After standardization, weight j becomes the raw weight multiplied by σⱼ, and bias becomes the sum of raw weight times μⱼ, preserving the same predictions. Fit scaling only after constructing the training features, and apply the same transformation at inference.
