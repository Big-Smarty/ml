Why do equal sensor readings need different answers?

A raw reading can depend on load and vibration as well as the quantity we want to measure. Your next calibration model uses all three measurements. The baseline already fits the raw sensor; you will build the vector gradient that makes the other measurements useful.

Recall the scalar rule: multiply an input by its learned weight, then add a bias. If two rows have the same input, that rule must give them the same prediction. In this chapter's invented instrument, the same raw reading under two different loads requires different calibrated targets. No number of scalar training steps can use information that is absent from the input.

How do several measurements become one prediction?

A vector is an ordered collection of numbers. Here one feature vector is x=[raw sensor, load, vibration]. The positions are part of the measurement schema. Its matching weight vector has three entries, one per feature. A scalar bias is added once.

Take x=[0.5,500,−0.5], weights [2,0.003,−1], and bias 1. Matching products are 1,1.5,0.5. Add them to get 3, then add the bias to predict 4. Adding matching products is the dot product, written w·x.

ŷ = w·x+b = w₁x₁+w₂x₂+w₃x₃+b

Each subscript names a position, not a power. Both vectors have dimension 3; their dot product is one scalar. The code stores parameters as [w₁,w₂,w₃,b], an array of length 4. A dataset of N rows contains N vectors of length 3 and N scalar targets. There is no general tensor library hiding these dimensions.

// Matching entries multiply; addition reduces the three products to one value.
let prediction = weights.iter().zip(features)
    .map(|(weight, feature)| weight * feature)
    .sum::<f64>() + bias;

Fixed arrays make a length mismatch impossible here. They cannot detect meaning: swapping load and vibration keeps the same length but changes the prediction. With the swapped raw vector[0.5,−0.5,500], the same raw weights predict−498.0015. The computation is well typed and wrong for the schema.

Linear regression fits numeric targets with a weighted sum. It is linear in its parameters. We can later supply transformed features, such as a product of two inputs, without changing the weighted-sum algorithm. A fitted coefficient describes this model in these units; correlated features can trade weights, so the coefficient does not establish a causal effect.

As a small implementation checkpoint, add a diagnostic in the learner's report that prints each feature contribution and their total for one new vector. Explain why a three-element array of products is not itself the final prediction.

Worked reasoning

The product array still has three entries. The dot product sums those entries into a scalar; bias shifts that scalar once. Reporting contributions separately helps catch a swapped column even when the array shapes match.

Can one error update every relevant weight?

Use one standardized row x=[1,1,−1], target 7, and a zero model. The error is−7. From Chapter 02, the square's derivative is2e=−14. Multiply that by each input: weight derivatives are[−14,−14,+14], and the bias derivative is−14. At rate 0.01 the new parameters are[0.14,0.14,−0.14,0.14]. The new prediction is0.56, closer to7.

For N examples, average these contributions. Let i select an example and j select one of its three features. The formula for weight j is:

gⱼ = (2/N)Σᵢeᵢxᵢⱼ; gb = (2/N)Σᵢeᵢ, where eᵢ=w·xᵢ+b−yᵢ

The gradient has four components, one for every parameter. Compute the example error from all current weights before contributing to any component. Finish all accumulations before updating the model. In the eight symmetric standardized rows, the initial gradient is[−4,−6,+2,−2]. One step at rate 0.1 gives[0.4,0.6,−0.2,0.2].

Why can the unit of load break a correct update?

Recall that each weight derivative multiplies error by its feature value. Our raw load uses values±1000, while other features use±1. At the zero model, the raw load derivative is−6000. A rate 0.1 update makes its weight 600, which contributes 600,000 at load 1000. The correct raw coefficient is only 0.003. The update has overshot by an enormous amount even though the derivative is correct.

Run the solution's raw-units comparison. It uses the same rate and step count and reports either a very large MSE or an explicit nonfinite error. Reducing the rate enough for load can make the other weights move extremely slowly. Feature units have distorted the optimization coordinates.

Standardization subtracts each feature's training mean μ and divides by its training population standard deviation σ. For load in this fixture, μ=0 and σ=1000, so raw 500 becomes 0.5. All three standardized features have mean 0 and mean squared value 1.

zⱼ=(xⱼ−μⱼ)/σⱼ; μⱼ=(1/N)Σᵢxᵢⱼ; σⱼ=√[(1/N)Σᵢ(xᵢⱼ−μⱼ)²]

The square root reverses squaring so σ has the original feature's units. To see a less symmetric case, values[1,2,3] have mean 2; deviations[−1,0,1] have mean square 2/3; standard deviation is approximately 0.8165. A future value 4 transforms to about 2.4495 using those same fitted statistics.

The supplied Scaler fits only training rows and rejects a constant column because σ=0. Removing that column explicitly is sensible; silently dividing by zero is not. Model and scaler must travel together to inference. Fitting a new scaler on each incoming row would erase or distort the evidence the weights learned.

Answer

One standardized load unit is1000 raw units. Its contribution is0.003×1000=3. In general, the standardized weight is raw_weight×σ; the standardized bias is raw_bias+Σraw_weight×μ. Predictions can stay identical while parameter values change with coordinates.
