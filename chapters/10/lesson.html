What does one digit look like before it becomes a prediction?

A digit image is a small grid of brightness values. The classifier sees those values as an ordered row of numbers and must produce one of ten class IDs. We will run that complete pipeline on tiny synthetic images before asking for larger files.

Run just lab 10. The program prints the first block glyph as # and . characters, its shape and target, then training and held-out metrics. The supplied baseline learns class biases only, so it can learn frequencies but cannot distinguish images with the same prior class distribution. Your task is to let pixels affect the learned class scores through all their weights.

The offline fixture contains 30 course-authored 5×3 training block glyphs: three brightness variants for each of ten labels. The held-out fixture has ten distinct brightness variants and two intentionally ambiguous blank images, labelled 1 and 7. Identical inputs with conflicting labels cannot both be classified correctly by a deterministic image-only model. These are synthetic mechanism checks, not MNIST examples or handwriting performance.

MNIST stores images and labels in separate IDX files. Multi-byte header integers are big-endian: the most significant byte comes first. An image file begins with magic number 2051, then image count, row count, and column count as 32-bit unsigned integers. Its payload is count×rows×columns unsigned bytes in row-major image order. A label file begins with magic 2049, then count, followed by one unsigned label byte per image.

The official training set contains 60,000 28×28 images and the official test set 10,000. Pixels range from 0 to 255. The project converts each byte to f64 in [0,1] by dividing by 255. This scaling improves optimization while preserving ordering. Labels must lie in 0..9 because the model has ten outputs.

Decode a tiny header

The first four image bytes 00 00 08 03 represent hexadecimal 0x00000803, decimal 2051. The next four bytes 00 00 00 03 declare three images. If rows and columns are both encoded as two, the parser expects exactly 16 header bytes plus 3×2×2=12 pixel bytes. The corresponding label file must contain eight header bytes plus three labels. One missing byte is an error, not a shorter dataset.

Validation happens before allocation based on external dimensions. Counts must agree, dimensions must be positive, checked multiplication must not overflow, and the exact payload length must match. These checks turn corrupt files into clear errors and prevent untrusted headers from requesting nonsensical work.

Parsing and splitting solve different problems. IDX tells us where arrays begin and how large they are; it does not mark a validation subset. A trustworthy experiment records how rows moved from the original training collection into fit and validation files, while keeping image-label pairs aligned. Preprocessing decisions must also be fit without consulting held-out examples.

The supplied data module generates IDX bytes for the fixture and sends them through the same checked parser as user-supplied files. You implement learning, not binary file plumbing. Change one header count on paper and calculate the expected byte length before inspecting the parser's error checks.

How can ten competing scores express one target?

A linear multiclass model gives each class c a logit zc=biasc+Σⱼweightsc,jfeaturesⱼ. Chapter 4 introduced a logit as an unrestricted score; the only change here is producing one for every class. Softmax exponentiates and normalizes the ten logits, producing ten positive probabilities that sum to one.

pc = exp(zc−m) / Σk exp(zk−m), where m=maxkzk.

Subtracting the maximum changes neither probability because the same factor cancels in numerator and denominator. It prevents a large positive logit from overflowing its exponential. For logits [1000,1001], direct exponentials overflow, while shifted logits [−1,0] yield finite probabilities about [0.269,0.731].

For target class y, cross-entropy loss is −ln py. An equivalent logit expression is logΣexp(z)−zy. In floating-point code, cross_entropy_from_logits calculates this as (m−zy)+ln Σexp(z−m), so a large shared offset cancels before adding the small logarithm. Otherwise ten equal logits of 10¹⁶ can incorrectly produce loss 2 instead of ln 10≈2.3026. The derivative with respect to each logit is pc−1[c=y]: subtract one only at the target class. This is the ten-class counterpart of Chapter 4’s sigmoid-cross-entropy gradient.

One three-class illustration

Ignore seven classes briefly and take logits [2,1,0] with target zero. After subtracting 2, exponentials are [1,0.3679,0.1353], sum 1.5032, and probabilities approximately [0.6652,0.2447,0.0900]. Loss is −ln 0.6652≈0.4076. The logit gradient is [−0.3348,0.2447,0.0900]; its entries sum to zero because raising every logit equally cannot change softmax.

Why must the same blank yield the same class regardless of whether the hidden label is 1 or 7? The model receives the image, never the held-out target.

Answer

Both blanks supply identical values to every dot product. The logits and probabilities are therefore identical, and deterministic argmax must return the same class. Supplying the label to prediction would leak the desired answer. Softmax always distributes probability across the ten named classes, even when the input is an unreadable blank.

Can you fit pixel weights with one complete minibatch gradient?

The supplied Linear model stores weights as [10,in_features] and biases as [10]. For the fixture, in_features=15. Its forward calculation is Chapter 09's dense dot product, one row at a time. objective returns a stable per-example cross-entropy and ten probabilities from those logits. Prediction is the greatest-logit class; it need not compute softmax because softmax preserves ordering.

Open the Chapter 10 learner file. Replace gradient, which currently trains biases alone, with the complete mean minibatch gradient. Validate the half-open range start..end, visit each image once, calculate logits and probabilities, subtract one at its target, accumulate one weight derivative for every class/input pair and one bias derivative per class, and divide every result by the actual number of examples.

One row contributes a full weight row

At zero parameters, all ten probabilities are 0.1 and loss is ln 10≈2.302585. If the target is 2, class 2's logit derivative is −0.9; the other nine derivatives are 0.1 each. For a pixel value 0.8, its class-2 weight derivative is −0.9×0.8=−0.72. Gradient descent subtracts a negative derivative, increasing that weight and making class 2's score larger on similar bright pixels. A zero-valued pixel contributes zero to that weight, but its class bias still receives −0.9.

// One row, one class, one pixel; mean reduction is applied exactly once.
weight_gradients[class * model.input + feature] += signal * image[feature];
bias_gradients[class] += signal;

A parameter receives contributions from every example because it is shared across the batch. The supplied train applies your already-averaged gradient as parameter -= rate * gradient. It does not divide again. For a dataset length not divisible by batch size, the final batch has fewer examples; its denominator must be end-start, not the configured maximum batch size.

When has the linear model taught us enough to add a hidden layer?

Before moving on, compare three pieces of evidence: uniform initial loss ln 10, the bias-only baseline's report, and your pixel-trained report. The bias-only model estimates how often a class appears without observing the image. A lower training loss from pixel weights indicates that image content helps explain targets. A good held-out result provides some evidence beyond the fit rows, but our few synthetic variants are a weak test of handwriting recognition.

Class c still receives a weighted sum of raw pixels. Each class-pair comparison zₐ−zᵦ is affine in the input, even though the probabilities use exponentials. Softmax changes score interpretation, not the class boundary family. A hidden nonlinearity can learn combinations of pixel patterns, just as it did for XOR; it does not guarantee better held-out behavior.
