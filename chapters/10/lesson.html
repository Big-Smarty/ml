A dense layer can process rows, but a real dataset arrives as bytes with a contract. This chapter parses MNIST’s IDX format, normalizes pixels, trains a ten-class linear softmax model, and evaluates predictions on data excluded from its updates.

Milestone

The default command generates valid IDX bytes in memory and sends them through the same parser and training code as MNIST. An explicit CLI mode reads the four official-format image and label files. Missing or malformed files fail with actionable errors.

Code and terminology carried forward

Chapter 9 introduced a dense layer with row-major inputs [batch,in_features], weights [out_features,in_features], bias [out_features], and outputs [batch,out_features]. Its forward calculation is Y=XWT+bias, while backward returns parameter-gradient sums and leaves any batch averaging to the loss or caller. Chapter 10 keeps that layout and arithmetic. The Linear model fixes out_features at ten classes, stores weights as [10,in_features] and bias as [10], and computes one image row at a time. These names follow the course conventions.

Dataset.images and Dataset.labels retain the names used by the two source IDX files. image(n) exposes one normalized row as the model’s features; labels[n] is a stored discrete class ID. When that class ID is passed to the generic loss primitive it is named target, meaning the desired class for those logits.

Chapter 4 separated a binary classifier’s single logit, positive-class probability, and thresholded class-valued predict. Here the multiclass model emits ten logits, softmax returns ten probabilities, and prediction is the class index with the greatest logit. The stable primitive is therefore cross_entropy_from_logits(logits, target), the multiclass counterpart to Chapter 4’s binary_cross_entropy_from_logit(logit, target).

1. Parse structure before interpreting pixels

MNIST stores images and labels in separate IDX files. Multi-byte header integers are big-endian: the most significant byte comes first. An image file begins with magic number 2051, then image count, row count, and column count as 32-bit unsigned integers. Its payload is count×rows×columns unsigned bytes in row-major image order. A label file begins with magic 2049, then count, followed by one unsigned label byte per image.

The official training set contains 60,000 28×28 images and the official test set 10,000. Pixels range from 0 to 255. The project converts each byte to f64 in [0,1] by dividing by 255. This scaling improves optimization while preserving ordering. Labels must lie in 0..9 because the model has ten outputs.

Decode a tiny header

The first four image bytes 00 00 08 03 represent hexadecimal 0x00000803, decimal 2051. The next four bytes 00 00 00 03 declare three images. If rows and columns are both encoded as two, the parser expects exactly 16 header bytes plus 3×2×2=12 pixel bytes. The corresponding label file must contain eight header bytes plus three labels. One missing byte is an error, not a shorter dataset.

Validation happens before allocation based on external dimensions. Counts must agree, dimensions must be positive, checked multiplication must not overflow, and the exact payload length must match. These checks turn corrupt files into clear errors and prevent untrusted headers from requesting nonsensical work.

Parsing and splitting solve different problems. IDX tells us where arrays begin and how large they are; it does not mark a validation subset. A trustworthy experiment records how rows moved from the original training collection into fit and validation files, while keeping image-label pairs aligned. Preprocessing decisions must also be fit without consulting held-out examples.

2. Turn ten logits into one objective

A linear multiclass model gives each class c a logit zc=biasc+Σⱼweightsc,jfeaturesⱼ. Chapter 4 introduced a logit as an unrestricted score; the only change here is producing one for every class. Softmax exponentiates and normalizes the ten logits, producing ten positive probabilities that sum to one.

pc = exp(zc−m) / Σk exp(zk−m), where m=maxkzk.

Subtracting the maximum changes neither probability because the same factor cancels in numerator and denominator. It prevents a large positive logit from overflowing its exponential. For logits [1000,1001], direct exponentials overflow, while shifted logits [−1,0] yield finite probabilities about [0.269,0.731].

For target class y, cross-entropy loss is −ln py. An equivalent logit expression is logΣexp(z)−zy. In floating-point code, cross_entropy_from_logits calculates this as (m−zy)+ln Σexp(z−m), so a large shared offset cancels before adding the small logarithm. Otherwise ten equal logits of 10¹⁶ can incorrectly produce loss 2 instead of ln 10≈2.3026. The derivative with respect to each logit is pc−1[c=y]: subtract one only at the target class. This is the ten-class counterpart of Chapter 4’s sigmoid-cross-entropy gradient.

One three-class illustration

Ignore seven classes briefly and take logits [2,1,0] with target zero. After subtracting 2, exponentials are [1,0.3679,0.1353], sum 1.5032, and probabilities approximately [0.6652,0.2447,0.0900]. Loss is −ln 0.6652≈0.4076. The logit gradient is [−0.3348,0.2447,0.0900]; its entries sum to zero because raising every logit equally cannot change softmax.

3. Train a real linear classifier

The model’s flat weights vector represents [10,in_features], exactly Chapter 9’s [out_features,in_features] dense layout with out_features=10. Array element weights[class * in_features + feature] is Wclass,feature, and bias[class] is biasclass. Passing data.image(n) as features to logits computes the dense output; passing data.labels[n] as target to cross_entropy_from_logits measures that example.

This exact reference excerpt shows the dense parameter indexing, stable probability conversion, and logits-first loss interface:

fn logits(&self, features: &[f64]) -> [f64; CLASSES] {
    let mut logits = self.bias;
    for (class, logit) in logits.iter_mut().enumerate() {
        for (feature, &input) in features.iter().enumerate() {
            *logit += self.weights[class * self.in_features + feature] * input
        }
    }
    logits
}
fn probabilities(logits: [f64; CLASSES]) -> [f64; CLASSES] {
    let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    let mut probabilities = logits.map(|logit| (logit - maximum).exp());
    let sum = probabilities.iter().sum::<f64>();
    for probability in &mut probabilities {
        *probability /= sum
    }
    probabilities
}
fn cross_entropy_from_logits(logits: [f64; CLASSES], target: usize) -> f64 {
    let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    (maximum - logits[target])
        + logits
            .iter()
            .map(|logit| (logit - maximum).exp())
            .sum::<f64>()
            .ln()
}

For every example in a minibatch, training computes logits and probabilities, forms logit_gradients[class] = probabilities[class] - 1[class == target], then accumulates weight_gradients[class,feature] += logit_gradient * input and bias_gradients[class] += logit_gradient. These accumulators are sums, like Chapter 9’s dW and dbias. The update multiplies them by learning_rate / minibatch_len, so each step uses the gradient of mean cross-entropy over that minibatch, including a shorter final minibatch. Evaluation separately reports mean cross-entropy over every supplied example.

This is actual optimization of multiclass cross-entropy. No label-derived prediction shortcut exists, and no dummy gradient is substituted. At initialization all weights and biases are zero, so each of ten classes has probability 0.1 and the per-example and dataset-mean losses are both ln 10≈2.3026. Training must reduce that measured objective by learning pixel-to-class weights.

Prediction selects the greatest logit and returns that class index; softmax preserves the same ordering, so the greatest probability names the same class. Accuracy is correct predictions divided by example count. Cross-entropy and accuracy answer different questions: loss notices confidence changes even when the predicted class stays the same; accuracy only notices whether the class is right. Report both.

The generated fixture uses 2×2 images for labels zero, one, and two. It is course-authored and deliberately separable. Its job is to exercise real IDX parsing, batching, softmax, loss, and updates in milliseconds. It says nothing about handwritten-digit quality. Unused output classes remain part of the ten-class competition, so the same model path is used.

Minibatches are visited in fixed order for clarity. That makes tests deterministic, but neighboring rows in a real dataset may be correlated. A production training loop normally shuffles training indices each epoch with a recorded random seed. Validation and test order never affects metrics because those paths make no updates.

Keep the official test set untouched.

If you tune learning rate, epoch count, or preprocessing, carve a validation subset only from the 60,000 official training examples. Choose settings on training and validation data, then inspect the 10,000-image test set once for the final estimate. Repeatedly tuning against test accuracy leaks test information into development.

The preparation tool verifies archive checksums recorded by torchvision’s official MNIST loader, preserves the official test set, and makes a stratified 55,000-example fit set plus 5,000-example validation set from original training rows. A verified one-epoch reference run moved held-out loss from about 2.3026 to 0.3523 and accuracy from 10.0% to 90.1%. These are measured values for this implementation and split, not a guaranteed score.

The program does not download or silently replace missing data. The four paths are explicit. MNIST’s source page records 60,000 training and 10,000 test cases and the IDX layout; review its current terms before redistributing files. To tune, make separate IDX validation files from training data and pass those as the held-out pair during development. Reserve the official t10k files for final evaluation.

One epoch is the default explicit MNIST run to keep intent and runtime visible. A linear model is a useful baseline, not the state of the art. Its weights connect pixels directly to classes, so it cannot form nonlinear combinations such as strokes assembled from several pixel patterns.

Debugging: NaN loss on confident examples

A learner computes exp(logit) directly and later takes ln(probability). It works initially, then produces infinity and NaN.

Answer

Exponentials overflow for large logits, and rounded probabilities can reach zero. Shift logits by their maximum for softmax and calculate the objective as log-sum-exp minus the target logit. The derivative remains probability minus one-hot target.

Transfer: confusion matrix

Add a 10×10 integer matrix whose row is the true label and column the predicted label. Explain what its diagonal and off-diagonal entries mean.

Worked answer

Initialize 100 counters to zero. For each example increment counts[target*10+prediction]. Diagonal cells are correct predictions by class. Off-diagonal cell (r,c) counts true class r mistaken for c, exposing errors hidden by one overall accuracy.

6. Review and transfer

From memory: What do 2051 and 2049 identify? How do images/labels map to features/target? Why subtract the maximum in softmax? What is the logit gradient, and where is it averaged? How do logits, probabilities, and a predicted class differ? Why must validation come from training rather than the official test set?

Answers

They are image and label IDX magic numbers. image(n) returns one normalized feature row; its stored label becomes the target class supplied to the loss. Maximum subtraction prevents overflow without changing probabilities. The per-example logit gradient is probability minus one at the target; summed parameter gradients are divided by minibatch length during the update. Logits are unrestricted scores, softmax probabilities are normalized over ten classes, and prediction is the greatest-logit class index. Keeping test data out of tuning preserves its role as a final estimate.

The linear model now learns from real image files, but each class score remains a weighted sum of raw pixels. Chapter 11 inserts a nonlinear hidden layer, compares momentum and Adam, and preserves complete training state in checkpoints.
