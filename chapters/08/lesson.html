Chapter 7’s gradients were correct but welded to one network. Automatic differentiation separates the chain rule from the model: each scalar operation records how its output was made, then one reverse walk computes every needed derivative.

Milestone

You will build a tiny scalar reverse-mode engine in Rust. It handles branches, shared nodes such as x×x, repeated backward calls, addition, multiplication, and tanh. A finite-difference test checks the result independently.

Code and terminology carried forward

Chapter 7 used forward to cache a network’s intermediate values, then computed parameter gradients for the mean binary cross-entropy over four explicit XOR examples. Its step(data, learning_rate) applies one optimizer update after every parameter gradient has been accumulated. The course conventions keep those meanings.

This chapter removes the fixed network and records scalar operations instead. backward differentiates one selected scalar output through that graph; it does not update parameters or average over a dataset. Each node’s grad field stores its adjoint, the derivative of that output with respect to the node. When the output is a loss and a leaf is a learned weight or bias, that leaf adjoint is a parameter gradient. Input and intermediate adjoints are derivatives too, but they are not parameter gradients.

1. Turn a calculation into a graph

Consider y=x²+x at x=3. Ordinary evaluation produces 12 and forgets how it got there. A computation graph retains the recipe. One leaf holds x. A multiplication node refers to x twice, and an addition node refers to that product and x again. Edges represent value dependencies, not merely the order of source-code lines.

The graph is a directed acyclic graph, or DAG: arrows lead from inputs to later results, and no result eventually depends on itself. It is not always a tree. The x node is shared by three operand positions. That distinction is central. A backward implementation that assumes one parent path will silently lose adjoint contributions.

Graph construction follows ordinary execution. If a branch of Rust code does not run, it creates no operation node. If a loop runs ten times, ten sets of scalar operations appear. This is convenient for learning because the recorded graph matches the concrete calculation, including data-dependent control flow. It also explains the memory cost: intermediates must survive until the reverse pass has consumed them.

Each Value in the project owns a reference-counted pointer to a mutable node. Rc allows several later operations to share the same scalar; RefCell permits adjoint accumulation while Rust still checks borrowing at runtime. The node stores its numerical data, its adjoint in a field named grad, and an operation enum containing parent values. This is a teaching engine for a single thread, so Rc is sufficient.

Draw and evaluate y=x²+x

Label the leaf x=3. The multiply node m=x×x receives two edges from the same leaf and stores m=9. The add node y=m+x stores y=12. The graph has three unique nodes but four operand uses. Counting unique nodes matters for traversal; counting operand uses matters for derivatives.

2. Reverse mode sends an adjoint backward

A node’s adjoint stores how the final scalar output changes with that node: ∂y/∂node. The code exposes this value through grad(), matching the familiar gradient vocabulary used by autodiff libraries. Start the output adjoint at one because ∂y/∂y=1. Then process operations from output toward leaves, multiplying the incoming adjoint by each local derivative.

“Automatic” does not mean numerical approximation or symbolic simplification. The programmer supplies exact local derivative rules once for each operation. The engine composes those rules for whatever graph the program builds. Unlike finite differences, it does not rerun the full function once per parameter; unlike symbolic algebra, it need not produce or simplify a new mathematical expression.

Addition has local derivatives one and one. Multiplication a×b contributes incoming×b to a and incoming×a to b. Tanh contributes incoming×(1−output²) to its input. These small rules know nothing about the whole model. The graph structure composes them through the chain rule.

Reverse the shared graph

The add node starts with adjoint 1. It contributes 1 to m and 1 directly to x. The multiply node m=x×x receives adjoint 1. Its first operand position contributes 1×x=3 to x; its second position contributes another 3. Accumulating all paths gives x.grad=1+3+3=7, matching the symbolic derivative 2x+1 at x=3.

If y=f(u) and u receives several downstream paths, ∂y/∂u = Σpaths k (incoming adjoint)k × (local derivative)k.

The plus sign is essential. Assignment would retain only the last visited path. In neural networks, shared parameters contribute to many examples and positions, so accumulation is the normal case rather than an edge case.

3. Visit each node once, in a valid order

A reverse pass must not process a node until every downstream user has added its contribution. The project first performs a depth-first search from the output. It visits parents, then appends the current node, producing a topological order. Reversing that list places consumers before their dependencies.

A set keyed by the identity of each Rc prevents duplicate visits. For x×x, both operand links point to the same allocation. The multiply rule still adds two contributions, but the traversal later executes the leaf once. Value equality would be the wrong identity test: two separate leaves can both contain 3 while representing independent variables.

Before seeding the output, backward rejects nonfinite intermediate values and clears adjoints on all reachable nodes. It also rejects overflowing adjoints during the reverse walk; a finite final output alone does not prove every intermediate or derivative is finite. This engine therefore treats each call as a fresh derivative calculation. Other libraries sometimes accumulate across backward calls intentionally; their users must call a zeroing operation. Either convention can work, but it must be explicit. The test calls backward twice and expects x.grad to remain 4 for y=x² at x=2 rather than becoming 8.

Mutation has an order.

The reverse loop copies a node’s adjoint and operation before mutating parents. Holding a mutable borrow while recursively borrowing a shared node would trigger a RefCell panic. Short borrow scopes keep the ownership model honest.

4. Build and inspect the Rust engine

Open the complete scalar autodiff project. Operator implementations for Add and Mul calculate forward data immediately and store cloned handles to their operands. tanh does the same. The backward method constructs an order, clears adjoints, seeds the root, and applies three local rules.

fn add_gradient(&self, contribution: f64) {
    self.0.borrow_mut().grad += contribution;
}

The starter and guided exercise expose add_gradient(total: &mut f64, contribution: f64). The reference wraps the same operation as Value::add_gradient(&self, contribution: f64): the standalone total corresponds to self.0.borrow_mut().grad. A shared &self receiver is sufficient because RefCell supplies checked interior mutability. Both forms add one path’s contribution to the node adjoint; assigning instead would erase contributions already delivered through other operand positions.

cargo test --manifest-path projects/ch08/Cargo.toml
cargo run --manifest-path projects/ch08/Cargo.toml

The default prints y=12 and dy/dx=7 for the shared graph, then evaluates tanh(1). The test suite also compares a composed tanh expression against central differences with h=10−5. The acceptance tolerance is absolute 10−6 plus relative 10−4, which allows floating-point rounding without hiding a chain-rule error.

Reverse mode is especially efficient when there is one scalar loss and many parameters. A single reverse sweep obtains all parameter gradients. Forward mode instead propagates a derivative direction alongside values and is attractive when inputs are few and outputs many. A training loss has exactly the shape that favors reverse mode.

This engine intentionally stays scalar. It creates one heap node per arithmetic operation and performs dynamic borrowing. That makes the graph legible, not fast. Chapter 9 introduces contiguous arrays and writes batched kernels directly; production systems combine tensor operations with graph-level differentiation.

The engine also assumes an acyclic graph created through its constructors. Rc reference cycles would leak memory, and a forged cycle would invalidate topological ordering. Private node fields prevent ordinary users from creating either condition. A larger library would need explicit lifetime, thread-safety, and operation-coverage policies, but those concerns do not change the reverse-mode invariant demonstrated here.

Debugging: x² has adjoint 3 instead of 6

At x=3, a learner’s multiplication rule writes a.grad = incoming * b.data and then writes the corresponding value for b. Both handles point to x. Explain the observed result.

Answer

The second assignment overwrites the first contribution. Each operand position contributes 3, so addition should produce an adjoint of 6 for x. Change both parent updates to add_gradient. The visited set should still process the shared node once.

Transfer: add exponentiation by a constant

Add an operation Pow(Value, f64) for finite exponents where the real-valued result and derivative exist. State its local backward rule and test x³ at x=2.

Worked answer

Forward data is xc. The parent contribution is incoming×c×xc−1. For c=3 and x=2, the result is 8 and the derivative is 12. Handle c=0 explicitly as a constant with derivative zero wherever your forward definition accepts it; blindly evaluating 0×x⁻¹ at x=0 creates NaN. Reject or document input/exponent pairs that produce nonfinite real results instead of allowing NaNs to spread.

6. Review and transfer

Retrieve these ideas without code: What does a node adjoint mean? When is it also a parameter gradient? Why is the root seeded with one? Why is a visited set needed? Why must shared paths add? When does clearing occur in this engine?

Answers

A node adjoint is the final output’s derivative with respect to that node. It is a parameter gradient when the output is a loss and the node represents a learned parameter. The output’s derivative with respect to itself is one. The set makes traversal operate on unique graph nodes. Each downstream dependency contributes a term to the total derivative. This engine clears all reachable adjoints at the start of every backward call.

The graph now automates scalar calculus, but thousands of scalar heap nodes are a poor way to process a batch. Chapter 9 gives arrays explicit shapes and derives one dense operation over an entire batch.
