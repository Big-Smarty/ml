Can the program remember how it obtained 12?

At x=3, the calculation x×x+x returns 12. The previous chapter taught you to derive its sensitivity by following each multiplication. Now you will make one reusable reverse pass do that work for any supported scalar graph.

Run just lab 08. Its working baseline records the entire forward calculation and reports sensitivities to the last operation's immediate inputs. For y=m+x, those sensitivities are both one. They are useful local answers, but they are not yet the final derivative through m=x×x. Your goal is to compose local answers all the way to the leaves.

Consider y=x²+x at x=3. Ordinary evaluation produces 12 and forgets how it got there. A computation graph retains the recipe. One leaf holds x. A multiplication node refers to x twice, and an addition node refers to that product and x again. Edges represent value dependencies, not merely the order of source-code lines.

The graph is a directed acyclic graph, or DAG: arrows lead from inputs to later results, and no result eventually depends on itself. It is not always a tree. The x node is shared by three operand positions. That distinction is central. A backward implementation that assumes one parent path will silently lose adjoint contributions.

Graph construction follows ordinary execution. If a branch of Rust code does not run, it creates no operation node. If a loop runs ten times, ten sets of scalar operations appear. This is convenient for learning because the recorded graph matches the concrete calculation, including data-dependent control flow. It also explains the memory cost: intermediates must survive until the reverse pass has consumed them.

The supplied lab uses an append-only Vec<Node>. Each operation stores earlier node IDs and its computed scalar value. A leaf is a supplied input or parameter; an operation node remembers addition, multiplication or tanh. Shared dependencies reuse one ID. Storage, validation and traversal are provided in tape.rs, so your work is the differentiation algorithm rather than Rust pointer ownership.

Why do three paths into x give a derivative of seven?

A node’s adjoint stores how the final scalar output changes with that node: ∂y/∂node. The code exposes this value through its grad field, matching the familiar gradient vocabulary used by autodiff libraries. Start the output adjoint at one because ∂y/∂y=1. Then process operations from output toward leaves, multiplying the incoming adjoint by each local derivative.

“Automatic” does not mean numerical approximation or symbolic simplification. The programmer supplies exact local derivative rules once for each operation. The engine composes those rules for whatever graph the program builds. Unlike finite differences, it does not rerun the full function once per parameter; unlike symbolic algebra, it need not produce or simplify a new mathematical expression.

Addition has local derivatives one and one. Multiplication a×b contributes incoming×b to a and incoming×a to b. Tanh contributes incoming×(1−output²) to its input. These small rules know nothing about the whole model. The graph structure composes them through the chain rule.

Reverse the shared graph

The add node starts with adjoint 1. It contributes 1 to m and 1 directly to x. The multiply node m=x×x receives adjoint 1. Its first operand position contributes 1×x=3 to x; its second position contributes another 3. Accumulating all paths gives x.grad=1+3+3=7, matching the symbolic derivative 2x+1 at x=3.

If y=f(u) and u receives several downstream paths, ∂y/∂u = Σpaths k (incoming adjoint)k × (local derivative)k.

The plus sign is essential. Assignment would retain only the last visited path. In neural networks, shared parameters contribute to many examples and positions, so accumulation is the normal case rather than an edge case.

What makes the supplied order safe for shared nodes?

Retrieve the difference between counting unique nodes and counting operand uses. The first controls traversal; the second controls how many derivative contributions must be added. We now inspect why a single reverse sweep is valid.

Every appended operation refers only to earlier node IDs. This insertion order is a topological order: dependencies precede their consumers. Its reverse guarantees that all consumers have contributed before a node's own rule executes. For node IDs x=0, m=1, y=2, the reverse order is [2,1,0]. If an unrelated node 3 was appended later, differentiating y must not seed or visit it.

The supplied preparation code marks the root reachable and walks earlier IDs in reverse. Every reached operation marks its parents. The resulting list contains each reachable ID once. It validates that each parent ID is earlier than its consumer, rejecting a forged cycle or forward reference. This is the same dependency invariant as a depth-first topological traversal, but append-only construction makes a separate recursive search unnecessary.

This lab clears all node adjoints on every call, including unrelated nodes, then seeds the chosen root. That explicit convention makes repeated calls fresh derivative calculations. Training systems sometimes intentionally accumulate across batches instead; their optimizers must clear buffers at a documented boundary. Neither convention lets stale values masquerade as the new derivative.

Ordering counterexample

Suppose x feeds u and v, then y=u+v. Processing x after u but before v would propagate only part of its incoming adjoint to its own parents. Sorting by source-code proximity or visiting every edge recursively can do this. Consumer-before-parent ordering and accumulation together prevent the error.

Change the selected root from y=x²+x to m=x² after one completed backward call. Predict x.grad=2x and verify that the former y adjoint is now zero. This changed-root experiment distinguishes fresh differentiation from accidental accumulation.

When is automatic differentiation the right tool?

A single reverse sweep obtains many leaf derivatives from one scalar output, matching the common training case of one loss and many parameters. Forward-mode differentiation carries a chosen input direction alongside the forward values and can be preferable with few inputs and many outputs. Both use local analytical derivative rules. Finite differences instead rerun perturbed calculations, and symbolic algebra manipulates expressions. “Automatic” describes composition, not magic or approximate slopes.

The append-only tape retains intermediate values until backward. It is scalar, allocates one node per operation and supports three operations. That makes it inspectable rather than fast. Production systems differentiate whole tensor kernels to avoid millions of scalar nodes. Appending operations from Rust loops records the iterations that actually execute; a branch that does not run leaves no nodes. A derivative therefore describes the executed path, which needs care around branch boundaries.
