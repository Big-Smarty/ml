## Claim-to-source notes

| Claim or design decision | Primary evidence and bounded interpretation |
| --- | --- |
| A production ML workflow is a dependency graph with explicit validation and deployment gates. | The [TFX User Guide](https://www.tensorflow.org/tfx/guide) describes a pipeline as a sequence of components, including data ingestion, statistics, schema generation, anomaly validation, training, evaluation, infrastructure validation, and pushing a model to serving. It also recommends using the same preprocessing for training and inference to reduce training-serving skew. The chapter can therefore present a small ordered pipeline and an explicit “validated before activation” gate; it should not imply that a hand-written local pipeline has TFX’s orchestration or scale. |
| Data, code, pipeline stages, and outputs need versioned links for reproducible reruns. | DVC’s [command reference](https://dvc.org/doc/command-reference/) documents the core workflow: initialize a project, track data with `dvc add`, codify dependencies and outputs in `dvc.yaml`, reproduce or restore a pipeline with `dvc repro`, and share cached artifacts with `dvc push`/`dvc pull`. The chapter’s local equivalent should record a data version and pipeline/config version beside the model; this is the transferable invariant, not a claim that the project implements DVC. |
| A resume-capable checkpoint contains more than model weights. | PyTorch’s official [Saving and Loading Models](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html) guide distinguishes a model `state_dict` from a general checkpoint and shows saving `epoch`, `model_state_dict`, `optimizer_state_dict`, and `loss`. It explains that optimizer state includes buffers and parameters updated during training. The chapter should use a compact versioned checkpoint with model parameters, optimizer state (if present), training step, and loss; format/version, dimensions, finite-value checks, and a checksum are engineering safeguards added by the course, not requirements asserted by this source. |
| HTTP serving needs explicit method, retry, and status semantics. | [RFC 9110, HTTP Semantics](https://datatracker.ietf.org/doc/html/rfc9110) defines method semantics and says that `PUT`, `DELETE`, and safe methods are idempotent; it cautions that clients should not automatically retry non-idempotent requests without knowing whether the effect was applied. The miniature service can expose `GET /health` and `POST /predict`, return a success response only after a validated prediction, and make malformed input and unavailable model states distinct errors. The exact endpoint and status mapping is the chapter’s application design, not a new HTTP standard. |
| Validate the request structure before model execution and keep semantic checks in application code. | The [JSON Schema Draft 2020-12 Validation specification](https://json-schema.org/draft/2020-12/json-schema-validation) defines assertions over JSON instance structure, including type, required properties, bounds, and array/object constraints. It explicitly distinguishes `format` annotation from optional format assertion and recommends application-level semantic validation when schema support is insufficient. The chapter should reject malformed JSON, missing or extra fields as specified by its contract, non-finite numbers, wrong dimensions, and out-of-range values before inference; a schema alone is not evidence that a model-safe request was received. |
| Monitoring request data can detect anomalies, training-serving skew, and drift; a model alias can provide a reversible release handle. | The TFX guide states that TFDV can monitor new inference-request data for anomalies or drift and can inform retraining; it also documents schemas for types, presence, and ranges. The [MLflow Model Registry workflow](https://mlflow.org/docs/latest/ml/model-registry/workflow) documents immutable model versions, aliases that identify a deployed version, reassignment of an alias, and loading by alias. Together these support a small monitor that stores request summaries against a reference window and a rollback that switches the active version pointer back to a known checkpoint. An alias change is a control-plane operation; the course must explicitly reload or restart its local process and verify health rather than claiming that every serving runtime updates atomically. |

## Sources

1. TensorFlow, [“The TFX User Guide”](https://www.tensorflow.org/tfx/guide) — pipeline components, schemas, validation, shared preprocessing, serving, and monitoring inference data for anomalies or drift.
2. Data Version Control, [“Command Reference”](https://dvc.org/doc/command-reference/) — data tracking, `dvc.yaml` stages, reproduction, and remote artifact transfer.
3. PyTorch, [“Saving and Loading Models”](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html) — model state dictionaries and the additional optimizer/step/loss state needed by a general checkpoint.
4. IETF, [RFC 9110: HTTP Semantics](https://datatracker.ietf.org/doc/html/rfc9110) — method safety/idempotency and retry semantics for an HTTP service.
5. JSON Schema, [“JSON Schema Validation: A Vocabulary for Structural Validation of JSON, Draft 2020-12”](https://json-schema.org/draft/2020-12/json-schema-validation) — structural assertions and the limits of `format` validation.
6. MLflow, [“Model Registry Workflows”](https://mlflow.org/docs/latest/ml/model-registry/workflow) — model versions, aliases, alias reassignment, and loading a version by alias.

## Bounded miniature limitations

- The course service is a local, single-process teaching implementation. It does not establish production guarantees for concurrency, TLS, authentication, durable metrics, autoscaling, or multi-node rollout.
- A small reference-window drift statistic demonstrates the control loop but cannot establish model degradation, causality, fairness, or population-wide data quality. Thresholds require domain validation and labeled outcome monitoring.
- A checkpoint can preserve the state needed by this project’s deterministic resume path, but floating-point kernels, hardware, library versions, and nondeterministic execution can still prevent bitwise cross-platform reproduction.
- Rollback is limited to selecting a previously validated local artifact, atomically replacing the active pointer where the filesystem permits, restarting or reloading the service, and checking health. It does not model canary traffic, distributed transactions, or automatic rollback policy.

## Astra High final implementation audit (2026-09-08)

Luna High reverified the six cited primary URLs. The reference supports fresh deterministic linear fitting and an inference artifact, **not resumable optimizer training**. There is no `/health` endpoint, deployment registry, or unavailable-model response: load errors stop startup; requests return 200 or 400. The canary chooses the previous object before saving/loading it; no model alias, pointer service, or live swap is implemented. Mean drift is now also connected to successful real HTTP requests and logged with cumulative count/mean; the no-argument demo exercises a fixed synthetic window. Health verification in prose means a valid inference probe after restart. Earlier source-table descriptions of larger systems are background, not claims that this reference implements their APIs. Artifact loading is bounded to 1024 bytes and saving validates before writing.
