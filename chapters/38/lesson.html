Adapt each parameter's update scale

AdamW maintains a first moment m, an exponential average of gradients, and second moment v, an exponential average of squared gradients. At step t, mₜ=β₁mₜ₋₁+(1−β₁)gₜ and vₜ=β₂vₜ₋₁+(1−β₂)gₜ². Both operations are elementwise over the full parameter vector.

Because moments start at zero, early values are biased low. Correct with m̂=m/(1−β₁ᵗ) and v̂=v/(1−β₂ᵗ). The adaptive update is m̂/(√v̂+ε). The reference uses β₁=0.9, β₂=0.999, and ε=10⁻⁸, all stored in the checkpoint.

AdamW applies weight decay separately: θ←θ−η[adaptive+λθ]. The data objective remains Chapter 36's mean next-token cross-entropy. train_accumulated returns that data loss, and λθ is absent from both the returned scalar and the gradient moments. Adding an L2 penalty to the data objective would instead send its gradient through Adam's adaptive normalization. The reference decays every flat parameter for compactness. Many larger recipes exclude normalization gains and biases; that policy should be explicit and would use Chapter 36's named parameter spans.

First AdamW update

Let gradient g=0.2, β₁=0.9, β₂=0.999, parameter θ=2, λ=0.01, η=0.001. Moments become m=0.02 and v=0.00004. Bias corrections give m̂=0.2 and v̂=0.04. Ignoring tiny ε, adaptive term is 1. Decay term is 0.02. New parameter is 2−0.001×1.02=1.99898.

Which gradients belong to the same update?

Retrieve: a mean over four targets and a mean over two targets do not have equal weight. If losses are 2 and 5, the combined loss is (4×2+2×5)/6=3. If their gradient vectors are [3,0] and [0,6], the combined gradient is [2,2]. The new lab supports these unequal document tails; the historical reference described below only accumulates equal-size windows.

Compare with the preserved equal-size trainer

Activation memory grows with sequence length, width, and layers. Gradient accumulation approximates a larger batch without keeping every microbatch's activations alive simultaneously. Compute one microbatch loss and gradient, add its gradient divided by the number of equal-sized microbatches, release its intermediates, and update only after all are processed.

The public method uses one tokens value for every microbatch, so each microbatch has exactly T next-token targets. With M microbatches, one optimizer update represents M×T targets and advances the cursor by T after each microbatch. Dividing each mean gradient by M therefore gives the mean over all M×T targets. The returned scalar is the same equal-microbatch average of the data losses.

This interface does not accept unequal microbatches. An extension with target counts Tᵢ must combine microbatch mean gradients as ΣTᵢgᵢ/ΣTᵢ and apply the same weighting to their data losses. Averaging those means equally would give shorter microbatches too much influence.

Average two gradients

Two equal microbatches produce gradients [3,4] and [1,−2]. Their accumulated average is [(3+1)/2,(4−2)/2]=[2,1]. Updating after the first and then computing the second at changed weights would be two optimizer steps and would not match this effective batch.

Clipping happens after accumulation. Compute global norm ||g||₂=√Σgᵢ². If it exceeds limit c, multiply every component by c/||g||₂. Clipping each microbatch separately or each parameter tensor separately changes the direction and effective threshold.

Clip one vector

For g=[3,4], norm is 5. With limit one, scale is 1/5. Clipped gradient is [0.6,0.8], whose norm is one. With limit ten, leave the vector unchanged.

step counts completed AdamW updates, and total_steps configures that unit. The project exposes no epoch counter: an epoch would mean one pass through the chosen training examples, while this tiny deterministic demonstration cycles fixed-length windows by cursor. Changing M changes tokens processed per optimizer step without changing the meaning of step.

When should we bound a large gradient?

Global clipping changes one vector’s length while preserving its direction. [3,4] has norm 5; limit 1 multiplies both components by 1/5. Compute the norm in f64 even for f32 gradients so squaring a large finite f32 value does not overflow. Accumulate first, clip once, update once. The clipped gradient bounds the input to Adam; it does not guarantee the adaptive parameter step has that same norm.

Follow one update and its recovery boundary

Suppose two equal-sized microbatches produce gradient vectors [3,0] and [0,4] at the same parameter values. Their average is [1.5,2], whose Euclidean norm is 2.5. With clipping limit one, multiply both coordinates by 1/2.5 to obtain [0.6,0.8]. Clipping the separate vectors first would produce [1,0] and [0,1], whose average [0.5,0.5] has a different direction and magnitude. Accumulation and clipping therefore cannot be freely reordered.

Feed [0.6,0.8] into initially zero Adam moments with β₁=0.9 and β₂=0.999. The new first moment is [0.06,0.08]; the second is [0.00036,0.00064]. Bias correction divides by 0.1 and 0.001 respectively, recovering [0.6,0.8] and [0.36,0.64]. Ignoring only the tiny epsilon for this hand calculation, each adaptive update component is one. This shows why clipping the raw gradient need not bound Adam's final parameter-step norm to the same limit. The learning rate and adaptive denominator still determine the actual update.

Use f64 while computing the squared global norm even though stored gradients are f32. A finite f32 gradient can have a square that overflows f32; then an apparent infinite norm would give scale zero and silently erase the update. The reference accumulates squares in f64 and validates the result before scaling. After clipping, it checks every proposed moment and parameter before committing any of them. Finiteness alone is insufficient for restored second moments: a negative finite value also violates the optimizer invariant.

The scheduler argument is the number of completed updates before the next update begins. With four warmup steps and peak learning rate one, arguments zero through three produce 0.25, 0.5, 0.75, and 1. The cosine branch begins at argument four with the same peak. At argument total_steps it reaches the minimum, and later arguments remain there. If warmup occupies the entire schedule, there is no cosine interval: the endpoint explicitly switches to the minimum. These conventions are implemented and tested, so a saved step number has one unambiguous interpretation.

Exact continuation also requires preserving call-level choices. The checkpoint records model and optimizer configuration, but the caller supplies tokens per microbatch and microbatches per update again when training resumes. Record and reuse those choices along with the same token stream. A bound fingerprint checks the data on the next training call; it does not encode every experiment setting. The preserved example’s stored RNG is advanced by that deterministic training example as an explicit state bookmark, while window selection itself follows the saved cursor rather than a random shuffle.

File replacement has a separate ownership rule. If exclusive creation of the temporary sibling fails, that file belongs to another writer and must remain untouched. Only after successful creation may this save operation clean up its own file on failure. The regression test plants sentinel contents and requires them to survive. Successful writing synchronizes the file before rename; the example does not synchronize the parent directory or attach a checksum. Next-step equality tests establish state restoration within the stated executable, rather than guaranteeing recovery from every possible storage failure.

Which step selects the next learning rate?

Four warmup updates with peak rate 1 use rates 0.25,0.5,0.75,1 at completed-step indices 0,1,2,3. Cosine decay begins at completed step 4. With minimum 0.1 and total 12, the halfway decay rate at step 8 is 0.55. At step 12 and later it is 0.1. These index choices are part of the experiment, not a universal scheduler convention.

Change learning rate with training progress

Warmup raises the learning rate linearly for the first configured optimizer steps. It avoids applying the full peak learning rate while moments and hidden statistics are newly initialized. After warmup, cosine decay moves smoothly from peak ηmax to minimum ηmin. In the code, these two hyperparameters are peak_learning_rate and min_learning_rate:

η(t)=ηmin + ½(ηmax−ηmin)[1+cos(πp)]

Here p is progress from zero to one through the decay interval. The implementation clamps p, so training beyond the planned total stays at the minimum. Step definition matters: the scheduler advances once per optimizer update, not once per microbatch.

Read the cosine

With ηmax=0.002, ηmin=0.0002, and p=0.5, cos(π/2)=0. The learning rate is 0.0002+0.5×0.0018=0.0011. At p=0 it is 0.002; at p=1 it is 0.0002. These schedule values do not establish the best learning rate for another model.

Resume the exact next step

Checkpoint keeps the Chapter 11 definition: a model-only snapshot can support inference, while exact training resume needs every state item that can affect the next update. Chapter 38 implements the exact-resume form. It stores architecture dimensions, all parameters, first and second moments, optimizer hyperparameters, current optimizer step, data cursor, RNG state, and training-data fingerprint. Its versioned magic header is CH38LM02. The loader validates dimensions, expected parameter count, exact file length, finite floating-point values, and nonzero RNG state.

The save writes a sibling temporary file and renames it into place after writing and synchronizing the full byte sequence. This reduces the chance that interruption leaves a partially written file at the requested path. Filesystem durability and cross-device rename behavior still depend on the platform; production systems may add parent-directory synchronization, checksums, and retained generations.

The strongest small resume test branches one trainer into two paths. Path A saves and continues. Path B loads and performs the same next accumulated step. The test requires identical loss bits, parameters, both moment vectors, step, data identity, cursor, RNG, and next learning rate afterward. Merely checking that a loaded model produces the same current logits would miss optimizer or progress state.

The preserved trainer checkpoint also stores a stable fingerprint of its training token sequence. A newly created trainer uses fingerprint zero to mean unbound. Saving before any training preserves that unbound state, so its first training call chooses the data identity. Once a nonzero fingerprint is stored, a resumed update rejects a different fingerprint before advancing state. This small 64-bit hash is an accidental-change check, not cryptographic proof of identical data. This catches accidental corpus replacement while preserving evaluation-only loads. A production experiment should bind tokenizer and provenance-manifest identities too.

How much storage is hidden behind the parameter count?

For P f32 parameters, weights need 4P bytes; two Adam moments add 8P. A gradient adds another 4P before activations, temporary proposals, checkpoint serialization and allocator overhead. Attention probabilities in this implementation use L×H×T² floats. Doubling context quadruples that term; it does not quadruple every part of model memory.

Account for memory before scaling

For P f32 parameters, model weights occupy 4P bytes. Adam moments m and v add 8P, so persistent model-plus-optimizer storage is 12P before gradients, activations, allocator overhead, and GPU staging. The 14,442,496-parameter configuration therefore needs 173,309,952 bytes for these three buffers alone.

Training activations depend on T, D, F, heads, and layers. Attention probabilities alone are layers×heads×T×T floats in this straightforward implementation. Doubling context can quadruple that component. Measure process memory or device allocation for a real run; a formula is a budget estimate, not a measured peak.
