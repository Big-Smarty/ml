A decoder that learns one tiny batch is not yet a dependable training run. Larger work needs an optimizer that handles uneven gradient scales, a learning-rate schedule, accumulation across microbatches, clipping, memory accounting, and a checkpoint that resumes the exact next update.

Goal

Train Chapter 36's complete decoder with AdamW, cosine decay and warmup, global gradient clipping, deterministic data progress, and versioned checkpoints containing model, optimizer, scheduler, RNG, and cursor state.

1. Adapt each parameter's update scale

AdamW maintains a first moment m, an exponential average of gradients, and second moment v, an exponential average of squared gradients. At step t, mₜ=β₁mₜ₋₁+(1−β₁)gₜ and vₜ=β₂vₜ₋₁+(1−β₂)gₜ². Both operations are elementwise over the full parameter vector.

Because moments start at zero, early values are biased low. Correct with m̂=m/(1−β₁ᵗ) and v̂=v/(1−β₂ᵗ). The adaptive update is m̂/(√v̂+ε). The reference uses β₁=0.9, β₂=0.999, and ε=10⁻⁸, all stored in the checkpoint.

AdamW applies weight decay separately: θ←θ−η[adaptive+λθ]. This differs from adding an L2 penalty gradient before Adam because adaptive normalization would rescale that penalty. The reference decays every flat parameter for compactness. Many larger recipes exclude normalization gains and biases; that policy should be explicit and would use Chapter 36's named parameter spans.

First AdamW update

Let gradient g=0.2, β₁=0.9, β₂=0.999, parameter θ=2, λ=0.01, η=0.001. Moments become m=0.02 and v=0.00004. Bias corrections give m̂=0.2 and v̂=0.04. Ignoring tiny ε, adaptive term is 1. Decay term is 0.02. New parameter is 2−0.001×1.02=1.99898.

2. Change learning rate with training progress

Warmup raises the rate linearly for the first configured steps. It avoids applying the full peak rate while moments and hidden statistics are newly initialized. After warmup, cosine decay moves smoothly from peak ηmax to minimum ηmin:

η(t)=ηmin + ½(ηmax−ηmin)[1+cos(πp)]

Here p is progress from zero to one through the decay interval. The implementation clamps p, so training beyond the planned total stays at the minimum. Step definition matters: the scheduler advances once per optimizer update, not once per microbatch.

Read the cosine

With ηmax=0.002, ηmin=0.0002, and p=0.5, cos(π/2)=0. The rate is 0.0002+0.5×0.0018=0.0011. At p=0 it is 0.002; at p=1 it is 0.0002. These are schedule values, not evidence that this rate is optimal for every model.

Resume must restore the optimizer step before asking for the next rate. Saving only model weights and restarting the schedule can create a discontinuous update even when predictions initially match.

3. Accumulate microbatches before one update

Activation memory grows with sequence length, width, and layers. Gradient accumulation approximates a larger batch without keeping every microbatch's activations alive simultaneously. Compute one microbatch loss and gradient, add its gradient divided by the number of equal-sized microbatches, release its intermediates, and update only after all are processed.

If microbatches contain different token counts, weight by tokens rather than averaging batch averages equally. The reference requires equal configured token length, so dividing by the microbatch count equals a token-average gradient. It advances a deterministic data cursor after each microbatch.

Average two gradients

Two equal microbatches produce gradients [3,4] and [1,−2]. Their accumulated average is [(3+1)/2,(4−2)/2]=[2,1]. Updating after the first and then computing the second at changed weights would be two optimizer steps and would not match this effective batch.

Clipping happens after accumulation. Compute global norm ||g||₂=√Σgᵢ². If it exceeds limit c, multiply every component by c/||g||₂. Clipping each microbatch separately or each parameter tensor separately changes the direction and effective threshold.

Clip one vector

For g=[3,4], norm is 5. With limit one, scale is 1/5. Clipped gradient is [0.6,0.8], whose norm is one. With limit ten, leave the vector unchanged.

4. Account for memory before scaling

For P f32 parameters, model weights occupy 4P bytes. Adam moments m and v add 8P, so persistent model-plus-optimizer storage is 12P before gradients, activations, allocator overhead, and GPU staging. The 14,442,496-parameter configuration therefore needs 173,309,952 bytes for these three buffers alone.

Training activations depend on T, D, F, heads, and layers. Attention probabilities alone are layers×heads×T×T floats in this straightforward implementation. Doubling context can quadruple that component. Measure process memory or device allocation for a real run; a formula is a budget estimate, not a measured peak.

The program prints its exact persistent byte count. For throughput, use a release build, fixed data, a warmup period, and enough repeated updates. Report tokens per second with CPU or GPU model, precision, dimensions, microbatch count, and whether checkpoint I/O lies inside timing. The default prints calculated storage and observed losses; measuring throughput is the separate procedure described here.

5. Resume the exact next step

A resumable training checkpoint stores architecture dimensions, all parameters, first and second moments, optimizer hyperparameters, current optimizer step, data cursor, RNG state, and training-data fingerprint. It has a versioned magic header. The loader validates dimensions, expected parameter count, exact file length, finite floating-point values, and nonzero RNG state.

The save writes a sibling temporary file and renames it into place after writing and synchronizing the full byte sequence. This reduces the chance that interruption leaves a partially written file at the requested path. Filesystem durability and cross-device rename behavior still depend on the platform; production systems may add parent-directory synchronization, checksums, and retained generations.

The strongest small resume test branches one trainer into two paths. Path A saves and continues. Path B loads and performs the same next accumulated step. The test requires identical loss bits, parameters, both moment vectors, step, data identity, cursor, RNG, and next learning rate afterward. Merely checking that a loaded model produces the same current logits would miss optimizer or progress state.

The checkpoint also stores a stable fingerprint of the training token sequence. On the first update, the trainer binds that fingerprint. A resumed update rejects different data before advancing state. This catches accidental corpus replacement while preserving evaluation-only loads. A production experiment should bind tokenizer and provenance-manifest identities too.

cargo test --offline --manifest-path projects/ch38/Cargo.toml
cargo run --release --offline --manifest-path projects/ch38/Cargo.toml

The reference run uses the complete Chapter 36 model, accumulates two microbatches, trains briefly, saves, reloads, and prints persistent memory. The library implements reusable Trainer. GPU feature methods use the Chapter 36 GPU backward route and retain the same optimizer logic on CPU.

Failures must leave state coherent. The implementation validates all proposed Adam moments and parameters in one pass, then commits them in a second pass. Cursor, RNG, and step advance only after the update succeeds. Otherwise one nonfinite element late in the vector could leave a half-updated model.

Resume equivalence has a defined boundary. Within the same executable and CPU arithmetic, the test requires exact bits. Moving between CPU and GPU or changing reduction order can produce valid rounding differences, so cross-backend verification uses tolerances and compares loss trends. Deterministic seeds do not override floating-point execution order.

Test optimizer arithmetic independently from the full model. With one parameter θ=2, gradient 0.2, η=0.001, and decay 0.01, the first-step result should match 1.99898 within the stated epsilon convention. A schedule test checks the first warmup rate, peak, and decay endpoint. An accumulation test compares two microbatches with an explicitly averaged gradient. These narrow checks make a failed end-to-end run easier to diagnose.

Corrupt-file tests should fail before allocating from untrusted dimensions. The loader reads a bounded file, calculates the checked parameter count, and requires remaining bytes to equal exactly three f32 arrays. A negative second moment is invalid even though it is finite, because square-gradient averages cannot be negative and their square root would fail later.

Follow one update and its recovery boundary

Suppose two equal-sized microbatches produce gradient vectors [3,0] and [0,4] at the same parameter values. Their average is [1.5,2], whose Euclidean norm is 2.5. With clipping limit one, multiply both coordinates by 1/2.5 to obtain [0.6,0.8]. Clipping the separate vectors first would produce [1,0] and [0,1], whose average [0.5,0.5] has a different direction and magnitude. Accumulation and clipping therefore cannot be freely reordered.

Feed [0.6,0.8] into initially zero Adam moments with β₁=0.9 and β₂=0.999. The new first moment is [0.06,0.08]; the second is [0.00036,0.00064]. Bias correction divides by 0.1 and 0.001 respectively, recovering [0.6,0.8] and [0.36,0.64]. Ignoring only the tiny epsilon for this hand calculation, each adaptive update component is one. This shows why clipping the raw gradient need not bound Adam's final parameter-step norm to the same limit. The learning rate and adaptive denominator still determine the actual update.

Use f64 while computing the squared global norm even though stored gradients are f32. A finite f32 gradient can have a square that overflows f32; then an apparent infinite norm would give scale zero and silently erase the update. The reference accumulates squares in f64 and validates the result before scaling. After clipping, it checks every proposed moment and parameter before committing any of them. Finiteness alone is insufficient for restored second moments: a negative finite value also violates the optimizer invariant.

The scheduler argument is the number of completed updates before the next update begins. With four warmup steps and peak rate one, arguments zero through three produce 0.25, 0.5, 0.75, and 1. The cosine branch begins at argument four with the same peak. At argument total_steps it reaches the minimum, and later arguments remain there. If warmup occupies the entire schedule, there is no cosine interval: the endpoint explicitly switches to the minimum. These conventions are implemented and tested, so a saved step number has one unambiguous interpretation.

Exact continuation also requires preserving call-level choices. The checkpoint records model and optimizer configuration, but the caller supplies tokens per microbatch and microbatches per update again when training resumes. Record and reuse those choices along with the same token stream. The fingerprint rejects changed data on the next training call; it does not encode every experiment setting. The stored RNG is advanced by this deterministic training example as an explicit state bookmark, while window selection itself follows the saved cursor rather than a random shuffle.

File replacement has a separate ownership rule. If exclusive creation of the temporary sibling fails, that file belongs to another writer and must remain untouched. Only after successful creation may this save operation clean up its own file on failure. The regression test plants sentinel contents and requires them to survive. Successful writing synchronizes the file before rename; the example does not synchronize the parent directory or attach a checksum. Next-step equality tests establish state restoration within the stated executable, rather than guaranteeing recovery from every possible storage failure.

If gradients g₄ and g₂ are each averages within their own batch, combined gradient is (4g₄+2g₂)/6. The simple mean (g₄+g₂)/2 gives the shorter batch too much influence.

7. Review and transfer

Explain moment bias correction, decoupled decay, schedule step, accumulation normalization, clipping order, memory terms, and exact resume state. Why can two correct GPU runs differ in final bits?

Answers

Moments start at zero, so divide by missing mass. AdamW applies λθ outside adaptive moments. Advance schedule per update. Weight accumulation by tokens, then clip the combined vector. Persistent f32 AdamW storage is 12P bytes before other buffers. Reduction order and fused operations can change rounding without changing the algorithm.
