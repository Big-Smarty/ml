An autoregressive language model applies classification to the next token: after a piece of text, it assigns probabilities to the possible continuations in its vocabulary. We begin with bytes, counts, and a trainable embedding model so that every part of this prediction can be inspected.

Goal

Train a real next-byte predictor on course-authored text. You will compare byte and Unicode-character n-grams, calculate cross-entropy by hand, and update both an embedding table and an output matrix.

Code and terminology carried forward

Chapter 23 turned adjacent scalar values into sequence-regression examples: its model predicted one numerical value and loss averaged squared error over the supplied sequence. This chapter keeps the adjacent-example construction and explicit data argument, but changes the task to classification. Each input byte and following target byte is a discrete class ID from 0 through 255. Model::logits returns 256 raw scores, Model::probabilities normalizes them, and Model::predict returns the class ID with the largest score. Accordingly, Model::loss now averages next-byte cross-entropy instead of mean squared error.

Chapter 24 owns the broad definition of embedding: a learned vector may come from an ID lookup or from an encoder. Chapter 33 uses the lookup case, with one row per byte ID. Chapter 32 used f32 arrays for GPU kernels; this checkpoint keeps f32 but returns to a small CPU reference so the language-model arithmetic is visible before later acceleration. The standard names data, target, loss, step, predict, and learning_rate follow the course code and terminology guide.

1. Turn text into supervised examples

A byte is an integer from 0 through 255. UTF-8 represents every text string as bytes, so a byte vocabulary has complete coverage without an unknown-token escape hatch. For the byte string rust, next-token training creates three examples: r → u, u → s, and s → t. The input is the earlier byte and the target is the following byte. Both are stored as u8 class IDs. The target ID selects which of the 256 output probabilities should be high; it is not itself a probability or a numerical quantity to regress toward. During evaluation the target remains hidden until after the model has predicted it.

With a longer context, the input is a prefix rather than one byte. If context length is three, rus → t is one example. Chapter 35 will learn how to combine an entire prefix. This chapter deliberately starts with one preceding token because it makes the loss and every gradient small enough to trace. It is still an actual language model: it produces a normalized distribution over next tokens and learns that distribution from text.

Character and byte units differ. The string é is one Unicode scalar value but two UTF-8 bytes, hexadecimal C3 A9. A character bigram treats é! as one pair; a byte bigram sees C3→A9 and A9→21. Neither choice is universally correct. Characters align better with what readers perceive, while bytes guarantee a fixed vocabulary and preserve arbitrary input. Grapheme clusters such as a letter plus combining accent can contain several scalar values, so even “character” needs a precise definition.

Make the training rows

For aba, the observed pairs are a→b and b→a. If the corpus is ababa, a→b occurs twice and b→a occurs twice. There are four training targets, not five, because the final byte has no following byte inside this document. Joining unrelated documents would invent a transition from one document's last byte to another document's first. Chapter 37 later cleans, deduplicates, and splits whole documents, but it does not construct token windows. A downstream training-data consumer must keep those document records separate and call windows(2) within each document so no example crosses a boundary.

2. Counts are the first language model

An n-gram is a contiguous sequence of n units. A bigram contains two units; a trigram contains three. A count-based bigram model records C(x,y), the number of times token y follows token x. Its maximum-likelihood prediction is p(y|x)=C(x,y)/ΣᵥC(x,v). The denominator sums counts for all possible successor tokens v.

Normalize successor counts

Suppose a is followed by b three times and by c once. The total is four. The model assigns p(b|a)=3/4=0.75 and p(c|a)=1/4=0.25. Every other byte receives zero probability. If the held-out sequence contains a→d, negative log probability is infinite. Add-one smoothing would change each count to C+1, avoiding zero, but it also spreads substantial mass over 256 outcomes. We keep raw counts here to expose this failure rather than hiding it.

More context can distinguish patterns that a bigram merges. A trigram model estimates p(z|x,y). Yet the number of possible histories grows as V^(n−1), where V is vocabulary size. Most histories are absent even in a large corpus. This sparse-table problem motivates learned representations: related contexts can share parameters rather than owning unrelated counters.

The reference program computes both byte bigrams and Unicode-character trigrams. Rust's as_bytes() exposes UTF-8 bytes. The chars() iterator yields Unicode scalar values. The code names both units instead of calling either one simply “characters.” Inspecting units before training is an inexpensive defense against silent tokenization mistakes.

3. Replace a token ID with learned coordinates

An embedding table E has shape [V,D]: V rows, one per token, and D columns called the embedding width. Looking up byte x selects row E[x,:]. The row is a dense vector of learned f32 values. An output matrix W has shape [D,V], and bias b has shape [V]. Logits are z=E[x,:]W+b. A logit is an unnormalized score; softmax turns all V scores into probabilities.

Here V=256. Rust stores E and W contiguously in row-major order. embeddings[input * width + h] selects coordinate h of the input byte's row, while output_weights[h * 256 + class_id] selects the weight from coordinate h to one output class. A logit may be negative or greater than one. A probability lies from zero to one, and all 256 probabilities sum to one. predict returns the winning u8 class ID; displaying that byte as a character is a separate presentation step.

This output projection keeps row-major weights in [in_features,out_features] = [D,V] order to expose the row-vector multiplication E[x,:]W. Earlier dense layers stored [out_features,in_features] and computed input×weights-transpose. The mapping is output_weights[h*V+class_id] = earlier_weights[class_id*D+h]. The formula is unchanged; the stored transpose is explicit. The Rust field is output_weights because it stores learned parameters, while logits stores the computed scores.

The lookup does not claim byte 97 is numerically close to byte 98. IDs are addresses. Learning moves rows so bytes useful in similar predictive situations can acquire useful directions. Only rows observed as inputs receive an embedding gradient in this one-step model. Every output column can receive a gradient because the softmax compares the target against every alternative.

Trace a two-token vocabulary

Let V=2, D=2, E[a]=[1,2], and W=[[1,−1],[0.5,0.5]], with zero bias. The logits after a are [1×1+2×0.5, 1×(−1)+2×0.5]=[2,0]. Softmax subtracts max 2, giving exponentials [1,e^(−2)]≈[1,0.1353]. Their sum is 1.1353, so probabilities are approximately [0.8808,0.1192]. If target b is index 1, loss is −ln(0.1192)≈2.1269.

The logit gradient is probability minus one-hot target: [0.8808,−0.8808]. Therefore ∂L/∂E[a]=gWᵀ=[1.7616,0]. The first embedding coordinate must move down under gradient descent. The output gradient is the outer product E[a]ᵀg, producing [[0.8808,−0.8808],[1.7616,−1.7616]]. This calculation is exactly what the Rust loop performs for 256 outputs.

For N observed pairs, the project averages cross-entropy and gradients over N. Stable softmax subtracts the largest logit before exponentiation. This changes neither probability nor loss because multiplying numerator and denominator by the same constant cancels, but it prevents large exponentials from overflowing.

fn probabilities(&self, input: u8) -> Vec<f32> {
        let logits = self.logits(input);
        let maximum = logits.iter().copied().fold(f32::NEG_INFINITY, f32::max);
        let normalizer = logits
            .iter()
            .map(|logit| (*logit - maximum).exp())
            .sum::<f32>();
        logits
            .iter()
            .map(|logit| (*logit - maximum).exp() / normalizer)
            .collect()
    }

cross_entropy_from_logits(logits, target) reuses the stable multiclass objective from Chapter 10, with logits before the target ID. Here it borrows an &[f32] slice from the model’s score vector instead of taking a fixed ten-class f64 array. The primitive scores one target; Model::loss averages those scores over adjacent byte pairs.

fn loss(&self, data: &[u8]) -> f32 {
        assert!(data.len() >= 2);
        data.windows(2)
            .map(|pair| {
                let logits = self.logits(pair[0]);
                let target = pair[1] as usize;
                cross_entropy_from_logits(&logits, target)
            })
            .sum::<f32>()
            / (data.len() - 1) as f32
    }

4. Train the Rust predictor

The complete program is projects/ch33/src/main.rs. It contains a course-authored byte corpus, count tables, and a trainable embedding model. No ML or tensor crate performs the gradient. The loops map directly to the outer-product arithmetic above.

cargo test --manifest-path projects/ch33/Cargo.toml
cargo run --release --manifest-path projects/ch33/Cargo.toml

The default run is deterministic and small. It prints a count, compares character units, and reports the measured cross-entropy before and after training. The test checks that both the embedding table and output matrix changed. A falling training loss proves the implementation can fit this small sequence; it does not establish held-out language quality.

Model::loss(data) evaluates the documented mean next-byte cross-entropy without updating parameters. Model::step(data, learning_rate) takes the same explicit data, computes the mean gradient of that loss, and performs one update. Model::predict(input) uses learned parameters without updating them and returns one byte class ID. To inspect the full classification result, logits(input) gathers one embedding row, multiplies it by all output columns, and adds bias; probabilities(input) applies stable softmax to those scores.

let mut model = Model::new(16);
let before = model.loss(bytes);
let learning_rate = 1.0;
for _ in 0..250 {
    model.step(bytes, learning_rate);
}

The value (probabilities[class_id] − one_hot_target) / example_count is named logit_gradient: it differentiates mean cross-entropy with respect to a logit, not with respect to a probability. The training step first accumulates all parameter gradients and then updates all parameters simultaneously. Updating W while still computing the embedding gradient would use a mixture of old and new weights and no longer implement the derived gradient.

Bytes can decode badly during generation.

The model may emit a continuation that is not valid UTF-8. Byte modeling guarantees representability of input, not that every sampled intermediate sequence is valid human-readable text. Preserve generated bytes, and use a lossy display only as a display choice. Chapter 34 shows why token decoding must be byte exact.

Debugging · Loss becomes NaN

A learner exponentiates raw logits and some logits reach 100. Explain the root cause and repair.

Answer

exp(100) exceeds useful f32 range. Find the row maximum m, use exp(z−m), and compute log-sum-exp as m + ln Σexp(z−m). Clamping probabilities treats the symptom and changes the objective.

Independent variation

Change the context from one byte to the previous two bytes by giving each observed byte bigram its own embedding row. Compare training loss and held-out loss on a final document kept out of training. Record how many contexts in validation never occurred in training.

Worked expectation

The wider context can fit repeated training phrases better, but sparse histories can hurt validation. A lower training loss alone is not evidence of improvement. The useful comparison reports both losses and unseen-context count.

6. Review and transfer

Answer from memory: What is the target for each position? How do a class ID, logit, probability, and prediction differ? Why is a byte ID an address rather than a magnitude? What shapes are E and W? Why does subtracting the maximum preserve softmax? Which parameters receive gradients when one input byte is used?

Answers

The target is the following token's class ID. That ID indexes one of 256 classes; a logit is its unrestricted raw score, a probability is its normalized softmax value, and predict returns the class ID with the largest score. E is [V,D], W is [D,V], and their product yields V logits. Adding or subtracting one constant from every logit multiplies every exponential by the same factor, which cancels during normalization. The selected embedding row receives input gradient; every output column and bias can receive gradient.

Retrieve the difference between training and inference from Chapter 1 and stable log-sum-exp from the classification chapters. In Chapter 34, frequent byte sequences become reusable tokens. The model here uses one preceding byte and a tiny fixture; it does not show long-range context, tokenizer compression, or real-world generalization.
