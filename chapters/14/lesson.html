Once a table is converted into stable numeric vectors, classification does not require a neural network. One method asks which stored examples are nearby. Another builds a probability model for each class. Comparing them reveals how assumptions shape predictions.

The goal

You will standardize two features, implement k-nearest neighbors, derive Gaussian naive Bayes in log space, and compare both on a tiny three-class fixture. Every number used by the default run is local and course-authored.

Code and terminology carried forward

Chapter 13 established that Preprocessor::fit(training_rows) learns preprocessing state from training rows, while Preprocessor::transform applies that fixed state without learning from validation, test, or inference rows. Its transform returns a variable-length Vec<f64> because the fitted category vocabulary determines the encoded width, and it keeps the discrete RawRow.label separate. This chapter preserves those responsibilities in Scaler::fit and Scaler::transform, and stores each discrete class ID as Point.label.

The bundled classifier fixture deliberately narrows each vector to exactly two numeric features: [f64; 2], so the distance and Gaussian arithmetic stays visible. Its label representation changes from u8 to usize only because the label directly indexes vote counts and per-class statistics. To connect Chapter 13's encoded vectors to these estimators, either select two documented columns or generalize every fitted array and distance input to the preprocessor's fixed output width; never silently truncate a vector. The course-wide names and operation roles are collected in the code and terminology conventions.

1. Distance turns similarity into arithmetic

A point with d features is a vector x = [x₁, x₂, …, xd]. Here x is mathematical notation for the Rust field Point.features, and the query vector z is the features argument passed to predict. Euclidean distance between x and z is the square root of the sum of squared coordinate differences:

distance(x,z) = √[Σⱼ (xⱼ − zⱼ)²]

The index j visits features from 1 through d. For ranking neighbors, the square root can be omitted because it preserves order. The project stores squared Euclidean distance, saving one operation per comparison.

A 3–4–5 triangle

Let x = [1, 2] and z = [4, 6]. Coordinate differences are −3 and −4. Their squares are 9 and 16, so squared distance is 25 and distance is √25 = 5. A second candidate with squared distance 20 is closer even if neither square root is calculated.

The exercise, starter, and reference use the same two-array primitive. Its first argument is a stored Point.features; its second is the query's features:

fn squared_distance(features: [f64; 2], other_features: [f64; 2]) -> f64 {
    features
        .into_iter()
        .zip(other_features)
        .map(|(value, other_value)| (value - other_value).powi(2))
        .sum()
}

Distance encodes a choice about similarity. Euclidean distance assumes coordinate differences combine through squared magnitude. It is sensible for measurements in a continuous space after scale has been considered. It is usually meaningless for integer codes assigned to unordered categories. Chapter 13’s one-hot vectors provide a different geometry: two distinct single categories differ in two binary positions.

Missing-value indicators also contribute to distance. Their influence depends on scaling and domain meaning. A nearest-neighbor model does not discover whether a distance is appropriate; it faithfully applies the geometry you provide.

2. Scale before measuring neighbors

Suppose feature one ranges from 1 to 5 while feature two ranges from 10 to 50. A difference of one unit in feature two can outweigh a meaningful difference in feature one simply because its unit is larger. Standardization centers each feature and divides by its training standard deviation:

zⱼ = (xⱼ − μⱼ) / σⱼ

Here μⱼ is the training mean for feature j, σⱼ is its training standard deviation, xⱼ is the original coordinate, and zⱼ is the standardized coordinate. The project uses population variance, dividing squared deviations by N. Consistency between fit and transform matters more here than the sample-versus-population convention.

Scale one coordinate

Training values [10, 20, 30] have mean μ = 20. Their squared deviations are 100, 0, and 100. Population variance is 200/3 ≈ 66.667, so σ ≈ 8.165. A query value 25 becomes (25 − 20)/8.165 ≈ 0.612. A training value 10 becomes approximately −1.225.

Call Scaler::fit(train_data) once to estimate μ and σ on training rows only, then call scaler.transform(features) for every training, validation, test, and inference vector. This is the same fit/transform boundary used by Chapter 13. Using test values to set scale is preprocessing leakage. The reference replaces a zero standard deviation with one, leaving a constant training feature centered at zero. That feature provides no neighbor discrimination, but the transform remains finite.

Compared with Chapter 3, Scaler::fit now receives labeled Point rows rather than a slice of feature arrays, but it reads only features; labels never enter the statistics. Chapter 3 rejected constant columns to expose division by zero. This estimator instead stores scale one for a constant column, allowing a fixed-width table to retain it without dividing by zero. The centering and scaling formula is unchanged.

Scaling changes kNN because it changes distances. Gaussian naive Bayes can operate without standardization because it estimates a separate variance for each feature and class. We still feed both methods the same scaled data in the comparison so their input boundary is identical and easy to inspect.

3. k-nearest neighbors votes from memory

k-nearest neighbors, or kNN, stores labeled training points. Knn::fit validates and retains train_data, k, and the number of classes; it estimates no weights. To classify a query, Knn::predict computes its distance to every training point, sorts, keeps the nearest k, and returns the label with the most votes. Fitting is therefore cheap; inference does the distance work.

Vote among three neighbors

A query has sorted neighbor pairs (squared distance, label): [(0.04, 1), (0.09, 1), (0.16, 2), (1.20, 0)]. With k = 3, label 1 receives two votes and label 2 receives one, so prediction is label 1. With k = 1, the closest point also yields label 1. With k = 4, label 1 still wins two to one to one.

Small k creates flexible boundaries and can follow noise. Larger k smooths local variation but can erase a small class or boundary. Choose k using training and validation data, never the final test. An odd k reduces ties in binary classification but does not eliminate multiclass ties.

The reference resolves a tied vote deterministically in favor of the lower label index. This is an implementation policy, not a statistical theorem. Other systems use distance-weighted votes. If a distance is zero, weighted schemes need an explicit rule to avoid division by zero.

distances.sort_by(|a, b| a.0.total_cmp(&b.0).then(a.1.cmp(&b.1)));
let mut votes = vec![0usize; self.classes];
for &(_, label) in distances.iter().take(self.k) {
    votes[label] += 1;
}

A direct scan and sort costs roughly O(nd + n log n) per query for n rows and d features. Spatial indexes can help in low dimensions. In high dimensions, distances often become less informative and indexes lose their advantage. The tiny project intentionally uses the direct algorithm because its entire decision is visible.

Knn::fit rejects k = 0, k greater than the training count, invalid labels, and nonfinite training features. Knn::predict rejects nonfinite query features. Allowing NaN into sorting would produce an arbitrary neighbor order disguised as a result. Finite coordinates can still overflow when squared, so prediction also rejects nonfinite distances. Gaussian NB likewise rejects nonfinite queries, fitted statistics, and resulting log scores.

4. Gaussian naive Bayes models each class

Bayes’ rule reverses a conditional probability:

P(c | x) ∝ P(c) P(x | c)

P(c | x) is the posterior probability of class c after observing features x. P(c) is the class prior. P(x | c) is the likelihood of those features within the class. The omitted denominator is the same for every class, so classification can compare proportional scores.

Naive Bayes assumes features are conditionally independent given the class. That gives P(x | c) = Πⱼ P(xⱼ | c). Gaussian naive Bayes models each numeric feature in each class as a normal distribution with fitted mean μcj and variance σ²cj.

One Gaussian log contribution

For one class and feature, let mean μ = 2, variance σ² = 1, and query x = 3. Ignoring the prior, log density is −½[ln(2πσ²) + (x−μ)²/σ²] = −½[ln(2π) + 1] ≈ −½(1.838 + 1) = −1.419. A feature far from the class mean contributes a more negative score.

For continuous measurements, these Gaussian values are probability densities, not probabilities of exact coordinates. Probability belongs to an interval and is the area under the density across that interval. A narrow Gaussian can have density greater than one while its total area remains one. In the Bayes formulas above, the continuous-feature likelihood is a density; the class posterior is still an ordinary probability over discrete classes.

Products of many small densities underflow toward zero, so implementations add logarithms:

score(c) = ln P(c) − ½ Σⱼ [ln(2πσ²cj) + (xⱼ−μcj)²/σ²cj]

The class with greatest log score wins. GaussianNb::predict returns that class's discrete label. The internal log_score is an unnormalized ranking value, so it is not named probability; obtaining class probabilities would require normalizing all class log scores with log-sum-exp. The project adds 10⁻⁹ to each fitted variance. Without this smoothing, a feature constant within a class would have zero variance and cause division by zero. The constant is a numerical safeguard; a serious model should tune or derive a variance floor relative to feature scale.

The independence assumption is often false, yet classification can still work because a model need not reproduce the full data distribution to rank classes usefully. In an implementation that normalizes these scores into class probabilities, those probabilities may be overconfident, particularly when correlated features count the same evidence several times. Use Chapter 12’s calibration checks before interpreting such normalized output as operational confidence.

5. Run a fair small comparison

The bundled fixture contains two points for each of three classes. Each Point stores contiguous features: [f64; 2] and a separate discrete label: usize. The label is the desired class ID and is kept out of scaling and distance. The same training-fitted scaler transforms stored points and query. kNN stores those transformed points; Gaussian NB estimates per-class counts, means, and variances from them.

let scaler = Scaler::fit(&raw_data)?;
let train_data: Vec<Point> = raw_data
    .iter()
    .map(|point| Point {
        features: scaler.transform(point.features),
        label: point.label,
    })
    .collect();
let query = scaler.transform([3.1, 31.0]);
let knn = Knn::fit(&train_data, 3, 3)?;
let gaussian_nb = GaussianNb::fit(&train_data, 3)?;
cargo test --manifest-path projects/ch14/Cargo.toml
cargo run --manifest-path projects/ch14/Cargo.toml

The test checks that both predict methods assign a query near the middle cluster the label 1. That agreement is a mechanism check, not a benchmark or agreement of probabilities. With six points, there is no trustworthy estimate of future accuracy. Compare methods on identical folds, identical preprocessing fitted within each fold, and metrics chosen for the task.

kNN can form irregular local boundaries but stores every training vector and pays at inference. Gaussian NB compresses each class into counts, means, and variances; inference cost depends on classes and features, not training row count. kNN’s inductive assumption is local label similarity. Gaussian NB’s is a Gaussian, conditionally independent feature model.

For an optional real-data extension, use UCI Iris, which the UCI page licenses under CC BY 4.0. Record attribution and a checksum, define your own stratified split, fit scaling only on training flowers, and report per-class results. The default project downloads nothing.

Read the reference implementation. Change k from three to one and perturb a point near a boundary. Then duplicate one class’s points. kNN votes change because training density changes; Gaussian NB priors change because class counts change. These are expected consequences, not implementation bugs.

Debugging · Millimeters defeat kilograms

A kNN model uses weight in kilograms and length in millimeters. Almost every neighbor is chosen by length. Why, and what is the leakage-safe repair?

Answer

Squared numeric differences inherit feature units, so a numerically large scale dominates the sum. Fit a scaler on training rows and use it unchanged for validation, test, and inference. Do not fit the scaler on all rows.

Independent variation · Correlated evidence

Duplicate feature zero as a third feature and extend Gaussian NB. Predict what happens to its score.

Worked answer

The independence model treats the duplicate as fresh evidence and adds the same log-density contribution twice. The winning class may become more confident without receiving new information. kNN also changes because that direction now contributes twice to squared distance. Removing redundant features or modeling covariance can repair the geometry.

Answer from memory: Why can squared distance replace distance for ranking? Why is scaling fitted? What does k control? Why add Gaussian scores in log space? Why can naive Bayes probabilities be overconfident?

Answers

Square root is monotonic. Scale parameters summarize training data. k trades local flexibility against smoothing. Logs prevent products of small densities from underflowing. Correlated features violate conditional independence and can count evidence repeatedly.

These methods establish two strong baselines. In Chapter 15, trees replace global distance and Gaussian assumptions with learned threshold rules, then ensembles stabilize and refine those rules.
