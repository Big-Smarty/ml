What does supervised fine-tuning optimize?

Supervised fine-tuning, or SFT, starts with existing parameters and trains on prompt-response demonstrations. After tokenization, it still uses next-token cross-entropy. “Instruction tuning” describes the data format and desired behavior; it does not create a different gradient rule.

The project first pretrains a base decoder for 60 updates on two generic cyclic token sequences. Its SFT pairs are then input [1,2,3] with targets [2,3,4], and input [5,6,2] with targets [6,2,3]. Each step's loss averages across three target positions; average_loss then gives the two equal-length demonstrations equal weight. The preserved full-sequence reference cycles through both demonstrations, calls the real decoder’s all-parameter loss_and_gradient, and applies SGD with learning_rate. Token embeddings, learned positions, attention, normalization, feed-forward weights, and vocabulary projection can all change.

fn sft(
    model: &mut Decoder,
    data: &[([usize; 3], [usize; 3])],
    steps: usize,
    learning_rate: f32,
) -> Result<(), Box<dyn Error>> {
    for step in 0..steps {
        let (input, targets) = &data[step % data.len()];
        let gradients = model.loss_and_gradient(input, targets)?;
        model.apply_sgd(&gradients, learning_rate)?;
    }
    Ok(())
}

One cross-entropy term

Suppose a position has logits [2,0] and target token 0. Stable softmax gives probabilities about [0.881,0.119]. Cross-entropy is −ln(0.881) ≈ 0.127. The logit derivative p−y is [−0.119,0.119], so an update raises the target logit relative to the other. SFT averages these contributions over supervised positions.

In the preserved full-sequence reference, measured fixture loss falls from 1.3315 to 0.0147. The new response-mask run reports its selected-position loss separately. This proves that the small decoder can fit these two demonstrations. It does not establish held-out instruction following, safety, or retention of previous abilities. A useful pretrained checkpoint and separate validation prompts are necessary for a real adaptation claim.

How can we supervise responses without deleting the prompt?

Implement masked_gradient, keeping the decoder’s existing API. It returns mean loss and parameter gradients over true mask positions. In [false,false,true], the two prompt targets contribute no direct loss, but all three input tokens remain. Changing masked target IDs must leave the response loss and gradient unchanged; changing a prompt input can still alter the response.

The decoder gives a mean over each prefix. Suppose prefix means for one, two and three targets are 1.0,1.5,2.0. Their loss sums are 1,3,6, so the last target contributes 6−3=3.0. Causality makes the first two losses identical in the length-two and length-three forwards. The same subtraction works for gradients: gradient of 3L₃−2L₂ selects the third target. For several selected positions, sum their contributions and divide by the number selected.

Hint 1 · Find the invariant

Multiply each prefix mean by its length before subtracting the previous prefix sum. Otherwise you mix differently weighted losses.

Hint 2 · Plan the algorithm

For each true mask index i, add (i+1) times the prefix gradient and subtract i times the earlier prefix gradient. Divide by the mask count and retain complete parameter shape.

It is exact up to f32 subtraction error but costs extra forwards/backwards; it is not an efficient large-context implementation.

How does a low-rank update change a frozen matrix?

Low-Rank Adaptation, or LoRA, freezes a base matrix W₀ and learns a structured update. Our Chapter 36 output projection is stored [D,V], with model width D and vocabulary size V. We represent ΔW = AB, where A has shape [D,r] and B has shape [r,V]. The effective projection is W = W₀ + (α/r)AB.

Some papers write BA because they choose the opposite matrix orientation. Shapes settle the issue: [D,r] times [r,V] produces [D,V]. The rank of a matrix counts independent directions it can represent. Every column of AB is a combination of the r columns of A, so its rank is at most r; the update cannot independently change every possible direction when r is small. This is a restriction on the change, not a claim that W₀ itself has low rank. Here r is smaller than D and V. The base projection has DV parameters; the adapter has Dr+rV. With D=8, V=8, r=2, it trains 16+16=32 numbers instead of the decoder’s 784 base parameters.

Zero initialization and a 2×2 update

Let W₀=[[1,2],[3,4]], A=[[1],[−1]], and B=[[0,0]]. Then AB is exactly zero, so inserting the adapter preserves W₀. After training changes B to [0.1,0.2], AB=[[0.1,0.2],[−0.1,−0.2]]. With α/r=1, add that matrix to W₀. Initializing one factor to zero preserves the base function while the other nonzero factor allows the first gradient to reach the zero factor.

The project initializes A to small deterministic values and B to zeros. It builds a temporary effective decoder for each step, obtains the gradient G = ∂L/∂W from the actual full decoder, and applies the chain rule: ∂L/∂A = (α/r)GBᵀ and ∂L/∂B = (α/r)AᵀG. Only A and B update, using both factor gradients computed from the old factors before either changes. The teaching implementation still computes a full decoder backward pass and clones the base, so its 32 trainable values do not demonstrate practical LoRA memory or training-speed savings. A production implementation would freeze unnecessary gradient paths and compute the adapter branch directly. A test compares one derivative with a central finite difference after making B nonzero.

fn delta(&self) -> Vec<f32> {
        let scale = self.alpha / self.rank as f32;
        low_rank_delta(&self.a, &self.b, self.width, self.rank, self.vocab)
            .into_iter()
            .map(|value| value * scale)
            .collect()
    }

The base parameter slice is copied before training and compared afterward. The adapter’s initial maximum change is zero; its measured fixture loss falls from 1.3315 to 0.0016. This is a real adapter on the decoder’s vocabulary projection, although practical LoRA commonly targets attention projections and may train several modules.

Can we train both factors and then merge the adapter?

The supplied fixed-A baseline is already a useful linear adapter: B learns coefficients over fixed features. Replace Lora::step with the full two-factor chain rule. Compute both da and db from the old A and B, then update together. Keep the base immutable. The goal checks a nonzero A derivative after making B nonzero, so a fixed-A implementation cannot satisfy the full LoRA goal.

For A=[1,−1]ᵀ, B=[0.1,0.2], upstream projection derivative G=[[2,3],[4,5]] and scale one, da=GBᵀ=[0.8,1.4]ᵀ; db=AᵀG=[−2,−2]. At learning rate 0.1, A becomes [0.92,−1.14] and B becomes [0.3,0.4]. Computing db from the new A would give a different, incorrect simultaneous gradient.

What information is in a teacher distribution?

Knowledge distillation trains a student to match probabilities from a teacher. A hard next-token target supplies one vocabulary ID. A soft target supplies a probability for every vocabulary item: [0.70,0.20,0.10] says the second token is more plausible than the third even though the first has the highest probability.

For teacher probabilities q and student probabilities p at temperature τ=1, soft cross-entropy is L = −Σᵢqᵢ ln pᵢ. Its student-logit derivative is p−q. The reference uses a useful linearity trick because Chapter 36 exposes hard-target derivatives. For every possible vocabulary target i, it asks for the hard-target Gradients value gᵢ, weights its loss and parameter derivatives by qᵢ, and sums Σqᵢgᵢ. Since Σqᵢ=1, this equals the soft-target loss and derivatives exactly at τ=1. Soft cross-entropy equals KL(q||p) plus teacher entropy −Σqᵢln qᵢ. That entropy is constant while the student trains, so both objectives have the same student derivatives even though their numerical loss values differ.

Combine hard-target derivatives into one soft-target derivative

Let student p=[0.5,0.5] and teacher q=[0.75,0.25]. The hard-target logit derivative for target 0 is [−0.5,0.5]; for target 1 it is [0.5,−0.5]. Weighting gives 0.75[−0.5,0.5]+0.25[0.5,−0.5]=[−0.25,0.25], exactly p−q. The update raises the first student logit.

The teacher is the SFT decoder with width eight. The student has width four, one attention head, and a smaller feed-forward block. On four transfer tokens, measured mean KL divergence at temperature τ=1 falls from its initial value to a lower value. KL(q||p)=Σqᵢln(qᵢ/pᵢ) is zero only when distributions match. The implementation subtracts teacher and student log-softmax values directly, then weights by teacher probabilities. It never clips the student probability to a floor: clipping would change the reported divergence for a confidently wrong student. A central-difference check also verifies the weighted soft-target gradient against the direct soft cross-entropy.

Temperature τ greater than one produces softer probabilities from logits/τ. Then derivatives include temperature factors, and common distillation objectives multiply the soft loss by τ² when combining it with hard-target loss. The first comparison stays at τ=1; the new lab also implements a temperature-consistent τ=2 experiment described in the final checkpoint. Each distillation input has one token (T=1), and the clear code performs V backward passes for that token; that clear method is suitable only for the eight-token teaching vocabulary.

Which adaptation boundary fits the evidence?

Full SFT spends updates on every parameter and can express broad changes, but it stores a full model checkpoint per adaptation and can overwrite useful behavior. LoRA stores a small task-specific delta and preserves one shared base, but rank and target modules constrain what it can learn. Distillation changes the deployed architecture: the student can be smaller and may be faster depending on implementation and hardware, but matching a teacher is an optimization problem with its own transfer data.

These techniques can be combined. An SFT model can become a teacher. A LoRA adapter can teach a smaller student. The clean comparison keeps training examples, evaluation prompts, tokenization, and metrics fixed. Count trainable parameters and checkpoint bytes separately from runtime, because a low-rank training representation may be merged into a dense matrix for inference.

Data quality sets the behavior being copied. Demonstrations can contain errors or narrow preferences; teacher probabilities can be confidently wrong. Fine-tuning does not verify factual truth. Track dataset provenance, inspect failures, and reserve evaluation items that did not influence training choices.

The pretrained base in this chapter has learned only two tiny synthetic cycles; it is not a useful language model. It does make the adaptation boundary real: SFT and LoRA begin from the same already trained parameter state and use different demonstrations. The preserved decoder averages over complete sequences. The new response-mask checkpoint selects response positions by prefix-gradient differences while retaining prompt context; masking is part of the required SFT experiment.

Does a softer teacher require a different gradient?

Implement temperature_gradient at temperature τ=2. Define pτ=softmax(student logits/τ), qτ=softmax(teacher logits/τ), and use loss τ² times their soft cross-entropy. Its derivative with respect to the original student logits is τ(pτ−qτ): one factor 1/τ comes from dividing logits and two factors τ come from scaling the loss.

With student logits [0,0], teacher probabilities at τ=2 equal [0.75,0.25], and τ=2, the derivative is 2([0.5,0.5]−[0.75,0.25])=[−0.5,0.5]. A τ=1 mixture would produce half that magnitude and optimize different probabilities. Compare the analytical gradient with finite differences of the same temperature-scaled objective.
