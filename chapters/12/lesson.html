A test score is an estimate, not a property engraved into a model. Change the examples and the score changes. This chapter turns that variation into an uncertainty interval and asks a second question: when a classifier says “80%,” does that event happen about eight times in ten?

The goal

You will measure uncertainty in accuracy with a bootstrap, inspect probability calibration, and compute a Brier score. The bundled Rust project uses eight course-authored predictions, a deterministic random-number generator, and no network access.

Code and terminology carried forward

Chapter 11 trained a ten-class classifier, converted each row's logits into ten softmax probabilities, and saved the model parameters needed for later inference. This chapter performs no training and defines no new model. It consumes frozen model outputs and observed labels from held-out rows. The bundled probabilities are course-authored so the statistical calculations stay small and auditable; they are not claimed outputs from a trained checkpoint. These roles follow the course code and terminology conventions.

To derive a binary evaluation row from Chapter 11, choose one digit as the positive class before opening the test results. Restore the saved model, run inference on one held-out image, and take that digit's entry from the ten-element softmax output. Store that value as Prediction.probability; store 1 in Prediction.label when the observed digit is the chosen class and 0 otherwise. Thus a Prediction is one paired positive-class probability and binary observed outcome. The model's training cross-entropy is not an input. Accuracy, Brier score, and calibration summaries are new evaluation statistics computed from these held-out rows.

1. A sample gives an estimate

Suppose a frozen model is evaluated on eight new cases. Six classifications are correct, so measured accuracy is 6/8 = 0.75. The arithmetic is exact for those eight rows. The uncertainty comes from using them to say something about other cases from the population we care about.

A population is the larger set of cases described by the evaluation claim. A sample is the finite set actually observed. A statistic is a number computed from that sample, such as accuracy. The unknown population counterpart is a parameter. Sampling uncertainty asks how much the statistic would vary if we could repeat the sampling process.

One row changes the headline

With six correct predictions among eight, accuracy is 0.75. If a different sample replaced one correct row with an incorrect row, accuracy would be 5/8 = 0.625. Replacing an incorrect row with a correct one gives 7/8 = 0.875. A single row moves this small evaluation by 0.125, so reporting “75%” without its sample size hides useful information.

A confidence interval is produced by a procedure. A nominal 95% interval procedure aims to cover the target population quantity in 95% of repeated samples when its assumptions and approximation are adequate. It does not mean there is a 95% probability that a fixed population quantity lies inside this one computed interval. That common shortcut changes the interpretation.

The evaluation rows must match the intended claim. Eight independent devices may support a claim about new devices better than eight readings from one device. Temporal drift can make yesterday’s sample a poor description of tomorrow. No interval repairs a biased sample, label errors, leakage, or distribution shift. It quantifies variation within a stated sampling story.

2. Resample the observed cases

The bootstrap approximates repeated sampling by drawing from the observed rows with replacement. “With replacement” means a selected row remains available for the next draw. A bootstrap sample has the same size as the original, but it may contain a row several times and omit another row.

Work one bootstrap replicate

Number four evaluation rows 0 through 3 and record correctness as [1, 1, 1, 0]. The observed accuracy is (1 + 1 + 1 + 0)/4 = 0.75. Suppose a random draw of four indices is [3, 0, 3, 2]. The resampled correctness values are [0, 1, 0, 1], so this replicate’s accuracy is 2/4 = 0.50. Another draw, [1, 2, 2, 0], gives [1, 1, 1, 1] and accuracy 1.00.

Repeat this process many times. The resulting collection of accuracies approximates the sampling distribution of the estimator. It is the distribution of estimates under resampling, not a set of newly measured outcomes.

For a percentile confidence interval, sort B bootstrap estimates. Choose the empirical 2.5th and 97.5th percentiles as endpoints. Here B is the number of bootstrap repetitions. The reference uses B = 2,000 and takes the entries at floored zero-based indices 0.025B and 0.975B. More repetitions make Monte Carlo noise in the endpoints smaller, but cannot add information absent from eight original observations.

for _ in 0..repetitions {
    sample.clear();
    for _ in 0..data.len() {
        sample.push(data[rng.index(data.len())]);
    }
    estimates.push(accuracy(&sample)?);
}
estimates.sort_by(f64::total_cmp);

The generator seed makes the demonstration repeatable. It does not make the interval universally exact. The simple percentile bootstrap can have poor coverage for very small samples, highly biased estimators, or statistics near a boundary. More refined intervals exist, but the first responsibility is to state the resampling unit correctly.

Rows are not always independent.

If several rows come from one patient, user, site, or machine, resample whole groups. For time series, preserve local dependence with blocks. Row-wise resampling would pretend correlated measurements supply more independent evidence than they do.

3. Accuracy ignores the probability scale

Accuracy thresholds probabilities into decisions. Predictions 0.51 and 0.99 both become class 1 at threshold 0.5, even though they make very different probability claims. Calibration connects probability statements to observed frequencies. Among cases assigned probability 0.8, roughly 80% should be positive if the predictions are calibrated for that population.

A reliability diagram estimates this relationship. Divide [0,1] into bins. For each nonempty bin, compute the mean predicted positive-class probability and the fraction of observed outcomes equal to one. Plot mean probability on the horizontal axis and positive-outcome frequency on the vertical axis. Perfect calibration lies on the diagonal. Binning is an estimate: narrow bins show local structure but contain fewer observations; wide bins are steadier but can hide structure.

Calculate one calibration bin

Take probabilities [0.55, 0.70, 0.85, 0.95] with observed outcomes [1, 0, 1, 1]. If the upper-half bin contains all four, mean probability is (0.55 + 0.70 + 0.85 + 0.95)/4 = 3.05/4 = 0.7625. The positive-outcome frequency is (1 + 0 + 1 + 1)/4 = 0.75. The estimated calibration gap is 0.0125 for this bin. That small gap is descriptive; four examples cannot establish precise calibration.

Calibration and discrimination answer different questions. A model can rank positive cases above negative cases yet attach probabilities that are too extreme. It can also be calibrated while offering little discrimination: always predicting the base rate is calibrated when the rate is stable, but it does not distinguish cases.

If a separate calibration model is fitted, its training data must be independent of the data that fitted the base model. Otherwise the calibrator sees overly optimistic in-sample predictions. Cross-fitting is one solution: generate held-out predictions inside training folds, fit the calibrator on those, and reserve the final test set for evaluation only. The chapter project measures calibration; it does not fit a recalibration mapping.

4. Score probabilities and map the maths to Rust

The Brier score is mean squared error between predicted positive-class probabilities and observed binary outcomes:

Brier = (1/N) Σᵢ (pᵢ − yᵢ)²

N is the number of evaluation rows, pᵢ is the predicted positive-class probability for row i, and yᵢ is its observed outcome, encoded as 0 or 1. Lower is better. The score rewards probabilities close to outcomes and penalizes confident errors strongly.

Two predictions by hand

For p = [0.2, 0.8] and y = [0, 1], squared errors are (0.2 − 0)² = 0.04 and (0.8 − 1)² = 0.04. Their mean is (0.04 + 0.04)/2 = 0.04. If the second probability were 0.2, its error would be (0.2 − 1)² = 0.64 and the mean would rise to 0.34.

The Rust Prediction keeps each probability next to its observed binary label so resampling cannot break their pairing:

#[derive(Clone, Copy)]
struct Prediction {
    probability: f64,
    label: u8,
}

brier divides once by data.len(), so the denominator is the number of evaluation rows:

fn brier(data: &[Prediction]) -> Result<f64, &'static str> {
    validate_predictions(data)?;
    Ok(data
        .iter()
        .map(|p| (p.probability - p.label as f64).powi(2))
        .sum::<f64>()
        / data.len() as f64)
}

The shared validate_predictions boundary rejects empty input, nonfinite values, out-of-range probabilities, and labels other than zero or one before accuracy, Brier score, or calibration is computed. calibration_bins stores each bin as count, probability sum, and label sum, then divides only nonempty bins.

A Brier score mixes calibration, resolution, and outcome uncertainty, so comparing two Brier values does not isolate calibration alone. Inspect the reliability bins and the decisions the application actually uses. Likewise, a bootstrap interval around accuracy does not quantify uncertainty in every metric; rerun the bootstrap with the statistic whose uncertainty matters.

Read the complete reference implementation. The small xorshift generator is included only to make the course example dependency-free and repeatable. Do not use it for cryptography. The algorithm’s statistical work is resampling paired observations; the generator is plumbing.

5. Run and perturb the experiment

cargo test --manifest-path projects/ch12/Cargo.toml
cargo run --manifest-path projects/ch12/Cargo.toml

The run prints measured accuracy, an illustrative deterministic 95% bootstrap percentile confidence interval, the Brier score, and four nonempty calibration summaries. Each summary reports its row count, mean predicted positive-class probability, and observed positive-outcome frequency. Exact values are measurements of the bundled eight-row fixture. They do not claim real-world model quality.

First change the seed while leaving data and B fixed. Endpoints may move because bootstrap computation itself has Monte Carlo variation. Next raise repetitions from 2,000 to 20,000; the run is still small, and seed-to-seed variation should shrink. Then duplicate every row. A naive row bootstrap may appear more precise even though you created no new independent evidence. This demonstrates why the resampling unit matters.

Finally, change 0.70 with label 0 to 0.99. Its thresholded decision was already wrong, so accuracy does not change. Its Brier contribution grows from (0.70 − 0)² = 0.49 to 0.9801, showing that probability-sensitive metrics notice increased overconfidence.

The fixture is original course data and requires no download. A real evaluation should record how examples were sampled, whether groups repeat, when labels became available, and which data fitted the model and any calibrator. Those facts define what the interval and calibration plot can support.

Debugging · An impossibly narrow interval

A dataset contains 100 measurements from each of two patients. A learner bootstraps 200 rows and reports a tight interval. Explain the bug.

Answer

The 200 rows are not 200 independent sampling units. Measurements within a patient share biology and collection conditions. Resample patients as clusters; with only two patients, uncertainty about new patients will be large and bootstrap approximation itself will be fragile.

Independent variation · Uncertainty in Brier score

Change the bootstrap statistic from accuracy to Brier score. Before running, predict whether replacing a correct 0.55 prediction with a correct 0.95 prediction shifts the interval up or down.

Worked answer

For label 1, squared error falls from (0.55 − 1)² = 0.2025 to (0.95 − 1)² = 0.0025. Bootstrap samples containing that row therefore tend to have lower Brier scores, shifting the distribution downward. The amount still depends on which rows each replicate draws.

From memory: What is resampled in an ordinary bootstrap? Why can two identical accuracies hide different probability quality? What does a 95% confidence procedure promise? Why must calibration use held-out predictions?

Retrieval answers

Paired observed cases are sampled with replacement. Accuracy discards probability magnitude after thresholding. Over repeated samples under the assumptions, the procedure covers the target about 95% of the time. Held-out predictions prevent a calibrator from learning the base model’s training optimism.

This chapter quantifies uncertainty conditional on a sampling design; it does not prove representativeness or causal validity. Chapter 13 next makes the split itself respect groups and time before any preprocessing learns from data.
