Scalar graphs reveal the chain rule, but an image or minibatch contains many related numbers. This chapter introduces a deliberately small matrix type and implements one dense layer over a batch, including both parameter gradients and the gradient returned to the previous layer.

Milestone

You will trace a 2×3 input through a 3-to-2 dense layer, obtain a 2×2 output, and verify its complete backward pass by hand and by central differences.

1. Shape gives a flat array meaning

A tensor is an array together with dimensions and a data type. We begin with rank-two tensors, or matrices. An activation batch has shape [batch, features]. Two examples with three features each therefore have shape [2,3]. The shape is not decoration: it determines which values may be multiplied and how an offset maps to a logical coordinate.

The Rust project stores values in one contiguous Vec<f64> using row-major order. Coordinate (row, column) maps to row * cols + column. The matrix [[1,2,3],[4,5,6]] becomes [1,2,3,4,5,6]. Each example occupies one contiguous row, which makes the data easy to inspect and traverse.

Shape and storage are separate facts. The same six values could be interpreted as [2,3], [3,2], or [6,1], but each interpretation gives coordinates different meanings. A reshape can be free when it only changes metadata and preserves element order; a transpose usually needs new strides or a data copy. Our small type stores only contiguous matrices, so it never hides strided access behind a simple index.

A dense layer with in_features=3 and out_features=2 stores weights as [out,in]. Output unit zero’s three weights come first, followed by output unit one’s. Bias has shape [out]. For an input X with shape [batch,in], the output Y has shape [batch,out].

Yb,o = bo + Σi=0…in−1 Xb,i Wo,i

Here b is a batch-row index, o an output-feature index, and i an input-feature index. The symbol b is also often used for bias; subscripts and prose disambiguate them. The project calls the bias vector bias to avoid that visual collision.

Forward two rows

Let X=[[1,2,3],[4,5,6]], W=[[1,0,−1],[2,1,0]], and bias=[0.5,−0.5]. For row zero and output zero, 0.5+1×1+2×0+3×(−1)=−1.5. Output one is −0.5+1×2+2×1+3×0=3.5. Repeating for row one gives −1.5 and 12.5. Flattened row-major output is [−1.5,3.5,−1.5,12.5].

2. Derive the three backward results

The layer receives dY, the derivative of the final scalar objective with respect to every output. It must return dX for earlier layers and compute dW and dbias for its trainable parameters. The local forward equation makes each rule direct.

dXb,i=ΣodYb,oWo,i;   dWo,i=ΣbdYb,oXb,i;   dbiaso=ΣbdYb,o

The sums differ because each object is shared along a different axis. An input value feeds every output, so dX sums over outputs. A weight is reused by every example, so dW sums over the batch. One bias affects every example at its output position, so its gradient also sums over the batch.

You can recognize the formulas as matrix products when weights are written [out,in]: Y=XWT+bias, dX=dY·W, and dW=dYT·X. Bias is broadcast across input rows in the forward pass, so its reverse rule reduces across those same rows. The loops are the authority here; matrix notation is a concise cross-check of the indices.

Backward with complete arithmetic

Use dY=[[1,2],[3,4]]. For the first input row, dX₀₀=1×1+2×2=5, dX₀₁=1×0+2×1=2, and dX₀₂=1×(−1)+2×0=−1. The second row gives [11,4,−3]. For W₀₀, sum over examples: 1×1+3×4=13. W₀₁ receives 1×2+3×5=17, and W₀₂ receives 1×3+3×6=21. The second weight row is [18,24,30]. Bias gradients are [1+3,2+4]=[4,6].

These are sums, not means. A loss function that averages over the batch should put its 1/batch factor in dY, or the caller should scale the returned gradients once. Hiding an extra average inside every layer would make reduction conventions difficult to audit.

3. Map equations to loops and storage

The forward kernel nests batch, output, and input loops. Its innermost loop reads a contiguous input row but walks one weight row, also contiguous because weights are [out,in]. The output offset is b * output + o. There is no general broadcasting or tensor abstraction; the layer implements exactly the shapes it promises.

The backward kernel uses the same three loop indices. For each scalar g=dY[b,o], it adds g×W[o,i] to dX[b,i] and g×X[b,i] to dW[o,i]. It also adds g to dbias[o]. Starting all three buffers at zero makes accumulation explicit.

Input, output, and parameter lengths are validated before indexing. Matrix dimensions must be positive, multiplication must not overflow usize, flat data length must match rows×columns, and external values must be finite. backward requires X=[batch,in] and dY=[the same batch,out]. A shape mismatch returns an explanation instead of panicking at an unrelated offset.

A central-difference test turns the layer output into a scalar score Σ(Y×dY). The derivative of that score with respect to Y is exactly the chosen dY. Perturbing one weight therefore checks the same vector-Jacobian product that backward computes. This technique tests a component without needing a larger network.

Finite differences are deliberately limited to a tiny smooth fixture. Checking every weight would require two forward evaluations per parameter and scale badly. In routine development, sample values across inputs, weights, and biases, use double precision, and keep the numerical checker separate from analytical backward code so the two paths do not share the same mistake.

Shapes prevent plausible wrong answers.

If weights were accidentally indexed as [in,out], some square examples would still run. The nonsquare 3-to-2 fixture and exact values expose that transpose error.

4. Run the dense layer checkpoint

Read the complete project. Matrix owns row-major data and validates construction. Dense owns weights in [out,in] layout. The default program executes the exact hand-worked forward and backward example.

cargo test --manifest-path projects/ch09/Cargo.toml
cargo run --manifest-path projects/ch09/Cargo.toml

Expected forward data is [-1.5, 3.5, -1.5, 12.5]. Expected backward arrays are dx=[5,2,-1,11,4,-3], dw=[13,17,21,18,24,30], and db=[4,6]. These small integer-like results are exact in binary where halves are involved; general floating-point matrix products should be compared using absolute plus relative tolerances.

This implementation is a scalar reference kernel. It performs no SIMD, threading, tiling, or library call. Its purpose is to define layout and arithmetic against which faster kernels can be compared. Optimizations may reorder additions and change final low bits; they must preserve shapes and agree within a tolerance appropriate to accumulation length.

Batching amortizes parameter handling and exposes regular loops, but it does not change which model each row sees. Every example uses the same W and bias. That sharing is why parameter gradients reduce across rows, and why a batch is more than unrelated matrices placed beside one another.

Debugging: dW fits one row but not two

A learner assigns dw[o*input+i] = g*x inside the batch loop. The gradient matches a batch of one but only reflects the final row for larger batches.

Answer

Every example reuses the same weights, so their contributions must sum. Use addition assignment into a zeroed gradient buffer. Average exactly once if the upstream loss convention requires it.

Transfer: add a second leading batch dimension

Suppose X represents two groups of three examples, shape [2,3,in]. Without adding broadcasting, explain how to reuse the same kernel.

Worked answer

Flatten the two leading dimensions into one batch of six because each row is independently multiplied by the same weights. Run the existing [6,in] kernel, then interpret output as [2,3,out]. This works only because storage is contiguous and no operation distinguishes the two batch axes.

6. Review and transfer

From memory, state the layouts of X, W, bias, and Y. Which axis does each backward gradient sum over? Why does a nonsquare fixture catch more errors? Where should averaging occur?

Answers

X is [batch,in], W is [out,in], bias is [out], and Y is [batch,out]. dX sums over outputs; dW and bias gradients sum over batch rows. Nonsquare shapes reveal accidental transposes. This layer returns sums implied by dY; the loss or caller owns the batch-average convention.
