Distance methods compare a query with stored points, and Gaussian naive Bayes assumes a probability shape. A decision tree asks a sequence of concrete questions such as “is feature 0 at most 2?” Ensembles then combine many such rules to reduce instability or correct remaining error.

The goal

You will build a binary classification tree, a random forest with bootstrap rows and fresh random feature candidates at every node, and squared-error gradient boosting with regression stumps. One local table drives all three demonstrations.

These classical estimators use fit for estimating tree structure and leaf values. Even though boosting adds learners over several rounds, it does not expose the repeated parameter-update train interface used by earlier gradient models.

The early-course signed error was prediction - target. Boosting reverses that sign to form its correction target: residual = target - prediction = -error. For MSE, the derivative is 2 * error / N, so the residual points in the negative-gradient direction, apart from the fixed positive scale 2/N.

1. A tree partitions the feature space

A decision tree is a nested set of threshold rules. An internal node chooses a feature j and threshold t. Rows with xⱼ ≤ t go left; the rest go right. A leaf returns a prediction, such as the majority class among training rows that reached it.

Trees are nonparametric in the practical sense that they do not assume a fixed linear or Gaussian form. Their predictions are piecewise constant: every point in one leaf receives the same answer. This flexibility handles nonlinear interactions, but a deep tree can isolate tiny quirks of training data.

To choose a classification split, measure node impurity. For a binary node with positive fraction p, this chapter uses Gini impurity:

Gini = 1 − p² − (1−p)² = 2p(1−p)

Compare a mixed and pure node

A node with three negatives and one positive has p = 1/4 = 0.25, so Gini = 2 × 0.25 × 0.75 = 0.375. A proposed split sends all three negatives left and the one positive right. Both children are pure, and their weighted impurity is (3/4)×0 + (1/4)×0 = 0.

For each candidate threshold, calculate the size-weighted child impurity:

weighted impurity = (NL/N)Gini(L) + (NR/N)Gini(R)

N is parent row count; NL and NR are child counts. Choose the candidate with smallest weighted impurity. This split criterion is distinct from the residual squared error used by the regression stumps below. The reference considers observed feature values as thresholds. Production tree packages often test midpoints between sorted unique values and use faster scans, but both describe the same partition logic on this fixture.

Recursion stops at a pure node, when fewer than two rows remain, or at max_depth. Depth is a regularization control. Without a limit or minimum leaf size, a tree can keep dividing until leaves memorize individual examples. The reference predicts ties as class 1; a different deterministic tie policy is acceptable if it is documented.

2. Bag unstable trees into a random forest

A small change in training rows can change a tree’s early split and therefore its entire lower structure. Bagging, short for bootstrap aggregating, fits models on bootstrap samples and combines their predictions. This project implements classification, so forest_predict takes a majority vote. A regression forest would average numerical predictions, but that operation is not implemented here.

Bootstrap one tree

Suppose row indices are [0,1,2,3]. One four-draw bootstrap sample might be [3,0,3,2]. Row 3 appears twice and row 1 is absent. A second tree sees [1,1,0,2]. Each tree learns from a perturbed table. If their errors differ, voting can be steadier than either tree.

A random forest adds feature randomness. At every split node, it selects a random subset of candidate features and finds the best split only among them. This matters: selecting one feature set once for the whole tree creates less diverse structures and is not the standard algorithm. The two-feature project chooses one candidate feature independently at each node.

After fitting, forest inference aggregates the class labels returned by its trees:

fn forest_predict(trees: &[Tree], features: [f64; 2]) -> usize {
    let ones = trees
        .iter()
        .filter(|tree| tree.predict(features) == 1)
        .count();
    (ones * 2 >= trees.len()) as usize
}

Bootstrap rows decorrelate trees through cases; feature sampling decorrelates them through available split choices. Breiman’s analysis describes forest quality through individual tree strength and correlation among trees. Randomness that makes trees identical offers little variance reduction. Excessive randomness can make each tree too weak.

Rows omitted from one bootstrap sample are that tree’s out-of-bag rows. Aggregating predictions only from trees that omitted a row gives an internal error estimate. The compact project does not track sample membership, so it does not claim an out-of-bag score. Use explicit validation or cross-validation for model selection.

The deterministic xorshift generator makes tests repeatable; it is not cryptographic. The forest returns an error for zero trees or empty data. Real implementations also validate feature dimensions, class values, minimum leaves, and nonfinite input at the ingestion boundary.

3. Boosting corrects what remains

Forests fit trees independently and vote on their predicted labels. Gradient boosting fits an additive regression model sequentially. Each new weak learner targets the signed error left by the current ensemble.

For squared-error regression, begin with the mean target. If targets are [0, 1, 3, 4], the base prediction is (0+1+3+4)/4 = 2. Residual for row i is rᵢ = yᵢ − ŷᵢ. At the start, residuals are [−2, −1, 1, 2]. A regression stump—a tree with one split—fits those residuals.

One boosting round

Split after the second row. Left residual mean is (−2 + −1)/2 = −1.5; right mean is (1 + 2)/2 = 1.5. The stump predicts −1.5 on the left and 1.5 on the right. With learning rate η = 0.2, updated predictions are 2 + 0.2(−1.5) = 1.7 on the left and 2 + 0.2(1.5) = 2.3 on the right. Residual magnitudes shrink for the extreme rows, though one stump does not solve the curve.

The ensemble's optimized loss is mean squared error between numerical predictions and targets, averaged over the training rows. Its negative derivative with respect to each prediction is twice that row's residual divided by the fixed row count, so fitting residuals gives the same split choices up to a positive constant scale. Within fit_stump, candidate leaves are compared by residual SSE: the sum of squared differences between current residuals and the stump's residual predictions. Dividing each candidate by the same row count would choose the same stump. In general gradient boosting fits each learner to a loss-specific negative gradient, then adds a scaled contribution:

Fm(x) = Fm−1(x) + η hm(x)

Fm is the ensemble after round m, hm is the new weak learner, and η is the learning rate. Smaller η usually requires more rounds. Depth, number of rounds, and learning rate jointly control capacity. More rounds always reduce neither validation error nor future error; monitor held-out performance.

The project’s boosting task is regression even though its tree and forest demonstrations classify. Keeping the squared-loss arithmetic explicit shows why residual fitting works. Classification boosting changes the loss and score-to-probability mapping; do not interpret this regression output as a class probability.

4. Trace the three Rust implementations

Row makes the task distinction concrete: label is a discrete class ID and target is a numeric regression answer.

#[derive(Clone, Copy, Debug)]
struct Row {
    features: [f64; 2],
    label: usize,
    target: f64,
}

The deterministic baseline fit_tree receives both feature indices and recursively searches them. fit_forest first draws rows.len() rows with replacement, then calls a separate recursive fitter that samples one candidate feature at every node. Both produce the same Tree enum, so Tree::predict uses one traversal function and returns a label.

The explicit enum captures the tree invariant: a node is either a leaf or a split containing two child trees. At prediction time, exactly one branch is followed. Fitting temporarily partitions rows into vectors. That allocation-heavy approach is clear for six rows; a larger implementation would sort indices and reuse buffers.

The boosting Stump holds a feature, threshold, and one numeric residual prediction for each side. fit_stump tests candidates, sets leaf values to mean residuals, and minimizes residual SSE. Boost::fit repeats that stagewise procedure for rounds; Boost::predict performs inference by adding the base and every learning_rate-scaled stump output.

Inside Boost::fit, the primitive subtraction maps the model's numerical prediction and regression target to the next stump's training target:

let residuals: Vec<f64> = rows
    .iter()
    .zip(&predictions)
    .map(|(row, prediction)| row.target - prediction)
    .collect();
let stump = fit_stump(rows, &residuals);

Read the complete reference. Its tests require the baseline tree and forest to classify the upper region and require boosting to reproduce a training endpoint within 0.05 after 40 rounds. This is a correctness check for the algorithms, not an evaluation of generalization.

The code is intentionally specialized to two features and binary classification. Generalizing dimension and class count would add indexing and validation around the same algorithms, but a tensor framework or generic trait hierarchy would obscure the lesson without helping this project.

5. Run the ensemble and inspect capacity

cargo test --manifest-path projects/ch15/Cargo.toml
cargo run --manifest-path projects/ch15/Cargo.toml

The no-argument run fits the estimators from six course-authored rows. It prints one classification from the tree and forest and one boosted regression prediction. No data is downloaded, and no long fitting process begins implicitly.

First set baseline tree depth to one. Inspect whether a single threshold separates classes. Then swap one label near the boundary and raise depth to five. The deep tree may isolate that row, reducing training error while making its rule more fragile. Evaluate on separate points before calling the deeper tree better.

For the forest, compare one tree with 31 trees across several seeds. One tree’s prediction can change with its bootstrap sample and feature choices. Majority vote should become more stable as useful, nonidentical trees accumulate, though adding copies eventually brings little benefit.

For boosting, compare η = 1 with η = 0.2 for the same number of rounds. The larger step corrects residuals aggressively. The smaller step moves more gradually and usually needs more stumps. Plot or print training and validation MSE by round; choosing rounds from training MSE alone invites overfitting.

Feature importance is not causality.

A tree splitting often on a feature shows predictive use inside this dataset and algorithm. Correlated substitutes, cardinality, leakage, and sampling can change importance. It does not establish that intervening on the feature changes the outcome.

Real tree libraries provide missing-value policies, categorical splits, pruning, parallel training, histogram algorithms, and calibrated probabilities. Those are valuable after the core split, randomization, and residual-fitting logic is understood.

6. Practice, debug, and transfer

Exercise A · Compute Gini impurity

Edit ch15_01.rs and run Rustlings. Its count-based gini_impurity(positive, total) is the arithmetic primitive used by the reference's row-based gini_impurity(rows): both calculate the positive-class fraction and return 2p(1-p).

Hint 1

Convert positive count and total to f64, then compute p.

Hint 2

For binary classes use 2.0 * p * (1.0 - p).

Worked solution
fn gini_impurity(positive: usize, total: usize) -> f64 {
    assert!(total > 0 && positive <= total);
    let p = positive as f64 / total as f64;
    2.0 * p * (1.0 - p)
}

A pure node returns zero; a balanced binary node returns the maximum 0.5.

Exercise B · Guided checkpoint

Complete weighted_impurity(left, right) in projects/ch15/starter/src/main.rs, then run cargo test --manifest-path projects/ch15/starter/Cargo.toml. Each child tuple is (positive_labels, row_count); call the provided count-based gini_impurity for each child.

Progressive hint

Calculate each child Gini, multiply by that child's row count, add, then divide by the combined parent row count.

Worked arithmetic

A left child with three negative labels has Gini 0; a right child with one positive label has Gini 0. Weighted impurity is (3×0 + 1×0)/4 = 0. A split into [two negatives, one positive] and [one negative] has left p=1/3 and Gini=4/9, yielding weighted impurity (3/4)(4/9)=1/3.

Debugging · A forest of clones

A learner chooses one feature subset before growing a tree and reuses the same subset at every node. Explain the deviation.

Answer

Standard random forests resample candidate features independently at each node. Reusing one subset restricts the whole tree to the same features and changes its distribution. Draw candidates inside recursive node construction, while still using one bootstrap row sample per tree.

Independent variation · Classification boosting

Keep the regression code, but encode binary labels as −1 and +1 targets and inspect score signs. What can the output support?

Worked answer

Residual-fitting squared loss can learn a real-valued score whose sign supplies a classifier. The raw score is not a calibrated probability. Converting it to probability requires a justified link or a separate leakage-safe calibrator evaluated on held-out data.

Retrieve: Why weight child impurity by size? What two random mechanisms create a forest? How do forests differ from boosting? Under squared loss, what target does the next boosting stump fit? Why can a deeper tree hurt?

Answers

Weighting measures expected child impurity for a random parent row. Forests bootstrap rows and sample candidate features at each node. Forest trees fit independently and vote; boosting fits learners sequentially to correct current errors. Squared-loss boosting fits residuals. Depth can isolate noise and increase variance.

The project omits pruning, out-of-bag bookkeeping, multiclass trees, and classification loss for boosting. Those belong in production tools or later extensions. In Chapter 16, margins and kernels offer another route to nonlinear boundaries.
