Accuracy answers one narrow question about one labeled sample. It does not tell you why a prediction changed, how an attacker can move it, whether error rates differ across groups, what training data leaked, or what would happen under an intervention. Responsible evaluation keeps those questions separate and attaches every claim to the evidence that can support it.

The audit

You will run six quantitative checks on a fictional twelve-row classifier: local feature ablation, bounded perturbation, multiple group metrics, a membership-inference attack, input-boundary validation, and crude versus stratum-standardized association. The output is an evidence record, not a certificate that the model is fair, private, secure, robust, interpretable, or causal.

1. Begin with a claim and its denominator

The model has two numeric features, weights [0.8,0.4], bias −0.2, sigmoid output, and threshold 0.5. Each row includes a fictional group A or B, a binary label, and whether the row belonged to a separate model's training subset. The data are course-authored to make several failures visible. They are not people, medical cases, credit records, or evidence about any population.

Overall accuracy is correct predictions divided by all rows. Group true-positive rate is correctly predicted positives divided by positive labels in that group. False-positive rate is incorrectly positive predictions divided by negative labels in that group. Positive prediction rate uses every row in the group. The numerators can overlap, but the denominators answer different questions. Always print the group count beside a rate; 100 percent from one example has different uncertainty from 100 percent from ten thousand.

Responsible evaluation is not a function that combines six numbers into one moral score. Security has an attacker and attack surface. Robustness has a perturbation set. Privacy has a protected unit and release mechanism. Fairness has affected groups, decisions, and harms. Causality has an intervention and assumptions. Combining them too early hides which evidence failed and which trade-off a decision maker chose.

2. Interpretability and robustness ask different counterfactuals

The project's feature attribution is simple ablation. For input x = [1,1], the original logit is 0.8(1)+0.4(1)−0.2 = 1.0. Replace feature zero with baseline zero: the logit becomes 0.2, so its contribution by this rule is 1.0−0.2 = 0.8. Replace feature one: the logit becomes 0.6, giving contribution 0.4. Together with the baseline logit −0.2, the contributions reconstruct one.

This exact decomposition works because the model is linear and additive. It explains model arithmetic near a declared baseline. It does not say increasing feature zero in the world causes an outcome to rise. The feature may be a proxy, the baseline may be unrealistic, and correlated features can make “remove one” inputs unlike any observed case. For nonlinear models, interactions mean isolated ablations need not add back to the original score.

Interpretability methods need sanity checks. A plausible-looking heatmap can remain similar after model parameters or labels are randomized. The relevant test depends on the method: compare with a randomized model, alter the data relation, test repeatability, and check whether the explanation changes when the prediction changes. Visual appeal is not validation.

Robustness asks how predictions behave under allowed changes. The project defines a threat model: an evaluator may add or subtract 0.25 from feature zero, leaves feature one fixed, and tests both directions for every row. It counts threshold flips and records the greatest probability change. The measured run finds four flips and a maximum probability change around 0.050.

Why a small probability change can flip a decision

A row with logit 0 has probability 0.5. Moving feature zero by −0.25 changes the logit by 0.8(−0.25)=−0.2. The new probability is sigmoid(−0.2)≈0.450. Its absolute probability movement is only about 0.05, yet a 0.5 threshold changes the decision. Report both continuous change and discrete flips.

A threat model names access, goal, perturbation rule, and budget. This one-dimensional test does not cover changes to both features, other norms, adaptive optimization, physical transformations, distribution drift, or poisoned training. “Four flips at radius 0.25” is defensible. “The model is not robust” or “robustness is 83 percent” without the threat model is not.

Equal accuracy hides different positive, true-positive, and false-positive rates. True-positive-rate parity may be relevant when missed positives create a shared harm, but it is not automatically the correct policy target. False positives may dominate another setting. Calibration, base rates, thresholds, delayed labels, and measurement quality also matter. Some fairness criteria cannot all be satisfied except under restrictive conditions. Mathematics exposes the conflict; it does not choose which costs society should accept.

This fixture has only six rows per group, no confidence interval, hand-set group labels, and a preset threshold. The project therefore says the metrics differ, not that a deployed decision is discriminatory or fair. A serious analysis would document how groups and outcomes were defined, include intersecting groups, quantify uncertainty, examine missing labels, and connect rates to the actual action taken.

Privacy is another axis. A membership-inference attacker guesses whether a candidate row was in training. The project first trains a separate logistic model only on rows marked as members. It then computes every member and nonmember loss. The attacker knows each candidate’s true label and can obtain its predicted probability; the reference computes the corresponding loss directly through model.loss. This is a label-assisted, probability-access attack, not a label-only interface. The attacker guesses “member” when loss is below 0.45 and reports attack true-positive rate, false-positive rate, and advantage TPR−FPR. The measured fictional fixture yields 0.875, 0, and 0.875.

That high advantage shows successful membership discrimination for this operating point and candidate set. It does not by itself prove that memorization caused the separation: the deliberately different member and nonmember rows can differ in difficulty or distribution. A lower result would not prove privacy either; another threshold, auxiliary data, repeated query access, or stronger attack could perform better. Membership inference also differs from reconstructing attributes or stealing parameters. The audit must state what the attacker sees and which records count as candidates.

Differential privacy is a formal guarantee about output distributions on neighboring datasets. Noise alone does not establish it. A valid claim requires a protected unit, adjacency definition, sensitivity or clipping bound, calibrated random mechanism, epsilon and delta, and composition accounting across all releases. This project adds no training noise, implements no accountant, and reports no budget. It makes no DP claim. Even if we added arbitrary Gaussian noise to the weights, the correct conclusion would remain “unverified privacy” until the complete mechanism were analyzed.

4. Validate hostile inputs and resist causal language

The local input parser, which could be called by the preceding chapter’s server, accepts exactly schema=1,f0=<number>,f1=<number>. It rejects wrong schema, missing fields, extra structure, parse failures, NaN, infinity, and values outside [−5,5]. The model also validates its weights, bias, threshold, and output. These checks prevent malformed numbers from contaminating metrics and predictions. They are security basics, not a complete defense against denial of service, model extraction, malicious training data, compromised artifacts, or unauthorized access.

Stable binary loss avoids overflow. Define softplus(a) as a + ln(1+exp(−a)) when a is positive, and ln(1+exp(a)) otherwise. For a positive label the loss is softplus(−logit); for a negative label it is softplus(logit). At logit 1000, the negative-label loss is about 1000 rather than infinity. The same stable calculation supports the privacy attack on extreme but finite scores.

The final experiment demonstrates why prediction is not intervention. There are low-risk and high-risk strata. In low risk, treated outcomes are 1/10=0.10 and control outcomes 18/90=0.20. In high risk, treated outcomes are 54/90=0.60 and control outcomes 7/10=0.70. Within both strata, treated rows have an outcome rate 0.10 lower.

Opposite aggregate and standardized associations

Most treated rows are high risk. Aggregated treated outcomes are (1+54)/(10+90)=0.55; control outcomes are (18+7)/(90+10)=0.25. The crude treated-minus-control association is +0.30. Give the two strata equal weight: [(0.10−0.20)+(0.60−0.70)]/2 = −0.10. Merely choosing a comparison changes the sign.

The standardized result is still an association. Calling it an effect requires causal identification: a defined intervention plus assumptions or a design that connects observed quantities to the intervention. Here we have not established no unmeasured confounding, treatment consistency, overlap for the target population, or measurement validity. The safe output labels both numbers as associations and explains the missing assumptions.

Observational data can support causal inference when a defensible graph or design identifies the desired quantity. The lesson is not “causality requires randomized trials in every case.” It is that predictive accuracy and adjustment code cannot manufacture the assumptions. When an effect is not identified, report that limit instead of changing verbs from “associated with” to “caused.”

Guided audit work

  1. Complete true-positive rate using only rows with the requested group and positive label.
  2. Debug a report where a group with no positive labels gets TPR 0.0. Preserve “undefined” so absence of evidence is visible.
  3. Change the robustness radius from 0.25 to 0.5. Predict whether maximum probability change and flip count must both increase; run and explain the result.
  4. Independent variation: sweep membership thresholds 0.1 through 1.0, print TPR and FPR, and choose an operating point using a stated attacker cost. Do not call the best observed point a privacy guarantee.
Hint 1: group denominator

Count positive labels first. The numerator adds a prediction condition, but the denominator does not.

Hint 2: robustness monotonicity

For this fixed linear logit, enlarging the symmetric radius moves each tested endpoint monotonically away from its original score, so maximum change and endpoint flip count cannot decrease. A nonlinear model can cross the threshold and cross back, so endpoint-only flip counts are not generally monotone; sampling or optimization over the entire allowed interval would be needed.

Worked answers

Filter by group, count all positive labels, count predicted positives among them, and use (positives > 0).then_some(true_positives as f64 / positives as f64). Undefined is not zero. For attack sweeping, print the candidate population, access to per-row loss, threshold, both rates, and advantage at every point.
