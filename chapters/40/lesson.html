Training ends with fixed parameters, but useful text appears one token at a time. Re-running the entire decoder after every token repeats almost all earlier work. This chapter turns the Chapter 36 model into a small inference serving loop: it caches real keys and values in every layer, samples deliberately, round-robins active requests, and streams each completed token.

Milestone

You will prove that incremental logits match full-prefix logits at every position. Then two requests with different prompt and output lengths share a scheduler while keeping separate caches and random-number state.

This inference chapter computes no loss and performs no averaging over examples or tokens. CachedDecoder::step is one token-cache advancement owned by the cached decoder; Chapter 39's optimizer step is one parameter update owned by its trainer. A request batch groups independent sequences, while each request's cache position indexes tokens within that sequence. The scalar loop does not create a tensor batch axis.

Chapter 36 stores every projection matrix row-major as [input features,output features], abbreviated [in,out], so matvec computes input[i] * weights[i * out_features + j]. This matches Chapter 36's published parameter spans and is the storage transpose of the earlier dense-layer [out,in] convention; it represents the same linear map. Chapter 40 preserves every span name, range, order, and byte layout. Its private parameter_slice(name) reads a named range. The one-row matvec and layer_norm helpers specialize Chapter 36's batched operations for the newest token and omit backward caches.

Decoder::forward and Decoder::trace both process a complete token slice. Reusing either inside each generation iteration would repeat the work this chapter removes. The necessary new local type is a persistent CachedDecoder per request; it reads Chapter 36's existing parameters(), parameter_spans(), and config() interfaces and applies the same operators only to the new token.

1. Reuse the past without changing the model

In the causal decoder from Chapter 36, each attention layer projects the current hidden vector at position t into a query qt, key kt, and value vt. The new query may attend to keys and values from positions 0 through t, but causality prevents earlier outputs from depending on the new token. Their projected keys and values therefore remain valid.

A KV cache stores those projected vectors per layer. A genuine cached decoder still executes token embedding, position embedding, both normalizations, attention, residual paths, and the feed-forward block for the new token. It does not store an old final output and pretend that it represents the internal state.

Count a two-layer cache

Our demonstration has L = 2 layers, width D = 8, and t = 5 cached positions. Each layer stores one D-element key and one D-element value per position. The count is 2 × L × t × D = 2 × 2 × 5 × 8 = 160 f32 values, or 640 bytes. Queries are used immediately and need not persist. For batch B, standard multi-head attention scales this storage as 2BLtD values.

Without caching, producing token t recomputes projections for t prefix positions. Summed over n generated tokens, that repeated prefix work grows like 1 + 2 + … + n. Caching makes projection work linear in n, although the newest query must still compare with every cached key. Dense decoder attention therefore retains a growing per-token attention cost.

Learned positions impose an invariant. Chapter 36 numbers positions from zero inside its context window. When the cache reaches the configured context length, our program returns an error. Sliding farther requires discarding state and replaying a cropped window with positions restarted, or using a model and cache policy designed for another positional scheme.

2. Match full-prefix logits, layer by layer

The complete reference depends on the real Chapter 36 decoder. It reads the published parameter spans: token and position embeddings; layer-normalization gains and biases; QKV, attention-output, and feed-forward matrices; final normalization; and the language-model projection. Each matrix uses the same row-major [in,out] layout as the decoder.

let (q, rest) = qkv.split_at(c.width);
let (k, v) = rest.split_at(c.width);
self.layers[layer].keys.extend_from_slice(k);
self.layers[layer].values.extend_from_slice(v);

For every head, the new query forms scaled dot products with all cached keys. Stable softmax subtracts the largest score. The probabilities weight cached values; the combined context continues through the output projection, residual addition, second normalization, GELU feed-forward block, and second residual. Only after every decoder layer do final normalization and the vocabulary projection produce logits.

The strongest local oracle is the unchanged decoder. For prefix [2], then [2, 9], through [2, 9, 1, 6, 4, 3], the test compares the cache’s newest vocabulary row with the last row returned by Decoder::forward. This catches wrong position indices, transposed matrices, keys cached after the wrong normalization, head-layout mistakes, and missing residual paths. A token-ID match alone is weaker because different logits can share an argmax.

Diagnose a tempting fake cache.

Suppose an implementation stores only the previous final logits and appends a new embedding. It may repeat the same sampled tokens on one prompt, yet it cannot reconstruct layer-two attention because that layer needs keys and values projected from layer-one contextual states. The repair is not another output field: cache K and V separately inside every layer and verify all logits against full-prefix inference.

3. Turn logits into a controlled choice

Decoder::forward and CachedDecoder::step return logits, which are unnormalized scores rather than probabilities. sample_token divides retained logits by temperature τ and normalizes them: pᵢ = exp(zᵢ/τ) / Σⱼ exp(zⱼ/τ). Here zᵢ is token i’s logit and pᵢ is its sampling probability. The function returns one sampled token ID: the generated choice, not the logits or probability vector. Different RNG draws can choose different tokens from the same predictive distribution. τ below one sharpens differences; τ above one flattens them. Temperature must be finite and positive.

Temperature, then top-k

Take logits [2, 1, 0] and τ = 2. Dividing gives [1, 0.5, 0]. After stable softmax the probabilities are about [0.5065, 0.3072, 0.1863]. With top-k = 2, discard the third token and renormalize the survivors: [0.6225, 0.3775, 0]. The ordering matters only conceptually here because top-k ranking is unchanged by a positive temperature.

Top-k sampling limits choice to the k largest logits. Setting k = 1 is greedy decoding. Larger k admits more alternatives, but neither k nor temperature has a universally correct setting. They trade determinism and diversity against the risk of selecting low-score tokens. Evaluate them on the target task.

The implementation keeps a deterministic SamplingRng per request. This local linear-congruential generator has its own fixture seeds; it does not restore Chapter 36's xorshift Rng from a training checkpoint. Samples from different generators need not match even when the logits do. That makes the small test reproducible and prevents scheduling order from sharing one accidental global random stream. Production random-number requirements differ, especially where unpredictability matters; this generator exists only for a repeatable numerical experiment.

4. Schedule requests and stream completed tokens

Prompts and requested output lengths differ. A fixed request batch makes a short request wait until the longest finishes, or wastes slots on finished sequences. Continuous batching reconsiders the active request set after each one-token decoding iteration. New work can enter and finished work can leave at that boundary.

Our run_request_batch CPU scheduler is deliberately small: it loops over an initially supplied request set, samples one token from each request’s current logits, emits a stream event immediately, advances only that request’s sequence cache, and skips it in later iterations when its token quota reaches zero. This is real per-request state and real cached model inference, although the scalar loop does not fuse requests into a matrix kernel or admit late arrivals. Adding an input queue at the iteration boundary is the next step toward full continuous batching.

Token streaming exposes each token when it is ready. It can improve time to first visible output while leaving total generation time unchanged. A network server also needs cancellation, bounded queues, backpressure, timeouts, and a transport such as server-sent events. Those concerns are outside this executable; the emitted stream request: token records make the scheduling boundary observable.

Fairness is a policy choice. Round-robin service, used here, prevents one request from consuming every turn, but it does not optimize throughput or deadlines. Real serving systems group compatible work, control maximum batch size, and budget cache memory. Measure the actual request-length distribution before claiming that a scheduler improves latency.
