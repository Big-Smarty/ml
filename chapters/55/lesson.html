You can now inspect a learning system down to its arithmetic. That knowledge becomes more useful when you work with an established framework: you can tell whether a short API call computes the function you intended. This chapter exports a small scratch model, imports its parameters into Burn, and checks the entire path from prediction through gradients to a restored model.

A concrete integration boundary

The standard-library project remains independent. A separate optional Cargo package pins Burn 0.21.0 and runs on its CPU ndarray backend. It actually executes tensor operations and automatic differentiation. Nothing in the ordinary course build requires this framework or a network download.

Code and terminology carried forward

Chapter 9 introduced Dense::forward, row-major activations [batch,input features], and weights stored as [output features,input features]. This chapter keeps that layer name, operation, parameter orientation, and bias meaning in a fixed f32 fixture. Chapter 36 separated loss_and_gradient from apply_sgd; the scratch oracle keeps that separation and represents derivatives with a distinct Gradient type. Chapter 38 distinguished inference state from exact training-resume state. The same distinction governs the small affine artifact here. The course-wide rules are on the conventions page.

1. Decide what must stay the same

Suppose you replace the hand-written affine layer from Chapter 9 with a library layer. Both programs compile, both return two numbers, and both losses decrease. Those observations do not show that you ported the same model. One implementation might transpose the weights, omit a bias, divide the loss by a different denominator, or apply an update before all gradients have been calculated.

A framework parity check applies Chapter 47's broader numerical parity check to corresponding calculations across two implementations under an explicit contract. Our contract fixes input values, target values, parameter values, layout, floating-point type, loss reduction, and learning rate. We check outputs before checking gradients, then check one update and serialization. This order localizes the first divergence. A final score alone would mix all those possible failures together.

A framework supplies reusable tensors, differentiation rules, parameter organization, optimizers, serialization, and execution backends. A tensor is still an array with a shape and an element type. A module usually organizes named parameters and a forward calculation; a backend supplies operations for a class of devices; a device chooses an execution destination. These conveniences replace code you have already written, while preserving the need to understand the underlying numerical contract.

The optional implementation deliberately uses explicit tensors rather than a complete trainer abstraction. Its backend type is Autodiff<NdArray<f32>>. The inner backend performs CPU arithmetic and the outer decorator records derivative information. The 2 in Tensor<Cpu, 2> specifies rank, not a dimension length. A matrix can have two axes while still having an incorrect runtime shape. Inspect dimensions when importing data or weights.

Use the Burn tensor reference to confirm operations and shapes for the pinned version. Burn 0.21 retains ndarray during a transition but recommends its newer Flex backend for new CPU development. We keep ndarray here because it is the verified, isolated parity fixture. The 0.21 release notes explain that status; this chapter is not a recommendation to start a new long-lived application on a deprecated backend.

2. Calculate the port before running it

The scratch model stores a 2×2 weight matrix in row-major [output,input] order. Input x is [1.5,−2], target t is [1,−0.5], and bias b is [0.05,−0.2]. The weight rows are [0.2,−0.4] and [0.7,0.1]. Output component o is the dot product of weight row o with x, plus bias component o.

Forward, loss, gradient, update

The first output is 0.2×1.5+(−0.4)×(−2)+0.05 = 1.15. The second is 0.7×1.5+0.1×(−2)−0.2 = 0.65. Errors are [0.15,1.15]. Mean squared error across the two outputs is (0.15²+1.15²)/2 = 0.6725.

The derivative of this mean with respect to output is 2(y−t)/2 = y−t. Weight derivatives are outer products of output derivatives and inputs: [[0.225,−0.3],[1.725,−2.3]]. Bias derivatives are [0.15,1.15]. At learning rate 0.1, updated scratch weights are [[0.1775,−0.37],[0.5275,0.33]], and updated biases are [0.035,−0.315].

Run forward again with those updated values. The output is [1.04125,−0.18375]. Its errors are [0.04125,0.31625], so the new MSE is approximately 0.0508578. These are hand calculations; the executable uses f32 and compares with tolerances.

For a batch with B examples and O outputs, the general reduction is L = ΣᵦΣₒ(yᵦₒ−tᵦₒ)²/(BO). Its output derivative is 2(yᵦₒ−tᵦₒ)/(BO). Our fixture has B=1 and O=2, which explains the convenient cancellation. Do not memorize “MSE gradient equals error” without its denominator. Increasing batch size or output width changes that expression.

fn loss_and_gradient(&self, input: [f32; 2], target: [f32; 2]) -> (f32, Gradient) {
    let output = self.forward(input);
    let error: [f32; 2] = std::array::from_fn(|o| output[o] - target[o]);
    let loss = error.iter().map(|x| x * x).sum::<f32>() / error.len() as f32;
    // d(mean(error²))/doutput = error because there are two outputs.
    let gradient = Gradient {
        weights: std::array::from_fn(|o| std::array::from_fn(|i| error[o] * input[i])),
        bias: error,
    };
    (loss, gradient)
}

The raw Burn matrix multiplication follows [batch,input] × [input,output]. We therefore transpose the stored scratch matrix into [[0.2,0.7],[−0.4,0.1]]. The four numbers are unchanged, but their positions change. The gradient undergoes the same mapping: Burn's flat gradient is [0.225,1.725,−0.3,−2.3]. Compare named coordinates rather than interpreting a flattened array without its shape.

let input = Tensor::<Cpu, 2>::from_floats([[1.5, -2.0]], &device);
let target = Tensor::<Cpu, 2>::from_floats([[1.0, -0.5]], &device);
// Burn matmul expects [in, out]; the scratch oracle stores [out, in].
let weights = Tensor::<Cpu, 2>::from_floats([[0.2, 0.7], [-0.4, 0.1]], &device).require_grad();
let bias = Tensor::<Cpu, 1>::from_floats([0.05, -0.2], &device).require_grad();
let output = input.clone().matmul(weights.clone()) + bias.clone().unsqueeze_dim::<2>(0);
let loss = (output.clone() - target).powf_scalar(2.0).mean();
close(&values(output), &[1.15, 0.65]);
close(&[loss.clone().into_scalar()], &[0.6725]);

The bias becomes shape [1,2] and broadcasts across the batch. That is a deliberate operation, not a repair for an arbitrary mismatch. Nor is transposing a universal framework rule: PyTorch's linear operation accepts [output,input] weights and performs the transpose internally. Translate the equation into each API's documented convention.

3. Keep differentiation separate from optimization

In the scratch reference, loss_and_gradient returns the scalar MSE and a distinct Gradient value. A gradient has arrays with the same shapes as the parameters, but it is derivative data rather than another trained Dense model. The framework computes the same derivatives by following recorded operations backward. A differentiable backend does not infer which arrays you meant to train: the example marks weights and bias with require_grad() before the forward pass.

After the intervening output and loss parity assertions shown above, the exact autodiff retrieval is:

let gradients = loss.backward();
let weights_gradient = weights.grad(&gradients).ok_or("missing weight gradient")?;
let bias_gradient = bias.grad(&gradients).ok_or("missing bias gradient")?;

Burn's backward operation returns a gradient container. The autodiff guide documents that contract. Do not transfer assumptions about mutable parameter gradient fields from another library. Missing derivatives should be reported as errors rather than replaced with zeros, because a disconnected parameter would otherwise appear to train normally.

The project applies plain SGD to both inner weights and bias tensors. Removing the autodiff wrapper before subtraction makes the update an operation on parameter values rather than a differentiable optimizer step. No momentum, weight decay, scheduler, or clipping participates in this fixture. More elaborate optimizers would introduce state and extra equations that need their own parity boundary.

All derivatives must describe the same old model. Retrieving the weight gradient, updating weights, and then deriving a bias gradient through a partly changed graph would not implement the step calculated above. The reference obtains both derivatives first, constructs both updated tensors, and checks their values and resulting prediction. This is the same simultaneous-update rule you learned with one neuron.

fn apply_sgd(&mut self, gradient: &Gradient, learning_rate: f32) -> Result<(), &'static str> {
    if !learning_rate.is_finite() || learning_rate <= 0.0 {
        return Err("learning rate must be finite and positive");
    }
    if self
        .weights
        .iter()
        .flatten()
        .chain(&self.bias)
        .zip(gradient.weights.iter().flatten().chain(&gradient.bias))
        .any(|(parameter, derivative)| {
            !parameter.is_finite()
                || !derivative.is_finite()
                || !(parameter - learning_rate * derivative).is_finite()
        })
    {
        return Err("nonfinite model, gradient, or update");
    }
    for o in 0..2 {
        for i in 0..2 {
            self.weights[o][i] -= learning_rate * gradient.weights[o][i];
        }
        self.bias[o] -= learning_rate * gradient.bias[o];
    }
    Ok(())
}

The closeness predicate uses |a−b| ≤ 10⁻⁶ + 10⁻⁵ max(|a|,|b|). Here a and b are corresponding f32 results; the first term is absolute tolerance and the second scales with magnitude. Require equal lengths and finite values before this comparison. Infinity can make both the difference and tolerance infinite, accidentally satisfying an inequality; NaN comparisons behave differently again. A tolerance should handle rounding, never excuse malformed numbers.

Do not loosen tolerances merely until a port passes. First inspect shape, the maximum-error coordinate, reduction order, activation formula, and precision. A transpose error on our fixture changes the function substantially and needs a mapping correction. Small last-digit differences after equivalent f32 reductions are a different phenomenon. For a larger port, add probes near zero and at meaningful extremes while keeping inputs within the model's defined domain.

4. Export an inference contract, then restore it

Runtime interchange means carrying a defined computation and its state across execution implementations. This project uses a deliberately small, course-owned binary format. Its first eleven bytes spell CH55DENSE01. The next six little-endian f32 values contain four weights in scratch row order followed by two biases. Exactly 35 bytes describes this fixed affine architecture. Wrong headers, extra or missing bytes, and nonfinite values are rejected.

The scratch executable exports the parameters after its checked SGD update. The optional importer reads those actual bytes, transposes the four weights, constructs Burn tensors, and compares three input probes against a scalar calculation using the imported parameters. The probes include the training input, [−1,3], and [0,0]; the zero vector isolates the bias. A successful import is therefore more than reproducing the same hard-coded fixture in two programs.

Saving uses exclusive creation so an existing path is not overwritten. The loader reads at most 36 bytes, which is enough to reject an oversized artifact without loading an arbitrary file into memory. The ordinary demonstration creates a temporary artifact, checks exact parameter round-trip equality, and removes it. Byte round-trip equality is appropriate for storing and restoring the same f32 values; numerical execution parity still uses a tolerance.

The framework also serializes the updated weight-and-bias tensor pair with a Named MessagePack bytes recorder and restores both before checking a prediction. Burn records are an interchange mechanism within Burn's type and backend system. This record does not encode the scratch file format, an optimizer, or a universal computation graph. Recreating the right operations remains part of loading the model.

Standardized graph formats solve a broader problem. ONNX describes graphs with operators, inputs, outputs, and stored tensor values. Exporting such a graph still requires a runtime that supports its operators and version, plus a compatible preprocessing contract. The present implementation does not export ONNX. Its small format demonstrates the same need to specify names, layouts, dtypes, and operations without introducing an untested conversion toolchain.

An inference artifact also differs from a training-resume checkpoint. Our exported affine values are sufficient to evaluate this fixed function. If training used Adam, resuming the exact next step would additionally require moment estimates, step count, schedule, and data position. Keep the distinction from Chapter 38: successful inference restoration is not evidence of exact optimizer continuation.

Guided gradient and tolerance checks

Hint 1: follow the scalar dependency

Changing one weight changes its output by the corresponding input. Multiply that local derivative by the output derivative. The reduction factor has already canceled for this particular two-output fixture.

Hint 2: write the conditions before the comparison

Validate nonnegative finite tolerances, equal lengths, and finite elements. Only then compare each absolute difference with absolute tolerance plus relative tolerance times the larger magnitude.

Debugging: forward matches, training drifts

A port passes the initial prediction check and restores the correct weights. After one training step, every output differs. Inspect whether the bias was updated and serialized, then inspect the loss denominator. Explain which check would locate each error.

Worked diagnosis

A weight-only update passes a weight test but fails the updated-bias probe [0,0]. An incorrect reduction changes both gradients before serialization is involved. Compare derivatives first, then updated values, then restored predictions. Do not start by changing the learning rate to hide the discrepancy.

6. Retrieve the contract before using a larger tool

Close the source and explain why equal shapes do not imply equal layouts; why backward does not itself perform SGD; why a zero-input probe is useful; and why an inference artifact is insufficient for Adam resume. Also explain which failures tolerances should accommodate and which they should reject.

Check your explanations

A 2×2 transpose preserves shape while changing coordinate meaning. Backward computes derivatives; an optimizer applies a separate update. Zero input exposes the bias independently of weights. Adam continuation needs its moments and step-dependent state. Tolerances allow bounded numerical rounding after equivalent computations; they do not justify wrong reduction, missing parameters, NaN, or infinity.
