A linear digit model combines pixels only once. A hidden layer can learn intermediate stroke features, but it also makes initialization and optimization more consequential. This chapter trains a real ReLU MLP, compares momentum with Adam, and saves enough state to resume exactly.

Milestone

You will train a [pixels,16,10] classifier on a generated IDX fixture or MNIST files. Its checkpoint contains dimensions, every parameter, optimizer kind, moment buffers, hyperparameters, and step count, with validation before allocation or resume.

1. Add one nonlinear hidden layer

The model receives an image vector x with input normalized pixels. Its first dense layer computes a hidden pre-activation a=W₁x+b₁. A rectified linear unit applies h=max(0,a) element by element. The second dense layer computes ten logits z=W₂h+b₂. The mathematical x and y correspond to the code’s image and discrete label; the generic class argument to a loss is target. Softmax cross-entropy is identical to Chapter 10.

hj=max(0,b₁j+ΣkW₁j,kxk);   zc=b₂c+ΣjW₂c,jhj

The ReLU is nonlinear, so two dense layers no longer collapse to one. A hidden unit can respond to a pattern of pixels, while an output combines several hidden patterns. The fixture uses 16 hidden units; official 28×28 images give shapes W₁=[16,784] and W₂=[10,16]. This is a small educational model, not a competitive architecture.

The implementation stores W₁, b₁, W₂, and b₂ consecutively in one parameters vector so the optimizer can keep same-length state arrays. The offsets name that packing explicitly: W₁ starts at weights1, b₁ at bias1, W₂ at weights2, and b₂ at bias2. Within each dense matrix, weights use [out_features,in_features] row-major order.

fn parameter_offsets(&self) -> (usize, usize, usize, usize) {
    let weights1 = 0;
    let bias1 = self.hidden * self.input;
    let weights2 = bias1 + self.hidden;
    let bias2 = weights2 + CLASSES * self.hidden;
    (weights1, bias1, weights2, bias2)
}

ReLU’s derivative is one where its input is positive and zero where negative. The reference stores the hidden activation cache and checks each activation against zero during backward. At exactly zero the derivative is undefined; the implementation chooses zero. Gradient checks avoid that point because central differences there do not represent one unique derivative.

For each example, cross_entropy_from_logits uses maximum-shifted log-sum-exp. The fused method sums per-example losses and packed gradients, then divides both by end - start. Thus the reported batch loss and every parameter derivative have the same mean-over-examples reduction used in Chapter 10.

fn cross_entropy_from_logits(logits: [f64; CLASSES], target: usize) -> f64 {
    let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    (maximum - logits[target])
        + logits
            .iter()
            .map(|logit| (logit - maximum).exp())
            .sum::<f64>()
            .ln()
}

A one-unit forward and backward trace

Suppose x=[0.5,1], one hidden unit has weights [0.4,−0.1] and bias 0.2. Its pre-activation is 0.4×0.5−0.1×1+0.2=0.3, so h=0.3. If an output path sends hidden gradient 2, ReLU passes 2 because the activation is positive. The first weight gradients are 2×0.5=1 and 2×1=2; the hidden bias gradient is 2. If the pre-activation were −0.3, h would be zero and all three gradients would be zero for this example.

2. Initialize signals without erasing diversity

All-zero initialization would make every hidden unit identical. They would compute the same activation, receive the same gradient, and remain redundant. The project uses a deterministic pseudo-random sequence to give weights distinct values. First-layer weights are uniform in ±√(6/input), whose variance is 2/input because a uniform range ±a has variance a²/3. Output weights similarly use ±√(6/hidden). Biases remain zero. This width-aware scaling keeps typical ReLU signals from exploding while preserving symmetry breaking.

Determinism makes the tiny fixture and tests repeatable. It does not guarantee bitwise results across every optimized platform, because floating-point additions may be reordered. For real experiments, record the seed, data split, shapes, optimizer, and training schedule alongside metrics.

Initialization cannot repair every training issue. A unit whose pre-activation stays negative for all examples receives no ReLU gradient. Excessively large weights can create unstable logits. Tiny weights can make signals hard to distinguish. Inspect loss, finite values, activation proportions, and gradient magnitudes before assuming that more epochs are the answer.

Debug the mechanism before quality.

The generated 2×2 fixture proves IDX parsing, nonlinear forward/backward passes, optimizer updates, and checkpoint restore. It is not evidence about handwriting recognition. MNIST mode is the meaningful dataset run, with a validation split carved from training for tuning.

3. Momentum and Adam remember previous gradients

Plain gradient descent uses only the current gradient. Momentum stores a velocity v. The convention in this project is vt=βvt−1+gt, then θt=θt−1−ηvt. Here θ is any parameter, g its current gradient, η the learning rate, and β=0.9 the memory factor. Conventions differ, so code and checkpoint must preserve the exact one used.

Two momentum steps

Start θ=1, v=0, η=0.1, β=0.9. With gradient 2, v becomes 2 and θ becomes 0.8. If the next gradient is zero, velocity remains 1.8 and θ moves to 0.62. Momentum carries direction through a flat or noisy step; it can also overshoot when direction changes.

Adam stores an exponential first moment m and second raw moment v. It updates m=β₁m+(1−β₁)g and v=β₂v+(1−β₂)g². Because both begin at zero, early values are biased downward. Dividing by 1−β₁t and 1−β₂t corrects that bias before the parameter step.

θt=θt−1−η m̂t/(√v̂t+ε)

The reference uses β₁=0.9, β₂=0.999, ε=10−8, and learning_rate 0.01 for Adam. Its momentum learning_rate is 0.1. Optimizer::step means one update of the complete parameter vector; step_count records how many such updates have completed and supplies Adam’s t. Adam rescales each parameter’s update using recent squared gradients; that often reduces manual scaling effort, but it does not remove the need to monitor validation performance or choose a schedule.

4. A checkpoint is part of the algorithm

Saving only parameters is sufficient for inference but not exact training resume. Momentum needs its velocity. Adam needs first moments, second moments, and optimizer step count t for bias correction. The checkpoint also records optimizer kind and hyperparameters, model input and hidden dimensions, parameter and state lengths, and a format version.

Resume semantics also affect the CLI. When an existing checkpoint is supplied, its recorded optimizer kind and hyperparameters win over the command’s creation-time choice. This prevents a nominal “Adam resume” from silently applying fresh defaults to momentum state. The program prints the actual restored kind and step so the experiment record is visible.

The loader treats checkpoint bytes as untrusted input. It verifies magic and version, uses checked arithmetic for expected parameter count, bounds lengths against remaining bytes before allocation, rejects trailing data and nonfinite values, requires a positive learning rate and epsilon, requires β values in [0,1), and rejects negative Adam second moments. It also confirms that checkpoint input width matches the selected dataset.

Saving appends .tmp to the complete checkpoint path, creates that sibling file only if it does not already exist, flushes it, and renames it into place. A temporary-file collision returns an error without changing either existing file; inspect the reported temporary path before retrying. This reduces the chance that interruption leaves a partially written target. Filesystem guarantees vary, so a production system may also sync the containing directory and retain generations. The chapter’s compact implementation states its boundary instead of inventing a storage framework.

The CLI saves only at epoch boundaries and always resumes sequential batches of 32 with a fixed learning rate. Exact continuation assumes the same training rows in the same order, so the next batch starts at row zero again. There is no shuffle or scheduler state to restore here; changing the dataset or batch size changes the update sequence even with identical optimizer state. The exact-resume test trains Adam, saves, restores, then applies the same next minibatch to the original and restored states. Parameters and step counts must match exactly. This proves optimizer state participated in serialization; merely checking that a file can be reopened would miss a reset moment buffer.

The preparation command checksum-verifies source archives, preserves the official test files, and derives a stratified validation split solely from original training rows. For the one final evaluation, keep the existing checkpoint, replace the validation paths with the matching t10k paths, and set the epoch argument to 0. Zero epochs requires an existing checkpoint, restores and evaluates the saved model without performing more updates, and leaves the checkpoint file unchanged. Keeping the earlier epoch count would continue training and evaluate a different model.

A verified one-epoch Adam smoke run on 55,000 fit images and 5,000 validation images moved held-out loss from 2.4401 to 0.4512 and accuracy from 10.9% to 88.0%, then wrote a checkpoint at optimizer step 1,719. These measured values confirm the full MNIST path and checkpoint write; they are not a promised accuracy target.

Create validation files only from the official training set while tuning. After choices are fixed, run evaluation against the official test files without using that score to adjust the model. If the checkpoint path already exists, the command resumes its recorded optimizer, even if a different optimizer word is supplied; printed output identifies the restored kind.

Debugging: resumed Adam takes a large jump

Parameters were restored, but moments and step_count were initialized to zero. The first resumed update behaves like a new optimizer.

Answer

Adam’s update depends on m, v, and t as well as parameters. Restoring only model parameters changes bias correction and scaling. Save and validate both moment arrays, the optimizer step count, kind, learning_rate, β values, and epsilon.

Transfer: measure dead ReLUs

During evaluation, count how often each hidden activation is zero. What would a unit at 100% zero suggest?

Worked answer

Maintain one counter per hidden unit and increment when h=0, then divide by example count. A unit always at zero is inactive on that dataset and receives no ReLU gradient there. Inspect its pre-activations, initialization, input scaling, and learning rate before deleting or replacing it.

6. Review and transfer

Retrieve: Why does the hidden layer add expressive power? Why should hidden units start differently? What state distinguishes momentum and Adam? Why is Adam’s step counter required? Which data may guide hyperparameter changes?

Answers

ReLU makes the composition nonlinear. Different initial parameters break hidden-unit symmetry. Momentum stores velocity; Adam stores first and second moments. Its optimizer step count determines bias correction. Use training and a validation split carved from training for choices; preserve the official test set for final evaluation.
