Can the classifier learn its own intermediate pixel features?

Chapter 10 learned one weight from each pixel to each class. Now we insert a small nonlinear hidden layer and let it adapt too. The project ends with a model that can be trained, evaluated and restored with its optimizer state.

The model receives an image vector x with input normalized pixels. Its first dense layer computes a hidden pre-activation a=W₁x+b₁. A rectified linear unit applies h=max(0,a) element by element. The second dense layer computes ten logits z=W₂h+b₂. The mathematical x and y correspond to the code’s image and discrete label; the generic class argument to a loss is target. Softmax cross-entropy is identical to Chapter 10.

hj=max(0,b₁j+ΣkW₁j,kxk);   zc=b₂c+ΣjW₂c,jhj

The ReLU is nonlinear, so two dense layers no longer collapse to one. A hidden unit can respond to a pattern of pixels, while an output combines several hidden patterns. The fixture uses 16 hidden units; official 28×28 images give shapes W₁=[16,784] and W₂=[10,16]. This is a small educational model, not a competitive architecture.

The implementation stores W₁, b₁, W₂, and b₂ consecutively in one parameters vector so the optimizer can keep same-length state arrays. The offsets name that packing explicitly: W₁ starts at weights1, b₁ at bias1, W₂ at weights2, and b₂ at bias2. Within each dense matrix, weights use [out_features,in_features] row-major order.

    pub fn parameter_offsets(&self) -> (usize, usize, usize, usize) {
        let weights1 = 0;
        let bias1 = self.hidden * self.input;
        let weights2 = bias1 + self.hidden;
        let bias2 = weights2 + CLASSES * self.hidden;
        (weights1, bias1, weights2, bias2)
    }

ReLU’s derivative is one where its input is positive and zero where negative. The reference stores the hidden activation cache and checks each activation against zero during backward. At exactly zero the derivative is undefined; the implementation chooses zero. Gradient checks avoid that point because central differences there do not represent one unique derivative.

For each example, cross_entropy_from_logits uses maximum-shifted log-sum-exp. The fused method sums per-example losses and packed gradients, then divides both by end - start. Thus the reported batch loss and every parameter derivative have the same mean-over-examples reduction used in Chapter 10.

    pub fn cross_entropy_from_logits(logits: [f64; CLASSES], target: usize) -> f64 {
        let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
        (maximum - logits[target])
            + logits
                .iter()
                .map(|logit| (logit - maximum).exp())
                .sum::<f64>()
                .ln()
    }

A one-unit forward and backward trace

Suppose x=[0.5,1], one hidden unit has weights [0.4,−0.1] and bias 0.2. Its pre-activation is 0.4×0.5−0.1×1+0.2=0.3, so h=0.3. If an output path sends hidden gradient 2, ReLU passes 2 because the activation is positive. The first weight gradients are 2×0.5=1 and 2×1=2; the hidden bias gradient is 2. If the pre-activation were −0.3, h would be zero and all three gradients would be zero for this example.

Why should hidden units begin different but not enormous?

All-zero initialization would make every hidden unit identical. They would compute the same activation, receive the same gradient, and remain redundant. The project uses a deterministic pseudo-random sequence to give weights distinct values. First-layer weights are uniform in ±√(6/input), whose variance is 2/input because a uniform range ±a has variance a²/3. Output weights similarly use ±√(6/hidden). Biases remain zero. This width-aware scaling keeps typical ReLU signals from exploding while preserving symmetry breaking.

Determinism makes the tiny fixture and tests repeatable. It does not guarantee bitwise results across every optimized platform, because floating-point additions may be reordered. For real experiments, record the seed, data split, shapes, optimizer, and training schedule alongside metrics.

Initialization cannot repair every training issue. A unit whose pre-activation stays negative for all examples receives no ReLU gradient. Excessively large weights can create unstable logits. Tiny weights can make signals hard to distinguish. Inspect loss, finite values, activation proportions, and gradient magnitudes before assuming that more epochs are the answer.

Predict the zero case

With zero first-layer weights and biases, every ReLU output is zero. The implementation chooses derivative zero at the kink. Output-weight derivatives multiply by zero activations, and hidden derivatives receive zero output weights. Only output biases can move. Symmetry breaking and activation behavior matter even though the SGD/Adam code itself can be correct.

What does a previous gradient contribute to the next step?

Return to the ordinary SGD update θ←θ−ηg from Chapter 06. It forgets the previous gradient as soon as it changes the parameter. That can make it slow through a long shallow region or sensitive to noisy changes in direction. Momentum keeps a running velocity with the same shape as the parameters.

Plain gradient descent uses only the current gradient. Momentum stores a velocity v. The convention in this project is vt=βvt−1+gt, then θt=θt−1−ηvt. Here θ is any parameter, g its current gradient, η the learning rate, and β=0.9 the memory factor. Conventions differ, so code and checkpoint must preserve the exact one used.

Two momentum steps

Start θ=1, v=0, η=0.1, β=0.9. With gradient 2, v becomes 2 and θ becomes 0.8. If the next gradient is zero, velocity remains 1.8 and θ moves to 0.62. Momentum carries direction through a flat or noisy step; it can also overshoot when direction changes.

The reference's velocity convention adds g without a (1−β) multiplier. Another implementation may use an exponential average and compensate through its learning rate. Do not mix the formulas while retaining the same numerical rate or old checkpoint.

How does Adam scale a step using two kinds of memory?

Adam stores an exponential first moment m and second raw moment v. It updates m=β₁m+(1−β₁)g and v=β₂v+(1−β₂)g². Because both begin at zero, early values are biased downward. Dividing by 1−β₁t and 1−β₂t corrects that bias before the parameter step.

θt=θt−1−η m̂t/(√v̂t+ε)

The reference uses β₁=0.9, β₂=0.999, ε=10−8, and learning_rate 0.01 for Adam. Its momentum learning_rate is 0.1. update means one update of the complete parameter vector; step_count records how many such updates have completed and supplies Adam’s t. Adam rescales each parameter’s update using recent squared gradients; that often reduces manual scaling effort, but it does not remove the need to monitor validation performance or choose a schedule.

What must survive if the next update is to stay the same?

Saving only parameters is sufficient to reproduce inference for a fixed architecture. Training continuation also depends on the optimizer: momentum needs velocity; Adam needs first and second moments and the step counter used for bias correction. The checkpoint includes input/hidden dimensions, every packed parameter, optimizer kind, rate, beta values, epsilon, step count and both state buffers.

The supplied checkpoint implementation writes versioned binary data. The reader checks magic/version, positive dimensions, checked parameter counts, exact remaining byte lengths, finite values, valid hyperparameter ranges and nonnegative Adam second moments before accepting state. It neither executes saved code nor trusts a file's claimed allocation sizes.

Saving creates a new sibling temporary file by appending .tmp to the full target path, writes and syncs its contents, then renames it into place. A pre-existing temporary sibling causes a useful error rather than overwriting that file. The current implementation does not sync the containing directory, so it is not a complete power-loss durability guarantee.

Every normal lab run saves to a newly-created temporary directory, restores, applies the identical next seven-row minibatch to both states, compares the resulting parameters and counters exactly, then removes only that directory. The solution goal check does this for both optimizers. This checks actual continuation; reopening a file or reproducing a prediction alone would not detect missing moment buffers.

The demonstration assumes the same ordered rows and next batch. There is no shuffle or learning-rate schedule in this small lab. Exact resume with those features would additionally require random-generator, data-position and schedule state. Changing the data or batch boundaries changes the training procedure even when the checkpoint itself is intact.
