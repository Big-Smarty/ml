Chapter 47 made computation sparse with a fixed mask. A mixture-of-experts layer chooses a sparse path separately for each input. That choice is useful only if the router actually learns, expert overload is visible, and the code does not erase the router's task gradient by normalizing one selected gate to one.

The concrete goal

You will train three scalar experts and a two-input router jointly, retain a differentiable top-1 gate, impose per-expert capacity, add a Switch-style balancing term, and verify both router and expert derivatives with central differences.

1. More parameters, selected computation

A mixture of experts contains several expert functions Eᵢ(x) and a router that scores them. A dense mixture evaluates every expert and combines every output. A sparse mixture selects only the highest-scoring k experts for each input.

This conditional computation can hold many expert parameters while using a smaller subset per token. It does not make router scoring, dispatch, memory, or communication free. Our CPU layer has three linear experts, each mapping two inputs to one output. Evaluating one expert is far too small to show a speed benefit; it makes the training calculus inspectable.

The router is a 3×2 matrix Wr. For input x=[x₀,x₁], expert i receives logit zᵢ=Wr,i·x. Stable softmax produces

pᵢ = exp(zᵢ−max z) / Σⱼ exp(zⱼ−max z)

Top-k routing chooses the indices with largest probabilities. The project uses k=1, calling the selected index m. Each expert is linear: Eₘ(x)=wₘ·x+bₘ. Its sparse output is

ŷ = pₘ Eₘ(x)

Only Eₘ executes for this input. The full router softmax still executes because every probability participates in pₘ's derivative. On the tiny fixture this means three dot products for the router and one for the expert.

One routed prediction

Suppose router logits are [1.0,0.0,−1.0]. Stable softmax is approximately [0.665,0.245,0.090], so expert zero is selected. If its output is 3, the layer returns 0.665×3=1.995. The gate expresses confidence and keeps a smooth path from task loss into the router.

2. The top-1 normalization trap

A tempting implementation takes selected probability pₘ and renormalizes it by the sum of selected probabilities. With one selection, that computes pₘ/pₘ=1. Away from an exact routing tie, argmax m is locally constant. The layer becomes ŷ=Eₘ(x), independent of every router logit. Therefore the task-loss router gradient is zero almost everywhere.

A changing route is not a usable ordinary derivative.

Argmax can switch at a boundary, but infinitesimal changes away from that boundary keep the same index. Ordinary backpropagation cannot learn through a piecewise-constant top-1 index. Normalizing the only continuous selected weight to one removes the remaining task path.

The reference follows the Switch top-1 form and retains the selected full-softmax probability. Let u=Eₘ(x), ŷ=pₘu, target y, and half-squared task loss L=½(ŷ−y)². First dL/dŷ=ŷ−y. The expert-output derivative is

dL/du = (ŷ−y)pₘ

For selected probability, dL/dpₘ=(ŷ−y)u. Softmax gives ∂pₘ/∂zⱼ=pₘ(I[j=m]−pⱼ). Combining them:

dL/dzⱼ = (ŷ−y)u pₘ(I[j=m]−pⱼ)

Trace the router gradient

Continue with p=[0.665,0.245,0.090], u=3, and target 1. The prediction is 1.995 and error is 0.995. The common factor error×u×pₘ is about 1.985. The selected-logit gradient is 1.985(1−0.665)=0.665. Other gradients are about −0.486 and −0.179. They sum to zero, as softmax logit gradients should. Gradient descent lowers the overconfident selected logit because this gated prediction is too high.

Top-2 routing offers another differentiable choice. If two selected logits are softmaxed within their pair, neither normalized weight is fixed. Its output derivative depends on the difference between expert outputs. This chapter stays with selected full-softmax top-1 because it needs only one expert evaluation and makes the zero-gradient failure unmistakable.

3. Capacity turns imbalance into a concrete event

A router may send most tokens to one expert. In a distributed system, that expert becomes a bottleneck while others sit idle. Expert capacity bounds how many tokens each expert accepts in a routing group.

capacity = max(1, ceil[(T/E) × capacity_factor])

T is batch token count, E is expert count, and the capacity factor is a positive allowance. Rounding upward and imposing a minimum of one are explicit conventions of this project; the Switch paper gives the proportional budget, not a universal integer-allocation rule. For T=12, E=3, and factor 1.25, capacity is ceil(5)=5. Balanced routing fits four tokens per expert. If counts are [8,3,1], three assignments to expert zero overflow.

The reference processes examples in a rotating order each epoch. An accepted token contributes task gradients to its expert and router. An overflow token contributes no expert task computation in this standalone layer, but it still contributes the balancing gradient described next. The returned drop count makes this behavior observable.

Large transformer blocks often have a residual path around the MoE layer, so an overflow token can bypass the dropped expert computation instead of becoming a zero model representation. Our scalar regression layer has no residual stream to preserve. The lesson therefore does not silently pretend its zero task contribution is a production policy.

Higher capacity reduces overflow but reserves more memory and expert work. It can also hide a collapsed router during a tiny test. The unit test uses factor 0.5, computes pre-update route counts, subtracts capacity from overloaded experts, and requires the exact returned overflow count. Checking only “some drops happened” would not verify the formula.

4. Train for fit and usable traffic

Task loss alone can reinforce early routing accidents. An expert that receives a useful group improves on that group, making the router more likely to keep selecting it. Other experts receive no examples and no expert gradients. A load-balancing loss adds pressure to use available experts.

For batch size T, define fᵢ as the fraction of hard top-1 assignments to expert i and Pᵢ as its mean router probability:

fᵢ=(1/T)Σₜ I[mₜ=i]    Pᵢ=(1/T)Σₜpᵢ(xₜ)
Lbalance = αE Σᵢ fᵢPᵢ

The assignment fraction f is discrete and treated as constant during differentiation. P is smooth. For every token, ∂Lbalance/∂pᵢ=αE fᵢ/T. The code sends that probability gradient through the full softmax Jacobian and into router weights. The coefficient α is 0.02 in the training fixture.

Collapsed versus balanced value

With three experts, collapsed routing has f=[1,0,0]. If mean probability is also P=[1,0,0], EΣfᵢPᵢ=3. Perfect balance has both vectors [1/3,1/3,1/3], giving 3×3×(1/9)=1. The balanced reference value does not prove useful specialization, and one is not a universal global minimum of this auxiliary term. For example, with two experts, give three quarters of tokens probabilities [0.51,0.49] and the remaining quarter [0.01,0.99]. Then f=[0.75,0.25], P=[0.385,0.615], and the unweighted value is 2(0.75×0.385+0.25×0.615)=0.885. Hard frequencies and mean probabilities need not match, which is why this term is a training heuristic rather than a certificate of perfect balance.

Here is how the probability gradient becomes the implemented logit gradient. Write gᵢ=∂L/∂pᵢ, including both the selected task contribution and the auxiliary contribution. Multiplying by the softmax Jacobian gives ∂L/∂zⱼ=pⱼ(gⱼ−Σᵢgᵢpᵢ). The Rust variable weighted is exactly the inner sum. For the router row j, multiply this scalar by each input component xₖ to obtain ∂L/∂Wr,jk. Even an unselected expert's router row can change because its probability competes with the selected gate. Its expert parameters remain untouched by this token's task loss.

The separate balancing-gradient test freezes hard frequencies from the original model, enables the auxiliary weight, and chooses enough capacity to accept every example. It compares every router-weight derivative with central differences of uncapped mean task loss plus that fixed-frequency auxiliary objective. Freezing frequencies is not a numerical shortcut: it expresses the stop-gradient convention. A finite perturbation large enough to change the winning expert would instead cross a nonsmooth boundary and invalidate this local test.

Capacity also changes the objective's normalization. The implementation divides accepted task-gradient sums by all T examples, rather than by the accepted count. Overflow examples have zero task-gradient contribution in this layer. Increasing overflow can therefore reduce the task-gradient magnitude even when accepted examples have the same errors. Reporting both uncapped inference loss and drop counts prevents that shrinkage from being mistaken for improved fit.

The model accumulates task and balance gradients over all 54 examples, then changes parameters once. Expert gradients are divided by total batch size, matching the reported mean task convention. Hard routes and capacity are computed at the old parameters. Updates are checked for finite results.

The printed loss is deliberately different from the training objective: it is uncapped inference mean half-squared task loss, with every input routed and no balance term. This lets before/after task fit be compared, but it cannot reveal overflow cost or the weighted auxiliary objective by itself. The output separately reports final-epoch overflow and route counts.

The complete reference implementation builds three synthetic regimes and trains for 1,500 full-batch epochs. Illustrative deterministic output is:

MoE mean half-squared loss: 1.36810 -> 0.00222
route counts=[18, 18, 18], final-epoch overflow=0

Balanced final counts are expected for this constructed fixture, but they do not show that real tokens will distribute evenly. Inspect the printed router and expert weights to confirm both moved. More decisively, the gradient test chooses an input away from a routing tie, disables balancing, uses inactive capacity, and compares one router and one expert derivative with central differences. This isolates the selected-gate task gradient.

Exercise B · Complete one routed gradient

After completing the starter, add three router logits and three constant expert outputs. Select the maximum probability, compute half-squared loss, and derive every router-logit gradient. Check one component with ±10−6.

Hint 1 · Chain rule

First obtain error, then dL/dpₘ=error×expert_output.

Hint 2 · Softmax

Multiply by pₘ times one-minus-pₘ for the selected logit, or by −pₘpⱼ for another logit.

Reference reasoning

Choose logits with a clear maximum so the finite perturbation cannot switch argmax. A test at a tie is testing a nondifferentiable boundary rather than your smooth derivative.

Debugging · Experts learn, router does not

A learner computes selected weights as p[selected] / sum_selected with k=1. Expert loss falls, but router task gradients remain zero.

Answer

sum_selected equals the same p, so their ratio is one. The expert output no longer depends smoothly on router logits. Retain the selected full-softmax p as this project does, or use top-2 selected softmax so relative selected weights remain variable. A balancing loss alone may move routes but does not restore the missing task gradient.

Independent variation · Top-2 mixture

Select the two largest logits, normalize those two with a stable softmax, and combine both expert outputs. Derive the first selected-logit gradient and test that it is zero when the two expert outputs are exactly equal.

Worked answer

With weights q₁ and q₂=1−q₁, output is q₁E₁+q₂E₂. Its derivative with respect to the first selected logit is q₁q₂(E₁−E₂). Equal expert outputs make routing between them irrelevant, so zero is correct. Unequal outputs and nonsaturated gates yield a task gradient.
