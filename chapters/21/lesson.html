A convolutional layer can learn local features, but simply stacking more transformations creates a harder optimization path. A residual block gives every transformation a direct shortcut around its learned branch. Normalization controls scale, and augmentation states which image changes should preserve the label. Together they make a small but genuinely deeper model trainable.

Your milestone

You will train two consecutive residual convolutional blocks. Each block normalizes its input, applies a learned 3×3 branch, scales that branch, adds the identity shortcut, and applies ReLU. Backpropagation crosses the second normalization and shortcut to update the first block.

Code and terminology carried forward

Chapter 20 established row-major image storage, a model forward pass that retains a cache for backward, class logits, stable cross_entropy_from_logits(logits, target), and a fused loss_and_gradient. Chapter 21 keeps those roles and still performs sample-at-a-time updates. The chosen update setting is consistently named learning_rate. See the course code and terminology guide.

The justified change is the model body. One 6×6 image, flattened to [f64; 36], now passes through two same-shape residual blocks before a two-logit dense head. residual_block_forward is a layer operation: its output is a 36-value activation map. ResidualNet::forward is the whole model computation: its ForwardCache stores both block caches and the final logits. The task prediction used by metrics is the class whose logit is larger; neither a layer output nor the cache itself is a class prediction.

Here “residual” names the architectural sum of an identity path and a learned branch. It does not name the signed prediction error prediction - target used in regression. The code uses output_gradient and input_gradient for layer derivatives, and Gradient for derivatives of learned parameters, so those meanings stay separate.

1. Learn a correction instead of rebuilding the input

The Chapter 20 classifier sent each layer's output only through the next transformation. If a useful signal should survive several such transformations, every layer must learn to preserve it. An identity shortcut copies the input directly to an addition. The learned branch computes F(x), and the block returns y = ReLU(x + αF(Norm(x))). Here α is a learned scalar in the course project.

The addition is elementwise, so x and F(x) must both have shape [6,6], represented by row-major arrays of length 36. This same-shape case needs no shortcut parameters. When a production residual block changes channel count or spatial resolution, a projection can transform the shortcut, but then it is no longer a pure identity path.

Trace one shortcut

Suppose one pixel value is x = 0.60, the normalized convolution branch produces F(x) = −0.25, and α = 0.20. Before ReLU, the block value is 0.60 + 0.20×(−0.25) = 0.55. If a later layer sends gradient 0.8 and the pre-activation is positive, the direct shortcut contributes 0.8 to the input gradient. The branch also contributes a term through convolution and normalization. The derivative with respect to α is 0.8×(−0.25) = −0.20.

This direct term is the practical reason a residual connection changes optimization. It creates a route whose derivative contains one. It does not guarantee good training or make gradients immune to every failure. ReLU can still block a location, normalization can be misimplemented, and an excessive learning rate can still diverge.

The original residual-network formulation was motivated by a degradation problem: deeper plain networks could have higher training error even though extra layers should in principle represent identity mappings. Writing the desired mapping as x + F(x) makes a near-identity solution accessible when the residual branch begins small. Our learned scales start at 0.1, so each block initially perturbs its input modestly.

2. Normalize with named axes and a real backward pass

Normalization is not one universal operation. Batch normalization computes statistics across a mini-batch for each feature or channel and uses running statistics at inference. This project has tiny sample-at-a-time updates, so it uses per-image normalization across all 36 pixels. That is closer to a simple instance-style normalization. The difference is deliberate and explicit.

For pixel values xj, compute μ = (1/N)Σxj, variance v = (1/N)Σ(xj−μ)², and yj = (xj−μ)/√(v+ε). N is 36 and ε is 10−5. Epsilon prevents division by zero for a constant image. Statistics are recomputed independently for every image in both training and evaluation.

fn normalize(input: &[f64; PIXELS]) -> ([f64; PIXELS], f64) {
    let mean = input.iter().sum::<f64>() / PIXELS as f64;
    let variance = input
        .iter()
        .map(|value| (value - mean).powi(2))
        .sum::<f64>()
        / PIXELS as f64;
    let inv_std = 1.0 / (variance + 1e-5).sqrt();
    (input.map(|value| (value - mean) * inv_std), inv_std)
}

Normalize four values

For [1,1,3,3], μ = 2. Deviations are [−1,−1,1,1], so v = 1. Ignoring the tiny epsilon for hand arithmetic, normalized values are [−1,−1,1,1]. Their mean is zero and variance is one. For [5,5,5,5], the deviations are zero; epsilon makes the divisor finite and every normalized value remains zero.

Because the second block normalizes the first block's output, backward must differentiate the statistics. Let goutj be the output_gradient arriving at normalized value yj, and let q = 1/√(v+ε). Then the project uses ginj = (q/N)[N goutj − Σgout − yjΣ(gouty)]. Both sums and the division by N cover all 36 pixels of this one image. This coupling means changing one input changes the mean and variance used by every normalized output.

Stopping the gradient at normalization would leave the first block unaware of how its output changes the second block's standardized input. The reference stores normalized arrays and inverse standard deviations for both blocks, then applies the formula in reverse order. Its finite-difference test perturbs a kernel weight in block one and differentiates the final classification loss through block two. Agreement therefore checks convolution, both shortcuts, ReLU masks, and normalization together.

3. Encode acceptable image changes in training data

The fixture classifies a vertical bar versus a horizontal bar. Each base image has one- or two-pixel thickness. Training adds deterministic shifts left, right, up, and down. This is data augmentation: transformed views keep the original label.

An augmentation is a claim about the task. Small translations preserve “vertical versus horizontal.” Rotating by 90 degrees would exchange the classes and therefore corrupt labels. A flip might be safe for an animal category but unsafe for written letters or traffic direction. The architecture cannot decide this policy for you.

Count the fixture views

There are two classes, two thicknesses, and five allowed training shifts, giving 2×2×5 = 20 training images. Validation contains four separately dimmed and perturbed canonical images. The arrays are byte-for-byte disjoint, which prevents exact duplication, but they deliberately come from the same four underlying bases. This is a functional perturbation check, not an independent-source estimate.

A generalization study would split independent source objects first and apply augmentation only to training. This fixture has no extra source objects, so it cannot perform that stronger split. Its assertion catches identical arrays only; it does not remove source-level relatedness. Real evaluation should use independent images and several naturally occurring conditions with meaningful sample sizes.

Augmentation and normalization address different concerns. Augmentation supplies alternate observations and encourages a chosen invariance. Normalization rescales one computation. A model can normalize perfectly and still fail a shift it never learned; it can see many shifts and still train poorly if intermediate scales become unstable.

4. Train two residual image blocks

The reference implementation keeps each block deliberately small: one input plane, one 3×3 kernel, one branch bias, and one learned residual scale. The second block consumes the first block's 36-value layer output. A two-class dense head turns the final 36 values into logits, and cross_entropy_from_logits supplies the loss. The target argument is a discrete class index; it follows the logits, as in Chapters 10, 11, and 20.

fn cross_entropy_from_logits(logits: [f64; CLASSES], target: usize) -> f64 {
    let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    (maximum - logits[target])
        + logits
            .iter()
            .map(|logit| (logit - maximum).exp())
            .sum::<f64>()
            .ln()
}

loss_and_gradient fuses one model forward pass with backward so both results share the same cached activations; fusion does not change the meaning of either result. It returns cross-entropy for one example and derivatives of that same scalar in Gradient. The fields kernels, scales, branch_biases, head, and class_bias mirror the model parameters. Because training updates after every example, these are per-example gradients rather than the gradient sums returned by Chapter 9's standalone dense layer or the mean minibatch gradients used in Chapters 10 and 11.

Backward begins at the head. second_block_output_gradient has shape [36]. For block two, each positive ReLU output sends its gradient along two paths: unchanged to the identity input and multiplied by α into the convolution branch. Convolution backward accumulates nine kernel_gradient values, one scale_gradient, one bias_gradient, and a 36-value normalized_gradient. Normalization backward converts the latter to another 36-value contribution. Their sum is first_block_output_gradient, which becomes the output_gradient argument for block one. All derivatives use the old parameter values before training applies learning_rate.

5. Practice and debug

Exercise A · Add an identity shortcut

Complete ch21_01.rs. Its residual_add(input, residual_branch) primitive receives the identity values and an already computed branch contribution of the same shape. In ResidualNet::residual_block_forward, those roles are input[at] and scale * z; the reference then applies ReLU.

Hint 1 · Preserve position

Each output element uses one input element and the residual-branch element at the same index.

Hint 2 · Use paired iteration

Zip the slices, add each pair, and collect the results. The tiny exercise assumes equal lengths; the fixed reference arrays have length 36.

Worked solution
fn residual_add(input: &[f64], residual_branch: &[f64]) -> Vec<f64> {
    input
        .iter()
        .zip(residual_branch)
        .map(|(input, branch)| input + branch)
        .collect()
}

The method-level operation it isolates is:

output[at] = (input[at] + scale * z).max(0.0);

A general slice API would reject unequal lengths rather than letting zip truncate. The exercise and reference use fixed equal shapes, so no external shape boundary is introduced here.

Debugging · The first block never changes

The second block and head train, but the first kernel remains at initialization. The code applies normalization in forward and sends the branch gradient only to kernel two.

Answer

The learner stopped gradient propagation at the second block's input. Add the shortcut contribution and the normalization-input gradient, sum them, and pass that array into block one backward. A finite difference of a first-block parameter against final loss detects this bug directly.

Independent variation · Compare augmentation policies

Train once with only canonical training images and once with the five shifts. Create a separate validation set shifted by two pixels, keeping base sources disjoint. Freeze epochs and learning rate before comparing.

Worked protocol

The only experimental difference should be the training augmentation list. Report loss and accuracy on the same shifted validation rows, plus denominators. If a two-pixel shift crops the class-defining bar, reject it as label-changing or design a larger canvas. Do not tune the transform after seeing validation results without recording a new development cycle.
