An image and a caption have different shapes, yet they can describe the same thing. A multimodal retrieval model learns two encoding functions whose outputs can be compared. This chapter builds the smallest honest version: four pixels, real caption strings, two trainable towers, a symmetric contrastive objective, and measured retrieval.

Visible goal

Given three 2×2 patterns and the captions “two vertical pixels,” “two horizontal pixels,” and “main diagonal,” rank the correct caption first. The reference trains fourteen parameters from scratch. Its perfect three-item retrieval result validates the fixture, not open-vocabulary vision-language understanding.

1. Two input languages need two encoders

The image input is a row-major vector [top-left, top-right, bottom-left, bottom-right]. The vertical pattern is [1,0,1,0]. The text input begins as a string. A tiny vocabulary counts the words vertical, horizontal, and diagonal, producing [1,0,0] for “two vertical pixels.” This is a real text preprocessing path, though it recognizes only three words.

A multimodal encoder can use different parameters for each modality. The image matrix has shape [2,4], and the text matrix has shape [2,3]. Multiplying either input by its matrix yields a two-component embedding. Separate towers are necessary because pixel positions and word counts do not share input coordinates. Their outputs share a dimension so a common scoring rule can compare them.

For an image vector x, image embedding before normalization is u = Wᵢx. For caption features c, text embedding is v = Wₜc. The learned fields are image_weights [2,4] and text_weights [2,3], both in fixed [out,in] layout. There is no decoder and no class-specific output head. The information that connects the modalities comes from paired rows: image 0 belongs with caption 0, image 1 with caption 1, and image 2 with caption 2.

This representation is deliberately closed. An unknown caption such as “bright marks” contains no vocabulary feature and is rejected rather than mapped to a zero vector. A production text encoder tokenizes many words and learns contextual representations; a production image tower sees larger arrays and local structure. Those changes increase capacity. They do not change the core contract that paired embeddings must become comparable.

2. Normalize before comparing directions

Raw dot products mix direction with magnitude. If u = [3,4], its Euclidean norm is √(3²+4²) = 5, so the normalized vector û is [0.6,0.8]. If v = [0,2], then v̂ = [0,1]. Their normalized dot product is 0.6×0 + 0.8×1 = 0.8. This equals cosine similarity: one means the same direction, zero means perpendicular, and negative values point more than ninety degrees apart.

Embedding normalization divides by the norm. The implementation rejects a norm below 10⁻¹² because dividing a zero embedding would create nonfinite values. It also rejects nonfinite pixels and caption features. These checks sit at the point where the invariant matters; downstream scoring can then assume two finite unit vectors.

Build one logit row

Suppose a normalized vertical image is [0.8,0.6]. The normalized caption embeddings are vertical [1,0], horizontal [0,1], and diagonal [−0.8,0.6]. Their raw similarities are 0.8, 0.6, and −0.28. With temperature τ = 0.2, the temperature-scaled logits become [4,3,−1.4]. Stable softmax subtracts the maximum: exponentials are [1, exp(−1), exp(−5.4)] ≈ [1,0.368,0.0045]. Normalizing those values produces probabilities over this three-caption training candidate set. The probability assigned to the paired vertical caption is 1/1.3725 ≈ 0.729, giving cross-entropy −ln(0.729) ≈ 0.316.

Temperature τ rescales raw similarities into logits: ℓᵢⱼ = (ûᵢ·v̂ⱼ)/τ. Smaller positive τ makes logit differences sharper and gradients more concentrated; larger τ flattens them. The raw similarities still determine retrieval order because division by one shared positive value does not change rank. The implementation rejects nonpositive or nonfinite temperature and also rejects a finite temperature so tiny that scaling produces nonfinite logits. The reference fixes τ = 0.2 so only encoder parameters vary. This is an experiment setting, not a universal optimum. The CLIP paper describes learning a logit scale and limiting it during training; this reference uses a fixed temperature.

3. Contrast a pair against the batch

Three images and three captions make a raw similarity matrix and a temperature-scaled logit matrix, both [3,3]. Cell ℓᵢⱼ compares image i with caption j. The diagonal contains the supplied pairs, while the six off-diagonal cells are mismatches. Contrastive alignment asks each correct cell to outrank alternatives.

For image-to-text loss, apply cross_entropy_from_logits to each row with target index j=i. The row loss is −ℓᵢᵢ + log Σⱼexp(ℓᵢⱼ). For text-to-image, apply the same rule to each column with target index i=j. The project sums three row losses and three column losses, then divides by 2N = 6:

L = (1/2N) Σᵢ [CE(ℓᵢ,:, i) + CE(ℓ:,ᵢ, i)], with N = 3 and 2N = 6.

The colon means “all entries along this axis.” Both directions matter because retrieval can start from either modality. A row-only objective directly teaches which caption an image should select, while a column objective also teaches which image a caption should select. The matrix reuses the same embeddings, so every example supplies one positive and N−1 negatives.

The stable calculation keeps the subtraction grouped as (maximum - target_logit) + ln Σ exp(logit - maximum). This avoids forming a large maximum + ln_sum and then canceling it against the target logit:

fn cross_entropy_from_logits(logits: [f64; 3], target: usize) -> f64 {
    let maximum = logits.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    (maximum - logits[target])
        + logits
            .iter()
            .map(|logit| (logit - maximum).exp())
            .sum::<f64>()
            .ln()
}

loss receives the paired images, captions, and temperature explicitly. Its paired target for row and column i is index i:

fn loss(
    &self,
    images: &[[f64; 4]; 3],
    captions: &[&str; 3],
    temperature: f64,
) -> Result<f64, &'static str> {
    let logits = self.logits(images, captions, temperature)?;
    let mut total = 0.0;
    for (i, row) in logits.iter().copied().enumerate() {
        total += cross_entropy_from_logits(row, i);
        total += cross_entropy_from_logits([logits[0][i], logits[1][i], logits[2][i]], i);
    }
    let loss = total / 6.0;
    if !loss.is_finite() {
        return Err("contrastive loss is nonfinite");
    }
    Ok(loss)
}

The trainer optimizes all fourteen matrix entries with central finite differences. Each slope needs two full loss evaluations at parameter ±10⁻⁵. That would be wasteful for a real encoder, but for fourteen values it makes the complete training rule short and auditable. It is explicitly finite-difference optimization, not an ML dependency disguised behind an API. The fixed call still supplies its data and settings:

let model = initial.train(&IMAGES, &NAMES, 300, 0.03, TEMPERATURE)?;

After 300 steps at learning rate 0.03, the measured symmetric loss falls from about 1.1322 to 0.0014. A unit test also checks that training changes both tower matrices. If only the image matrix changes, image embeddings might chase frozen arbitrary text directions; the loss can still move, but the implementation has failed the promise to train both encoders.

4. Evaluate the ranking you will use

At inference, encode one image, encode each explicitly supplied candidate caption, calculate raw cosine similarities, and return the largest. Chapter 24 defines Recall@k as the fraction of each query's relevant set retrieved in its top k, averaged across queries. With one known positive caption per image, Recall@1 is correct-first count divided by query count.

A complete retrieval metric

If the correct caption ranks first for two of three images, Recall@1 is 2/3 ≈ 0.667. If it ranks second on the remaining query, Recall@2 is 3/3 = 1.0. Reporting only Recall@2 would hide that one user sees the wrong first result. Recall@1 equals HitRate@1 here only because every query has exactly one positive. With several relevant captions, HitRate@1 asks whether any positive appears, while recall divides retrieved positives by all positives. The evaluation must define that relevance set rather than treating every non-diagonal caption as wrong.

The project evaluates slightly perturbed versions of the same three patterns: values such as 0.9 and 0.1 replace exact zeros and ones. The measured Recall@1 is 100 percent. “Held-out” here means these exact arrays were not used in the loss. They still share the same three shapes, positions, captions, and hand-built vocabulary, so this is a local stability check rather than an independent generalization benchmark.

Ranking uses raw similarities, not softmax probabilities or the scalar training loss. The implementation deliberately keeps Rust iterator tie behavior: max_by retains the last candidate when similarities are equal. The paired candidate order therefore remains part of this fixed metric fixture.

Batch composition matters. If every negative is visually unrelated, contrastive loss is easy. If two captions are both valid—“two vertical pixels” and “left column”—treating one as a negative creates a false-negative gradient. Web-scale pairs also contain noisy text and social bias. Normalized embeddings and a low training loss do not remove those data problems. Evaluation must reflect the intended languages, visual conditions, candidate set, and harms of retrieval errors.

Do not infer zero-shot ability.

The three-word encoder cannot represent a new class description. Perfect closed-set retrieval verifies the similarity matrix, training path, and ranking for this fixture. It supplies no evidence about natural images, unfamiliar vocabulary, multilingual captions, counting, or deployment safety.

5. Build, debug, and vary the dual encoder

The complete implementation is projects/ch52/src/main.rs. Run from the repository root:

cargo run --release --manifest-path projects/ch52/Cargo.toml
cargo test --manifest-path projects/ch52/Cargo.toml
cargo run --manifest-path projects/ch52/starter/Cargo.toml
cargo test --manifest-path projects/ch52/starter/Cargo.toml

The starter runs a useful prior checkpoint: its cosine helper receives raw two-vectors and divides their dot product by both norms. Its fixed fixture supplies finite, nonzero vectors; unlike the reference's Result boundary, this unchecked helper is only valid under that precondition. The reference model's similarities method instead dots embeddings already normalized by image_embedding and caption_embedding; these are the same cosine calculation under that unit-length precondition. The starter's intentional TODO asks for the best-caption index. The Rustlings exercise ch52_01.rs asks you to implement cosine on raw two-vectors.

Guided work

  1. Complete best_caption by enumerating candidates and retaining the greatest cosine value.
  2. Debug a model whose loss is low but caption-to-image queries fail. Check whether the implementation averaged both rows and columns or trained only rows.
  3. Debug NaNs appearing on the first step. Print both pre-normalization norms and locate a zero tower output.
  4. Independent variation: add the caption “right column” and its 2×2 image. Extend the vocabulary and both text-matrix rows, then report the full 4×4 raw similarity matrix and Recall@1.
Hint 1: retrieval

Keep the candidate index together with its raw cosine similarity. Compare values with total_cmp after validation has excluded NaN. Iterator max_by retains the last candidate when values tie; preserve that behavior.

Hint 2: symmetric loss

For direction one, use logits[i]. For direction two, construct [logits[0][i], logits[1][i], logits[2][i]]. Both targets are i.

Worked answer

The starter can enumerate resolved caption vectors, map each to (index, cosine(image, caption)), and select the maximum with max_by; equal values select the last candidate. The one-direction bug is fixed by adding column cross-entropies before dividing by 2N = 6. For the four-item variation, do not reuse a three-element fixed array; update dimensions deliberately and add a test that every diagonal index ranks first.

Review and transfer

Without looking: Why are there two parameter matrices? What does L2 normalization change? Which cells are positives? Why average two cross-entropy directions? What is the denominator of Recall@1? Why is the perturbed metric not broad held-out evidence?

Check your answers

Each modality needs its own input mapping. Normalization removes magnitude from the dot-product similarity. Supplied pairs occupy the diagonal. Row and column losses train both retrieval directions. Recall@1 divides successful queries by all queries. The perturbed inputs reuse the same three concepts and vocabulary, so they test local ranking stability rather than transfer.
