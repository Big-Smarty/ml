An image and a caption have different shapes, yet they can describe the same thing. A multimodal retrieval model learns two encoding functions whose outputs can be compared. This chapter builds the smallest honest version: four pixels, real caption strings, two trainable towers, a symmetric contrastive objective, and measured retrieval.

Visible goal

Given three 2×2 patterns and the captions “two vertical pixels,” “two horizontal pixels,” and “main diagonal,” rank the correct caption first. The reference trains fourteen parameters from scratch. Its perfect three-item score validates the fixture, not open-vocabulary vision-language understanding.

1. Two input languages need two encoders

The image input is a row-major vector [top-left, top-right, bottom-left, bottom-right]. The vertical pattern is [1,0,1,0]. The text input begins as a string. A tiny vocabulary counts the words vertical, horizontal, and diagonal, producing [1,0,0] for “two vertical pixels.” This is a real text preprocessing path, though it recognizes only three words.

A multimodal encoder can use different parameters for each modality. The image matrix has shape [2,4], and the text matrix has shape [2,3]. Multiplying either input by its matrix yields a two-component embedding. Separate towers are necessary because pixel positions and word counts do not share input coordinates. Their outputs share a dimension so a common scoring rule can compare them.

For an image vector p, image embedding before normalization is u = Wᵢp. For caption features c, text embedding is v = Wₜc. Both matrices are trainable. There is no decoder and no class-specific output head. The information that connects the modalities comes from paired rows: image 0 belongs with caption 0, image 1 with caption 1, and image 2 with caption 2.

This representation is deliberately closed. An unknown caption such as “bright marks” contains no vocabulary feature and is rejected rather than mapped to a zero vector. A production text encoder tokenizes many words and learns contextual representations; a production image tower sees larger arrays and local structure. Those changes increase capacity. They do not change the core contract that paired embeddings must become comparable.

2. Normalize before comparing directions

Raw dot products mix direction with magnitude. If u = [3,4], its Euclidean norm is √(3²+4²) = 5, so the normalized vector û is [0.6,0.8]. If v = [0,2], then v̂ = [0,1]. Their normalized dot product is 0.6×0 + 0.8×1 = 0.8. This equals cosine similarity: one means the same direction, zero means perpendicular, and negative values point more than ninety degrees apart.

Embedding normalization divides by the norm. The implementation rejects a norm below 10⁻¹² because dividing a zero embedding would create nonfinite values. It also rejects nonfinite pixels and caption features. These checks sit at the point where the invariant matters; downstream scoring can then assume two finite unit vectors.

Build one score row

Suppose a normalized vertical image is [0.8,0.6]. The normalized caption embeddings are vertical [1,0], horizontal [0,1], and diagonal [−0.8,0.6]. Cosine scores are 0.8, 0.6, and −0.28. With temperature τ = 0.2, logits become [4,3,−1.4]. Stable softmax subtracts the maximum: exponentials are [1, exp(−1), exp(−5.4)] ≈ [1,0.368,0.0045]. The probability assigned to the paired vertical caption is 1/1.3725 ≈ 0.729, giving cross-entropy −ln(0.729) ≈ 0.316.

Temperature rescales all cosine logits: sᵢⱼ = ûᵢ·v̂ⱼ/τ. Smaller positive τ makes ranking differences sharper and gradients more concentrated; larger τ flattens them. The reference fixes τ = 0.2 so only encoder parameters vary. This is an experiment setting, not a universal optimum. The CLIP paper describes learning a logit scale and limiting it during training; this reference uses a fixed temperature.

3. Contrast a pair against the batch

Three images and three captions make a 3×3 score matrix S. Cell Sᵢⱼ compares image i with caption j. The diagonal contains the supplied pairs, while the six off-diagonal cells are mismatches. Contrastive alignment asks each correct cell to outrank alternatives.

For image-to-text loss, apply cross-entropy to each row with target j=i. The row loss is −Sᵢᵢ + log Σⱼexp(Sᵢⱼ). For text-to-image, apply the same rule to each column with target i=j. The project averages all six row and column losses:

L = (1/2N) Σᵢ [CE(Sᵢ,:, i) + CE(S:,ᵢ, i)], with N = 3.

The colon means “all entries along this axis.” Both directions matter because retrieval can start from either modality. A row-only objective directly teaches which caption an image should select, while a column objective also teaches which image a caption should select. The matrix reuses the same embeddings, so every example supplies one positive and N−1 negatives.

The implementation uses stable log-sum-exp: find the largest logit m, calculate m + ln Σexp(s−m), then subtract the target. It optimizes all fourteen matrix entries with central finite differences. Each slope needs two full loss evaluations at parameter ±10⁻⁵. That would be wasteful for a real encoder, but for fourteen values it makes the complete training rule short and auditable. It is explicitly finite-difference optimization, not an ML dependency disguised behind an API.

After 300 steps at learning rate 0.03, the measured symmetric loss falls from about 1.1322 to 0.0014. A unit test also checks that training changes both tower matrices. If only the image matrix changes, image embeddings might chase frozen arbitrary text directions; the loss can still move, but the implementation has failed the promise to train both encoders.

4. Evaluate the ranking you will use

At inference, encode one image, encode each candidate caption, calculate cosine similarities, and return the largest. Recall at k counts a query as successful when a relevant item appears in its top k. With one known caption per image, recall@1 is correct-first count divided by query count.

A complete retrieval metric

If the correct caption ranks first for two of three images, recall@1 is 2/3 ≈ 0.667. If it ranks second on the remaining query, recall@2 is 3/3 = 1.0. Reporting only recall@2 would hide that one user sees the wrong first result. With exactly one relevant item per query, this query-success convention is also called hit@k. A larger dataset may have several relevant captions per image; then item-level recall divides retrieved relevant items by all relevant items, and the evaluation must define that relevance set rather than treating every non-diagonal caption as wrong.

The project evaluates slightly perturbed versions of the same three patterns: values such as 0.9 and 0.1 replace exact zeros and ones. The measured recall@1 is 100 percent. “Held-out” here means these exact arrays were not used in the loss. They still share the same three shapes, positions, captions, and hand-built vocabulary, so this is a local stability check rather than an independent generalization benchmark.

Batch composition matters. If every negative is visually unrelated, contrastive loss is easy. If two captions are both valid—“two vertical pixels” and “left column”—treating one as a negative creates a false-negative gradient. Web-scale pairs also contain noisy text and social bias. Normalized embeddings and a low training loss do not remove those data problems. Evaluation must reflect the intended languages, visual conditions, candidate set, and harms of retrieval errors.

Do not infer zero-shot ability.

The three-word encoder cannot represent a new class description. Perfect closed-set retrieval proves the score matrix, training path, and ranking for this fixture. It supplies no evidence about natural images, unfamiliar vocabulary, multilingual captions, counting, or deployment safety.

5. Build, debug, and vary the dual encoder

The complete implementation is projects/ch52/src/main.rs. Run from the repository root:

cargo run --release --manifest-path projects/ch52/Cargo.toml
cargo test --manifest-path projects/ch52/Cargo.toml
cargo run --manifest-path projects/ch52/starter/Cargo.toml
cargo test --manifest-path projects/ch52/starter/Cargo.toml

The starter runs a useful prior checkpoint: it computes cosine similarity between a fixed image embedding and two caption embeddings. Its intentional TODO asks for the best-caption index. The Rustlings exercise ch52_01.rs asks you to implement cosine similarity itself.

Guided work

  1. Complete best_caption by enumerating candidates and retaining the greatest cosine value.
  2. Debug a model whose loss is low but caption-to-image queries fail. Check whether the implementation averaged both rows and columns or trained only rows.
  3. Debug NaNs appearing on the first step. Print both pre-normalization norms and locate a zero tower output.
  4. Independent variation: add the caption “right column” and its 2×2 image. Extend the vocabulary and both text-matrix rows, then report the full 4×4 score matrix and recall@1.
Hint 1: retrieval

Keep the candidate index together with its score. Compare floating-point scores with total_cmp after validation has excluded NaN.

Hint 2: symmetric loss

For direction one, use scores[i]. For direction two, construct [scores[0][i], scores[1][i], scores[2][i]]. Both targets are i.

Worked answer

The starter can enumerate caption embeddings, map each to (index, cosine(image, caption)), and select the maximum. The one-direction bug is fixed by adding column cross-entropies before dividing by 2N. For the four-item variation, do not reuse a three-element fixed array; update dimensions deliberately and add a test that every diagonal index ranks first.

Review and transfer

Without looking: Why are there two parameter matrices? What does L2 normalization change? Which cells are positives? Why average two cross-entropy directions? What is the denominator of recall@1? Why is the perturbed score not broad held-out evidence?

Check your answers

Each modality needs its own input mapping. Normalization removes magnitude from the dot-product score. Supplied pairs occupy the diagonal. Row and column losses train both retrieval directions. Recall@1 divides successful queries by all queries. The perturbed inputs reuse the same three concepts and vocabulary, so they test local ranking stability rather than transfer.
