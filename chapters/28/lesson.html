What a lane represents

SIMD means single instruction, multiple data. A 256-bit register holds eight 32-bit f32 values; a 512-bit register holds sixteen. A lane receives one pairwise product at a time. For 19 values and width 8, process indices 0..8, then 8..16. Lane zero accumulates a[0]b[0]+a[8]b[8], lane one accumulates indices 1 and 9, and so on. Reduce all lane sums horizontally to one scalar, then add indices 16..19 as a scalar tail.

How can an executable call only supported instructions?

Goal: explain and preserve every precondition of an explicit SIMD call. Architecture-specific intrinsics live behind cfg(any(target_arch="x86",target_arch="x86_64")). This excludes x86 names entirely when compiling for another architecture. The private function has #[target_feature(enable="avx2,fma")]. A generic caller checks is_x86_feature_detected!("avx2") and is_x86_feature_detected!("fma") separately before calling it.

AVX2 support alone does not establish FMA support. FMA performs a multiplication and addition with one final rounding. It may differ from separate scalar multiply and add, so compare with the documented tolerance and f64 oracle. If either required feature is absent, the default returns the scalar result. It never executes the intrinsic speculatively.

Unsupported target-feature execution is undefined behavior, not a numerical fallback strategy. The safe boundary also checks equal lengths and finite inputs, then rejects nonfinite output. The private function can rely on equal lengths because every caller established them. Inside the vector loop, the remaining length must be at least eight. Unaligned loads accept arbitrary alignment, but still require eight valid readable values. A store into an eight-element local array requires eight writable values.

Each unsafe block has a SAFETY comment proving those facts. A comment saying merely “this is fast” does not establish a precondition. Keep private raw-pointer operations small and finish with safe suffix slices.
