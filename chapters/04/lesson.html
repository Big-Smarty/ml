Linear regression can produce any real number, but a category is not “3.7 of class one.” We need a model that expresses uncertainty between two outcomes, a loss that rewards probability assigned to the observed outcome, and arithmetic that survives confident predictions.

Your goal

You will train binary logistic regression from scratch on two-dimensional points. The project keeps raw logits for a stable loss, converts them to probabilities for interpretation, and applies a threshold only when a class decision is needed.

Code and terminology carried forward

Chapter 3 introduced LinearModel: three weights and a bias turn [f64; 3] features into a numeric prediction, and mean squared error (MSE) measures regression mistakes. This chapter keeps the affine calculation, explicit data argument, mean reduction, separate Gradient, and method sequence loss, gradient, loss_and_gradient, step, and train from the course conventions. A test-only numerical_gradient method here reuses the central-difference technique from Chapters 1–2 to check the new classification objective. In both chapters, step(self, data, learning_rate) and train(self, data, steps, learning_rate) consume a small model and return its updated value.

The task changes, so some meanings must change. LogisticModel has two weights because this fixture has two features. Its affine output is named logit; probability applies sigmoid; and predict returns the discrete class 0 or 1 at the chapter's fixed 0.5 threshold. A probability such as 0.82 is never called a class. Regression's MSE is replaced by mean binary cross-entropy (BCE), so the derivative changes from 2 * (prediction - target) to probability - target.

1. A classifier starts with a score

Suppose two sensor measurements describe a point and the target is either zero or one. Chapter 3's numeric prediction used the calculation z = w·x+b. Here the same calculation has a new role: it is evidence for a class. Large positive z can support class one and large negative z class zero. But z is unbounded, so it is not yet a probability.

This raw score is a logit. Logistic regression passes it through the sigmoid function σ(z) = 1/(1+e⁻ᶻ). The result p lies between zero and one. At z = 0, p = 0.5. Sigmoid is increasing, so rankings by z and p agree.

From point to probability

Let x = [2,−1], w = [1.2,0.4], and b = −0.5. The logit is 1.2(2)+0.4(−1)−0.5 = 1.5. Since e⁻¹·⁵ ≈ 0.2231, p = 1/(1+0.2231) ≈ 0.8176. At threshold 0.5 this becomes class one.

For logit −1.5, symmetry gives probability about 0.1824. Neither probability states certainty about an individual case, and a fitted model may be miscalibrated. It is the model's conditional estimate under its data and assumptions.

A threshold is a separate policy. The project's predict method returns class one when p ≥ 0.5 and class zero otherwise; at that threshold it is equivalent to checking z ≥ 0. The probability method still returns p, not that class. Applications may choose another cutoff, so training preserves the continuous evidence rather than baking a decision into the loss.

The name logit comes from log-odds. Odds are p/(1−p): probability divided by the probability of the other outcome. Taking the natural logarithm gives ln[p/(1−p)] = z. At p = 0.8, odds are four to one and the logit is ln 4 ≈ 1.386. Adding this relationship helps explain why adding a fixed amount to z multiplies odds by a fixed factor, while the probability change depends on where it starts.

Direct sigmoid has a numerical trap. For a large negative z, computing e⁻ᶻ asks for an enormous exponential that can overflow. The Rust implementation uses p = eᶻ/(1+eᶻ) when z is negative, so the exponential is at most one. For nonnegative z it uses the ordinary form. Equivalent mathematics can have very different floating-point behavior.

2. Learn by assigning probability to what happened

If the binary target y is one, the model assigns the observation probability p. If y is zero, it assigns 1−p. The compact expression pʸ(1−p)¹⁻ʸ selects the correct term. Viewed as a function of model parameters for observed data, this is a likelihood.

To multiply the example likelihoods, we model the labels as independent once their inputs and shared parameters are given. Repeated measurements from one entity can violate that assumption; the split and uncertainty lessons will revisit this. Multiplying many probabilities yields extremely small numbers. Logs turn products into sums, and negating gives a quantity to minimize. The per-example binary cross-entropy is:

ℓ(p,y) = −[y ln p + (1−y) ln(1−p)]

Compare a useful and harmful probability

For y = 1 and p = 0.8, loss is −ln(0.8) ≈ 0.223. For the same target and p = 0.1, loss is −ln(0.1) ≈ 2.303. The confident wrong prediction costs more. At p = 0.5, either target gives ln 2 ≈ 0.693.

For two examples with losses 0.223 and 0.511, the project reports their mean, 0.367. Averaging means duplicating the entire dataset does not change the loss or gradient convention.

Computing logs after sigmoid is fragile. A sufficiently large logit rounds p to exactly one; then ln(1−p) becomes ln 0 for a negative target. Instead combine the operations algebraically:

ℓ(z,y) = max(z,0) − zy + ln(1 + exp(−|z|))

Every exponential here receives a nonpositive input, so it cannot overflow. At z = 1000,y = 1 the loss remains finite and near zero. At z = 1000,y = 0 it is near 1000, correctly expressing a severe confident error. This is why the project calculates cross-entropy from logits and uses sigmoid only when displaying probabilities.

3. The likelihood gives a simple gradient

For 0 < p < 1, differentiating the loss with respect to p gives −y/p + (1−y)/(1−p) = (p−y)/[p(1−p)]. The sigmoid derivative is dp/dz = p(1−p). The chain rule multiplies these two factors, canceling the denominator and leaving dℓ/dz = p−y. Use this simplified expression in code, rather than computing the two potentially unstable factors separately.

Differentiate sigmoid and cross-entropy together and the logit derivative simplifies to p−y. For weight j, z changes by xⱼ when wⱼ changes, so:

∂L/∂wⱼ = (1/N)Σᵢ(pᵢ−yᵢ)xᵢⱼ   and   ∂L/∂b = (1/N)Σᵢ(pᵢ−yᵢ)

The factor two from Chapter 3's MSE gradient is absent because BCE is a different objective. The interface remains familiar: loss_and_gradient returns the mean loss together with a Gradient value containing one derivative per weight plus one for bias. Gradient data is not a classifier, so it does not use LogisticModel. A positive example with p below one has negative p−y and pulls its logit upward; a negative example has positive p−0 and pushes downward.

One update at the neutral model

Use x = [2,1], y = 1 and zero parameters. Then z = 0, p = 0.5, and p−y = −0.5. Gradients are [−1,−0.5] for the weights and −0.5 for bias. At learning rate 0.1, parameters become [0.1,0.05] and 0.05. The new logit is 0.30 and p ≈ 0.574, moving probability toward the observed positive target.

As in Chapter 2, finite differences can check this derivative. Perturb each parameter in the stable mean BCE objective, use h = 10⁻⁵, and compare with absolute plus relative tolerance. Check finite, moderate inputs; extreme logits are important loss tests but poor gradient-check locations because probabilities saturate and tiny differences can be dominated by rounding.

Linearly separable data introduces a subtle limitation: without regularization, cross-entropy may keep decreasing by making weights larger even after every class is correct. There may be no finite parameter value that achieves the mathematical infimum. The small fixed step count in this chapter demonstrates classification and stability; it is not a convergence theorem.

4. Run the stable classifier

Read the complete reference. The two-feature arrays make the shape explicit. Inspection methods borrow &self: logit returns the raw score, probability returns sigmoid of that score, and predict returns a class. binary_cross_entropy_from_logit(logit, target) keeps predictions before targets. loss_and_gradient(&self, data) shares each logit between the stable mean loss and its derivatives, then returns a separate Gradient; loss and gradient select either result. The test-only numerical_gradient measures the same loss; step performs one update, and train repeats it.

The tests require loss at z = 0 to equal ln 2, stable loss to remain finite at logits ±1000, analytical gradients to match central differences, and training BCE to fall below 0.04 while predict classifies every fixture point correctly. The demonstration prints a logit, probability, and class for each of three new points. Those probabilities are illustrative outputs from a tiny separable sample, not measured real-world risk.

Experiment by reducing training to one step and hand-checking the direction. Then calculate a class outside predict with u8::from(model.probability(features) >= 0.8). The model's logit, probability, and training loss remain unchanged; only the policy decision can change. This separation becomes central in Chapter 5, where threshold selection belongs to validation.

Do not report training accuracy as evaluation.

The eight points show that the implementation can fit its fixture. They do not estimate performance on future points, probability calibration, or consequences of false decisions.

5. Practice and diagnose

Exercise A · Stable sigmoid

Complete ch04_01.rs. It must return one half at zero and finite probabilities for logits ±1000. Its output remains a probability; no threshold or class decision belongs in this function.

Hint 1 · Split on sign

For nonnegative z, the ordinary denominator is safe because exp(−z) ≤ 1.

Hint 2 · Negative branch

Compute exp = exp(z), then return exp/(1+exp). Here 0 ≤ exp < 1.

Worked solution
if logit >= 0.0 {
    1.0 / (1.0 + (-logit).exp())
} else {
    let exp = logit.exp();
    exp / (1.0 + exp)
}

Both branches are algebraically identical. The branch controls intermediate magnitude.

Exercise B · Stable loss checkpoint

The starter carries forward a two-weight affine model, then makes its three outputs explicit: logit, probability, and class-valued predict. Implement binary_cross_entropy_from_logit(logit, target) in projects/ch04/starter/src/main.rs. Run cargo test --manifest-path projects/ch04/starter/Cargo.toml, then add the mean gradient over two examples.

Hint 1 · Validate, then use the logit

Require finite inputs and a target in [0,1]. Do not call sigmoid or take the logarithm of a rounded probability.

Hint 2 · Rust functions

Return Ok(logit.max(0.0) - logit * target + (-logit.abs()).exp().ln_1p()) after validation.

Worked solution
if !logit.is_finite() || !target.is_finite() || !(0.0..=1.0).contains(&target) {
    return Err("logit must be finite and target must be in [0, 1]");
}
Ok(logit.max(0.0) - logit * target + (-logit.abs()).exp().ln_1p())

The complete reference project calls this primitive while averaging loss and Gradient contributions over the supplied data.

Debugging · NaN after a confident mistake

A learner computes -y*p.ln() - (1.0-y)*(1.0-p).ln(). At p = 1,y = 1 the second term becomes 0 × ln 0, yielding NaN. Explain the repair.

Answer

Real arithmetic treats the limiting second contribution as zero, but floating point evaluates ln 0 as negative infinity and zero times infinity as NaN. Keep the original logit and compute the stable combined formula. Clipping p avoids NaN but changes the objective and gradients at the boundaries.

Independent variation · Move the policy threshold

For scores [0.2,0.45,0.55,0.9] and targets [0,1,0,1], calculate counts at thresholds 0.5 and 0.4. A true positive (TP) is a correctly predicted one; a false positive (FP) is a zero predicted as one; a true negative (TN) is a correctly predicted zero; and a false negative (FN) is a one predicted as zero.

Worked answer

At 0.5, predictions are [0,0,1,1]: TP 1, FP 1, TN 1, FN 1. At 0.4, predictions are [0,1,1,1]: TP 2, FP 1, TN 1, FN 0. Lowering the threshold recovered one positive without changing the model scores, while the false positive remained.

logit returns an unbounded affine score, probability maps it to a number from zero to one, and predict applies the fixed 0.5 threshold to return class 0 or 1. Logs turn likelihood products into sums. Classification rewards probability assigned to the observed class, so BCE replaces regression's squared numerical distance. The logits formula avoids overflow and log zero. The per-example derivative is p−y, and the separate Gradient struct stores parameter derivatives. Correct classes at one threshold do not show that predicted probabilities match observed frequencies.
