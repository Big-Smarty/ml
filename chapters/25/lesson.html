How the numbers fit into Rust

Inputs X have shape [m,k]: m rows, k input features each. Weights W have shape [n,k]: n output features, k weights per output. The output Y has shape [m,n]. Contiguous row-major storage means all values of one row sit next to each other. With zero bias, X=[[1,2,3],[4,5,6]] and W=[[1,3,5],[2,4,6]] produce Y=[[22,28],[49,64]]. Nonzero bias adds one value per output column. In symbols, Y=XWᵀ+bias; the transpose symbol means we pair an input row with a weight row, not that the stored W has changed.

The timed arrays use f32, a common performance storage type. The oracle converts the same stored inputs to f64 before multiplication and accumulation. It is not a differently rounded dataset. Its floating-point representation stores a finite set of binary values. The 24-bit significand of ordinary f32 limits representable precision: (100000000 + −100000000) + 1 gives 1, while 100000000 + (−100000000 + 1) gives 0 after rounding. Fused multiply-add rounds a product-plus-sum once and can also change the low bits.

Our numerical check accepts |computed−reference| ≤ 2×10⁻⁶×max(k,1) + 2×10⁻⁵×|reference|. The absolute part allows small accumulated error near zero; the relative part scales with a large result. This is a documented allowance for these bounded fixtures, not a universal tolerance for arbitrary data. A hand answer checks the formula, nonsquare shapes check indexing, and the f64 oracle checks numerical agreement.

Predict: if an optimization skips the second input row entirely, can tolerance rescue it?

Answer

No. Tolerance covers rounding, not missing work. Every output must be present, finite, and individually compared. A checksum alone can hide compensating errors.

What moves through memory for one matrix product?

Goal: trace the actual multiply contributions and distinguish array bytes from measured memory traffic. Retrieve yesterday’s dense layout: X=[m,k], W=[n,k], Y=[m,n]. A CPU works with registers nearest the arithmetic units, then caches, then main memory. Reusing nearby values can reduce expensive movement. Spatial locality uses neighboring addresses; temporal locality reuses an earlier value.

For the two-row example, X contains 6 f32 values, W contains 6, bias contains 2, and Y contains 4. Reading each input array once and writing Y once gives (6+6+2+4)×4=72 bytes. There are 24 conventional FLOPs, so this cold-array estimate is 24/72=1/3 FLOP per byte. It is not a count of actual loads or measured DRAM traffic: warm calls may already have cached arrays, while cache eviction and write allocation can add traffic.

The Roofline model relates arithmetic intensity (useful work per transferred byte) to a memory-bandwidth ceiling and an arithmetic-throughput ceiling. You must name the memory boundary before applying it. A register-to-L1 count and a DRAM count are different quantities.
