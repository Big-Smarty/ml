# Chapter 56 research and implementation verification

## Primary sources

- Fedus, Zoph, and Shazeer, *Switch Transformers* ([arXiv:2101.03961](https://arxiv.org/abs/2101.03961); [HTML full text](https://arxiv.org/html/2101.03961v3)). The paper defines router probabilities p_i(x) as a softmax, top-k output as the weighted sum of selected expert outputs, and says the top-1 Switch output keeps the selected gate. Its expert capacity is (T/E) times the capacity factor; overflow skips expert computation and uses the residual path. Its auxiliary loss is alpha * E * sum_i(f_i * P_i), where f_i is the hard top-1 assignment fraction and P_i is the mean router probability. f is nondifferentiable and P is differentiable. The paper reports alpha = 10^-2 as a typical coefficient.
- Lepikhin et al., *GShard* ([arXiv:2006.16668](https://arxiv.org/abs/2006.16668); [HTML full text](https://arxiv.org/html/2006.16668v1)). GShard describes top-2 routing with a running per-expert capacity counter, overflow as a zero expert contribution passed through the residual connection, and a differentiable mean-gate approximation to the hard routing fraction. Its algorithm normalizes top-2 combine gates within the selected pair; this does not justify normalizing a sole top-1 gate by itself.
- Shazeer et al., *Outrageously Large Neural Networks* ([arXiv:1701.06538](https://arxiv.org/abs/1701.06538); [HTML full text](https://arxiv.org/html/1701.06538v1)). The original sparse MoE uses a trainable gating network to choose a sparse combination of feed-forward experts and applies the idea to language modeling and translation.
- Zoph et al., *ST-MoE* ([arXiv:2202.08906](https://arxiv.org/abs/2202.08906)). This is useful context for the chapter’s stability caveat: large sparse models require care around router numerical stability and training behavior; a tiny f64 CPU fixture is a mechanics demonstration, not a scaling result.

## Verification against `projects/ch56/src/lib.rs`

- The selected full-softmax task path is mathematically correct. For selected expert m, the forward path adds p_m * E_m(x) to the residual. Away from an argmax tie, the selected index is locally constant, so for scalar upstream derivative g, dL/dz_j = g * E_m(x) * p_m * (1[j=m] - p_j). The implementation accumulates the selected expert output into `drouter_prob`, applies the full softmax Jacobian, and finite-difference coverage passes in `router_and_expert_gradients_match_finite_differences`.
- The balance term matches Switch semantics: `attempted` is the hard top-1 route count for every token, while the mean router probabilities provide the smooth half. Its derivative contribution per token and expert is `balance_weight * experts * attempted[expert] / (tokens*tokens)`, which is alpha * E * f_i / T before the softmax Jacobian.
- Capacity is computed as `ceil((T/E) * capacity_factor).max(1)` and the first-come counter drops later assignments after an expert reaches capacity. This is a valid pedagogical policy, but it should be described as deterministic first-come routing. Switch/GShard implementations generally use fixed expert buffers and a residual path for overflow; this model has that residual path because `block_output` starts as `residual` and dropped tokens skip the expert add.
- `Model::forward` and `Trainer::evaluate` use `capped=false`, so inference/evaluation has no capacity drops and excludes the balance term. Training `loss`/`loss_and_gradient` is capped and includes the auxiliary term. The lesson labels the reported evaluation as uncapped task cross-entropy to avoid comparing it directly with the training objective.
- Current crate tests pass with `cargo test --manifest-path projects/ch56/Cargo.toml` (6 tests). The repository verifier still reports missing `chapters/56/lesson.html` and `chapters/56/meta.json` until those artifacts are added; it also reports the pre-existing missing chapter-55 source-link artifact.

## Recommended independent checks

1. **Dense equivalence.** Build a one-expert model and a three-expert clone with identical named trunk, output, and expert-0 parameters; set the three-expert router bias to a large margin for expert 0 and set `balance_weight=0`. With capacity above the sequence length, compare all logits for the same token sequence within a tight tolerance. This catches expert dispatch/gate/residual indexing errors. A stronger variant compares the selected expert and shared parameter gradients away from a route tie.
2. **Causality.** For equal-length sequences `[a,b,c]` and `[a,b,d]`, compare the logits rows at positions 0 and 1; they must match, while row 2 may change. Use `Model::forward`, because the training auxiliary loss intentionally aggregates route statistics over the whole sequence. Repeat with a small capacity factor to ensure an early token’s acceptance does not depend on later tokens.
3. **Capacity semantics.** Force all router logits to select expert 0, use T=4, E=2, and factor=0.5, then assert capacity 1, attempted `[4,0]`, accepted `[1,0]`, and dropped 3. The existing test covers this exact case.
