The final project trains a contextual language model whose tokens choose different feed-forward experts. It learns embeddings, attention, normalization, expert parameters, and a router; compares its next-token loss with a dense model; saves and resumes training; and serves generated text through a local HTTP endpoint. The dataset and model are small enough that you can inspect every calculation.

What finishing this capstone means

You will have evidence that the sparse model computes and learns the stated function, preserves training state, and responds to real requests. You will not have evidence that a few fictional sentences establish useful language competence or that sparse execution is faster. Keep those questions separate throughout the experiment.

1. Replace a decoder sublayer, preserve its context

Retrieve the decoder from Chapter 36 and routing from Chapter 48. A routing-only example maps isolated vectors to experts. A language model must first form a representation that depends on preceding tokens, predict a distribution over the next token, and propagate that prediction loss through the entire architecture. Otherwise, selecting experts would be an isolated demonstration rather than the promised capstone.

This independent Rust checkpoint continues the pre-normalized decoder design with one attention head and one block. It uses f64 for inspectable gradient checks, a 128-symbol ASCII vocabulary, context length 16, model width d=8, and expert hidden width f=12. There are three experts in the sparse model. It preserves token and learned position embeddings, causal attention, two residual additions, pre-attention and pre-expert LayerNorm, GELU, and final LayerNorm. It does not import a trained checkpoint or change the shared Chapter 36 implementation.

X = token_embedding + position_embedding
R = X + Attention(LN₁(X))
H = LN₂(R)
Uₜ = Rₜ + pₜ,ₘ Expertₘ(Hₜ)
logits = LN_final(U) W_output + b_output

Rows correspond to token positions t. X, R, H, and U have shape [T,d], where T is the sequence length. The selected expert index m can differ by row. Each expert maps d inputs to f hidden activations and back to d outputs. Attention masks positions after the current row. The final projection produces [T,V] logits for vocabulary size V=128, and the target at row t is the following byte.

All affine matrices here use row-major [input,output] storage so an activation row multiplies them directly. This differs from earlier scratch layers stored as [output,input]; use the shape map from Chapter 55. Token embeddings are [V,d], position embeddings [context,d], the combined query/key/value projection [d,3d], and each expert's two matrices [d,f] and [f,d]. Biases have the corresponding output lengths.

LayerNorm computes a mean and population variance across one token's d features, then applies learned gain and bias. For feature j, nⱼ=(xⱼ−μ)/√(variance+10⁻⁵), followed by γⱼnⱼ+βⱼ. It never averages across tokens. This matters for causality: later positions must not enter the normalization statistics of an earlier token. The original Layer Normalization paper provides the normalization idea; the executable verifies this particular implementation's backward pass.

Our attention and normalization design therefore allows a strong check: change only the last input token and compare every earlier output row. They remain equal. Truncate the input to an earlier prefix and the retained rows also remain equal during inference. A mask-shaped array in the source is not enough; these numerical checks establish the behavior the language model needs.

2. Keep the gate that lets the router learn

A selected expert gate is the full-softmax probability retained after selecting the largest router score. For normalized hidden row h, router logits are z=hW_router+b_router. Softmax produces p, a vector of E positive values that sum to one. The implementation selects m=argmax(p), evaluates only Expertₘ(h), and multiplies its output by pₘ. Ties resolve deterministically, but derivative checks avoid them.

A selected gate has a useful derivative

Router logits [2,1,0] produce probabilities approximately [0.665,0.245,0.090]. Select expert zero. If its output is [2,−1], the gated contribution is [1.330,−0.665]. With residual [0.5,0.2], the block output is approximately [1.830,−0.465].

Suppose the upstream derivative with respect to the block output is g=[0.1,−0.2]. The derivative with respect to the selected probability is g·Expert₀(h)=0.1×2+(−0.2)×(−1)=0.4. The derivative with respect to selected logit zero is 0.4×0.665×(1−0.665)≈0.0891. The other two router logits receive approximately −0.0652 and −0.0239. Their derivatives sum to zero, as expected for a softmax that ignores a common logit shift.

∂L/∂zⱼ = (g · Expertₘ(h)) pₘ (1[j=m] − pⱼ)

Here L is the task loss, g is the upstream vector derivative, and 1[j=m] is one for the selected expert and zero otherwise. The hard choice is treated as locally constant. We differentiate the probability attached to that choice, not the argmax itself. This is a piecewise derivative: a finite perturbation crossing a tie can change the computational path, so a smooth finite-difference comparison there is not a valid test.

Dividing the single selected probability by itself would make its value one and its derivative zero. Experts might still train and loss might still decrease, hiding a disconnected router. Our tests check that router gradients remain nonzero even when the balancing coefficient is zero. This follows the selected-probability construction in Switch Transformers; the top-two normalization used in other routing schemes cannot be copied blindly into top-one routing.

Only the selected expert receives the task derivative for an accepted token. Its output derivative is pₘg. The normalized hidden row also receives a contribution through the router matrix, in addition to the expert's ordinary backward pass. Ignoring that router-to-input path would leave the router weights trainable while producing an incorrect gradient for the shared decoder. The exhaustive small-model check includes both routes.

3. Separate limited training capacity from causal inference

An expert receiving almost every token would defeat the intended division of work. A capacity limit bounds how many rows an expert accepts within a training sequence. For T tokens, E experts, and positive capacity factor c, the project uses C=max(1,ceil(Tc/E)). Capacity refers to assigned tokens, not parameter count or vocabulary size.

With T=16, E=3, and c=1.25, capacity is ceil(6.666…)=7. If attempted routes are [2,6,8], accepted counts are [2,6,7] and one token skips expert computation. Its residual still passes through. Tokens are processed in position order; the first C assignments to an expert are accepted. Report both attempted and accepted counts so dropping does not disguise an overloaded expert.

Training also adds a balancing objective. Define fᵢ as the fraction of all tokens whose hard choice is expert i, before capacity drops. Define Pᵢ as the mean full-softmax probability of that expert over the same tokens. The added loss is αEΣᵢfᵢPᵢ, with α=0.01 in the tiny sparse configuration.

Differentiate the mean probability, not the count

For four tokens and three experts, suppose hard frequencies are [0.75,0.25,0] and mean probabilities are [0.60,0.25,0.15]. The auxiliary value is 0.01×3×(0.75×0.60+0.25×0.25)=0.015375. Holding the hard choices fixed, its derivative with respect to any token's probability for expert zero is 0.01×3×0.75/4=0.005625.

For expert one that probability derivative is 0.001875; for expert two it is zero before applying the softmax Jacobian. Expert two can nevertheless receive a nonzero logit derivative because changing its logit changes every probability. Do not interpret a zero direct probability derivative as a disconnected parameter.

The code stores counts, so its expression is αE countᵢ/T². One factor of T converts count to frequency; the other comes from differentiating a mean probability. Hard counts are stop-gradient values within the current routing region. Dropped tokens still contribute router probabilities and attempted frequencies to this objective, although they contribute no expert task gradient. GShard describes related capacity and balancing ideas for a different top-two architecture.

Capacity is disabled for evaluation and generation. This is a deliberate semantic distinction. If inference recomputed C from the current prefix length, adding a future token could change an earlier token's acceptance status. Even a causal attention implementation would then fail prefix invariance. Uncapped inference computes one selected expert for every token. Capped training still models overflow, and routing_stats reports a capped diagnostic; the printed evaluation loss always uses the uncapped function.

The training objective is mean next-token cross-entropy plus auxiliary loss. The evaluation metric is mean next-token cross-entropy alone. A model can improve its balance while worsening its predictive loss, so do not compare the combined training objective directly with an evaluation number. Large sparse models also have optimization and communication difficulties beyond this fixture; ST-MoE studies such issues. No distributed expert communication is implemented here.

4. Establish what the small experiment shows

The reference corpus contains original course-authored ASCII sentences such as “rust learns patterns” and “experts route tokens.” A separate held-out sentence combines the same small vocabulary. There are no downloaded datasets, pretrained weights, or hidden framework calls. Training takes cyclic windows of sixteen input bytes and their shifted targets. Wrapping introduces an artificial final-byte-to-first-byte transition; this is part of the fixture, not a recommended document boundary policy.

Evaluation visits every target byte in the supplied corpus exactly once using nonoverlapping context windows. It weights each window's mean by its actual target count, including the final short window. It does not evaluate only the first sixteen bytes, average windows of unequal sizes equally, or include the auxiliary term. Position indices restart within each window. Generation uses the most recent sixteen bytes, recomputes attention, and restarts learned positions when the window slides; it has no KV cache.

cargo run --release --manifest-path projects/ch56/Cargo.toml

The no-argument run trains dense and sparse models for 160 SGD steps at rate 0.08 and sixteen tokens per step. Both see the same 2,560 token presentations. Shared parameters and expert zero begin with matched values despite their different storage offsets. The dense baseline has one ordinary feed-forward block and no router parameters. It is checked against an independent evaluator that does not call the production forward, normalization, affine, or routing helpers.

The conventional active parameter budget, here nonexpert-plus-one-expert, removes the two inactive expert blocks. The observed sparse loss is lower for this one tiny run. That is a result to reproduce, not evidence of a general advantage. The comparison matches token budget and almost matches activated parameter count, but it does not match total parameters, training FLOPs, wall-clock time, or optimizer trajectories. Vocabulary and sentence overlap make the held-out result a limited recombination test. Larger claims need independent documents, multiple seeds, tuned dense baselines, measured resource use, and task-relevant evaluation.

The program prints changes for every named parameter family. Router weights, each expert, attention, all three normalizations, and embeddings change in the default run. Tests also check every parameter derivative in a much smaller two-expert model using central differences with epsilon 10⁻⁵ and tolerance 10⁻⁶+10⁻⁴ times the larger gradient magnitude. They force each expert in turn away from ties, check unselected expert task gradients are zero, and separately verify dropped-token counts.

Reference parameter storage is only 3,303×8=26,424 bytes, before gradients and activations. The code uses ordinary vectors and materializes attention and backward caches. Its checked configuration bound limits an aggregate of structural storage expressions to eight million elements; that is not a bound on peak process memory. Long contexts incur quadratic attention storage. Sparse parameter counts alone do not pay for those costs.

5. Train an artifact, resume it, and serve it

The complete model and trainer library, command-line program, and independent checks are readable source checkpoints. Train a model and resume it explicitly:

cargo run --release --manifest-path projects/ch56/Cargo.toml -- train /tmp/ch56-moe.bin 400
cargo run --release --manifest-path projects/ch56/Cargo.toml -- resume /tmp/ch56-moe.bin 100
cargo run --release --manifest-path projects/ch56/Cargo.toml -- generate /tmp/ch56-moe.bin rust 32

The versioned checkpoint includes model dimensions, capacity and balancing settings, finite f64 parameters, step, data cursor, random-generator state, and training identity. The identity contains corpus length and fingerprint, sequence length, and learning rate. SGD has no momentum state to store. Resuming with different data or settings returns an error before changing parameters. Same-state continuation is tested exactly on the same executable; cross-platform bitwise reproduction is not promised.

Loading validates dimensions and checked storage products before model allocation, rejects wrong versions and zero RNG state, and requires an exact payload length. Truncation, extra bytes, and nonfinite parameters fail. Saving validates public training state, writes to an exclusively created temporary path, synchronizes, and renames. If that temporary filename already exists, the save fails without deleting someone else's file. The corpus fingerprint detects accidental changes, not malicious tampering; the format is not authenticated.

The next commands launch a single-request server and call it from another terminal. The process exits after responding, so restart it for another request:

cargo run --release --manifest-path projects/ch56/Cargo.toml -- serve /tmp/ch56-moe.bin 127.0.0.1:8787
curl -i 'http://127.0.0.1:8787/generate?prompt=rust&tokens=24'

The server loads the actual checkpoint and returns JSON containing sampled text. It accepts only loopback addresses, a narrow HTTP/1.1 GET subset, a nonempty ASCII prompt of at most 256 bytes, and at most 64 new tokens. Header reads continue until a complete terminator arrives, rather than assuming one TCP read is a full request. Headers are capped at 4,096 bytes; duplicate query fields, duplicate content length, transfer encoding, nonzero bodies, and malformed requests receive 400. Successful generation receives 200. Read and write timeouts are five seconds.

Sampling subtracts the largest logit before temperature division, then normalizes exponentials. This ordering remains meaningful even for extremely small positive temperatures. Returned strings escape JSON metacharacters and replace control characters for display. The tiny model may still sample meaningless text, including control-token values internally. An HTTP success confirms execution, not content quality. There is no authentication, batching, streaming, KV cache, TLS, or production traffic management.

For an explicit longer data experiment, supply both training and held-out files:

cargo run --release --manifest-path projects/ch56/Cargo.toml -- train /tmp/ch56-custom.bin 2000 /path/to/licensed-train.txt /path/to/licensed-heldout.txt

Each file must contain between two bytes and eight MiB of ASCII. The command rejects identical corpora and an exactly shared 32-byte passage. This conservative overlap check does not establish document independence, license rights, or absence of shorter contamination. Its set of borrowed windows uses memory proportional to the smaller corpus. Choose licensed, separately collected documents and record provenance using Chapter 37; the example path is a user-supplied file, not an automatically downloaded dataset.

This command increases training duration and data, not model dimensions. To study a larger architecture, edit the visible tiny configuration and maintain the dense comparison, structural memory checks, and derivative tests. Width, context, and expert width all change resource requirements. Scaling to a multi-million-parameter model requires a separate resource estimate and explicit execution; no large training, GPU acceleration, or multi-device performance result is claimed for this capstone.

Hint 1: preserve the probability

The selected probability still depends on every router logit. Its derivative with respect to its own logit is positive unless the distribution has become exactly concentrated through numerical rounding.

Hint 2: apply the chain rule

Start with pₘ(1−pₘ), then multiply by the upstream derivative of loss with respect to pₘ. For expert output vectors, that upstream quantity is a dot product.

Worked solution
gate * (1.0 - gate)
// Capacity, for validated positive factor and expert count:

At p=0.665 the local gate derivative is approximately 0.2228. With seven tokens, three experts, and factor 1.25, capacity is ceil(2.9167)=3. Integer division first would compute ceil(2×1.25)=3 here by accident; eight tokens would expose the mistake: the correct capacity is ceil(3.3333)=4.

Debugging: sparse loss falls but the router never moves

Set the balance coefficient to zero in a scratch copy. A learner normalizes the top-one gate to one and sees improving loss. Identify why that result cannot verify router training. Name one numerical test and one training observation that expose the bug.

Worked diagnosis

The gate becomes the constant p/p=1 inside each routing region. Task loss can train the selected expert and decoder, while its derivative into router logits vanishes. Check a router coordinate with finite differences away from a tie, retaining the full selected probability, and compare router parameter values before and after actual updates. Turning auxiliary balance off ensures that balancing alone cannot conceal the missing task gradient.
