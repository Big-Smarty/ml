Where does an expert sit inside the tensor flow?

For T≤16 tokens, token and position embeddings sum into X of shape [T,8]. Pre-normalized causal self-attention projects queries, keys, and values of width eight. Its score matrix has shape [T,T]; positions to the right of each query are masked before softmax. Attention output is projected back to [T,8] and added to the original residual.

The second normalization produces one eight-coordinate vector per token for routing and expert input. Router weights map width eight to three logits, producing [T,3] probabilities. Each selected expert has an 8→12 affine layer, GELU, then a 12→8 affine layer. Its gated output is added to the attention residual. Final normalization and a width-eight-to-128 projection produce logits [T,128].

The task objective is mean next-token cross-entropy over all T targets. For input bytes “rus”, targets are “ust”. The model must not see each target through an unmasked future position. Causal masking therefore matters during training even though all target positions are known to the training program.

The supplied backbone contains explicit backward passes for attention, layer normalization, embeddings, and output projection. These remain readable in the common source. Your learner file owns moe_forward and moe_backward, including expert matrix operations and routing derivatives; do not replace them with a detached scalar demonstration.

Each expert contains 8×12+12+12×8+8=212 parameters. Three experts therefore add 424 expert parameters relative to one, plus the differing router size. The printed “nonexpert+one-expert” count is a parameter accounting convention, not a FLOP count: all router logits and the dense attention still run, and an overflowed token skips its expert.

How does a language-model loss reach an unselected router logit?

Let expert output for a token be vector e and selected probability pₖ. Its added contribution is pₖe. If the upstream gradient is vector g, the selected expert receives pₖg, while the selected probability receives dot(g,e). The gate derivative is a scalar even though the expert output has eight coordinates.

For one-coordinate intuition, e=2, upstream g=0.3, and pₖ=0.6. Expert-output gradient is 0.18; probability gradient is 0.6. With two router probabilities [0.6,0.4], the softmax derivative sends logit gradients [0.144,−0.144]. The unselected expert does no task matrix work, but its router logit still affects the selected full-softmax denominator.

Hard expert selection and admission are discrete. The taught backward holds the selected route and capacity decision fixed locally; it differentiates the smooth function inside that region. Renormalizing a singleton selected probability to one would erase this task signal to the router.

For balancing, attempted frequencies fᵢ are held fixed and mean full probabilities Pᵢ remain differentiable. Add αEΣfᵢPᵢ to training loss. Each token receives probability derivative αE fᵢ/T. Add it to the task probability derivative, then apply the full softmax backward dzⱼ=pⱼ(gⱼ−Σpᵢgᵢ).

The router’s linear backward updates router weights and bias and returns an additional gradient to the normalized token representation. Combine it with the selected expert’s input gradient before normalization backward. Omitting that input contribution leaves the router trainable while training the backbone against the wrong derivative.

Which saved values does a two-layer expert need?

For expert input u, first preactivation a=W₁u+b₁, hidden h=GELU(a), and output e=W₂h+b₂. Given expert-output gradient de, accumulate dW₂=de outer h and db₂=de. Propagate dh=W₂ᵀde, then da=dh⊙GELU′(a), dW₁=da outer u, db₁=da, and du=W₁ᵀda.

Shapes make these statements testable: W₁ is [12,8], W₂ is [8,12], de has eight coordinates, dh and da twelve, and du eight. Every token assigned to the same expert accumulates into the same parameter-gradient arrays. Gradients use old weights throughout; updates happen only after the complete batch gradient exists.

Dropped tokens have no expert task contribution. Their residual gradient still passes directly backward, and their router may receive the auxiliary balancing contribution because attempts count even when capacity drops them. Treating a drop as deleting the entire token would corrupt both the representation and the training objective.

Finite differences must avoid ties and capacity boundaries, where infinitesimal parameter changes may switch the discrete function. The goal fixture uses a clear router-bias preference, roomy capacity, and zero balance weight for a task-only derivative test. Separate tests cover the auxiliary and overflow cases.

How do you compare dense and sparse models fairly enough to learn something?

The default compares one expert with three experts using matched shared parameter initialization, the same corpus, token order, learning rate 0.08, sequence length 16, and 160 updates. Each model sees 2,560 token presentations. The three-expert model has more total parameters, so this is a declared small mechanism comparison, not a parameter-matched benchmark.

Training uses capacity factor 1.25 and balance coefficient 0.01 for the three-expert model. At T=16 and E=3, capacity is ceil(1.25×16/3)=7 per expert. A balanced allocation can admit all tokens, while a collapsed allocation drops nine. Record attempted routes, admitted counts, drops, capacity, and mean selected gate beside loss.

The report also prints the L2 change for each named parameter block. This verifies that attention, normalization, embeddings, router, experts, and output head are actually connected to updates. Keep task cross-entropy separate from auxiliary loss. A lower total training objective after reducing the balance coefficient may say nothing about language prediction. Why must evaluation avoid future-dependent capacity decisions?

During inference, adding a future token must not change earlier logits. Causal attention already enforces the prefix boundary, but a batch-dependent capacity rule could reintroduce dependence through routing admission. This model disables capacity dropping for evaluation and generation, retaining the selected route and probability gate.

The goal check compares the full sequence’s prefix logits with a standalone prefix under a restrictive training capacity setting. Exact prefix agreement on this deterministic fixture verifies that inference does not use the training drop rule. It does not establish every possible architecture’s causality.

The supplied held-out string differs from the training string but shares a tiny synthetic language and construction. Its cross-entropy is a useful separation of fitting from evaluation, not an independent language benchmark. Generation samples can be nonsensical even when loss falls substantially; this model has only sixteen bytes of context and very limited capacity.

Which state makes resumed training the same computation?

The binary checkpoint stores the architecture and routing configuration, parameter array, training step, data cursor, generation RNG state, and training identity. That identity includes corpus fingerprint and length, sequence length, and learning rate. Resuming with incompatible training settings is rejected instead of silently changing the run.

The optimizer is plain SGD with no momentum or adaptive state. If you replace it with Adam, the checkpoint must grow to include moments and their step-dependent semantics. The saved RNG matters for generation continuation even though the current training batches and updates are deterministic.

The header CH56MOE2 declares the byte-format version. Validation bounds dimensions and total storage before allocation, checks exact parameter counts, finite values, supported headers, and complete input. These checks prevent malformed metadata from allocating unbounded tensors or loading nonsensical state.

Use an uninterrupted run and an interrupted/save/load/resumed run with the same initial state. Compare every parameter, cursor, step, and subsequent generated sequence. The supplied solution tests include this complete continuation path and reject changed corpus or learning settings. Merely decoding a file or matching one prediction is weaker evidence.

The training command writes a checkpoint at the path you supply; use a fresh temporary directory for the following sequence so earlier artifacts remain available.
