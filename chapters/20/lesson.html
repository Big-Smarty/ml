Can one detector recognize a stroke in several places?

A bright vertical stroke remains a vertical stroke when it moves one column. A dense image classifier must learn a separate weight for each pixel position. A convolutional classifier instead moves one small detector across the image and reuses its weights. Our question is whether that shared local rule can help recognize ten tiny digits.

Check the connection

For z = wx+b and incoming derivative g = dL/dz, the chain rule gives dL/dw = gx. If the same w appears at many positions, its derivative is the sum of gx over those uses. Parameter sharing in forward therefore requires gradient accumulation in backward.

For a 3×3 patch [1,0,2; 0,1,0; 2,0,1] and kernel [−1,0,1; −1,0,1; −1,0,1], multiply matching positions. The three row sums are 1, 0 and −1, giving zero. A patch [0,0,2; 0,0,2; 0,0,2] gives 6. The same nine weights detect the same direction of brightness change wherever that patch occurs.

This operation is conventionally called convolution in neural networks, although these programs perform cross-correlation: they do not flip the kernel. A kernel is a small learned array, also called a filter. Each filter produces an activation map with one response per visited location. The bias is one scalar per filter, also shared across locations.

Which image positions contribute to an output?

We store one grayscale image as a flat row-major slice. Logical coordinate (r,c) is image[r * cols + c]. A kernel has shape [3,3], also row-major. With padding one and stride one, the response at (r,c) is bias plus the nine products K[a,b]X[r+a−1,c+b−1]. Here X is the image, K is the kernel, a and b range from zero through two, and values outside the image contribute zero. Padding supplies a computational convention, not observed pixels.

Stride is the distance between successive kernel positions. For input length I, kernel length K, padding P on each side and positive stride S, the output length is floor((I+2P−K)/S)+1, provided the padded input is at least as large as the kernel. Apply the formula independently to height and width. With I=7, K=3, P=1 and S=2, (7+2−3)/2+1=4. A 7×7 input becomes 4×4. The Rust model fixes P=1 and S=1; the illustration also lets you compare other geometries.

What should survive a small local shift?

Retrieve the difference between an activation map and a class prediction. The map records local detector responses. The classifier still needs a way to combine them. ReLU first computes max(0,z) at each location; a negative detector response is discarded rather than treated as evidence of the same positive feature.

A 2×2 max pool with stride two keeps the strongest response in each non-overlapping window. For [0.2,1.1;0.7,0.4], it returns 1.1. If the strongest feature moves within that window while retaining its strength, the pooled value stays the same. If it moves across a window boundary, the pooled representation can change. This is limited local tolerance, not general translation invariance.

The model has two filters. Its [2,8,8] rectified maps become [2,4,4] after pooling, leaving 32 inputs to the dense head. For an odd height or width, this implementation uses floor division and drops the trailing incomplete pool window. That choice must be stated: a 5×5 map produces 2×2 pooled values, not 3×3.

The microscope's first 2×2 window is [1.2,0;1.8,0]. Its maximum is 1.8 at (1,0). The 2.4 response in the third row is outside that pool; a stride-two pool on a 3×3 map discards the incomplete bottom and right edges. Predict what zero padding in convolution changes before selecting its preset.

Why must pooling remember an index?

The maximum alone is insufficient for training. Suppose a later layer sends derivative 0.6 to the pooled output 1.1. As long as its winner stays unique, changing any losing entry slightly does not change the maximum. Backward therefore sends [0,0.6;0,0], using the recorded winner's index. In an average pool, each entry would receive 0.6/4=0.15 instead; that is a different operator and derivative.

The supplied cache stores a flat winning index for every pooled value. During backward, the classifier adds the incoming derivative at that index. ReLU then blocks the derivative where its original pre-activation was nonpositive. For positive inputs its local derivative is one; at negative inputs it is zero. At zero and at max ties there is no unique mathematical derivative, so the code uses explicit conventions.

Your implementation should keep the first row-major maximum when values tie. Initialize the winner with the window's upper-left index and replace it only on a strict greater-than comparison. Storing an absolute index into the activation plane avoids reconstructing local coordinates during backward.

Trace [0.4,0.4;0.1,0.2] with incoming gradient −2. Which entry receives −2 under the chosen rule? Would a numerical perturbation of a tied winner be a reliable smooth-gradient test?

How does digit error reach a shared kernel?

Retrieve the shared-weight derivative from the opening session. This time the incoming derivative is produced by a real classifier. The dense head stores weights [10,32], meaning one row per output class. For class c, its logit is b[c]+ΣW[c,j]pooled[j], where j ranges over the 32 pooled features. The training label selects the desired class; it is not a numerical pixel feature.

The per-image cross-entropy is log-sum-exp of ten logits minus the target logit. Stable evaluation computes (maximum−target logit)+log Σexp(logit−maximum). Equal logits give log(10), even when all contain the same huge offset. The derivative at each logit is its softmax probability minus one for the target class, or minus zero for another class.

First compute dense-weight derivatives and each pooled-value derivative using the old dense weights. Route those derivatives to pool winners, apply the ReLU mask, and obtain a grid G[r,c] of derivatives at convolution pre-activations. Now the kernel derivative is ΣG[r,c]X[r+a−1,c+b−1] for each kernel coordinate (a,b), with the same padding rule as forward. The bias derivative is simply ΣG[r,c].

One shared coefficient sees source pixels 2 and 5 at two output positions, with incoming gradients 0.3 and −0.1. Its derivative is 0.3×2−0.1×5=0.1. An update with learning rate 0.02 subtracts 0.002 from this one coefficient. Updating separately after each location would change parameters during one backward pass and mix different models.
