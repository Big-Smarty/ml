A dense layer treats a pixel in the upper-left corner as unrelated to the same shape one column to the right. Images give us a useful prior: nearby pixels form local patterns, and the same pattern can appear in many places. A convolutional network turns that prior into shared arithmetic, then learns the shared weights from classification error.

1. Reuse a local detector across an image

Chapter 10 flattened each 28×28 image into 784 ordered features. That mapping is reversible, but the dense architecture did not encode grid locality or share a detector across positions. A convolution uses the grid directly. A small kernel, or filter, looks at one patch and produces one number. Moving the same kernel across the image reuses its weights.

Most neural-network software calls this operation convolution although it computes cross-correlation: it does not reverse the kernel. For a single-channel image X and 3×3 kernel K, the pre-activation at row r and column c is zr,c = b + Σi=0..2Σj=0..2Ki,jXr+i−1,c+j−1. X has shape [height,width], K has shape [3,3], and b is one learned scalar for the filter. An out-of-bounds X contributes zero.

Compute one filter response

Take the 3×3 image patch [1,0,2; 0,1,0; 2,0,1] and a vertical-edge kernel [−1,0,1; −1,0,1; −1,0,1], with bias zero. Multiply matching entries and add: (−1×1 + 0×0 + 1×2) + (−1×0 + 0×1 + 1×0) + (−1×2 + 0×0 + 1×1) = 1 + 0 − 1 = 0. On the patch [2,0,0; 2,0,0; 2,0,0], the same response is −6. The sign records edge direction; a following ReLU keeps only positive responses.

A dense unit over an 8×8 image needs 64 weights per output. One 3×3 filter needs nine weights no matter how large the image becomes. This weight sharing does not make the result perfectly translation invariant. It makes the detector equivariant before boundaries and reductions: shifting a pattern tends to shift the activation map. Pooling and training examples can make the final prediction less sensitive to small shifts.

Each activation sees a local receptive field. Stacking local layers grows the region that can influence a later value. Two 3×3 stride-one layers can connect a later activation to a 5×5 input region. This is one reason small kernels can build larger patterns without immediately connecting every pixel to every unit.

2. Padding and stride choose the output grid

Padding specifies a conceptual border. The reference uses one zero on each side, so a 3×3 kernel can be centered at every original pixel. Stride specifies how far the kernel moves between outputs. For one dimension, output size is floor((I + 2P − K)/S) + 1, where I is input size, P padding, K kernel size, and S stride.

Trace an output shape

For I = 7, K = 3, P = 1, and S = 2, the numerator is 7 + 2 − 3 = 6. Divide by two, take the floor, and add one: 6/2 + 1 = 4. A 7×7 image therefore becomes a 4×4 activation map. With stride one it would remain 7×7. The Rustlings exercise asks you to implement exactly this arithmetic.

The reference project fixes convolution stride at one and padding at one. Its row-major index is row * cols + col. Two filters produce contiguous planes: filter * rows * cols + row * cols + col. Keeping this indexing explicit is less convenient than a tensor library, but it exposes every shape invariant and every place padding matters.

After convolution, ReLU computes max(0,z). At z > 0 its derivative is one; at z < 0 it is zero. At exactly zero the function is nondifferentiable. The implementation chooses the zero branch. Its numerical gradient check constructs smooth nonzero activations, because a finite difference that crosses a kink is testing the convention rather than the chain rule.

3. Pool values and remember where they came from

The model next applies 2×2 max pooling with stride two. Each window becomes its largest activation, halving both spatial dimensions. An 8×8 map becomes 4×4. With two filters, the dense head receives 2×4×4 = 32 values.

Forward and backward through one pool

Suppose a pool window is [0.2, 1.1; 0.7, 0.4]. Its output is 1.1, at the upper-right position. If the later layer sends gradient 0.6 back to this pooled value, max-pool backward sends [0, 0.6; 0, 0]. The sum is preserved, but only the recorded winner receives it. If two entries tie for the maximum, the mathematical max has no unique derivative; the implementation deterministically chooses one index.

The dense head produces ten logits. For target class y, cross-entropy is log Σcexp(zc) − zy. The program subtracts the largest logit before exponentiation. This is algebraically the same loss and avoids overflow. It never clamps probabilities. The logit gradient is softmax(z)c − 1[c=y].

Backward order reverses forward order. First compute dense gradients and the gradient of every pooled value. Route each pool gradient to its winner. Apply the ReLU mask. For each surviving convolution activation, add its gradient times each input pixel to the corresponding shared kernel gradient. Because the same kernel appears at every location, all locations accumulate into the same nine numbers. Only after every gradient is computed does training update the old parameters.

The test perturbs one convolution weight by ±10−5. It compares the resulting central-difference loss slope with the analytic backpropagation gradient using absolute tolerance 10−6 plus relative tolerance 10−4. Unique pool winners and nonzero ReLU inputs keep the check away from nondifferentiable ties.

4. Train the small digit classifier

Read the complete reference source, then run:

cargo test --manifest-path projects/ch20/Cargo.toml
cargo run --release --manifest-path projects/ch20/Cargo.toml

The fixture draws ten seven-segment digits on 8×8 grids. Training contains three horizontal shifts per digit. Validation uses dimmed, perturbed images that are byte-for-byte disjoint from training. The run measured during authoring printed:

fit=30 validation=10 shape=8x8
validation cross-entropy 2.3062 -> 0.0630; accuracy 10.0% -> 100.0%

This is a deterministic mechanism check on thirty simple generated examples. Ten validation rows cannot estimate handwriting quality. Their disjointness catches direct duplication; their close construction does not make them representative of a new population.

For real MNIST, first use the course preparation command described in the dataset guidance. It creates a fit split and validation split from the original training set and preserves the official test set. Then run the classifier with explicit paths:

cargo run --release --manifest-path projects/ch20/Cargo.toml -- --mnist \

MNIST mode validates big-endian magic numbers, counts, dimensions, payload lengths, label range, and integer overflow. Missing files produce path-specific errors. It intentionally limits each split to 2,000 rows and uses one epoch, sample-at-a-time SGD, two filters, and CPU scalar loops. That makes it an inspectable extension, not a competitive benchmark. Do not use t10k while tuning; reserve it for one final evaluation after choices are frozen.

A verified authoring run on the prepared fit and validation files measured validation cross-entropy 2.3018 to 0.4614 and accuracy 10.2% to 86.7%, using exactly 2,000 fit rows, 2,000 validation rows, one epoch, and 28×28 inputs. This is a functional CPU smoke run under stated conditions, not a tuned or test-set result. The official test split remained untouched.

5. Practice, debug, and vary the model

Exercise A · Compute convolution shape

Complete ch20_01.rs. The function receives input, kernel, padding, and stride sizes.

Hint 1 · Count the padded span

Padding contributes on both sides, so start with input + 2×padding.

Hint 2 · Count valid starting positions

Subtract the kernel width, divide by stride with integer floor, then add one for the starting position at zero.

Worked solution
(input + 2 * padding - kernel) / stride + 1

At an external boundary, also reject zero stride and shapes where the kernel exceeds the padded input. The tiny exercise uses valid constants so the formula remains visible.

Reference checkpoint

The reference forward function repeats that calculation for both filters and all spatial positions, then stores ReLU activations and pool winners needed by backward.

Debugging · Every kernel location learns a different filter

A learner allocates a separate 3×3 kernel for every output row and column. Training loss falls, but a shifted validation digit fails.

Answer

The implementation removed weight sharing. It became a locally connected layer that can memorize position-specific patterns. Store one nine-value kernel per filter, reuse it at every output position, and accumulate gradients from every position before updating. Falling training loss did not establish the intended convolution.

Independent variation · Replace max with average pooling

Change each 2×2 pool to its mean. Predict how backward changes, then compare fixture loss and accuracy under the same seed, epochs, and learning rate.

Worked answer

The forward output is (a+b+c+d)/4. A later gradient g contributes g/4 to each of the four inputs. No winner indices are needed, and ties cause no kink. If results change, report the measured values; do not conclude generally that one pool is better from ten fixture rows.

The same nine kernel values serve every location. The size is floor((9−3)/2)+1 = 4. A max-pool gradient goes to the stored winning input, assuming a chosen tie convention. Log-sum-exp gives the exact stable objective without risky probabilities. Validation can guide choices; the preserved test set estimates the frozen final procedure once.

Stable cross-entropy requires attention to subtraction as well as exponentiation. Compute (maximum logit − target logit) + log(sum(exp(logit − maximum))). Adding the logarithm to an enormous common offset first can round it away. A regression test sets every class bias to 1016 and still obtains log(10), the loss of a uniform ten-class prediction.
