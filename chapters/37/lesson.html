A correct decoder can still learn the wrong lesson from duplicated, leaked, or undocumented text. Language-model data is part of the experiment: each document needs provenance, cleaning decisions, deduplication, and a stable split before a later consumer turns it into token windows.

Goal

Prepare an auditable corpus from course-authored documents or a user-supplied licensed file. The project parses document records, normalizes whitespace, removes exact and near duplicates, assigns whole documents to splits, and emits a manifest while preserving source and license fields.

Code and terminology carried forward

Chapter 33 established that next-token examples must stay within document boundaries. Chapter 34 fitted and serialized a byte-pair tokenizer, while Chapter 36 consumed token IDs and explicit shifted targets in a decoder. This chapter moves upstream: it accepts whole text documents and produces whole cleaned, deduplicated, split document records. It does not tokenize text, construct token windows, evaluate loss, compute gradients, or update a model. A downstream consumer remains responsible for processing each retained document separately.

The terms data leakage and checkpoint keep their definitions from Chapters 5 and 11. Here leakage can occur when copied content crosses the training/evaluation boundary, and a later checkpoint should identify the exact corpus manifest and tokenizer it used. Operation names and artifact meanings follow the course code and terminology guide.

1. Know what each document is

Provenance records where data came from and how it may be used. At minimum, retain source location, author or publisher when known, license or terms, retrieval date for changing sources, and a content identity such as a checksum. A URL alone is not a license, and a mirror's software license does not grant rights to mirrored text.

The bundled fixture is course-authored and marked CC0. It teaches mechanisms and is far too small to establish language quality. For larger work, pass a local file whose text you have permission to use. The project never downloads or silently substitutes a corpus. Its simple format begins each document with Title: and License: lines and separates documents with ===DOC===.

Identity after cleaning

Suppose a document contains Rust makes\nownership visible.. Whitespace normalization yields Rust makes ownership visible.. The reference hashes title plus cleaned text with a stable 64-bit FNV-1a teaching hash, producing a document ID. This detects accidental identity inside the pipeline; it is not a cryptographic authenticity claim. A production manifest can store SHA-256.

Keep raw source files or immutable references when policy permits. Cleaning is a transformation, so the manifest should distinguish raw identity from derived identity in a larger system. The chapter's minimal format stores the source path and derived ID, enough to expose the chain without building a data catalog. In the code, ParsedDocument is the parser artifact and CleanDocument is the derived artifact that owns this ID.

2. Clean with explicit, inspectable rules

Cleaning can remove broken extraction, markup, control bytes, repeated boilerplate, or disallowed personal data. Every rule changes the distribution a model sees. Broad blocklists can remove legitimate discussion of the terms they match and can disproportionately exclude particular communities. Treat “clean” as an operational recipe, not a neutral quality label.

The reference performs one transparent operation: any run of Unicode whitespace becomes one ASCII space and leading or trailing whitespace disappears. parse_documents rejects missing or empty title and license fields; clean_documents rejects content that is empty after normalization. It does not guess language, score quality, strip names, or censor terms. Those additions require a stated purpose, tests on retained and removed examples, and manifest fields recording versions and counts.

fn clean(text: &str) -> String {
    text.split_whitespace().collect::<Vec<_>>().join(" ")
}
Fit transformations on training data.

The fixed whitespace rule estimates no corpus statistics, so this project parses, cleans, globally deduplicates, and then assigns splits. If a later cleaner, tokenizer, or threshold learns from data, first assign whole documents, fit that learned transformation on training documents only, and apply it without refitting to validation and test documents.

3. Remove repeated documents before training

Exact duplicates overweight repeated text and can make validation appear easier if copies cross the split. Near duplicates differ by formatting, headers, or a few edits but pose the same risk. Deduplication also reduces repeated memorization and wasted compute.

The project compares lowercased three-word shingles. A shingle is a contiguous sequence; for rust makes errors visible, trigrams are rust makes errors and makes errors visible. For sets A and B, Jaccard similarity is |A∩B|/|A∪B|. The threshold is 0.8. Exact cleaned text is always a duplicate.

Calculate Jaccard similarity

Document A has shingles {a b c, b c d, c d e}. Document B has {a b c, b c d, c d f}. Intersection size is two; union size is four. Similarity is 2/4=0.5, below 0.8, so both remain. If B's third shingle were c d e, sets would be identical and similarity one.

deduplicate compares every retained document, O(N²), which is suitable only for the tiny teaching corpus. At scale, MinHash, locality-sensitive hashing, suffix structures, or distributed exact hashing reduce cost. Keep a small exact implementation as an oracle for samples. Each RemovedDuplicate record stores the removed document, the retained ID it matched, and the score.

Order affects which member of a duplicate cluster survives. The chapter preserves input order and keeps the first. A production recipe should stabilize order or choose by source quality and document that policy.

4. Split complete documents and bound contamination claims

Random token windows from one concatenated stream leak neighboring passages across training and validation. Assign whole documents first. The project maps stable document ID modulo ten: remainder 0 to test, 1 to validation, and 2–9 to training. This approximately creates 80/10/10 proportions on a large, non-adversarial collection and remains stable when execution order changes.

A tiny corpus may not land in every bucket; a real preparation command should report counts and fail or request a larger corpus when evaluation needs are unmet. Hash partitioning is deterministic, not automatically representative. Stratify by domain or time when the evaluation question requires it.

Evaluation contamination means evaluation content, answers, or close variants appear in training. This project compares all cleaned documents before assigning splits, so exact and detected near copies cannot survive into different split artifacts. It does not search for quoted substrings, paragraphs embedded in larger pages, or semantic paraphrases. A no-match result is evidence under this whole-document detector, not proof that contamination is absent.

fn split(document_id: u64) -> &'static str {
    match document_id % 10 {
        0 => "test",
        1 => "validation",
        _ => "train",
    }
}

Why document boundaries matter

Document A ends the answer is; document B begins forty two. Concatenation invents training window answer is forty. It also lets near-identical copies land in different splits if splitting happens after tokenization. This project deduplicates and assigns A and B as whole documents. A later consumer must then create windows within each retained document; SplitDocument cannot enforce how that consumer iterates.

5. Produce and inspect the audit

cargo test --manifest-path projects/ch37/Cargo.toml
cargo run --release --manifest-path projects/ch37/Cargo.toml
cargo run --release --manifest-path projects/ch37/Cargo.toml -- licensed-documents.txt audit.txt

The no-argument run uses only the bundled fixture. With one argument it reads the exact requested file and returns an actionable error if unavailable or malformed. A second path writes the audit. The reference source records IDs, split, title, license, source, byte length, duplicate links, similarity, and counts.

let parsed_documents = parse_documents(&raw, &source)?;
let original = parsed_documents.len();
let cleaned_documents = clean_documents(parsed_documents)?;
let (unique_documents, removed) = deduplicate(cleaned_documents, 0.8)?;
let split_documents = assign_splits(unique_documents);
let report = audit(&split_documents, &removed);

Review removed examples rather than treating count as success. Check that deduplication did not collapse short generic documents, that licenses remain attached, and that train/validation/test IDs are disjoint. Preserve the manifest beside the tokenizer and model checkpoint.

This chapter stops after producing the manifest; it does not run model training or evaluation. A downstream evaluation should report token-average cross-entropy on untouched validation documents. When comparing different tokenizers, per-token loss changes with token boundaries; bits per byte offers a common byte-normalized measure: total negative log₂ likelihood divided by original bytes. Final test evaluation happens after choices are fixed.

Keep domains visible in the report. One aggregate can hide improvement on repeated web prose while technical documentation or another language worsens. Report document counts, original and retained bytes, duplicate rates, and evaluation loss by relevant source group. Groups with few documents need uncertainty and should not support strong ranking claims.

Deletion requests and corrected licenses can arrive after training. Stable source and document IDs let an operator identify affected artifacts, rebuild a filtered corpus, and state which checkpoints used the old version. A manifest cannot untrain a model by itself, but without provenance even locating the affected examples becomes guesswork.

Retain rejected counts by reason. A single total cannot reveal whether a new rule removed empty extraction, duplicates, or an entire language. Small reviewed samples from every reason turn the pipeline into an inspectable decision process.

Why this order?

Document-level decisions remain inspectable. Once text becomes overlapping windows, reconstructing provenance is harder, and this chapter's artifacts no longer control whether a consumer crosses document boundaries.

Debugging · Validation loss looks impossibly low

Investigation finds the same article with different navigation headers in both train and validation.

Answer

Exact hashing missed a near duplicate. Normalize known extraction boilerplate, run near-duplicate comparison before split, and preserve the removal link. Recompute splits and discard contaminated evaluation results; changing only the reported metric does not repair training leakage.

Independent variation · Threshold audit

Run similarity thresholds 0.6, 0.8, and 0.95 on at least twenty licensed documents. Manually label a sample of removals and retained high-similarity pairs.

Worked interpretation

Lower thresholds remove more documents and risk false positives; higher thresholds preserve more near copies. Select a threshold from the error tradeoff and corpus goal, then record it. Do not choose solely for the largest deletion count.

From memory, explain provenance, transformation records, exact versus near duplicates, document splitting, contamination, and bits per byte. Before Chapter 38 can train from these artifacts, a downstream data builder must tokenize each retained document and construct target windows within that document only. The fixture and simple quadratic detector teach an audit trail; they do not certify a web-scale corpus as lawful, unbiased, or contamination-free.

The runnable report records cleaned-byte lengths and retains source, license, and title for removed duplicates as well as retained documents. Malformed metadata aborts parsing. Archiving original byte streams, counting every rejected parse, and auditing matching substrings or semantic paraphrases are further corpus controls; this whole-document shingle example does not implement those broader detectors.
