Chapter 1 learned a line by measuring the loss on both sides of every parameter. That made the learning loop visible, but it also did four complete loss evaluations per step. Here we derive the same direction from the equation itself, then keep finite differences as a test that catches mistakes.

Your goal

You will calculate the exact gradient of mean squared error, verify it numerically, and train the same neuron with one pass through the data per update. The result is the first piece of machinery that can scale beyond two parameters.

1. Replace repeated probing with a rule

Return to the model from Chapter 1: ŷ = wx + b. Its loss is the mean squared error L = (1/N)Σᵢ(ŷᵢ−yᵢ)². Chapter 1 asked how L changed by evaluating nearby values. For a model with two parameters this is affordable. A model with one million parameters would need about two million extra loss evaluations for one central-difference gradient. The arithmetic inside those evaluations repeats almost all the same work.

A derivative gives the limiting local slope directly. If a tiny change Δw causes a loss change ΔL, then ΔL/Δw is an average slope across that interval. As Δw approaches zero, the ratio approaches dL/dw when the function is smooth. The derivative's units matter: if loss is measured in squared target units and w in target units per input unit, then dL/dw tells us loss change per unit of weight.

One error term before the general formula

Use one example x = 2, y = 5 and the starting model w = 0, b = 0. The prediction is zero, the error e = ŷ−y is −5, and squared error is 25. Increase w by 0.01. The prediction becomes 0.02, error becomes −4.98, and squared error becomes 24.8004. The interval slope is (24.8004−25)/0.01 = −19.96. The exact derivative at w = 0 will be −20. The negative sign says increasing w locally lowers this example's loss.

The interval estimate is close but depends on a chosen step. Algebra can express the limiting result without choosing one. We need only three differentiation rules: the derivative of u² with respect to u is 2u; the derivative of wx+b with respect to w is x; and with respect to b it is 1. Combining a derivative of an outer expression with its inner expression is the chain rule.

2. Derive both gradient components

For example i, define eᵢ = wxᵢ+b−yᵢ. Its contribution to MSE is eᵢ²/N. Differentiate with respect to w. The outer square contributes 2eᵢ. The inner prediction contributes xᵢ. The constant 1/N remains:

∂L/∂w = (2/N) Σᵢ eᵢxᵢ

The curly ∂ denotes a partial derivative: change w while holding b fixed. For the bias, the inner derivative is one:

∂L/∂b = (2/N) Σᵢ eᵢ

Together these numbers form the analytical gradient. Notice the factor two. Some books define half-MSE, (1/2N)Σe², specifically so that the two cancels. This course uses ordinary MSE, so removing the two would change the update magnitude. It might still learn after retuning the learning rate, which makes the error easy to miss.

Calculate the complete gradient at zero

At w = 0 and b = 0, the five errors are 3, 1, −1, −3, and −5 for x values −2, −1, 0, 1, and 2. Multiply each error by x: −6, −1, 0, −3, and −10. Their sum is −20. Therefore ∂L/∂w = (2/5)(−20) = −8.

The errors themselves sum to −5, so ∂L/∂b = (2/5)(−5) = −2. With learning rate 0.1, simultaneous descent gives w = 0−0.1(−8) = 0.8 and b = 0−0.1(−2) = 0.2. These match Chapter 1's numerical step.

“Simultaneous” means both derivatives use the same old w and b. Calculate the gradient fully, store it, and only then update either parameter. If you update w inside the loop before calculating the bias derivative, later calculations describe a different point on the loss surface. That is neither the derived full-batch update nor a deliberate stochastic algorithm.

Inside gradient, the complete fold computes both named components before returning either:

let n = data.len() as f64;
let (weight, bias) = data
    .iter()
    .fold((0.0, 0.0), |(weight, bias), &(input, target)| {
        let error = self.predict(input) - target;
        (weight + 2.0 * error * input / n, bias + 2.0 * error / n)
    });

Each example contributes evidence. A positive eᵢxᵢ pushes the weight gradient upward; a negative product pushes it downward. Averaging makes the gradient convention independent of dataset length. If loss is averaged but gradients are summed, doubling a duplicated dataset unexpectedly doubles the effective step.

3. Check a derivation independently

Correct-looking calculus and correct-looking code can disagree. A finite difference supplies an independent numerical oracle. For each parameter θ, central difference computes [L(θ+h)−L(θ−h)]/(2h). The project uses h = 10⁻⁵, smooth MSE inputs, and f64.

Comparison needs a tolerance because floating-point values and the finite-difference approximation are not exact. The check accepts |a−n| ≤ 10⁻⁶ + 10⁻⁴ max(|a|,|n|), where a is analytical and n numerical. The absolute term helps near zero; the relative term scales with larger gradients. A single fixed percentage fails at zero, while a single tiny absolute tolerance can be unrealistic for large values.

Interpret a failed check

Suppose code reports analytical dw = −4 while the numerical value is −8, but db matches. The ratio and affected component are clues. A missing factor two in the weight formula produces exactly this pattern. If every component differs by a factor equal to N, inspect whether loss averages while the gradient sums. If only later parameter settings fail, inspect in-place updates, nonfinite arithmetic, or a nonsmooth operation.

A passing check is local evidence, not a proof for all inputs. Test more than the origin so accidental symmetry cannot hide a bug. The reference checks (w,b) = (0,0) and (1.3,−0.4). It rejects empty or nonfinite data before either calculation. Later networks will avoid checking at ReLU's nondifferentiable corner; this smooth line model has no such issue.

4. Build and run the analytical trainer

Read the complete reference source. Gradient names the two components so they cannot be confused with updated parameters. gradient makes one pass over the examples. numerical_gradient remains separate, deliberately slower, because its job is verification rather than training.

cargo test --manifest-path projects/ch02/Cargo.toml
cargo run --release --manifest-path projects/ch02/Cargo.toml

The small deterministic demonstration prints analytical weight = −8 and bias = −2, the matching numerical values, check: true, then parameters near weight = 2 and bias = 1 after 100 steps. These are measured properties of the bundled fixture. Final displayed zeros are rounded, and another platform may differ in final digits.

Trace the cost difference. One analytical call visits N examples once and accumulates two sums. A two-parameter numerical gradient visits N examples four times. With P parameters, naive central differences cost roughly 2PN example predictions, while reverse-mode differentiation later computes all parameter gradients at cost comparable to a small number of forward passes. This chapter's hand-derived formula is the simplest instance of that principle.

Gradient correctness is separate from optimizer success.

A verified gradient only says the local slope implementation matches the loss. A negative learning rate, an enormous positive rate, bad feature scales, or nonfinite data can still break training. Chapter 6 studies those optimization choices directly.

Worked solution

This is the body of weight_gradient in the solution file:

data.iter()
    .map(|&(input, target)| 2.0 * (weight * input - target) * input)
    .sum::<f64>() / data.len() as f64

For the two symmetric examples at weight zero, each contributes −4, so the average is −4.

Debugging · A plausible trainer learns slowly

A learner uses the deliberately broken update weight_derivative += error * input / n with ordinary MSE. The finite-difference result is exactly twice the analytical result. Explain why training may still appear to work and what to fix.

Answer

The code differentiated half-MSE while reporting MSE. Its gradient is half the required value, so a given learning rate produces half-size steps. A larger learning rate can mask the mismatch, but the claimed derivative remains wrong. Restore the factor two or explicitly redefine and report half-MSE everywhere.

Independent variation · Unsymmetrical inputs

Use points (0,1), (1,3), and (3,7). At w = 0, b = 0, calculate both derivatives by hand, then check them in code. Why is this fixture useful?

Worked answer

Errors are −1, −3, −7. Their x-products are 0, −3, −21. Thus dw = 2(−24)/3 = −16 and db = 2(−11)/3 = −22/3. Unlike the symmetric fixture, weight and bias contributions do not benefit from cancellation, so certain indexing and averaging errors become easier to see.

Check your explanations

A negative derivative says increasing that parameter slightly lowers loss. Differentiating a squared error produces 2e. Simultaneous updates must describe one shared point. Absolute tolerance handles values near zero while relative tolerance scales to larger values. A check supports agreement between two local computations on tested inputs; it does not prove good data, a suitable rate, or generalization.
