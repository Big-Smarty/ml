Why can two correct worker means give the wrong update?

Worker A has one example with gradient 6. Worker B has three examples whose gradients sum to 6, so its mean is 2. Averaging the two worker means gives 4. The four-example mean is (6+6)/4=3. Both worker calculations are correct; the reduction silently changed which examples matter.

In data parallelism, workers hold replicas of the same model and receive different examples. All replicas must begin the step with the same parameter values. Each worker computes a local gradient sum and an example count; the coordinator combines sums and divides by the total count once. Equal-size partitions can hide a wrong mean-of-means implementation because the two formulas coincide.

The fixture has four input features, four weights, one bias, and scalar targets. Prediction is ŷ=w·x+b. The mean squared error over N examples is N⁻¹Σ(ŷ−y)². One example contributes 2(ŷ−y)x to the weight-gradient sum and 2(ŷ−y) to the bias sum. The loss convention is full squared error, so removing the factor two would change the effective learning rate.

Retrieve the batch-reduction reasoning from chapters 5 and 6 before launching workers. Parallel execution cannot repair a wrong objective. Which messages make replicas agree?

A worker message contains four gradient sums, one bias-gradient sum, and one example count. A zero-example worker contributes zeros and count zero, rather than an undefined local mean. If the total count is zero, there is no training objective and the update must fail validation. Summing local counts is part of the algorithm, not bookkeeping to discard.

The teaching coordinator receives messages and orders them by worker identity for deterministic local reduction. A real all-reduce combines a contribution on every worker and returns the combined result to every worker. Its network topology, number of workers, and reduction tree affect communication and floating-point order. This CPU fixture verifies the message semantics; it implements neither an accelerator collective nor a multi-machine benchmark.

Some framework collectives average gradients across replicas. If each replica already averaged its examples, exact global-example weighting then requires compensating for unequal local counts. Do not transplant a “divide by world size” rule without specifying what was summed or averaged earlier. A serial oracle computed from the same frozen parameters makes that mistake observable.

For learning rate η=0.1, a scalar weight 2 and global gradient 3 become 1.7. The erroneous worker mean 4 gives 1.6. Comparing only final training loss could obscure this difference; compare the complete next parameter vector after one step first.

What must be summed when weights live on different workers?

Tensor parallelism partitions one operation instead of partitioning examples. Split a four-feature dot product into features 0–1 and 2–3. For x=[1,2,3,4], w=[0.5,−1,2,0.25], and b=0.1, the first shard produces −1.5 and the second produces 7. Their sum plus the bias is 5.6. Neither partial value is a complete prediction.

With target 4, the shared residual is 1.6. Each shard uses that same residual to compute its gradient components: 3.2 times its own features. The full gradient is [3.2,6.4,9.6,12.8] and bias gradient 3.2. Computing a separate residual from each partial activation would optimize two different models. Adding the bias on every shard would count it twice.

The learner file already contains a complete communicating tensor update to inspect and modify. Forward messages carry partial sums, and backward work returns gradient components to the owning shard. The coordinator applies a single bias update. Trace a shard’s feature interval through both paths; an array with two entries can represent local coordinates zero and one while its global coordinates are two and three.

Memory can decrease per worker when parameters are sharded, but required activations or partial sums still travel between workers. The relevant question is whether saved memory and computation justify that communication for the actual shape and hardware. The tiny thread example intentionally makes no throughput claim.

Why does the first stage need a message in the reverse direction?

Pipeline parallelism assigns consecutive layers to different workers. Our first stage maps one scalar input to two hidden activations hⱼ=tanh(aⱼx+cⱼ). The second predicts ŷ=v₀h₀+v₁h₁+d. It can calculate the residual after receiving h, but the first stage cannot update a or c from the forward activation alone.

Take x=2, a=0.5, c=0 for one hidden coordinate, so h=tanh(1)≈0.7616. If the shared residual is 0.3 and its output weight is 0.8, the loss derivative with respect to h is 2×0.3×0.8=0.48. The derivative before tanh is 0.48(1−0.7616²)≈0.2016, giving weight derivative about 0.4032 and bias derivative 0.2016. The second stage sends the 0.48 derivative backward; the first completes its own chain rule.

Messages retain example identifiers and the activations required for backward. All microbatches in this teaching minibatch use a frozen copy of both stages. Applying a parameter update while another example still needs its old activation derivative would mix parameter versions and defeat serial equivalence.

Microbatching can overlap stages, with idle time while the pipeline fills and drains. This simple unbounded-channel schedule sends the teaching batch forward and collects backward sums; it demonstrates communication and gradients, not a carefully optimized 1F1B schedule. Its memory use also grows with in-flight examples.

What does a checkpoint need to remember besides weights?

Suppose training has consumed minibatches zero and one. Reloading their final weights and restarting at minibatch zero repeats data and is a different computation. A resume-capable checkpoint must identify the next update: parameters, optimizer state if present, progress counters, and the data or random cursor that selects the next examples.

The local fixture uses deterministic plain SGD. There are no momentum buffers, adaptive moments, or stochastic sampling state to save. Its versioned text format stores the model, step number, and minibatch cursor. A header such as CH50v1 declares how the following fields are interpreted. Rejecting an unknown version is safer than guessing parameter order.

Do not generalize this small format to Adam by keeping only its weights. Adam’s first and second moment estimates change the next update; its step affects bias correction. Likewise shuffled data needs a reproducible sampler state, and dropout needs the relevant random state. A complete checkpoint is defined by the computation you intend to continue.

The supplied example serializes to a string and reloads in the same process. That tests representation and continuation, but does not demonstrate durable disk writes, restarting a crashed process, worker-failure detection, or agreement across different hardware. Name those missing boundaries when reporting your result.

How do you prove that an interruption changed nothing essential?

Create two copies of one initial state. Train copy A for a fixed number of minibatches without interruption. Train B partway, encode and decode it, then run the remaining minibatches. Compare the next cursor and step as well as every parameter. A checkpoint that reproduces predictions at load time can still resume from the wrong data position.

Validation rejects a malformed header, missing or extra fields, and nonfinite parameter values. A syntactically valid checkpoint can still refer to the wrong dataset; a larger application should store a data identity and configuration, as chapter 56 does. The current format’s narrow contract must be explicit.

Floating-point addition is not associative: changing worker order or reduction trees may change low bits even when mathematical sums agree. Use a justified numerical tolerance for cross-order comparisons. Deterministic same-process serialization can support a stronger equality check, but that is not a promise of bitwise equivalence across devices or compiler settings.

Before adding retries, decide whether an acknowledged step might be applied twice. Recovery protocols need a clear commit boundary. This lesson stops at validating local training state, because automatic distributed recovery would require a separate system and failure model.
