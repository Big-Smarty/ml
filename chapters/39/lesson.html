The pieces now form one honest workflow: prepare licensed bytes, keep validation separate, train every decoder weight, save complete state, reload it, and generate autoregressively. The default is tiny enough to inspect; an explicit configuration shows the exact cost of roughly fifteen million parameters.

Capstone

Run a scratch-trained dense decoder with no ML, tensor, BLAS, or autodiff dependency. The project accepts your local licensed text, measures its own throughput, evaluates untouched bytes, saves resumable checkpoints, and samples from learned logits.

Code and terminology carried forward

This capstone composes the existing APIs described by the course code and terminology guide. Chapter 36 supplies Decoder: forward(input) returns row-major logits [T,V], loss(input, targets) averages cross-entropy over T target positions, and loss_and_gradient(input, targets) returns that same mean loss with all parameter derivatives. Those calls inspect the model without updating it. Chapter 38 supplies Trainer, its public train_accumulated(data, tokens, micro_batches) update, AdamW state, and checkpoint I/O. Its private accumulate helper remains an implementation detail.

Chapter 34 remains a standalone preprocessing exercise: its private Bpe::fit, encode, and decode use u16 token IDs. This capstone does not import that type or its saved rules. 1. Define the experiment before training

The bundled training and validation documents are separate course-authored CC0 prose. They exist so the project runs offline and tests mechanisms. They are not enough text for a useful general language model. For an actual experiment, supply both --corpus TRAIN_PATH and --validation VALID_PATH pointing directly to raw byte files you may use. The CLI reads those two files with fs::read; it does not parse Chapter 37's CORPUS_AUDIT_V1 manifest or construct paths from it. Keep that manifest beside the inputs as separate provenance evidence.

let (raw_train_data, raw_validation_data) =
    if let (Some(train), Some(valid)) = (&a.corpus, &a.validation) {
        (fs::read(train)?, fs::read(valid)?)
    } else {
        (TINY.as_bytes().to_vec(), VALIDATION.as_bytes().to_vec())
    };

The program reads bytes exactly and never cuts one document into two splits. It rejects exact equality and a shared 32-byte passage between train and validation. The check stores windows from the smaller document, so very large corpora should use a streaming rolling-hash audit. A serious corpus should already be deduplicated and split by document; this guard does not replace Chapter 37's audit. Do not tune repeatedly against the final test split.

Byte IDs are 0–255, vocabulary size 256. For every T-target window x₀…xₜ, the input slice is x₀…xₜ₋₁ and the targets slice is x₁…xₜ; both have T token IDs. This teacher-forced shift, defined in Chapter 23, lets all positions train or evaluate against true preceding bytes while causal attention prevents future access. Cross-entropy is averaged over those T target tokens. Free-running generation is different: each sampled byte becomes a later input.

Build a four-target microbatch

Bytes [10,20,30,40,50] produce input IDs [10,20,30,40] and target IDs [20,30,40,50], four positions in each slice. Logit row zero predicts target byte 20 from input byte 10 and no later information. At generation time, after sampling one next byte, append it, crop to the most recent context window, and run forward again.

2. Train the complete tiny decoder

The default model uses byte vocabulary 256, context 12, width 16, two heads, one layer, and feed-forward width 32: exactly 10,896 trainable f32 parameters. The separate large configuration below has exactly 14,442,496. Chapter 36's count includes token and learned position embeddings, both normalization gains and biases, fused QKV projection and bias, attention output projection and bias, both feed-forward matrices and biases, final normalization, and output projection. AdamW updates the entire flat vector.

fn default_config() -> Config {
    Config {
        vocab_size: 256,
        context: 12,
        width: 16,
        heads: 2,
        layers: 1,
        ff_width: 32,
    }
}

Chapter 38's public train_accumulated method receives the training data explicitly and accumulates two equal microbatches per call. One call performs one optimizer step. The default --steps 40 therefore performs 40 optimizer steps and processes 40×2×12=960 target tokens. This cursor-based run does not define or report data epochs: its windows can wrap through the document, and an epoch would require a declared complete-pass boundary. The deterministic cursor persists across checkpoints. The run measures teacher-forced validation cross-entropy before and after training; a short run can overfit local patterns while validation worsens, so the code reports observed values rather than promising improvement.

Loss reduction is evidence with limits.

A lower training loss proves the optimizer found parameters better for seen windows. Lower held-out loss is stronger evidence for the selected validation documents. Neither result establishes factual accuracy, safety, or broad language competence.

Define exactly what the validation number averages

The evaluator processes non-overlapping blocks of target positions, including the final short block. Within each block it supplies the immediately preceding input bytes and computes a mean cross-entropy. It multiplies that mean by the number of targets before adding it to the total. Finally it divides by all evaluated targets. Every requested target is counted once, so an unusually short last block cannot receive the same weight as a full block.

while start < available {
    let targets_in_block = targets_per_block.min(available - start);
    let loss = model.loss(
        &validation_data[start..start + targets_in_block],
        &validation_data[start + 1..start + targets_in_block + 1],
    )?;
    weighted += loss * targets_in_block as f32;
    count += targets_in_block;
    start += targets_in_block;
}
Ok(weighted / count as f32)

Weight the final short block

Suppose a four-target block has mean loss 2 and a two-target tail has mean loss 5. The aggregate is (4×2+2×5)/6=3 nats per target. Averaging the two reported block means would instead give 3.5 and overweight the tail. Perplexity, if reported, would be exp(3), approximately 20.086. Average the token losses before exponentiating; the average of block perplexities represents a different statistic.

Block boundaries also define the available history. The first prediction in each new block receives only its first input byte, and learned positions restart at zero. This is a blockwise validation metric, not a sliding-window evaluation that retains maximum history for every target. Both can be useful, but their losses are not directly interchangeable. A context-length comparison must report this policy because changing block length changes how often history resets as well as how far attention can reach.

The token budget bounds the number of evaluated target positions, not the number of training updates. The ordinary default evaluates the available validation document; the explicit large-model smoke path caps evaluation at sixteen targets to keep its verification bounded. A sixteen-target result cannot stand in for the full held-out document. The implementation rejects zero context or zero budget rather than returning an empty average, and a regression test compares unequal block lengths against a manually weighted calculation.

Keep evaluation free of updates. The loss-only call computes logits and the scalar objective without changing parameters, moments, cursor, or RNG. Repeating it on unchanged bytes and parameters therefore measures the same predictive distribution. Sampling then uses a separate, advancing RNG state; visually different samples do not establish different model quality. The CLI saves its current state after generation, so resumed randomness starts after the samples already emitted. Record generation settings when reproducing a complete command sequence.

3. Turn logits into a continuation

Generation begins with prompt bytes. The model produces V logits at every position; use only the final row for the next byte. Sampling temperature τ divides logits before softmax. τ below one sharpens differences, τ above one flattens them, and τ must be positive.

Temperature and sampling

For logits [2,1], softmax at τ=1 gives probabilities approximately [0.731,0.269]. At τ=0.5, scaled logits are [4,2], giving [0.881,0.119]. At τ=2, logits [1,0.5] give [0.622,0.378]. Temperature changes randomness without retraining.

The sampler draws from cumulative probability with a checkpointable xorshift RNG. Greedy argmax is deterministic but can loop on locally preferred bytes. Sampling exposes distributional alternatives. Generated byte sequences may be invalid UTF-8, so the project preserves byte IDs and uses lossy UTF-8 only for terminal display.

The reference does a full forward pass for every new token. Chapter 40 caches each layer's past keys and values and checks cached logits against this oracle. Full recomputation is slower but simpler and provides a trusted equivalence target.

Inspect samples together with validation loss. A tiny byte model may learn spaces, punctuation, and short fragments while remaining unreadable. Cherry-picking one pleasing continuation is not evaluation. Fix prompt, RNG seed, temperature, and sample count before comparing checkpoints, and preserve raw bytes so display replacement characters do not hide output.

4. Save, load, and continue

Pass --checkpoint PATH to write the trainer after this command's training, evaluation, and generation. Continue from it with --resume PATH; --steps N then means N additional optimizer steps, and the output prints the stored starting step and resulting step. The Chapter 38 file contains architecture, parameters, Adam moments, optimizer configuration (including peak_learning_rate, min_learning_rate, warmup, and total-step schedule), completed optimizer step, data cursor, RNG state, and a training-ID fingerprint. It does not contain corpus bytes, paths, tokenizer rules or identity, prompt, temperature, requested generation count, executable revision, or the caller's targets-per-microbatch and microbatch-count choices. Loader checks reject truncation, dimension mismatch, trailing bytes, nonfinite floats, and invalid state.

cargo run --release --offline --manifest-path projects/ch39/Cargo.toml -- --steps 50 --checkpoint run.bin
cargo run --release --offline --manifest-path projects/ch39/Cargo.toml -- --resume run.bin --steps 50 --checkpoint run.bin

Using the same output path replaces it through a temporary sibling file and rename. When the saved training-data fingerprint is nonzero, the first resumed update checks the supplied IDs against it; loading alone and evaluation do not. A checkpoint saved before its first training update is still unbound and accepts the data supplied to its first update. Keep older generations for valuable long runs and record the executable revision, byte-tokenization rule (or an explicitly integrated tokenizer identity), dataset manifest, targets per microbatch, microbatch count, command, hardware, and compiler. The test branches after saving and compares the next public train_accumulated result and parameters exactly. Bitwise agreement across compilers, CPUs, or GPU reduction orders is not promised.

5. Build a resource budget for the roughly fifteen-million-parameter option

--large-info prints a configuration without allocating or training it: vocabulary 256, context 128, width 384, eight heads, eight layers, and feed-forward width 1536. Its exact trainable count is 14,442,496. Weight storage is 57,769,984 bytes; model plus two Adam moment buffers is 173,309,952 bytes, excluding gradients, activations, allocator overhead, GPU buffers, and checkpoint staging.

cargo run --release --offline --manifest-path projects/ch39/Cargo.toml -- --large-info
cargo run --release --offline --manifest-path projects/ch39/Cargo.toml -- --large-smoke
cargo run --release --offline --manifest-path projects/ch39/Cargo.toml -- --large --steps 1 --generate 0

--large-smoke explicitly allocates that model and performs one-token CPU forward, reporting measured elapsed time. It does not train. --large constructs the same configuration inside the real AdamW trainer and requires an explicit step budget. Its bounded verification update uses two eight-token microbatches and evaluates sixteen held-out target bytes while still differentiating all 14,442,496 parameters. A full 128-token backward step needs substantially more work and activation memory.

For actual GPU matrix products, build --features gpu and pass --gpu. This route sends forward and backward GEMMs through Chapter 30's persistent Vulkan device. Nonlinearities, attention softmax, transposes, optimizer, and storage remain host-side, with transfers around each GEMM. It is functional integration, not a claim of efficient fully resident GPU training.

cargo run --release --offline --features gpu --manifest-path projects/ch39/Cargo.toml -- --gpu --steps 20
cargo run --release --offline --features gpu --manifest-path projects/ch39/Cargo.toml -- --large --gpu --steps 1 --generate 0

Measure processed target tokens divided by timed seconds after warmup. Report hardware, dimensions, precision, context, accumulation, and feature flags. Monitor resident memory separately. Do not extrapolate the tiny run's tokens per second to the large model: matrix dimensions and transfer ratios change.

On the course validation host, one release-mode CPU update of the 14,442,496-parameter model processed sixteen target tokens in 0.215 seconds, or 74.4 tokens per second; loading its checkpoint and taking the next update took 0.212 seconds. A separate tiny GPU command completed two updates and resumed successfully. These bounded runs verify executable training and resume paths on that host. They are single smoke measurements, not stable performance benchmarks or evidence of language quality.

Budget time as well as memory. One successful large step proves the runnable path, while a meaningful experiment needs enough licensed tokens and updates to compare held-out loss. Use --generate 0 when measuring only training. Record checkpoints and stop by a predeclared validation rule. The course does not require extended large-model training.

Answer

Worked interpretation

Longer context adds position parameters and increases attention work, so it may run slower. It can use more history, but a tiny corpus may not show held-out benefit. Equal optimizer steps would process different token budgets, so compare equal target tokens.

Answers

Provenance supports lawful, reproducible input; shifting defines targets; masking blocks leakage; parameter-family checks establish gradient reach; held-out loss measures predictive fit on reserved text; next-step equivalence validates resume; round-trip load and generation test the artifact; exact counts and measured throughput bound resources.
