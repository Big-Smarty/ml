Which examples may influence each decision?

A data split gives examples a job. Training fits model weights. Validation supports choices such as the threshold and learning rate. Test evaluates the procedure after those choices are fixed. Using one dataset for all three questions rewards adaptation to its accidental details.

Can your splitter preserve a whole machine?

The baseline assigns rows by their position modulo 5. Because each machine has two adjacent rows, their remainders differ. Some visits enter training and others enter validation or test. Instead, assign the machine ID modulo 5: remainder 0 to validation,1 to test, and 2–4 to training. The deterministic rule yields 72 training rows,24 validation rows and 24 test rows.

Modulo 5 is a small teaching rule, not a universally representative split. Machine IDs might encode geography or time. In this disclosed synthetic generator, it gives an inspectable partition and a clear identity invariant. In a real dataset, choose a grouped sampling procedure that represents deployment and audit its distributions.

Can a perfect feature still be forbidden?

The dataset contains after_inspection, a bool that equals the fault label. It represents a historical field created after the inspection reveals the outcome. Using it predicts every test label correctly, even with perfectly disjoint machines. It is unavailable when the fault prediction is supposed to be made.

Leakage is information entering training, selection or evaluation that would not be available under the intended prediction conditions. The supplied report prints the forbidden feature's perfect counts beside the legitimate model to make the timeline problem concrete. The real classifier receives only sensor deviation and vibration.

Write a three-column availability table: feature, measurement time, prediction time. For each proposed feature, ask whether it exists before the decision. A column name that sounds harmless is not evidence of availability. Future repair cost, inspection outcome and time until failure are obvious traps when copied from completed historical records.

Preprocessing can leak without labels. Chapter 03's means and scales are fitted state. Fitting them on all rows lets the held-out feature distribution influence the procedure. Split first, fit on training only, then transform held-out rows with the stored statistics. Entity overlap tests do not catch this second leakage path.

Answer

No. Repeated-machine contamination, future-to-past leakage, fitted preprocessing, repeated test selection and distribution mismatch are separate issues. Which threshold best serves the stated cost?

Suppose a missed fault costs 5 units and a false alarm costs 1. Our development objective is cost=5FN+FP, selected before looking at test. For the completed test counts it is5×2+0=10, compared with 30 for always-negative. These are invented decision costs; a real application must justify its costs and operational constraints.

A threshold changes decisions, not probabilities or fitted weights. Lowering it usually catches more positives but can add false alarms. Precision need not improve monotonically as the threshold rises: inspect the actual finite sample. The Chapter 04 threshold illustration provides a small countable example.

Corresponding Rust excerpt
pub fn choose_threshold(
    validation: &[(f64, bool)],
    candidates: &[f64],
    miss_cost: usize,
) -> Result<f64, String> {
    let mut best = None;
    for &threshold in candidates {
        let cost = ch05::evaluate(validation, threshold)?.cost(miss_cost);
        if best.is_none_or(|(_, best_cost)| cost < best_cost) {
            best = Some((threshold, cost));
        }
    }
    best.map(|(t, _)| t)
        .ok_or("provide threshold candidates".into())
}

What a complete explanation includes

The cost belongs to policy selection, while BCE trained the probabilities. A higher miss penalty favors thresholds that reduce misses, but a finite candidate set and tied decisions can leave the selected threshold unchanged. The test report measures the frozen choice under a known synthetic sampling rule; it does not validate industrial deployment or probability calibration.

The stop condition is a passing split-and-policy check plus an audit report with those boundaries and residual errors. Closing a warning or obtaining high accuracy is not the learning outcome.
