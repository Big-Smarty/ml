A classifier can fit every training point and still fail when used. Evaluation is a controlled experiment: preserve examples that did not influence development, prevent hidden information from crossing boundaries, choose metrics that expose relevant errors, and compare against something simpler.

Your goal

You will audit a synthetic imbalanced classifier. The Rust project checks entity separation, chooses a threshold on validation data, computes confusion counts on untouched test data, and compares an always-negative baseline.

1. Training performance answers the wrong question

Chapter 4 classified all eight training points. That result answers whether the implementation can fit a small separable fixture. It does not answer how the fixed model behaves on new examples. Parameters were chosen to reduce training loss, so training performance is part of the optimization process rather than independent evidence.

A data split assigns examples distinct jobs. Training data fits weights. Validation data guides choices such as learning rate and decision threshold. Test data is opened once those choices are fixed. If test results cause another choice, the test has become validation data; a new independent test is needed for an honest final estimate.

Why one split cannot do every job

Suppose thresholds 0.3, 0.5, and 0.7 give test F1 values 0.62, 0.71, and 0.66. Reporting 0.71 after choosing the best is optimistic because random details of that test set influenced the choice. Choose on validation, then evaluate that fixed threshold on test. The test result may be lower; that is useful evidence about selection uncertainty, not a reason to retune on it.

Random row splitting is only appropriate when rows are independent and similarly distributed. If one patient has several visits, put the patient—not individual visits—into one split. For forecasting, train on earlier time and test on later time. The split must mimic what “new” means in intended use.

2. Stop information crossing the boundary

Data leakage occurs when development uses information unavailable at intended prediction time. Duplicate entities across splits are a direct form: the model can learn person-specific patterns and encounter the same person during evaluation. The project collects validation entity identifiers in a HashSet and rejects overlap with test identifiers.

Leakage also happens through preprocessing. Means, standard deviations, vocabularies, imputation values, and feature-selection decisions are fitted parameters. Fit them on training data, then apply them unchanged elsewhere. Even target-free use of validation features reveals the held-out distribution. A pipeline should make the fit boundary explicit.

A future-derived feature

Imagine predicting whether a customer will cancel on Monday. A field named days_until_account_closed is available in a historical table but can only be known after closure. A model may achieve spectacular test accuracy if random rows contain it, yet the feature does not exist Monday morning. This is temporal target leakage. Removing duplicate rows does not fix it; audit when each field becomes available.

A clean split does not guarantee future performance. Distribution can change, labels can be wrong, and sample sizes can be small. It does give evaluation a coherent interpretation: measured behavior on examples withheld from model development under a stated sampling rule.

3. Count errors before compressing them

A confusion matrix counts four outcomes. True positive (TP) means predicted positive and actually positive. False positive (FP) means a false alarm. True negative (TN) means correctly rejected. False negative (FN) means a missed positive. Every binary example enters exactly one cell.

Accuracy = (TP+TN)/N. Precision = TP/(TP+FP), the fraction of positive predictions that are correct. Recall = TP/(TP+FN), the fraction of actual positives found. F1 = 2PR/(P+R), the harmonic mean of precision P and recall R. Balanced accuracy averages positive recall and negative recall, giving both classes equal weight.

Audit ten test decisions

At threshold 0.5, the fixture produces TP = 1, FP = 1, TN = 7, FN = 1. Accuracy is (1+7)/10 = 0.8. Precision is 1/(1+1) = 0.5. Recall is also 1/(1+1) = 0.5. Negative recall is 7/(7+1) = 0.875, so balanced accuracy is (0.5+0.875)/2 = 0.6875.

An always-negative model yields eight correct decisions out of ten, also 0.8 accuracy, but recall zero. Accuracy alone makes a model that catches one of two positives look no better than a model that catches none.

When a denominator is zero, the project returns zero and still reports counts. That convention must be stated. Precision and recall emphasize different consequences; neither universally dominates. A medical screening system, spam filter, and fraud review queue face different costs and capacities.

4. Select decisions on validation and compare baselines

The model emits scores. A threshold converts each score into a decision: positive when score ≥ threshold. Lower thresholds usually flag more examples, tending to raise recall and lower precision. “Usually” is empirical; inspect the actual counts.

The project evaluates candidate thresholds [0.3,0.4,0.5,0.6,0.7] on validation and chooses the highest F1, breaking ties in favor of the first candidate. It selects 0.6. That threshold is then frozen for the test data. Candidate order and tie behavior are part of reproducibility.

One score changes sides

For targets [1,0] with scores [0.49,0.46], threshold 0.5 predicts [0,0], giving one FN and one TN. Threshold 0.45 predicts [1,1], giving one TP and one FP. The underlying ranking and scores did not change; the operating point traded a miss for a false alarm.

A baseline prevents empty victories. With 20% positives, always predicting the majority class gets 80% accuracy. A candidate should beat that baseline on metrics tied to the actual task. The baseline must use the same test examples and definitions.

Threshold tuning cannot rescue useless rankings, and F1 does not encode every cost. In a real project, choose an objective from requirements, examine score distributions and precision-recall curves, and estimate uncertainty. This chapter keeps one small candidate set so the selection boundary remains visible.
