What can a model learn when the input supplies the target?

Suppose four sensor coordinates tend to move together. Could two learned numbers preserve enough information to reconstruct them? An autoencoder asks exactly that question. A second experiment will ask a different one: can a representation identify a matching view among alternatives? Both learn vectors, but their objectives reward different information.

Retrieve the roles

A hidden activation is neither a class label nor a probability. It is a numerical representation consumed by a later calculation. Recall the shapes of a dense layer: weights [output features,input features], input [input features], output [output features]. Explain why a four-to-two encoder needs eight weights.

Answer

There are two output coordinates, each using a weighted sum of four inputs. Bias adds two further parameters. A two-to-four decoder has weights [4,2] and four biases.

Our encoder computes z[h]=tanh(b[h]+ΣW[h,j]x[j]), with input x of shape [4], code z of shape [2], weights W [2,4] and bias b [2]. The decoder reconstructs x̂[j]=c[j]+ΣV[j,h]z[h], with V [4,2] and c [4]. A cache stores the two code values and four reconstruction values for backward. Reconstructing a vector makes no class decision.

To see the compression arithmetic without tanh first, let x=[1,2], z=0.5×1+0.25×2=1, and decoder weights [1,2]. Reconstruction is [1,2], exactly the target. If z=0.8, reconstruction becomes [0.8,1.6], and coordinate MSE is ((−0.2)²+(−0.4)²)/2=(0.04+0.16)/2=0.10. The actual Rust model adds a tanh nonlinearity and uses four inputs and two code values.

What does a bottleneck force—and what does it leave ambiguous?

A bottleneck restricts the representation. A four-dimensional identity encoder and decoder could copy any four-dimensional input perfectly without compressing it. Reducing the code to two dimensions forces the network to choose which variations to preserve. On our six course-authored vectors, coordinates co-vary, so useful reconstruction is possible. That tiny training set is not evidence of broad transfer.

The code's axes do not automatically have human meanings. Flipping one code coordinate and the corresponding decoder weights preserves reconstruction. Different solutions may encode the same useful structure in rotated or rescaled coordinates. Evaluate what the code supports rather than naming an axis from a visually suggestive plot.

For N rows with four target coordinates each, the loss is L=Σ(x̂[n,j]−x[n,j])²/(4N). It is coordinate MSE, with no factor one half. Our row-at-a-time update differentiates Σ(x̂[j]−x[j])²/4 for one row, while the report averages those row losses over the six examples. This differs from a mean squared reconstruction norm that sums coordinates and averages only over rows; that statistic would be four times larger here.

Prediction: if the input contains a nuisance coordinate that changes randomly, does reconstruction training have any reason to ignore it? A reconstruction objective still penalizes losing that coordinate. A representation useful for classification may instead need to ignore it. Low reconstruction error answers one specific question.

Another target construction: denoising

A denoising autoencoder takes a corrupted input but compares its reconstruction with the separate clean target. The target's source is still the data, but input and target roles now contain different values. The default lab uses clean reconstruction; it does not silently claim denoising robustness.

For one row, the derivative at reconstruction coordinate j is d[j]=2(x̂[j]−x[j])/4. The derivative at code coordinate h is a[h]=ΣV[j,h]d[j]. Then tanh contributes 1−z[h]², giving δ[h]=a[h](1−z[h]²). Finally dL/dW[h,j]=δ[h]x[j] and dL/db[h]=δ[h]. Each symbol maps to an array with an explicit role; the sum over j combines every output coordinate's effect on one code value.

For a two-output hand example, let reconstruction [0.8,1.6], target [1,2], decoder column [1,2], and tanh code z=0.8. The reconstruction derivatives for MSE over two coordinates are [−0.2,−0.4]. Can the same representation recognize a matching view?

Retrieve how cross-entropy identifies one target among candidate logits. Contrastive learning uses the same machinery with a target supplied by paired data. View A[i] and view B[i] represent the same underlying item; B[j] for j≠i acts as a negative candidate for A[i]. The pairing rule declares the equivalence. If two distinct items are actually equivalent for your task, treating one as a negative can teach the wrong separation.

A shared linear encoder W [2,4] maps each view x [4] to raw vector r [2]. It then computes q=√(Σr[h]²+10⁻⁸) and e=r/q. This approximately unit-length embedding makes dot products depend mainly on direction. The small epsilon defines the zero-vector behavior. Both view sets use the same W; there are not two independently trained tables.

For anchor i and candidate j, score s[i,j]=eA[i]·eB[j]. Divide by positive temperature τ to obtain logit l[i,j]=s[i,j]/τ. For one anchor, InfoNCE is log Σexp(l[i,j])−l[i,i]. The batch averages those losses over N anchors; it does not divide by the number of candidates a second time.

For logits [2,1,−1] and positive candidate zero, subtract the maximum 2. Exponentials [1,e⁻¹,e⁻³] sum to about 1.4177. Loss is log(1.4177)≈0.3490. If candidate one is positive instead, the same normalizer applies but the loss is about 1.3490. The objective compares relative scores, not whether a raw score exceeds zero.

Lower temperature sharpens relative differences; it also enlarges derivative factors through division by τ. Temperature must be finite and positive, and a positive value can still be so tiny that arithmetic overflows. The trainer checks for nonfinite loss or gradient before applying an update. Clamping probabilities would hide the symptom and change the objective; stable log-sum-exp is the intended computation.

Why does each comparison return two derivatives?

For a batch of N anchors, the logit derivative is d[i,j]=(softmax(l[i])[j]−1[i=j])/N. The indicator is one at the paired candidate and zero elsewhere. A dot product depends on both operands: it sends d[i,j]eB[j]/τ to the anchor embedding and d[i,j]eA[i]/τ to the candidate embedding. Every candidate can receive contributions from every anchor.

Let two logits be [1,0], with the first positive. Probabilities are approximately [0.7311,0.2689], so for one anchor their derivatives are [−0.2689,0.2689]. With τ=0.5 and anchor eA=[1,0], the positive candidate receives [−0.5379,0]; the negative receives [0.5379,0]. The anchor receives a separate sum involving both candidate vectors. Omitting that second side changes the derivative of the shared model.

The baseline treats candidate representations as constants during each update. It then recomputes them with the modified shared encoder on the next iteration. This is a useful contrasting update rule, but it is not the total derivative of the displayed shared-encoder loss. The full derivative must include both uses of W.

Normalization also has a derivative. For incoming embedding gradient g, raw r and q=√(r·r+ε), the raw gradient is g/q−r(g·r)/q³. The second term accounts for the changing norm. Multiplying each raw derivative by each source feature gives a [2,4] matrix contribution. Sum contributions from both A and B before updating W.

Trace a failure before editing

A programmer normalizes in forward but returns g unchanged in backward. Even if every code has length one, is that correct?

Answer

No. The function's output may have near-unit length, but changing its raw input changes the normalizer too. Backward must differentiate that dependency. The gradient in a purely radial direction is largely removed; returning g unchanged misses that geometric effect.

Which meaning of “near” matches the downstream question?

A code supports different later computations. Euclidean distance measures coordinate separation, cosine similarity measures direction, and a dot-product recommender can reward magnitude as well as alignment. These are choices, not interchangeable definitions of a good representation. The model's normalized contrastive outputs make cosine-like comparison natural; a lookup-table recommender in Chapter 24 will deliberately use raw dot products.

Exit answers

Autoencoder targets come from the input; denoising uses a separate clean target. A bottleneck limits representation capacity but does not identify unique axes. Contrastive positives come from the pairing policy. Shared encoder gradients must include both operands of every similarity, and normalization must be differentiated. A successful six-pair retrieval run does not establish utility on new items or labels.

Chapter 23 turns a learned representation into a state carried through time. Retrieve the rule that a shared parameter accumulates derivatives from all its uses: time steps will be additional uses of the same recurrent weights.
