Labels tell a model which distinctions matter, but labels can be scarce and every task asks a different question. Representation learning creates an intermediate code from structure in the inputs themselves. This chapter runs two complete experiments: an autoencoder reconstructs vectors through a bottleneck, and a contrastive encoder identifies matching views among alternatives.

Your milestone

You will train a four-to-two-to-four autoencoder with analytic backpropagation, then train a shared linear encoder with stable InfoNCE. You will differentiate vector normalization and both sides of every contrastive pair, and keep reconstruction and retrieval results separate.

Code and terminology carried forward

Chapter 21 used forward for a model computation that retains values needed by backward, loss_and_gradient for a fused objective and derivative calculation, and learning_rate for the update setting. Chapter 22 keeps those roles. The model no longer receives a class label: the autoencoder reconstructs input features, while the contrastive model identifies each anchor's paired view. See the course code and terminology guide.

Both models retain the course method name loss; the owning model specifies its objective. Autoencoder::loss is coordinate mean squared error: it sums all squared reconstruction errors and divides by rows times four coordinates. Contrastive::loss sums one cross-entropy over all candidates for each anchor, then divides by the number of anchors; there is no extra division by candidate count. Their gradients use those same denominators. In Chapter 17, the frozen statistic mean_squared_reconstruction_norm instead sums coordinate errors within each row and divides only by the number of rows. That statistic is twice coordinate MSE for Chapter 17's two-coordinate rows, so the names remain distinct.

1. Make the input supply its own target

An autoencoder contains an encoder and a decoder. The encoder maps features x in R4 to a code z in R2. The decoder maps z back to a reconstruction x̂ in R4. In clean reconstruction, the same x supplied as input features also supplies the reconstruction target. They are two roles in the objective, even though they contain equal values. No separate class label is required.

The project computes zh = tanh(bh + Σj=1..4Wh,jxj) for h in {1,2}. It then computes x̂j = cj + Σh=1..2Vj,hzh. W has shape [2,4], V has shape [4,2], b has two entries, and c has four. For one row, reconstruction_mse(reconstruction, target) is (1/4)Σ(x̂j−xj)²:

fn reconstruction_mse(reconstruction: &[f64], target: &[f64]) -> f64 {
    reconstruction
        .iter()
        .zip(target)
        .map(|(prediction, target)| (prediction - target).powi(2))
        .sum::<f64>()
        / target.len() as f64
}

The reference calls this primitive only with fixed four-coordinate arrays, so the slices have equal nonzero length. loss(inputs) then averages those row losses across N inputs. Algebraically, the result is the sum of all squared coordinate errors divided by N×4.

Trace a tiny bottleneck

Let x = [1,2], use one code value z = 0.5×1 + 0.25×2 = 1, and decode with weights [1,2]. The reconstruction is [1,2], so MSE is zero. If z were 0.8, the reconstruction would be [0.8,1.6]. Squared errors are 0.04 and 0.16; their mean is 0.10. The code is useful for this decoder because it retains the shared scale of both coordinates.

The two-value bottleneck prevents a literal four-coordinate copy. It does not force one unique explanation. Flipping the sign of one encoder coordinate and its matching decoder weights leaves reconstruction unchanged. Rotations can also preserve a linear solution. Interpret a code by what it supports, not by assigning stories to coordinates after one run.

Autoencoder::forward returns an AutoencoderForwardCache containing z and x̂ because backward needs both. reconstruct(features) exposes only x̂, the model output for this task; neither operation makes a class decision. Backpropagation for one row starts with dL/dx̂j = 2(x̂j−xj)/4. Decoder gradients are this value times z. The code gradient sums through the old decoder weights, and tanh contributes 1−z². encoder_gradient returns the encoder derivatives of this coordinate MSE. Training preserves the decoder until those gradients have been computed.

2. Reconstruction is one test of a representation

A representation is useful relative to a later job. Reconstruction rewards every detail that contributes to input error. A classifier may want to ignore lighting, background, or sensor noise. Conversely, a representation trained to ignore color may be useless when color is the target.

The fixture has six four-value input rows. Some concentrate mass in the first two coordinates and others in the last two, with intermediate mixtures. Compressing them to two values is plausible because the four coordinates co-vary. The default run trains on all six and reports training coordinate MSE over 24 reconstructed targets. It does not evaluate on unseen vectors, so it demonstrates optimization and compression rather than generalization.

Why a wide identity is not enough

A four-dimensional linear encoder with W equal to the 4×4 identity and a matching decoder reconstructs every vector perfectly without discovering compression. With the two-dimensional code, the model must choose which variations to preserve. Even then, it can memorize six examples if nonlinear capacity is large enough. Dimension, dataset size, corruption, regularization, and downstream evaluation jointly determine what the learned code means.

Denoising autoencoders make the two roles visibly different: corrupted features enter the encoder, while the clean vector remains the reconstruction target. That can encourage stable structure instead of exact copying. The reference keeps clean reconstruction so the gradients fit on one page; an independent variation asks you to add deterministic corruption.

3. Identify a matching view among alternatives

Contrastive learning starts from paired views. In the fixture, Ai and Bi are slightly different feature vectors representing the same underlying item. Bj for j≠i supplies alternatives. A shared weights [2,4] matrix maps every view to a two-value raw vector r, then divides by √(Σr²+10−8) to obtain an approximately unit-length embedding e. Contrastive::forward retains r, its norm, and e for backward; embed returns only e. Retrieval later converts similarities into a candidate choice, so the cache and embedding are not themselves task predictions.

Cosine-like similarity is the dot product eA·eB. Divide by temperature τ = 0.2 to get logits. For anchor i, InfoNCE is log Σjexp(si,j/τ) − si,i/τ. The batch loss averages six anchors. It is ordinary multiclass cross-entropy where the correct class is the matching candidate index.

Compute one stable contrastive loss

Suppose an anchor has candidate logits [2,1,−1] and candidate zero is positive. Subtract max 2 before exponentiation: [1,e−1,e−3] sum to about 1.4177. The loss is log(1.4177) = 0.349. Equivalently, log-sum-exp of the original logits minus positive logit gives the same value. If the positive logit were 1 and the first negative were 2, the loss would be larger.

For each logit, the derivative is (softmax probability − positive indicator)/6 because the loss averages six anchors. The softmax already normalizes across six candidates; the objective does not average those logits again. A similarity depends on both its anchor and candidate embeddings. The implementation accumulates gradients into every A embedding and every B embedding, then sums both paths into the one shared encoder weight gradient. Omitting candidate gradients would optimize only half of the shared encoder's uses.

Normalization also needs a derivative. For raw r, norm q, normalized e=r/q, and incoming embedding gradient g, the exact epsilon-aware derivative is g/q − r(g·r)/q³. This projects away most gradient parallel to the vector's current direction; changing only magnitude barely changes a normalized embedding. Each raw gradient multiplies the original input coordinates to produce the shared encoder-matrix gradient.

loss_and_gradient(view_a, view_b, temperature) fuses the InfoNCE calculation with its derivative so both results share the same forward caches; fusion does not change the objective or denominator. The test keeps numerical gradients as an oracle. It perturbs one encoder weight by ±10−5 and compares central difference with analytic InfoNCE backpropagation. Training itself uses the analytic gradient for the full paired batch once per epoch, so the experiment reflects the method a larger implementation would use. Its exact signature is:

fn loss_and_gradient(
    &self,
    view_a: &[[f64; INPUTS]],

4. Run both learning experiments

Open the complete reference. The file contains two deliberately separate models because their objectives answer different questions.

cargo test --manifest-path projects/ch22/Cargo.toml
cargo run --release --manifest-path projects/ch22/Cargo.toml

The measured authoring run printed:

autoencoder reconstruction MSE 0.38879 -> 0.00252; first code [-0.635, 0.478]
contrastive InfoNCE 1.22625 -> 0.79667; paired retrieval 16.7% -> 50.0%

The autoencoder result says the two-coordinate code and decoder reconstructed these six training vectors closely. The contrastive loss says matching logits improved relative to the six candidates. Paired retrieval chooses the highest-scoring B view for each A view; three of six are correct after training. This remains training-pair retrieval, not a held-out transfer result.

Why does loss improve without perfect retrieval? Cross-entropy depends on all score margins continuously, while top-one retrieval changes only when two candidates exchange order. Several near-duplicate fixture pairs are intentionally ambiguous. A lower contrastive loss can improve confidence across many comparisons without flipping every top-ranked candidate.

The project validates finite positive learning_rate and temperature before training. It computes InfoNCE from logits using log-sum-exp, never by taking the logarithm of a clamped probability. The normalized-vector epsilon prevents division by zero but does not make nonfinite external inputs acceptable; a production loader would reject them at its boundary.

Debugging · InfoNCE becomes NaN

A learner exponentiates raw similarity divided by a very small temperature, sums probabilities, clamps each probability to 10−12, and takes a logarithm.

Answer

Large positive logits overflow before normalization. Compute log-sum-exp by subtracting the maximum logit, then subtract the positive logit. Validate that temperature is finite and positive. Clamping probabilities changes the objective and can hide the numerical cause.

Independent variation · Denoise instead of copy

Create a fixed corrupted view by zeroing one coordinate of each input, but retain the clean vector as target. Train the same autoencoder, then compare clean-target reconstruction on separately corrupted views.

Worked protocol

Freeze which training coordinates are removed, make a different deterministic corruption for evaluation, and leave architecture and optimizer unchanged. Pass corrupted features to forward while comparing its reconstruction with the separate clean target. Report coordinate MSE and its rows-times-coordinates denominator. A gain supports robustness to that corruption only; it does not establish general semantic features.

Check your answers

The original input supplies the reconstruction target. Reconstruction may preserve nuisance information and ignore class boundaries. The data/view process declares which observations represent the same item. A dot product depends on both operands. InfoNCE is a smooth training objective, while retrieval measures the actual ordering used by a candidate-selection task.

This chapter does not establish transfer to new labels, images, or large candidate sets. It shows two complete ways to learn codes without class labels and checks their gradients. In Chapter 23, a representation will become a state carried through ordered observations, and backpropagation will cross time as well as layers.

Training checks autoencoder inputs and both contrastive views for finite values. A positive temperature can still be so small that division overflows; the trainer detects a non-finite loss or gradient and returns an error before applying that gradient. Use a temperature appropriate to the similarity scale. As in classification, InfoNCE computes maximum minus positive logit before adding the logarithmic normalizer. The numerical-gradient calculations remain tests of the analytic implementation, rather than the optimizer used for training.
