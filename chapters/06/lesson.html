Diagnostic reasoning

Sharp growth on both suggests instability, such as an oversized rate or bad scaling. Diverging train/validation trends can suggest fitting training-specific variation. Neither pattern uniquely identifies a cause; a wrong loss implementation, distribution difference or noisy small sample can also affect the curves.

Why is a bigger step not just faster learning?

Use a single-weight loss L(w)=(w−2)2. At w=0 its derivative is −4. Rate 0.1 moves to 0.4, reducing loss 4 to 2.56. Rate 1 moves to 4, leaving loss 4; the next step returns to 0. Rate 1.1 moves to 4.4, increasing loss to 5.76. All three use the same correct slope.

The slope describes local behavior. A large step changes the point where the next derivative is evaluated, so it can overshoot the useful region. Scaling the learning rate does not preserve the entire path. The stable range depends on loss curvature, feature units and training procedure.

The lab compares rates 0.001,0.03 and 1 with other full-batch choices fixed. After 80 epochs, the slow run's validation MSE is about 6.2138, while the moderate run reaches 0.0244. Can a partial view of the data produce a useful update?

At w=b=0, row (−1,−1) contributes weight gradient −2, while row (1,3) contributes −6. Their two-row average is −4. A batch containing either row alone produces a different but correct gradient for that batch. A minibatch estimates an update from a subset of training rows.

With 12 rows and batch size 5, one epoch contains batches of sizes 5,5,2 and makes 3 updates. Eighty epochs make 240 updates. Full-batch training makes 80. Comparing equal epoch counts therefore compares equal numbers of row presentations, but different update counts and trajectories. Neither axis alone establishes equal wall-clock cost.

What does it mean to prefer a smaller weight?

Recall that gradients follow the chosen objective. We can modify that objective to resist extreme coefficients. L2 regularization adds λw2 to mean data loss. λ, spelled l2 in Rust, is a finite nonnegative strength. Bias remains unpenalized in this lab.

J(w,b)=MSE(w,b)+λw2;gw,total=gw,data+2λw

J names the full optimized objective; MSE remains the data-fit component. At weight 2, data gradient −3 and λ=0.1, the penalty adds 0.4. The total −2.6 moves weight upward by 0.13 at rate 0.05 instead of the unregularized 0.15. At weight −2 the penalty derivative is −0.4, so subtracting it pulls toward zero from the other side.

Add this term to the weight gradient in your minibatch trainer, using the old weight before any parameter changes. Do not add it to bias. Validate λ even when the epoch count is zero. Keep both reported curves as unregularized data MSE so training and validation use the same vertical definition.

Hint 1 · Penalize once per objective

Compute the batch-mean data gradient first, then add 2λw once. Adding it per row after averaging the other term multiplies the penalty by batch length.

Hint 2 · Check the objective independently

At a nonzero weight, central-difference the combined objective MSE+λw2. Compare it with your data-gradient component plus 2λw. Use a negative weight as well as a positive one.

Explained solution

The solution changes only the weight component before the optimizer uses the complete gradient. A short test uses constant input 0, where the model needs only a bias: L2 must not shrink that learned offset. Setting λ=0 recovers the original objective.

The shipped seed 7 minibatch run ends with validation MSE≈0.0416; adding λ=0.2 gives ≈0.0086 and shrinks weight from ≈2.0604 to ≈1.9402. This favorable result is specific to these noisy samples. Stronger shrinkage can destroy a real signal.

Does a better training objective imply better future predictions?

Generalization concerns useful performance on new examples from intended use. Optimization concerns reducing the training objective. They are related but different. L2 can deliberately increase training MSE while improving validation MSE. Lower training loss alone cannot choose its strength.

Use --l2 0, --l2 0.2 and --l2 1 to compare λ values using the same seed, rate, batch size and epochs. Print final weight, ordinary training MSE, validation MSE, and the combined training objective. Which model should be kept when validation stops improving?

A final-epoch model is not automatically the most useful observed model. An early-stopping procedure tracks the smallest validation loss and the corresponding parameters. A patience of 5 means stop after five consecutive epochs without a new lower validation loss.

Extend fit using the supplied patience field (0 disables stopping; --patience 5 requests five epochs) to remember the best validation loss, a copy of its model and the number of epochs since improvement. Update the record only when validation improves; reset patience then. Otherwise increment it. Return the saved best model when patience is exhausted, even if the latest model is worse.

Hint 1 · Save the model with the measurement

A remembered minimum loss does not identify its parameters after training has moved on. Store them together at the epoch where the loss was measured.

Hint 2 · Compare a complete trace

Print best epoch, best loss and returned-model loss. These should agree within tolerance. Returning the final model while printing the earlier best loss is a common reporting error.

Explained answer

Initialize the best record at epoch 0. After every epoch, compare validation MSE, copy the model on improvement, and stop after the chosen number of non-improving epochs.
