Quantized weights reduce model traffic, but long sequences create another pressure: every query compares with many keys. Materializing all attention scores makes memory grow quadratically with context length. This chapter computes the same causal attention output with online softmax and key tiles, checks it against a straightforward oracle, and shows how grouped-query attention reduces K/V heads.

Milestone

You will implement exact tiled attention on deterministic CPU tensors. Across several tile sizes, the result must agree with a full two-pass softmax oracle within a documented f32 tolerance.

1. Keep a simple full-attention oracle

For query Q, key K, and value V, scaled dot-product attention is softmax(QKᵀ/√d)V. The symbol d is the number of lanes in one head. Division by √d keeps dot-product magnitudes from growing unchecked as the head gets wider. Causal attention allows key position j only when j ≤ query position i.

All arrays are contiguous and token-major: Q has shape [t,Hq,d], K and V have shape [t,Hkv,d], and the output has Q’s shape. Here t counts tokens, H counts heads, and d counts lanes inside a head. The offset of lane k in head h at token i is (iH+h)d+k. Each query head has its own scores even when it shares K and V with another head.

The full oracle processes one query row and head at a time. It creates the permitted score row, subtracts its maximum, exponentiates, sums a denominator, then makes a weighted sum of values. This particular CPU oracle holds O(t) scores for one row, although the conventional batched matrix formulation materializes an H×t×t score tensor.

Stable softmax by hand

For scores [1,3,2], subtract maximum 3 to obtain [−2,0,−1]. Exponentials are about [0.1353,1,0.3679], with denominator 1.5032. Probabilities are [0.0900,0.6652,0.2447]. Subtracting a common value changes neither probability ratios nor the result, but avoids exponentiating a large positive number.

A clear oracle is valuable even when it is not the final algorithm. Tiling changes the order of floating-point operations, so bitwise equality is not expected. The test instead bounds each absolute error by 2×10⁻⁶ + 2×10⁻⁶|reference|. This absolute-plus-relative tolerance is selected for the small f32 fixtures; longer reductions need their own error study. The demo also prints maximum absolute error as a diagnostic. It also checks a causal invariant: at the first position, each query head’s output must equal the only visible value head.

2. Update softmax without seeing all scores first

Online softmax maintains a running maximum m and a shifted exponential sum ℓ. When a new score x arrives, compute m′ = max(m,x) and ℓ′ = ℓ exp(m−m′) + exp(x−m′). Start with m = −∞ and ℓ = 0.

Trace the recurrence

Process [1,3,2]. After 1, m=1 and ℓ=1. When 3 becomes the new maximum, rescale the previous unit by exp(1−3)=0.1353 and add one, giving ℓ=1.1353. Score 2 does not change the maximum; add exp(−1)=0.3679, giving ℓ=1.5032. This matches the two-pass denominator above.

Attention also needs the weighted value numerator, not only the denominator. Maintain vector o with the same head dimension as V. When the maximum changes, multiply every old component by exp(m−m′). For each new score xⱼ and value vⱼ, add exp(xⱼ−m′)vⱼ. After all visible keys, divide o by ℓ.

Rescaling is the crucial invariant. If an implementation updates m but leaves the old numerator and denominator on their previous exponential scale, it combines incomparable numbers. This bug can look harmless when scores arrive in decreasing order, because the maximum then never changes. Test an increasing score sequence.

3. Tile exact attention

A tile is a bounded block of keys and values. The reference iterates key positions in blocks of size B. It computes a small vector of tile scores, finds that tile’s maximum, merges it into the running m and ℓ, rescales the accumulated numerator, and then advances to the next block.

No approximation is introduced: every causal query-key pair is still evaluated. “Exact” here means the same mathematical dense attention, within floating-point reordering error. Tiling changes storage and memory movement, not the O(Ht²d) arithmetic count. Sparse or windowed attention changes which pairs exist and is a different method.

next_m = max(running_m, tile_max)
numerator *= exp(running_m - next_m)
denominator *= exp(running_m - next_m)
for score, value in tile:
    weight = exp(score - next_m)
    numerator += weight * value
    denominator += weight

FlashAttention applies this identity with hardware-aware blocks so score tiles stay in fast on-chip memory instead of repeatedly traveling to large external memory. Our scalar CPU loop demonstrates the recurrence and bounded score row. It does not reproduce a GPU kernel, shared-memory schedule, fused backward pass, or FlashAttention performance.

For sequence length t and H query heads, a fully materialized f32 score tensor needs 4Ht² bytes before probabilities and other activations. Doubling t multiplies that storage and pairwise arithmetic by roughly four. Tiled exact attention can avoid the quadratic intermediate, but cannot remove dense attention’s quadratic dot products.

Put scale on that formula. With H=8 and t=4,096, scores alone require 8×4,096²×4 = 536,870,912 bytes, about 512 MiB. At t=8,192 the same tensor is about 2 GiB. These are arithmetic storage estimates, not measured resident memory: an implementation also holds Q, K, V, outputs, model weights, workspace, and during training the state needed for backward. Causal masking halves useful pairs conceptually, but a naïve square allocation still reserves the full tensor.

Tile size B controls temporary score storage and locality. A tile of one minimizes that vector but adds loop overhead. A huge tile approaches the row oracle. Hardware kernels choose query and key tile shapes from available registers, shared memory, alignment, and occupancy. The correct B cannot be inferred from the recurrence alone; benchmark supported shapes on the actual device after preserving the oracle comparison. Different sequence lengths may prefer different tiles on the same machine.

4. Share keys and values across query heads

Standard multi-head attention has one key head and one value head for every query head. Grouped-query attention, or GQA, uses fewer K/V heads. If Hq query heads are divided across Hkv key/value heads, each KV head serves Hq/Hkv query heads.

Map four query heads to two KV heads

Let Hq=4 and Hkv=2. The group size is two. Query heads 0 and 1 use KV head 0; query heads 2 and 3 use KV head 1. The implementation computes kv_head = query_head / group_size. A cache that otherwise stored four K and four V heads now stores two of each, halving those vectors.

When Hkv=Hq, the mapping is ordinary multi-head attention. When Hkv=1, every query head shares one key and value head, often called multi-query attention. Shapes must be compatible; this project requires Hq divisible by Hkv.

GQA primarily reduces K/V projection parameters, decoder cache size, and cache bandwidth. It does not by itself remove each query’s comparison with each key position. Model quality depends on how the model was trained or converted. This random-tensor experiment checks mapping and arithmetic only.

Debugging · Tile size changes the answer badly

A learner resets m and ℓ at the start of every tile, then returns only the final tile’s normalized numerator. Explain the error.

Answer

Softmax normalization covers every visible key, not one tile. The state must persist across tiles, and earlier numerator and denominator terms must be rescaled when a later tile raises the global maximum.

Independent variation

Use eight query heads and two KV heads. Write the mapping for all query heads and the cache-size ratio relative to eight KV heads.

Answer

Heads 0–3 map to KV 0 and heads 4–7 map to KV 1. With equal head dimensions, K/V storage is 2/8 = one quarter of the standard eight-head cache.
