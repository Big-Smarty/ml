Chapter 25 gave us a benchmark that can tell the truth. Now we change the work it measures. Matrix multiplication performs the same products under several legal loop orders, but those orders visit memory very differently. This chapter begins with the scalar formula, measures two loop organizations, adds cache blocking, and keeps every output allocation outside the timed kernel.

Milestone

You will multiply nonsquare row-major matrices with i-j-k, i-k-j, and blocked kernels. Every version handles odd edge sizes, writes into a reused buffer, and agrees with an f64 reference before any timing is trusted.

1. One product, several traversals

Let A have shape [m,k], B shape [k,n], and C shape [m,n]. Matrix multiplication defines each output by reducing the shared k dimension:

Ci,j = Σp=0…k−1 Ai,pBp,j

Here i chooses one of m output rows, j chooses one of n output columns, and p visits the k paired values. In contiguous row-major storage, A[i,p] is a[i*k+p], B[p,j] is b[p*n+j], and C[i,j] is c[i*n+j]. The dimensions are intentionally nonsquare so a hidden transpose cannot pass by coincidence.

Multiply [2,3] by [3,2]

Let A=[[1,2,3],[4,5,6]] and B=[[1,2],[3,4],[5,6]]. C₀₀=1×1+2×3+3×5=22. C₀₁=1×2+2×4+3×6=28. The second row gives C₁₀=4×1+5×3+6×5=49 and C₁₁=4×2+5×4+6×6=64. The flat answer is [22,28,49,64]. Every optimized kernel must reproduce this mapping.

The direct i-j-p loop computes one C element at a time. Its inner loop walks one contiguous row of A, but B[p*n+j] jumps by n values as p changes. A cache line fetched for one B value contains neighboring columns that this inner loop does not immediately use.

for i in 0..m {
    for j in 0..n {
        for p in 0..k {
            c[i*n+j] += a[i*k+p] * b[p*n+j];
        }
    }
}

The formula fixes which products must contribute to each C element. It does not require one particular traversal. We can reorder independent loops as long as we initialize C once and preserve every contribution.

2. Put contiguous rows in the inner loop

The i-p-j organization loads A[i,p] once, then walks j across a complete B row and the matching C row:

c.fill(0.0);
for i in 0..m {
    for p in 0..k {
        let av = a[i*k+p];
        for j in 0..n {
            c[i*n+j] += av * b[p*n+j];
        }
    }
}

Cache locality describes access that reuses nearby or recently used data. The inner j loop has spatial locality: successive B and C offsets are adjacent. A cache line brings several useful f32 values. The A scalar stays in a local variable while it contributes across the row.

These source loops retain the same increasing p order for each output. Compiler vectorization and fused operations can still affect rounding, so the chapter compares both to an f64 accumulator with tolerance rather than asserting bit equality.

“Contiguous is faster” is a hypothesis until measured. Tiny matrices can fit in cache, and loop overhead or compiler choices may dominate. Some shapes favor transposition or packing, which this chapter does not implement. Run the Chapter 25 protocol in release mode and report observed values for your machine:

cargo test --manifest-path projects/ch26/Cargo.toml
cargo run --release --manifest-path projects/ch26/Cargo.toml
cargo run --release --manifest-path projects/ch26/Cargo.toml -- --large

The small experiment uses 37×29 times 29×31. The larger flag uses 257×259 times 259×263. Prime-like odd dimensions exercise tails and prevent a block size of 32 from dividing the problem exactly. 3. Reuse a working set before it leaves cache

Loop ordering improves the direction of access, but a large B row and C row may still exceed a nearby cache. Cache blocking, also called tiling, divides matrix axes into smaller ranges. The reference steps ii, pp, and jj by a block size, then runs the same i-p-j work inside each tile.

For block=2 and dimensions m=3, k=5, n=4, the first tile covers i=0..2, p=0..2, j=0..2. The next jj tile keeps i and p but moves to columns 2..4. When pp reaches 4, only one shared-dimension value remains. Each upper bound uses start.saturating_add(block).min(dimension), so edge tiles are smaller, even an enormous requested block cannot overflow, and no padding or out-of-bounds read is needed.

A tile aims to keep useful pieces of A, B, and C near the core while accumulating several operations. Its size is a calibration knob, not a mathematical constant. The reference uses 32 as one reasonable experiment. Real high-performance GEMM uses multiple levels of blocking, packed panels, register microkernels, architecture-specific instructions, and careful scheduling. Adding all of that would hide the central lesson; first prove whether this single tile level helps your actual shape.

Why edge arithmetic stays exact

For n=7 and block=4, jj takes values 0 and 4. The first inner j range is 0..4, four columns. The second is 4..min(8,7)=4..7, three columns. Together they cover each column exactly once. The same reasoning applies independently to m and k, so an odd 3×5 times 5×7 test exercises partial tiles on all three axes. The test also uses usize::MAX as a block to prove saturating bounds safely reduce it to each dimension.

Blocking can lose. A tile that is too small adds loop overhead; one too large behaves like the unblocked kernel. Cache topology, simultaneous threads, matrix shapes, and other live data affect the best size. Keep the benchmark and tune from evidence rather than naming one universal block.

4. Reuse storage so the kernel comparison stays clean

Each kernel accepts &mut [f32] for C. The caller allocates that vector once. Before multiplication, the kernel calls fill(0.0) because both i-p-j and the blocked form add contributions into existing values. Forgetting the reset silently mixes the current result with the previous repetition.

Allocation reuse separates memory ownership from repeated computation. Training repeatedly creates activations and gradients of known shapes; inference repeatedly writes outputs for similar batches. Holding a correctly sized buffer avoids allocator work and makes latency more predictable. It does not mean stale values may survive. Overwrite every output or clear accumulators at a deliberate boundary.

The timer includes c.fill(0.0) because zero initialization is required by these accumulating kernels. It excludes allocating C because all variants can reuse it. If an application genuinely allocates on every request, measure that end-to-end path separately. Fair comparison requires identical boundaries.

The project’s shape guard checks positive dimensions, checked products, and exact slice lengths before indexing. Block size zero is rejected before step_by. These checks are outside the inner arithmetic and protect the public boundary without putting a branch on every multiply.

5. Practice locality without losing correctness

Guided exercise: reorder the loops

Open ch26_01.rs. Implement i-p-j traversal for the worked 2×3 and 3×2 matrices.

Hint 1

Clear C, then make i the outer loop and p the middle loop. Save A[i,p] before entering j.

Hint 2

Inside j, add av * b[p*n+j] into c[i*n+j].

Solution
for i in 0..m {
    for p in 0..k {
        let av = a[i*k+p];
        for j in 0..n { c[i*n+j] += av*b[p*n+j]; }
    }
}

The assignment must be += because each p contributes one term to the same output.

Worked checkpoint

Test blocks 1, 4, 16, and usize::MAX on m=3, k=5, n=7. Block 1 is slow but structurally useful; 4 creates partial edges; 16 creates one tile larger than every axis; the maximum value checks overflow-safe bounds. All must match the same f64 reference.

Debugging: blocked answers are too small

A learner calls c.fill(0.0) inside the pp loop. Why does only the last part of each dot product remain?

Answer

The shared k dimension is split across pp tiles. Each tile contributes a partial sum to the same C entries. Clearing inside pp erases earlier partial sums. Initialize C once before any tile loop, then accumulate through every pp range.

Independent variation: calibrate the block

For the large flag, try block sizes 8, 16, 32, 64, and 128. Run each under identical conditions and write down median and range.

Worked answer

There is no predetermined winner. Choose the fastest stable median for that machine and shape only if the ranges support the difference. If two overlap heavily, report that the experiment cannot distinguish them. A production kernel may need shape-specific or architecture-specific selection, but one measured constant is enough for this course project.

6. Review and transfer

Retrieve: Which index is the reduction axis? Why does i-j-p stride through B? What does i-p-j reuse? How do partial tiles avoid out-of-bounds access? Why is clearing C inside pp wrong? Which allocation is excluded from the kernel timer?

Answers

p reduces the shared k dimension. Holding j fixed while p changes jumps by n through B. The reordered loop reuses one A scalar while walking adjacent B and C values. Each tile ends at the minimum of its nominal end and the dimension. pp tiles are partial sums, so only one clear may precede them. C is allocated once by the caller and reused across repetitions.

These kernels remain scalar and single-threaded. They establish correct traversal, edges, and measurement before adding concurrency. In Chapter 27, independent batch rows become thread shards for both inference and gradient calculation.

The benchmark prints m, k, n, precision, architecture, operating system, one execution thread, warmup count, and sample count. Timing includes the same shape checks and output clearing for each kernel. In the conventional names ijk and ikj, k denotes the shared reduction index; the implementation names that loop variable p because k already stores the shared dimension length.
