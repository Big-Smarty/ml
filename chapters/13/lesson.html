Real tables arrive with blank cells, words, repeated entities, and timestamps. The dangerous part is often not turning them into numbers. It is deciding which rows are allowed to teach that conversion. This chapter builds a preprocessor whose fitted state comes only from training data.

The goal

You will split by group and time, learn a numeric median and category vocabulary from training rows, and apply that fixed state to held-out rows. The project uses a four-row local fixture so every transformation can be inspected.

1. Split before learning anything

Earlier chapters separated training from evaluation. Preprocessing belongs inside the same boundary because it can learn from data. Choosing a median, discovering category names, selecting features, and estimating scale all create fitted state. If held-out rows influence that state, information crosses the evaluation boundary. This is data leakage.

Consider numeric training values [10, missing, 14] and one held-out value 100. Ignoring the missing entry, the training median is (10 + 14)/2 = 12. If all rows are combined before the split, the median of [10, 14, 100] is 14. The held-out value changed how a training row will be represented. Even without using its label, evaluation data influenced the learned pipeline.

The correct order

  1. Assign whole rows to training and held-out subsets using the deployment structure.
  2. Call fit on training rows only. It records median 12 and categories blue, red.
  3. Call transform with the same fitted state on both subsets.
  4. Fit the predictive model on transformed training rows and evaluate once on transformed held-out rows.

The held-out category green does not become a new feature during evaluation. Otherwise feature shape and meaning would depend on the test set.

The distinction between fit and transform is central. fit learns state. transform applies state without changing it. A production request should use exactly the state fitted during training. Recomputing a median from a single request or inventing new columns at inference changes the model input.

A validation set may guide model and preprocessing choices, but a final test set must remain untouched until choices are fixed. Cross-validation repeats the rule inside each fold: fit preprocessing on that fold’s training portion and transform its validation portion. Preprocessing the entire dataset before cross-validation leaks information across every fold.

2. Missing is information about measurement

A missing value is not automatically zero. Zero may be a valid temperature, balance, or count. Missingness means no value was recorded, and the reason can matter. A sensor can fail, a field can be optional, or a test may be ordered only for severe cases. Ask what generated the blank before choosing a numerical treatment.

Imputation replaces a missing entry with a usable value. Median imputation is robust to large outliers and simple to reproduce. Sort the present training values. With [2, 4, 100], the median is 4. For an even count [2, 4], this chapter averages the two middle values to obtain 3.

Transform a missing row

The fitted training median is 12. A training or held-out row with a missing numeric value becomes two features: numeric value 12 and missing indicator 1. An observed value 14 becomes [14, 0]. The indicator lets a later model distinguish “really measured as 12” from “unknown and replaced by 12.”

The indicator is useful when the fact of missingness relates to the target, but it does not make biased missing data harmless. If values are absent for reasons that change after deployment, the relationship learned from the indicator may fail. Multiple imputation and models with native missing-value handling can represent more uncertainty, but their fitting must still stay inside the training boundary.

The reference rejects a training set with no observed numeric values because it cannot learn a median. It also rejects nonfinite numbers. Quietly converting a NaN to a plausible default makes upstream corruption difficult to detect.

3. Categories need a stable vocabulary

Category strings such as red, blue, and green are names, not magnitudes. Assigning red = 1, blue = 2, green = 3 would imply an order and distances the data did not provide. One-hot encoding instead creates one binary feature per category learned during fitting.

Encode with training categories

Suppose sorted training vocabulary is [blue, red]. A blue row maps to [1, 0], a red row to [0, 1], and unseen green maps to [0, 0]. Combined with numeric value and missing indicator, a green row with observed value 100 becomes [100, 0, 0, 0]. Every transformed row has the same four features in the same order.

Mapping unknown categories to all zeros is a deliberate policy matching a common encoder option. It means “none of the categories known during training,” not “blue.” Another policy can reserve an explicit unknown column. Choose it during training and record it with the model; do not add the column only when an unknown appears.

High-cardinality identifiers are especially risky. One-hot encoding a customer ID often encourages memorization, creates a huge sparse feature space, and fails on new customers. If the ID identifies a group that will recur in deployment, separate entity modeling may be appropriate. If evaluation concerns new customers, use the ID to form the split rather than as a feature.

Category frequencies, rare-category grouping, and target encoding also learn from data. Target encoding is particularly leak-prone because it uses labels; it needs out-of-fold values for training rows and training-only statistics for held-out rows. The compact project stays with a stable vocabulary so the leakage boundary is visible.

4. Groups and time define believable tests

A random row split assumes rows are exchangeable for the intended claim. That assumption fails when one entity contributes several rows. If the same patient appears in train and test, a model can exploit patient-specific patterns. A grouped split assigns every row from a group to one side.

Group arithmetic

Rows have groups [A, A, B, C]. Holding out C yields three training rows and one test row. Holding out A yields two training rows and two test rows. The unit of independence is the group, so uncertainty estimates and cross-validation folds should also respect groups.

Time adds direction. When a system trains on past records to predict future records, evaluation must do the same. A temporal split with cutoff 4 sends times 1, 2, and 3 to training and time 4 to evaluation. Randomly putting time 4 into training while testing on time 2 lets the model learn from the future.

Time splits may also need a gap. Imagine features finalized seven days after an event while the target window begins immediately. Rows close to the boundary can share partially overlapping information. Excluding a gap between training and evaluation can better reproduce the real information delay.

Sometimes both constraints apply: predict future activity for unseen stores. Then the split must enforce future ordering and group isolation. There is no universal helper that understands the deployment claim automatically. Write the claim first: “train on stores and dates available by day D; evaluate later dates from stores not used for fitting.” Then test that split invariants hold.

Labels can leak through time.

A column may be recorded at row time but only become known after the prediction moment. Define an availability timestamp for each feature. A chronological row split alone does not prevent using information that arrives too late.

5. Build the Rust preprocessor

The project’s Row stores Option<f64> for the numeric field, a category, a group, a time, and a label. The label is kept out of transform output. Preprocessor::fit collects present values, sorts them with f64::total_cmp, computes the median, then sorts and deduplicates category strings.

let mut categories: Vec<String> = rows.iter()
    .map(|r| r.category.to_owned()).collect();
categories.sort();
categories.dedup();

Sorting makes column order deterministic. A hash set would find unique names, but iteration order would not define a stable feature layout. The returned vector is contiguous row-major feature data for one row: first numeric value, then missing indicator, then category columns in recorded order.

group_split and time_split return references so the source rows are not duplicated merely to decide membership. The small demonstration then copies its training references into a vector because fit accepts a slice of rows. In a larger implementation, an iterator-based fit could avoid that copy, but this fixture does not justify another abstraction.

Read the complete reference, then run:

cargo test --manifest-path projects/ch13/Cargo.toml
cargo run --manifest-path projects/ch13/Cargo.toml

The test plants value 999 and category secret exclusively in the held-out group. It verifies that fitted median remains 3 and vocabulary remains [a, b]. That is a direct leakage check: it fails if fitting happens before splitting.

The default fixture is course-authored and tiny. For an optional extension, obtain Auto MPG from the UCI repository, preserve its CC BY 4.0 attribution, record your checksum, and define the split yourself. Do not treat repository order as an official evaluation split.

Hint 1

Option distinguishes observed Some(value) from missing None.

Hint 2

The standard library method unwrap_or returns the contained value or a supplied fallback.

Worked solution
value.unwrap_or(training_median)

The median is passed in because it was fitted earlier on training rows. Recomputing it inside this function would require access to other rows and weaken the fit/transform boundary.

Exercise B · Guided checkpoint

Complete projects/ch13/starter/src/main.rs and run cargo test --manifest-path projects/ch13/starter/Cargo.toml. Then add the even-count median rule and an error for no observed values.

Progressive hints

Collect with filter_map, sort by f64::total_cmp, and index len()/2. For an even length, average the values immediately below and at that index.

Worked answer

For [2, missing, 6, 4], present sorted values are [2, 4, 6], so the median is 4. The missing entry contributes no numeric value during fitting; during transform it receives 4.

Debugging · Great validation, bad deployment

A team one-hot encodes all data, randomly splits rows, and sees excellent accuracy. Each account appears many times. Identify two leaks and repair the procedure.

Answer

The vocabulary was fitted before the split, and account-specific rows crossed the boundary. First assign complete accounts to folds. Inside each fold, fit the category vocabulary and all other preprocessing on training accounts only, then transform validation accounts. If deployment is future-facing, add temporal ordering too.

Independent variation · Add an unknown column

Change the encoder so transformed rows include one final unknown-category bit. Work out red and green vectors before coding when vocabulary is [blue, red].

Worked answer

With columns [blue, red, unknown], red maps to [0, 1, 0] and unseen green maps to [0, 0, 1]. The feature count is fixed at fit time: the unknown column exists even when no training row uses it.

Retrieve without looking: Why is median calculation fitting? What does all-zero one-hot output mean here? When is a group split needed? Why can chronological order still leak?

Answers

The median summarizes training data and changes with the sample. All zeros means a category outside the fitted vocabulary. Group splits keep correlated entity rows together. Chronological rows can still contain features whose values became available after the prediction moment.

This project handles one numeric and one categorical column to make state visible; it is not a general CSV system. In Chapter 14, the resulting numeric vectors feed two classifiers with very different assumptions.
