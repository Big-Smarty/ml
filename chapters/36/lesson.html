Assemble a pre-normalized decoder block

Let X have shape [T,D]. Add token embeddings and learned position embeddings to form the initial hidden rows. A block computes U=X+Attention(LN₁(X)), then Y=U+FFN(LN₂(U)). This is a pre-normalized block because layer normalization enters each learned branch before its projection. A final layer normalization precedes the output projection.

A residual connection combines an identity shortcut with a learned branch. If y=x+f(x), backward sends upstream gradient dy directly along the identity shortcut and also through f; those contributions add. The shortcut is one path, while the residual connection names the complete branch-and-sum operation. Omitting the identity contribution can make early layers nearly untrainable. The addition requires identical [T,D] shapes.

The feed-forward network acts independently at every position: FFN(x)=GELU(xW₁+b₁)W₂+b₂. The code uses the tanh approximation GELU(x)=½x[1+tanh(√(2/π)(x+0.044715x³))] and differentiates that same approximation. W₁ is [D,F], where F is the wider hidden size, and W₂ is [F,D]. It changes features within a position; attention exchanges information between positions.

Trace shapes through one block

For T=3, D=4, two heads, and F=8, token plus position embeddings are [3,4]. QKV projection uses [4,12] weights and yields [3,12], split into three [3,4] matrices. Each head has width two and a [3,3] causal probability matrix. Concatenated attention context is [3,4]. FFN first yields [3,8] and then [3,4], so both residual additions are defined. Output weights [4,V] produce [3,V] logits.

Where does token order enter the network?

A token embedding tells the model which byte occupies a row. Learned position embeddings tell it which row that is within the current window. If token a has embedding [0.2,−0.1] and positions 0 and 1 contribute [0.01,0.03] and [−0.04,0.02], the two initial rows are [0.21,−0.07] and [0.16,−0.08]. Identical tokens can therefore begin with distinct representations. The causal mask restricts visible positions; it does not itself supply a learned coordinate for each position.

The supplied decoder.rs::forward_with gathers token and position rows, calls your block once per layer, then final normalization and the vocabulary projection. Projection weights use [input,output] storage for compatibility with the existing reference. The earlier dense [output,input] convention is its transpose; the mathematical map is unchanged.

Why normalize features separately for each token?

Retrieve: a mean is a sum divided by a count. For [1,3], mean is 2 and population variance is 1. Ignoring only the tiny ε, normalized values are [−1,1]. Applying gain [2,0.5] and bias [1,−1] gives [−1,−0.5]. A second token computes its own mean; no time or batch dimension is mixed.

Normalize features within each token

Layer normalization computes statistics across a single row's D features. For row x, μ=(1/D)Σxⱼ, variance=(1/D)Σ(xⱼ−μ)², inverse standard deviation r=1/√(variance+ε), and output yⱼ=γⱼ(xⱼ−μ)r+βⱼ. Gain γ and bias β are trainable vectors [D]. The implementation uses ε=10⁻⁵.

Normalize two features

For x=[1,3], μ=2 and variance=[(−1)²+1²]/2=1. Ignoring tiny ε, normalized x̂=[−1,1]. With γ=[2,0.5] and β=[1,−1], output is [−1,−0.5]. Statistics for another token row are computed separately; sequence positions do not share a batch mean.

Backward receives gy. Let q=gy⊙γ and x̂=(x−μ)r. Then gx=r[q−mean(q)−x̂ mean(q⊙x̂)]. Gain gradient sums gy⊙x̂ over token rows, and bias gradient sums gy. The project includes a focused finite-difference test of this formula on non-symmetric inputs.

Normalization parameters are easy to forget when building a hand-managed parameter buffer. The model's named spans enumerate both γ and β for every block and the final normalization. Gradient checks cover representative identifiable parameter families; a parameter may legitimately receive zero gradient on a particular input.

How do mean and variance change the derivative?

An affine transform alone gives input gradient upstream×gain. LayerNorm is different because each input feature also changes the row’s mean and variance, so it influences other outputs. Set x̂=(x−μ)/√(variance+ε), q=upstream×gain and r=1/√(variance+ε). Then dx=r[q−mean(q)−x̂ mean(q×x̂)]. Gain and bias gradients sum upstream×x̂ and upstream over rows. The terms are elementwise except the explicitly named row means.

Store all trainable state in one checked buffer

Decoder owns a contiguous f32 parameter vector and a deterministic layout. Matrices use row-major [input features, output features]. This orientation lets activations [rows,input] multiply weights directly. Q, K, and V weights occupy one [D,3D] matrix with columns ordered Q then K then V. Some individual parameters can have zero gradient by symmetry—for example, a shared shift in key bias cancels inside softmax—so tests check identifiable representative paths rather than demanding every scalar move.

The parameter inventory is token embedding [V,D], position embedding [C,D], twelve spans per layer, final normalization gain and bias, output weight [D,V], and output bias [V]. Both projection biases and normalization vectors train. No attention weights are frozen, and the output head is not the only learned component.

Config::parameter_count uses checked arithmetic before allocation. For vocabulary 256, context 128, D=384, eight heads, eight layers, and F=1536, the exact count is 14,442,496. That is roughly 14.4 million decimal parameters. At four bytes per f32, weights alone require 57,769,984 bytes. AdamW later adds two equally sized moment buffers before counting gradients and activations.

The public parameter_spans() names every range for serialization and later controlled extensions. trace() exposes per-layer Q, K, V, and causal probabilities for inspecting this model. Chapter 40 instead reuses the decoder and its parameter spans while implementing its own incremental KV-cache path. Public raw mutable parameters are an expert boundary: checkpoint loaders validate lengths and finiteness before copying values.

Derive the parameter count and the prediction contract

Count one block by tensor shape rather than by its name. Fused QKV contributes 3D² weights and 3D biases. Attention output contributes D² weights and D biases. Two layer normalizations contribute four length-D vectors. The first feed-forward projection contributes DF weights and F biases; the second contributes FD weights and D biases. Adding these terms gives 4D²+2DF+9D+F parameters per layer. Head count changes how features are partitioned, but not these matrix sizes when total width D stays fixed.

Outside the blocks, token embeddings contribute VD, learned positions CD, final normalization 2D, vocabulary weights DV, and vocabulary bias V. Total count is therefore 2VD+CD+2D+V+L(4D²+2DF+9D+F). Token embeddings and vocabulary weights are separate trainable arrays: tying them would remove one VD term and require their gradient contributions to be combined. The present library does not tie them.

For the three-position shape example with V=5, C=3, D=4, F=8, and one layer, the block count is 64+64+36+8=172. The outside count is 40+12+8+5=65, for 237 parameters. Changing the number of input rows within the allowed context changes activation sizes, but leaves these 237 parameters unchanged. Changing configured context changes the learned position table and therefore the count.

The loss API accepts two equally long slices. It does not shift targets internally. A caller with tokens [1,4,2,7] supplies input [1,4,2] and targets [4,2,7]. The second output row (index 1) sees input tokens 1 and 4 and predicts target 2. Supplying the input itself as targets trains reconstruction of already visible tokens, an easier objective that does not test next-token prediction. Shape validation cannot detect that semantic mistake; construct a small explicit window as an integration check.

loss_and_gradient fuses loss evaluation with backpropagation because both need the same intermediate values. forward_cached records those values in private caches; the public forward method returns logits and discards them. The training data remains explicit as input and targets on every loss or gradient call, and neither operation updates parameters.

The private cross_entropy_with_gradient_from_logits(logits, targets, rows, v) helper returns (f32, Vec<f32>): mean cross-entropy over the target rows and derivatives with respect to the logits. Its dimensions and targets have already been validated by the model. These are intermediate logit derivatives, distinct from the parameter derivatives returned by loss_and_gradient.

For stable loss, let m be the largest row logit. Compute log(Σ exp(zⱼ−m))+(m−z_target), keeping the final difference grouped. Equal logits of 100,000,000 should still produce log(V). Adding log(V) to that large number before subtracting the target can round away the entire normalizer in f32. The regression test checks this shared-offset invariance. This transformation cannot recover distinctions already lost when logits were rounded, nor make arbitrarily large arithmetic representable. Forward and loss boundaries reject nonfinite results.

The activation derivative must match the chosen approximation too. Set u=√(2/π)(x+0.044715x³). Differentiating the implemented GELU gives ½(1+tanh(u))+½x(1−tanh²(u))√(2/π)(1+3·0.044715x²). Using the derivative of a different GELU formula would test the wrong function. This derivative multiplies the upstream feed-forward gradient element by element before the first projection is reversed. No derivative changes the stored parameter until the complete backward pass has finished.

How does the feed-forward branch finish the decoder?

The feed-forward branch transforms each position independently: normalize U, project D→F, apply the tanh GELU approximation to each value, project F→D, and add U. For a scalar x=0, GELU is 0 and its derivative is 0.5. The branch mixes features, while attention mixes sequence positions. Matching the implemented GELU approximation matters when deriving its gradient.

Backpropagate tensors in reverse order

Cross-entropy produces a [T,V] logit gradient averaged over T targets. The output projection backward computes dW=HᵀG, db=row-sum(G), and dH=GWᵀ. Final layer-normalization backward returns gradient to the last block.

Inside a reversed block, split the residual gradient: one copy travels directly to U and one enters the second projection. For FFN, dW₂=AᵀdY, dA=dY W₂ᵀ, multiply by GELU's derivative, then dW₁=NᵀdZ and dN=dZ W₁ᵀ. Normalize backward and add its result to the direct residual copy.

The attention branch follows the same pattern around Chapter 35's backward equations. Output projection produces context gradient. Each head derives dV, softmax-score gradient, dQ, and dK. Concatenate those into dQKV, compute the fused projection's weight, bias, and input gradients, pass through the first normalization, then add the block's identity gradient.

After all layers, hidden gradient reaches the input sum. Add each row to its selected token-embedding row and its position row. Repeated token IDs use +=; assignment would discard all but one occurrence.

Follow one residual scalar

If upstream gradient at one feature is 0.7 and the learned branch contributes input gradient −0.2, the preceding hidden state receives 0.7+(−0.2)=0.5. If that token occurs twice and the other position contributes 0.3, its shared embedding row accumulates 0.8. These additions are the small arithmetic behind the vector loops.
