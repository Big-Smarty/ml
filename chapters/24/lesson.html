What does it mean to recommend an unseen item?

Recommendation asks for an ordered list, and the relevant items differ by user. Our tiny catalog has four users and six items. We know two positive interactions for each user, reserve one additional positive for evaluation, and supply explicit negative examples. The task is to rank the held-out item above those negatives without training on its user–item pair.

Run just lab 24. Its working baseline trains item vectors while keeping user vectors fixed. Training loss falls from about 0.69065 to 0.62627, but held-out Recall@2 falls from 3/4 to 2/4. This is a real failure to learn useful shared user structure, not a broken executable. Retrieve the representation's role

Chapter 22 computed an embedding with an encoder. Here an ID selects a learned table row, an embedding. User ID 3 is not numerically “closer” to user 2 than user 0 in a way the model should assume. IDs are addresses; their selected vectors are numerical features.

The user table P has shape [4,2]; the item table Q has shape [6,2]. User u's raw preference score for item i is s(u,i)=P[u,0]Q[i,0]+P[u,1]Q[i,1]. Two factors mean two learned coordinates per row. This score is used for ordering; it is not a probability and has no calibrated universal scale.

For user vector [1,2], item A=[0.5,0.2] scores 0.5+0.4=0.9. Item B=[−0.1,0.4] scores −0.1+0.8=0.7. A ranks first. If both user and item vectors are rotated by the same orthogonal transformation, their dot products remain the same. Individual factor axes therefore need not have a unique human interpretation.

How can sparse interactions support a full score matrix?

Every user–item score is one row dot product. Arranging them in a [4,6] matrix gives PQᵀ: P [4,2] multiplied by Qᵀ [2,6]. This is matrix factorization: a larger relationship matrix is represented through two smaller shared tables. Users who prefer overlapping items can influence the same item vectors, which can help predict an unobserved relationship for another user.

Our training positives are: user 0 likes items 0 and 1; user 1 likes 0 and 2; user 2 likes 3 and 4; user 3 likes 3 and 5. Held-out positives are respectively [2,1,5,4]. The first two users share one item group and the last two another. No equation tells the optimizer these group names; the interaction structure supplies the evidence.

A missing interaction does not automatically mean dislike. A person might never have seen the item, might have had no opportunity to interact, or might have ignored it for an unrelated reason. Implicit-feedback systems need a stated exposure, confidence or negative-sampling policy. Our fixture uses three explicit negatives per user: [3,4,5] for users 0–1 and [0,1,2] for users 2–3. This avoids silently inventing labels from missing cells.

Would an item vector trained for user 0 be forbidden from influencing user 1's held-out prediction? What exactly must remain excluded?

Answer

Sharing the same item vector across users is the collaborative mechanism. The specific held-out (user,item) interaction must not appear as that user's positive or negative optimization example. An item can legitimately have training interactions with other users.

Cold start remains unresolved by this lookup-only model. A genuinely new user or item has no learned row supported by interactions. Side-information encoders, popularity priors or explicit onboarding are different model/design choices. More factors alone do not create missing evidence.

Train all three vectors to improve one ordering

A pairwise ranking triple (u,i,j) says user u prefers positive item i to negative item j. Define margin d=s(u,i)−s(u,j). The data loss is softplus(−d)=log(1+exp(−d)); it falls when the positive outranks the negative more strongly. We add λ times the squared norms of the three selected vectors. Thus one triple's loss is softplus(−d)+λ(‖p‖²+‖qᵢ‖²+‖qⱼ‖²), where p=P[u], qᵢ=Q[i] and qⱼ=Q[j].

Let a=sigmoid(−d). The gradients are −a(qᵢ−qⱼ)+2λp for the user, −ap+2λqᵢ for the positive item and +ap+2λqⱼ for the negative item. All three use the old vectors. The scalar a is an ordering derivative factor, not a calibrated recommendation probability.

For the earlier scores 0.9 and 0.7, d=0.2, data loss≈0.5981 and a≈0.450166. With λ=0, old user [1,2], positive [0.5,0.2], negative [−0.1,0.4], the gradients are [−0.270100,0.090033], [−0.450166,−0.900332] and [0.450166,0.900332]. At learning rate 0.1, subtract a tenth of each gradient from its corresponding vector. The user becomes about [1.02701,1.990997]. Item updates must still use old [1,2], not this new user vector.

Which candidates make a held-out score meaningful?

Retrieve the chronological-target boundary from Chapter 23. The same discipline now concerns user–item pairs instead of time. One held-out positive per user never enters that user's positive or negative training triples, training loss or stopping decisions. It must not be sampled as a negative merely because it is absent from the fitting table.

Evaluation ranks exactly four candidates for each user: that one held-out positive plus three explicit negatives. Already observed training positives are excluded. This is neither full-catalog ranking nor a large randomly sampled candidate test. The candidate set defines the difficulty and must accompany the metric.

For user 0, training positives are 0 and 1, held-out positive is 2, and explicit negatives are 3,4,5. The evaluation list contains [2,3,4,5] before sorting. Item 2 can be a training positive for user 1, but neither (0,2,negative) nor (0,positive,2) may be optimized.

Candidate IDs are sorted by descending score with item ID as the deterministic tie-breaker. Keeping IDs attached matters: sorting only scores would lose the information needed to look up relevance. The fixed arrays contain unique valid IDs. The supplied triple validator rejects empty or invalid closed-fixture triples before training; no external interaction-file parser is part of this lab.

What do recall, precision and rank discount actually count?

Let R be a nonempty set of relevant candidate IDs for one user and TopK the first k returned candidates. Recall@k is |R∩TopK|/|R|. Precision@k is |R∩TopK|/k. Compute these per user, then average across users. The denominator is part of the metric: users with more relevant items should not silently receive more weight unless that weighting is explicitly intended.

Our fixture has one relevant item per user. If it appears in the top two, recall is 1 and precision is 1/2. Under this special condition Recall@k equals HitRate@k, which asks only whether there is any hit. With three relevant items and one hit, recall is 1/3 but hit rate is 1.

Normalized discounted cumulative gain, nDCG, also rewards early rank. For binary relevance, DCG@k sums 1/log₂(r+2) at each relevant item whose zero-based rank r is below k. Ideal DCG is the same sum with all relevant items placed first, up to k. Divide actual DCG by ideal DCG. Using one-based rank instead requires r+1 inside the logarithm; do not mix indexing conventions.

One relevant item at first rank gives nDCG@2=1. At second rank it gives 1/log₂3≈0.6309. Across those two users, Recall@2 averages to 1, Precision@2 to 0.5, and nDCG@2 to (1+0.6309)/2≈0.8155. Recall and precision tie between the users while nDCG distinguishes their ordering.

The learner baseline reports normalized cumulative gain without a rank discount, labelled gain@2 (baseline nCG; goal nDCG). It can count retrieved relevance but cannot distinguish first from second. The source and report label make this a declared simpler metric, not a silently incorrect nDCG implementation.

A parameter that cancels

Consider extending the score to μ+bᵤ+bᵢ+p·qᵢ. Derive the same-user margin before adding code. Which bias parameters survive?

Answer

Global μ and user bias bᵤ cancel in s(u,i)−s(u,j). Item biases remain as bᵢ−bⱼ, with data derivatives −a and +a. A parameter useful for absolute rating prediction can be unidentifiable from a same-user pairwise objective.
