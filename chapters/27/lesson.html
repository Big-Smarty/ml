Transfer: why can a mutex-protected single output vector be race-free yet still lose to disjoint slices?

Answer

A mutex serializes protected access and adds synchronization. Disjoint slices encode ownership once and allow independent writes. False sharing and memory bandwidth can still limit performance even without a data race; these tiny tests do not measure either.

What does a fixed reduction order guarantee?

Goal: state the exact reproducibility boundary. A worker may finish first or last without changing its place in the handle vector. Joining and reducing in creation order fixes the grouping for that partition. A mutex around a shared total does not: acquisition order depends on scheduling, and floating-point addition is not associative.

This deterministic reduction removes scheduling-dependent grouping for a fixed partition, target, and build. Changing thread count can change grouping; different compiler flags, fused operations, CPUs, or vector widths can also change rounding. Fixed order does not promise bitwise identity across all those environments. Tolerance-based scalar agreement remains the numerical contract.

Run the same fixed-thread check twice and compare outputs. Then change the worker count and compare within tolerance. Values may happen to match exactly on these fixtures; that observation is weaker than a general guarantee.
