The embedding model saw only one preceding token. Language depends on several earlier positions, and different positions matter for different predictions. Causal self-attention learns a content-dependent weighted mixture while preventing the target from leaking into its own input.

Goal

Implement scaled dot-product attention and its full Q, K, and V backward pass. A finite-difference test checks every element on a smooth hand-computed fixture.

Code and terminology carried forward

Chapter 34 turned text bytes into token IDs and recovered the exact bytes by decoding those IDs. Token IDs are discrete addresses, so they cannot enter a dot product directly. A complete language model first looks up an embedding for each ID and applies learned projections. This standalone checkpoint begins after that preparation: callers supply flat row-major f64 query, key, and value arrays directly. It therefore checks the attention operation without claiming to train embeddings or projections.

The project carries forward row-major arrays and reverse-mode backward from Chapter 9, and stable row softmax plus the distinction among logits, probabilities, and a predicted class from Chapter 33. Here the scaled query-key scores are logits only for choosing source positions. Softmax returns one probability distribution per query row; it does not return a predicted token class. In Chapter 33, probability minus one-hot target was a gradient with respect to token-class logits. Here probability_gradients means the derivative of a later objective with respect to attention probabilities A. The exact naming, shapes, and reductions follow the course code and terminology guide.

1. Ask, match, and retrieve

For T positions and feature width D, arrange embedded input rows in X with shape [T,D]. Under the course's [out_features,in_features] dense-weight convention, three learned [D,D] projections would produce Q=XWQT, K=XWKT, and V=XWVT, each [T,D]. The reference does not implement these projections; its queries, keys, and values arguments are Q, K, and V. A query describes what the current position seeks. A key describes what each source position offers for matching. A value carries information to retrieve if that source receives probability.

Separating keys and values matters. Similarity decides where to look; values decide what comes back. One key can strongly match a query while its value carries a feature unrelated to the matching coordinates. Later, multiple heads repeat this operation in narrower feature slices.

Two positions, width two

Take q₀=[1,0], q₁=[0,1], k₀=[1,0], k₁=[1,1], v₀=[2,0], and v₁=[0,4]. Dot products for q₁ are q₁·k₀=0 and q₁·k₁=1. Divide by √2, giving scores 0 and 0.7071. Their exponentials are 1 and about 2.028. The normalized probabilities, also called attention weights, are 0.330 and 0.670. The weighted value is 0.330[2,0]+0.670[0,4]=[0.660,2.680].

The scale 1/√D controls score magnitude. If query and key coordinates have roughly unit variance, their dot product variance grows with D. Large logits push softmax toward nearly one-hot outputs with tiny gradients. Scaling does not guarantee good conditioning, but it removes that predictable width dependence.

Multi-head attention divides total width D among H heads. Each head uses d=D/H coordinates and its own 1/√d scale. Heads form separate [T,T] probability matrices, retrieve separate value slices, then concatenate back to [T,D]. A learned output projection mixes those features. Width must divide evenly by head count. The reference implements one head, so its width argument is the single head width used in the denominator.

S = QKᵀ / √D,   A = softmaxrow(S),   O = AV

S and A have shape [T,T]. Row i scores every key j for query i. O has shape [T,D]. Softmax operates independently across each permitted row, so each row's probabilities sum to one. The weighted-value sum reduces over permitted source positions j but preserves the query-position and feature axes.

2. Mask information from the future

During next-token training, all positions are processed in parallel. Without a mask, the representation at position i could read token i+1, which is exactly the target it is asked to predict. Training loss would collapse through leakage and generation would fail because future tokens do not exist then.

A causal mask permits key j only when j≤i. Conceptually add negative infinity to forbidden scores before softmax, making their probability exactly zero. The reference computes only permitted scores and leaves forbidden probability cells at zero. The mask restricts source-position probabilities, not predicted-token classes. Self-attention includes the current input token; a later language-model loss uses the following token as its target.

Why masking before softmax matters

Suppose row scores are [2,1,100], but position 2 is future. Mask first: softmax over [2,1] gives approximately [0.731,0.269,0]. If you softmax all three and then set the last probability to zero, the remaining weights are nearly zero and no longer sum to one. Renormalizing afterward can recover the forward numbers but complicates the backward contract. Exclude forbidden logits from both normalization and gradient.

3. Reverse the weighted mixture

Let G be output_gradients, the derivative of any later scalar objective with respect to O. Because O=AV, matrix-product derivatives give ∂objective/∂V=AᵀG and ∂objective/∂A=GVᵀ. A value row can influence several later queries, so AᵀG sums those paths. backward returns these as AttentionGradients::value_gradients, alongside query_gradients and key_gradients; every field has the same [T,D] shape as its corresponding input.

For one permitted softmax row a, let gA=∂objective/∂a be its probability-gradient row. The score gradient is ds=a⊙(gA−(gA·a)1). The symbol ⊙ means elementwise multiplication. The dot product subtracts the component that would change all logits equally; softmax probabilities are unchanged by a shared shift. Masked score gradients remain exactly zero.

Finally, S=QKᵀ/√D gives dQ=dS K/√D and dK=dSᵀQ/√D. If Q, K, and V came from one X, their three input gradients later add. With the [output,input] projection weights defined above, their gradients are dQᵀX, dKᵀX, and dVᵀX. Chapter 36 stores the transposed [input,output] representation, so its corresponding gradients are XᵀdQ, XᵀdK, and XᵀdV. Compute these gradients before updating any weight used in them.

Backpropagate a weighted scalar

For one attention row with a=[0.25,0.75], values [2,6], output is 5. If upstream gradient is 1, dV=[0.25,0.75] and dA=[2,6]. The dot dA·a is 5. Thus dS=[0.25(2−5),0.75(6−5)]=[−0.75,0.75], before the score scale. Increasing the second score shifts weight toward value 6 and raises the output, so its positive sign is sensible.

Carry the two-position example backward

Use the earlier two-feature values and define a scalar probe objective that selects only the second coordinate of the final attention output. Its upstream gradient at query one is [0,1], while query zero receives [0,0]. Write a for the first probability, approximately 0.330238, and b=1−a, approximately 0.669762. The scalar output is 4b, approximately 2.67905. This choice makes the sign of each derivative interpretable: increasing attention to the second value should increase the objective. It is not the next-token cross-entropy used to train a language model.

The two value gradients are a[0,1] and b[0,1]. Thus the first coordinates of both values have zero derivative, even though the values themselves are nonzero. The probability gradients are dot([0,1],[2,0])=0 and dot([0,1],[0,4])=4. Their probability-weighted mean is 4b. Applying the softmax rule gives dS=[−4ab,4ab], approximately [−0.884724,0.884724]. Their sum is zero. A shared increase in both scores cannot change which value is preferred.

Now include the scale exactly once. With k₀=[1,0] and k₁=[1,1], dQ₁=(−4ab k₀+4ab k₁)/√2=[0,4ab/√2], approximately [0,0.625594]. The first coordinate cancels because both keys have the same first coordinate. Key gradients from this query are dK₀=−4ab q₁/√2 and dK₁=4ab q₁/√2. Because q₁=[0,1], only their second coordinates change. This is a useful nontrivial cancellation, not evidence that the backward pass skipped a feature.

The first causal row contains a single probability equal to one. Its softmax derivative is exactly zero: a perturbation of its only score cannot alter that probability. If the objective also selected an output coordinate in this row, its value gradient would be nonzero, but its query and key score gradients would still vanish. Later rows can nevertheless contribute to key zero and value zero, which explains why shared source rows must accumulate gradients with addition.

Translate the reasoning into flat indices before optimizing. Probability Aᵢⱼ lives at iT+j; a key feature Kⱼd lives at jD+d. The dK loop fixes a source row j and sums contributions from permitted query rows i≥j. The dQ loop fixes i and sums permitted sources j≤i. Both use the same score derivative, but exchange the roles of the outer and inner position indices. A transpose bug often looks like replacing one of these sums with the other.

The standalone reference deliberately accepts Q, K, and V directly. It verifies this attention operation, including its derivatives, without claiming that projection weights were trained here. Chapter 36 adds those projections and the surrounding residual network. Keep that boundary clear when interpreting a passing gradient check: it establishes the operation actually tested, while integration tests establish the paths around it.

4. Check the whole chain numerically

Manual attention backward has several transpose and indexing opportunities for error. The test-only attention_probe_objective computes P=Σi,zOi,zGi,z, where G is a fixed non-symmetric upstream matrix. This is a sum over all T×D output elements, with no mean denominator. Its derivative with respect to O is exactly G. For every Q, K, and V element θ, central difference estimates [P(θ+ε)−P(θ−ε)]/(2ε). P is not Model::loss: this project has no model or token targets, and it does not compute the next-token cross-entropy introduced in Chapter 33.

#[cfg(test)]
fn attention_probe_objective(
    queries: &[f64],
    keys: &[f64],
    values: &[f64],
    positions: usize,
    width: usize,
    output_gradients: &[f64],
) -> f64 {
    let output = causal_attention(queries, keys, values, positions, width).output;
    assert_eq!(output.len(), output_gradients.len());
    output
        .iter()
        .zip(output_gradients)
        .map(|(value, gradient)| value * gradient)
        .sum()
}

The chapter 35 project uses f64 and ε=10⁻⁵ on a three-position, two-feature fixture. Each derivative must agree within absolute tolerance 10⁻⁶ plus relative tolerance 10⁻⁴ times the numerical derivative's magnitude. The fixture avoids dropout and nondifferentiable operations. Its values are deliberately non-symmetric so swapped rows or transposes cannot accidentally pass.

Read projects/ch35/src/main.rs. causal_attention stores the probability matrix needed by backward. The default run prints probabilities, outputs, and gradient norms for the two-position arithmetic above. The test perturbs every element in all three inputs.

A gradient check compares an implementation against the local derivative of the implemented forward function. It does not prove the forward function represents the intended architecture. That is why the independent causal test changes future keys and values and checks the first output exactly.

Also inspect invariants. Every permitted probability row should sum to one within tolerance, every forbidden entry should be exactly zero in this implementation, and the bounded fixture inputs should produce finite outputs. These checks localize failures faster than a final loss mismatch. A transpose error can still produce plausible numbers, so use non-symmetric fixtures.

When a check fails, compare one row at a time: raw dot products, scaled scores, allowed maximum, exponentials, normalized weights, and weighted values. The first differing stage usually identifies the faulty index or transpose.

One further test distinguishes numerical agreement from correct scaling. It doubles the fixed upstream matrix and checks that every analytical gradient doubles while attention probabilities stay unchanged. This follows from the summed linear probe objective. A gradient routine that accidentally averages or normalizes its upstream input would violate that relationship.

Use f32 tolerances later.

Chapter 36 uses f32 for a model that can scale to millions of parameters. Rounding grows with accumulation length, so its finite-difference epsilon and tolerance are looser. Copying the f64 threshold would create flaky or meaningless failures.

6. Review and transfer

Explain the roles and shapes of Q, K, V, S, A, and O. Why divide by √D? Where is the mask applied? What does backward consume and return? Why does a value gradient sum contributions from later rows? How does the derivative probe differ from next-token cross-entropy? What two kinds of tests establish confidence?

Answers

Q, K, V, and O are [T,D]; scores and probabilities are [T,T]. Scaling limits predictable dot-product growth. Mask scores before row softmax. backward consumes Q, K, V, cached probabilities, and output gradients, then returns query, key, and value gradients with [T,D] shapes. A value may be retrieved by many permitted queries, so reverse paths add. The probe sums O⊙G only to make attention derivatives measurable; next-token cross-entropy compares model logits with target token IDs. Finite differences check derivatives, while causal invariance checks intended information flow.
