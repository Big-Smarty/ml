What changes when actions collect the data?

In supervised learning, an example usually contains an input and desired target, and training compares the model's prediction with that supplied target. In reinforcement learning, the learner is an agent inside an environment. At time t it observes state st, chooses action at, receives reward rt+1, and moves to state st+1. The policy π(a|s) specifies the probability of choosing each action in a state. A return combines the reward after the chosen action with later discounted rewards; learning seeks high expected return.

The reward is evidence about a consequence, not a correct-action label. If an agent chooses left and receives zero, that does not necessarily prove right was better; right was not observed. Actions also change later evidence. This feedback creates two problems absent from a fixed labeled table: exploration decides what data is collected, and delayed rewards must be credited to earlier actions.

A one-step decision

Suppose a machine has three settings. Their unknown probabilities of success are 0.15, 0.55, and 0.85. Pulling one setting returns reward 1 on success and 0 otherwise. A single reward of 1 from setting zero does not make its true value one. Repeated samples estimate its mean. There is no next state, so this is a multi-armed bandit.

The program uses a small deterministic pseudorandom generator so the fixture repeats exactly. The generator is part of simulation control, not security. A fixed seed lets a failing test be reproduced, but one seed cannot characterize a stochastic algorithm. A serious experiment repeats independent seeds and reports variation.

How can exploration correct a lucky first estimate?

For arm a, keep a count N(a) and value estimate Q(a). After selecting it and receiving R, update the sample mean without retaining every earlier reward:

N(a)←N(a)+1Q(a)←Q(a)+R−Q(a)N(a)

The bracketed term is a prediction error. If two Bernoulli rewards were 0 and 1, Q is 0.5. If the third reward is 1, the update is 0.5+1−0.53=23. Expanding the arithmetic gives the same sample mean: 0+1+13=23.

Always choosing the largest current Q exploits present knowledge but can lock onto a lucky early arm. An epsilon-greedy policy explores with probability ε and otherwise chooses a largest estimate. Exploration samples uniformly from all actions. With three arms and ε=0.1, the greedy arm is chosen with probability 0.9+0.13, while each other arm gets 0.13.

The following excerpt is the selected-action update inside train_bandit; reward sampling occurs between action selection and the count update.

let action = if rng.next_f64() < epsilon {
    rng.index(means.len())
} else {
    argmax(&estimates)?
};
counts[action] += 1;
estimates[action] += (reward - estimates[action]) / counts[action] as f64;

The reference breaks ties by the first maximum. That makes behavior deterministic but favors the first arm before exploration supplies evidence. Optimistic initial values or randomized tie breaking are other choices. They alter early data collection, so they belong in an experiment record.

Training action selection is not evaluation.

A fixed ε continues to choose random actions even after values are accurate. Report the learned greedy action separately from reward obtained while exploring. How does delayed reward reach an earlier state?

A bandit cannot represent a consequence that arrives several steps later. Our chain has states 0 through 4. State 4 is terminal. Right increments the state, left decrements it but stops at zero. Every nonterminal move costs −0.02; entering state 4 gives reward 1. The short policy chooses right in states 0, 1, 2, and 3.

An action value Qπ(s,a) is the expected discounted return beginning with the immediate reward after taking the specified action a in state s, then following policy π. Q-learning learns the values of a greedy target policy while an epsilon-greedy behavior policy gathers transitions. We discount the next estimate by γ=0.95, then form the target:

target=r+γmaxa′Q(s′,a′)

For a terminal next state, target is only r. There is no future action to bootstrap. The update moves the old table entry a fraction α toward the target. In the Rust interface, α is learning_rate and γ is discount_factor:

Q(s,a)←Q(s,a)+α[target−Q(s,a)]

One Q-learning update

Let Q(s,right)=0.20. A right move gives reward 1, the next state's largest action value is 0.50, γ=0.90, and α=0.10. The target is 1+0.9×0.5=1.45. The temporal-difference error is 1.45−0.20=1.25. The new value is 0.20+0.10×1.25=0.325. If the next state were terminal, omitting the bootstrap would give 0.28 instead.

Behavior is epsilon-greedy, while the target uses the greedy maximum even when the observed next action may later explore. That difference makes Q-learning off-policy. The reference anneals ε from about 0.27 toward 0.02 over 600 episodes and uses a constant α. These convenient finite-run choices do not satisfy every assumption in the tabular convergence theorem, which requires continuing visits and suitable step sizes.

The table is [[f64; 2]; 5]. Its row is a state, its column is left or right. An enum converts actions to columns, avoiding unexplained numeric action constants throughout the transition code. environment_step is one transition in the simulated chain and never changes model parameters. The subsequent Q-table update changes one learned value. Keeping those operations distinct makes terminal handling easy to test independently.

fn q_update(
    old_value: f64,
    reward: f64,
    best_next_value: f64,
    done: bool,
    learning_rate: f64,
    discount_factor: f64,
) -> f64 {
    let target = reward
        + if done {
            0.0
        } else {
            discount_factor * best_next_value
        };
    old_value + learning_rate * (target - old_value)
}

How can reward change action probabilities directly?

Tables choose a greedy action only after estimating scalar expected returns for state-action pairs. A policy gradient instead changes parameters that directly produce action probabilities. Our two-action policy has logits θ0 and θ1: these are unrestricted learned scores, not Q-values or probabilities. Stable softmax maps logits [2] to normalized probabilities [2] whose sum is one.

fn softmax2(logits: [f64; 2]) -> [f64; 2] {
    let maximum = logits[0].max(logits[1]);
    let values = [(logits[0] - maximum).exp(), (logits[1] - maximum).exp()];
    let sum = values[0] + values[1];
    [values[0] / sum, values[1] / sum]
}

REINFORCE uses the identity ∇logπ(a) to turn a sampled action and return into a gradient estimate. For a softmax logit θi, the derivative is I(i=a)−pi: one minus probability for the chosen action, and negative probability for every other action. With advantage A, ascent is:

θi←θi+ηA[I(i=a)−pi]

Here η denotes the optimizer learning_rate. If p=[0.5,0.5], action 1 is selected, reward is 1, and the baseline is 0.2, then A=0.8. At η=0.1, θ1 increases by 0.1×0.8×0.5=0.04 and θ0 decreases by 0.04. The next softmax assigns action 1 more probability. If the reward is below the baseline, A is negative and the same selected action becomes less likely.

The reference's reward probabilities are 0.2 and 0.8. Each episode contains one action, so its observed reward is also its complete return. The code samples an action and its Bernoulli reward, computes advantage from the baseline carried from earlier interactions, then updates that baseline for the next interaction. It applies one optimizer update to both logits using the already computed advantage, the old probabilities, and learning_rate = 0.08. Computing advantage before the baseline update keeps the baseline independent of the current sampled action conditional on the past. This is an actual policy-gradient training loop: the action came from the current policy, and the update is the sampled log-probability derivative. After 5,000 seeded episodes, action 1 receives about 0.998 probability.

A baseline reduces variance but must not depend on which action was sampled in a way that biases the expected gradient. Our single scalar moving average is deliberately simple. Multi-step REINFORCE uses a discounted return-to-go for each visited time. A return-to-go at time t is Gt=rt+1+γrt+2+γ2rt+3+⋯ until termination. An episode is one such trajectory, and a baseline depending on the visited state is permitted if it remains independent of the action selected there. Value networks and advantage estimators improve practicality later, but they are not needed to verify this core calculation.

Why freeze the policy that collected a PPO batch?

REINFORCE above updates once from each freshly sampled action. Proximal Policy Optimization, or PPO, collects a batch under one policy and reuses it for several gradient updates. A ratio compares the current probability of a collected action with its probability when collected. That denominator must remain frozen across the batch’s update epochs. Our two-action, one-step simulator runs the clipped policy objective, without a learned critic or language decoder.

Suppose an action had old probability 0.5 and now has probability 0.8. Its ratio is 1.6. With positive advantage 1 and clip width ε=0.2, the raw contribution is 1.6 but the clipped contribution is 1.2. PPO maximizes the smaller, 1.2, so pushing farther in that favorable direction contributes no gradient through this term. With negative advantage −1 and ratio 0.4, the raw contribution is −0.4, clipped is −0.8, and the smaller is −0.8: excessive favorable reduction of a bad action is also clipped.

Write A for the collected advantage, ρ for current/old probability ratio, and ε for the clipping width. The objective contribution is min(ρA,clip(ρ,1−ε,1+ε)A). These letters name fixed numerical quantities from the example. In the active unclipped region, its derivative with respect to current action probability is Aold_probability. Multiply by the softmax probability derivative to obtain the logit gradient; in a clipped region, this contribution’s derivative is zero.
