A retrieved answer can be judged after it is produced, but Chapter 44 did not let that judgment change the next decision. Reinforcement learning closes that loop: an agent acts, observes a consequence, and changes how it will act later. We will build the loop three times—first without state, then with a table of states, and finally with a differentiable policy.

The concrete goal

A deterministic Rust program will identify the best uncertain bandit arm, learn the shortest direction through a five-state chain, and train an actual stochastic policy with REINFORCE. These are small simulations whose arithmetic can be inspected. They establish implementation mechanics, not real-world agent performance.

1. Learning from consequences

In supervised learning, an example usually contains an input and desired target. In reinforcement learning, the learner is an agent inside an environment. At time t it observes state st, chooses action at, receives reward rt+1, and moves to state st+1. The policy π(a|s) specifies the probability of choosing each action in a state.

The reward is evidence about a consequence, not a correct-action label. If an agent chooses left and receives zero, that does not necessarily prove right was better; right was not observed. Actions also change later evidence. This feedback creates two problems absent from a fixed labeled table: exploration decides what data is collected, and delayed rewards must be credited to earlier actions.

A one-step decision

Suppose a machine has three settings. Their unknown probabilities of success are 0.15, 0.55, and 0.85. Pulling one setting returns reward 1 on success and 0 otherwise. A single reward of 1 from setting zero does not make its true value one. Repeated samples estimate its mean. There is no next state, so this is a multi-armed bandit.

The program uses a small deterministic pseudorandom generator so the fixture repeats exactly. The generator is part of simulation control, not security. A fixed seed lets a failing test be reproduced, but one seed cannot characterize a stochastic algorithm. A serious experiment repeats independent seeds and reports variation.

2. Estimate while exploring

For arm a, keep a count N(a) and value estimate Q(a). After selecting it and receiving R, update the sample mean without retaining every earlier reward:

N(a) ← N(a)+1    Q(a) ← Q(a) + [R−Q(a)] / N(a)

The bracketed term is a prediction error. If two Bernoulli rewards were 0 and 1, Q is 0.5. If the third reward is 1, the update is 0.5 + (1−0.5)/3 = 2/3. Expanding the arithmetic gives the same sample mean: (0+1+1)/3 = 2/3.

Always choosing the largest current Q exploits present knowledge but can lock onto a lucky early arm. An epsilon-greedy policy explores with probability ε and otherwise chooses a largest estimate. Exploration samples uniformly from all actions. With three arms and ε = 0.1, the greedy arm is chosen with probability 0.9 + 0.1/3, while each other arm gets 0.1/3.

let action = if rng.next_f64() < epsilon {
    rng.index(means.len())
} else {
    argmax(&estimates)?
};
counts[action] += 1;
estimates[action] += (reward - estimates[action]) / counts[action] as f64;

The reference breaks ties by the first maximum. That makes behavior deterministic but favors the first arm before exploration supplies evidence. Optimistic initial values or randomized tie breaking are other choices. They alter early data collection, so they belong in an experiment record.

Training action selection is not evaluation.

A fixed ε continues to choose random actions even after values are accurate. Report the learned greedy action separately from reward obtained while exploring. The bundled test asks whether arm 2 has the largest estimate after 8,000 seeded interactions; it does not claim every run will make the same finite-sample estimate.

3. Add states with tabular Q-learning

A bandit cannot represent a consequence that arrives several steps later. Our chain has states 0 through 4. State 4 is terminal. Right increments the state, left decrements it but stops at zero. Every nonterminal move costs −0.02; entering state 4 gives reward 1. The short policy chooses right in states 0, 1, 2, and 3.

An action value Q(s,a) estimates return after taking action a in state s. Return combines future rewards. We discount the next estimate by γ = 0.95, then form the target:

target = r + γ maxa′ Q(s′,a′)

For a terminal next state, target is only r. There is no future action to bootstrap. The update moves the old table entry a fraction α toward the target:

Q(s,a) ← Q(s,a) + α[target − Q(s,a)]

One Q-learning update

Let Q(s,right)=0.20. A right move gives reward 1, the next state's largest action value is 0.50, γ=0.90, and α=0.10. The target is 1 + 0.9×0.5 = 1.45. The temporal-difference error is 1.45−0.20 = 1.25. The new value is 0.20 + 0.10×1.25 = 0.325. If the next state were terminal, omitting the bootstrap would give 0.28 instead.

Behavior is epsilon-greedy, while the target uses the greedy maximum even when the observed next action may later explore. That difference makes Q-learning off-policy. The reference anneals ε from about 0.27 toward 0.02 over 600 episodes and uses a constant α. These convenient finite-run choices do not satisfy every assumption in the tabular convergence theorem, which requires continuing visits and suitable step sizes.

The table is [[f64; 2]; 5]. Its row is a state, its column is left or right. An enum converts actions to columns, avoiding unexplained numeric action constants throughout the transition code. The environment transition is a pure function, which makes terminal handling easy to test independently.

4. Optimize the policy itself

Tables choose a greedy action only after estimating values. A policy gradient instead changes parameters that directly produce action probabilities. Our two-action policy has logits θ₀ and θ₁. Stable softmax subtracts their maximum and returns probabilities p₀ and p₁.

REINFORCE uses the identity ∇ log π(a) to turn a sampled action and return into a gradient estimate. For a softmax logit θᵢ, the derivative is I(i=a)−pᵢ: one minus probability for the chosen action, and negative probability for every other action. With advantage A, ascent is:

θᵢ ← θᵢ + η A [I(i=a) − pᵢ]

If p=[0.5,0.5], action 1 is selected, reward is 1, and the baseline is 0.2, then A=0.8. At η=0.1, θ₁ increases by 0.1×0.8×0.5=0.04 and θ₀ decreases by 0.04. The next softmax assigns action 1 more probability. If the reward is below the baseline, A is negative and the same selected action becomes less likely.

The reference's reward probabilities are 0.2 and 0.8. It samples both an action and its Bernoulli reward, computes advantage using the baseline from earlier interactions, and adjusts both logits from the old probabilities. It also updates the moving baseline for the next interaction. Computing advantage before that baseline update keeps the baseline independent of the current sampled action conditional on the past. This is an actual policy-gradient training loop: the action came from the current policy, and the update is the sampled log-probability derivative. After 5,000 seeded episodes, action 1 receives about 0.998 probability.

A baseline reduces variance but must not depend on which action was sampled in a way that biases the expected gradient. Our single scalar moving average is deliberately simple. Multi-step REINFORCE uses a discounted return-to-go for each visited time. A return-to-go at time t is Gt=rt+1+γrt+2+γ²rt+3+⋯ until termination. An episode is one such trajectory, and a baseline depending on the visited state is permitted if it remains independent of the action selected there. Value networks and advantage estimators improve practicality later, but they are not needed to verify this core calculation.

Trace the three blocks separately. The bandit updates only the selected arm's sample mean. Q-learning updates only the visited state-action cell using a next-state maximum. REINFORCE updates both logits because changing one softmax logit changes the normalization of both actions. Conflating these update rules is a common source of plausible-looking but incorrect code.

Debugging · Values grow past plausible returns

A terminal transition uses target 1.0 + gamma * max_next. Its Q values keep exceeding one. What is wrong?

Answer

The terminal state has no continuation. Bootstrapping from an arbitrary terminal row invents future reward. Set the terminal target to the observed reward. Initializing the terminal row to zero hides the bug temporarily, so a strong test fills that row with nonzero sentinels and confirms they are ignored.

Independent variation · A costly shortcut

Add an action in state 0 that jumps directly to state 4 with reward 0.70. Keep γ=0.95. Predict whether it beats four right moves whose intermediate costs are −0.02 and final reward is one, then train and inspect the learned choice.

Worked answer

The four-step discounted return is −0.02 + 0.95(−0.02) + 0.95²(−0.02) + 0.95³(1) = 0.800325 ≈ 0.800. It exceeds 0.70, so the longer route should win after enough exploration. This calculation also reveals whether your code applies discount once per transition.
