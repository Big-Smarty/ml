1. When does GPU inference become GPU training?

Chapter 30 moved matrix arithmetic to a GPU. Training requires a longer dependency chain: forward activations must survive until backward uses them; gradients must use the same parameter version as that forward pass; update must run only after every gradient is ready. Copying each intermediate to Rust would be correct but would abandon the main benefit of GPU training.

The project trains a fixed 2-4-1 network on eight course-authored XOR-like points. Two inputs feed four tanh hidden units, which feed one sigmoid probability. Inputs, weights, hidden activations, logits, gradients, and loss history remain in storage buffers across 800 steps. Rust records forward, backward, and update passes in order, then reads final weights and losses.

Residency is a data-flow claim.

A shader that computes one operation is not automatically resident training. Device residency means dependent tensors stay in GPU-accessible buffers between operations. The reference maps nothing inside the training loop.

2. Work through one nonlinear example

For hidden unit j, input x = [x₀,x₁], input weights wj,0,wj,1, and bias bj:

hj = tanh(wj,0x₀ + wj,1x₁ + bj)

The output logit is z = bo + Σj=03 vjhj, and probability p = 1/(1+e−z). Four hidden units let the model bend a decision boundary; one linear unit cannot represent XOR.

One forward and backward contribution

Suppose x = [−1,1], one hidden activation is h = 0.5, its output weight v = 0.4, the final probability is p = 0.6, and label y = 1. The output-logit derivative is δo = p−y = −0.4. This example contributes −0.4×0.5 = −0.2 to ∂L/∂v. Its hidden preactivation derivative is δh = δov(1−h²) = −0.4×0.4×0.75 = −0.12. Contributions to the two input weights are δhx₀ = 0.12 and δhx₁ = −0.12.

Loss is mean binary cross-entropy over N = 8 examples. Compute it directly from logit z:

L = (1/N) Σ[max(z,0) − zy + log(1 + exp(−|z|))]

This logit-space loss remains finite at z = ±1000 and differentiates exactly to p−y. Clamping a rounded probability while continuing to use p−y would make the displayed loss and gradient describe different objectives.

3. Order forward, backward, and update

The forward kernel launches one invocation per example. Each invocation reads two features and seventeen shared weights, writes four hidden activations and one logit, and never mutates parameters. Its bounds guard handles the partial 64-lane workgroup.

The teaching backward kernel uses one invocation. It clears seventeen gradients, loops over eight examples, accumulates chain-rule contributions, divides by N, and writes that epoch's mean loss. This is intentionally serial: it provides a transparent correctness bridge. A throughput implementation would parallelize examples and reduce private partial gradients, using chapter 30's cooperative ideas.

The update kernel performs θq ← θq − ηgq for each of seventeen parameters q with learning rate η = 0.3. Rust records three separate compute passes. This kernel ordering is the global synchronization. A workgroup barrier cannot coordinate separate dispatches.

forward → writes hidden, logits
backward → reads hidden, logits, old weights; writes gradients, loss
update → reads gradients; writes weights

All 801 loss evaluations and 800 updates are encoded before one queue submission. Each epoch has a small uniform containing example count, history index, and learning-rate bits. The large buffers persist. The final extra forward/backward pair records loss after the last update without applying an 801st update.

4. Check the derivative before trusting loss

A falling loss alone can conceal a mismatch. The CPU oracle implements the same shapes and equations. For selected parameters it estimates a central difference:

gq,num ≈ [L(θq+ε) − L(θq−ε)]/(2ε), with ε = 0.001

The test compares input, hidden, output, and bias gradients within 2×10−4. It avoids a nondifferentiable activation because tanh is smooth. Another CPU test verifies the nonlinear fixture's loss falls by at least seventy percent. The ignored hardware test trains both implementations for 80 steps and compares every resulting weight within 2×10−4.

GPU arithmetic can differ because exp, tanh, and instruction contraction are implementation-dependent within specified accuracy. Tolerances acknowledge this without making them so wide that a wrong sign passes. The final classification print applies sigmoid on CPU only after the trained logits have been recovered through the weights.

What this test proves.

It proves the shader stages agree with a scalar oracle on a tiny fixture and reduce its training loss. It does not establish generalization, GPU speed, large-batch scaling, or numerical behavior for every architecture.

5. Audit residency and parameter versions

Draw a line after each pass and label every buffer read or written. Forward reads inputs and weights, then writes hidden activations and logits. Backward reads inputs, labels, weights, hidden activations, and logits, then writes gradients and one loss. Update reads gradients and writes weights. This audit catches two subtle mistakes: recomputing hidden activations after weights changed, and updating output weights before they have been used to propagate hidden gradients.

The reference keeps the old weights intact until backward finishes. Within backward, it computes every gradient before update starts. This preserves the simultaneous-update rule from early chapters. If parameter 12 were updated while computing parameter 0's hidden derivative, later gradients would use a mixture of old and new models.

The seventeen-value layout is concrete: positions 0–7 hold four pairs of input weights, 8–11 hold hidden biases, 12–15 hold output weights, and 16 holds the output bias. The WGSL and CPU oracle use this same order. A production tensor system would attach shapes and names, but a fixed teaching network gains more from a short, inspectable contract. The gradient test deliberately samples positions from every region.

Labels and features are fixed training data. Only weights change. Hidden values, logits, gradients, and losses are derived state recreated for each epoch.

Residency does not mean the CPU has no role. Rust chooses shapes, creates resources, records the dependency graph, submits work, and eventually interprets results. It means the CPU does not shuttle training tensors through host memory at every boundary. The only final copies are seventeen trained weights and 801 diagnostic losses.

Measured course fixture

On the verified RX 6950 XT run, mean cross-entropy fell from 0.730555 to 0.013002 after 800 steps. The first four XOR probabilities were approximately 0.0157, 0.9949, 0.9905, and 0.0190 for labels 0,1,1,0. These numbers validate this deterministic fixture and implementation; they do not measure held-out generalization.

Debugging · Loss falls, then becomes NaN

A learner computes -y*log(p)-(1-y)*log(1-p). Confident predictions round to zero or one.

Answer

The logarithm receives zero even when the underlying logit is finite. Preserve logits and use the stable softplus form. Do not merely clamp p while claiming the unchanged p−y derivative belongs to that clamped objective.

Independent variation · Parallel partial gradients

Assign one workgroup to four examples. Each lane computes seventeen private contributions, then reduce each parameter into a partial-gradient buffer. A second dispatch combines two workgroups.

Worked answer

Keep weights unchanged through both reduction stages, divide once by eight, then update. Reading or updating weights after only the first workgroup would mix parameter versions.
