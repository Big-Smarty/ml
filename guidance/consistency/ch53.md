# Chapter 53 consistency revision

## Interface mapping

- The reference keeps `Model { format, model_version, input_schema, mean, scale, weight, bias, data_hash }`. `Model::predict(&self, raw) -> Result<f64, &'static str>` applies the stored normalization before the scalar weight and bias and retains model, input-range, and nonfinite-result validation.
- The private trainer is now `train(data, version) -> Result<Model, &'static str>`. It still fits population mean and scale, initializes weight and bias to zero, and takes exactly 300 full-data MSE-gradient updates at learning rate 0.05. The local names now spell out `learning_rate`, `weight_gradient`, and `bias_gradient`; the arithmetic and update order are unchanged.
- The starter now constructs a `Model` with stored model version, input schema, mean, scale, weight, and bias and calls the same fallible `Model::predict(raw)` operation. Its supplied fixture remains mean 10, scale 2, weight 0.75, bias -0.25, raw input 12, prediction 0.5. `parse_request` was renamed to the reference operation `parse_body`; its learner TODO remains unfinished.
- The HTTP body remains the two-field `schema=1&x=<scalar>` contract. The reference parser's existing `u32` conversion also accepts numeric spellings `schema=01` and `schema=+1`; tests and prose now record that compatibility rather than silently narrowing it. The Rustlings `parse_schema` task is explicitly an isolated canonical-field exercise whose literal match accepts only `schema=1`.

No external crate calls these private Chapter 53 functions. The CLI flags and argument positions, `MLMODEL` serialization fields and order, request framing, error strings, fixtures, canary tolerance, monitoring threshold, and checkpoint size limit remain unchanged.

## Numerical, shape, and reduction contract

Training data is `[(input, target)]` with scalar f64 values. `train` fits population mean and population scale over every input, then averages both derivatives of ordinary MSE over all examples. There is no half factor. `Model::predict` maps one raw scalar to one scalar prediction and performs no reduction. It can fail for invalid stored state, nonfinite or out-of-range external input, and nonfinite output.

The lesson now explains that this teaching function jointly fits preprocessing and model parameters while a production pipeline normally fits a scaler, transforms both training and serving inputs with the same fitted state, and packages scaler plus model together. The `MLMODEL` artifact is inference state rather than an exact optimizer-resume checkpoint. `Model::decode` parses that artifact; it is distinct from Chapter 34's tokenizer `Bpe::decode` and Chapter 36's neural `Decoder`.
