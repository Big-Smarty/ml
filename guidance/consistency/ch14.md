# Chapter 14 consistency revision

## Continuity and interface mapping

The early `continuity` section now links Chapters 13 and 5 plus `/conventions.html`. It carries Chapter 13's `Preprocessor::fit(training_rows)` and `Preprocessor::transform` boundary forward: `Scaler::fit(train_data)` estimates state only from training rows, and `Scaler::transform(features)` reuses it for later rows. It maps `RawRow.label` to `Point.label` and explains the deliberate shape change from Chapter 13's vocabulary-dependent `Vec<f64>` to this fixture's fixed `[f64; 2]`; adapting the prior encoder requires selecting two documented columns or generalizing every fitted array, never truncating silently. The label changes from `u8` to `usize` because it directly indexes vote and per-class-statistic arrays.

The reference, starter, exercise, solution, lesson, metadata, and research note now use `features` for model inputs and `label` for the stored discrete class ID. Mathematical `x`, `z`, and `c` remain local equation notation and are mapped before use. The exercise's `squared_distance(features, other_features)` arguments map directly to `Point.features` and the query passed to prediction.

The private reference interface changed as follows; all callers in the Chapter 14 binary and tests were updated:

| Before | After | Meaning |
| --- | --- | --- |
| `Point { x, class }` | `Point { features, label }` | Two numeric inputs plus a separate discrete class ID |
| `Scaler::fit(data)` | `Scaler::fit(train_data)` | Estimate training-only means and scales |
| `Scaler::transform(x)` | `Scaler::transform(features)` | Apply fitted state without refitting |
| `knn(train, query, k, classes)` | `Knn::fit(train_data, k, classes)?.predict(features)` | Fit/store one classical estimator, then return its label decision |
| `GaussianNb::fit(data, classes)` | `GaussianNb::fit(train_data, classes)` | Estimate the separate Bayes model's statistics |
| `GaussianNb::predict(x)` | `GaussianNb::predict(features)` | Return the winning discrete label |

`Knn::fit` and `GaussianNb::fit` are separate estimator operations, not optimizer steps or stages of one model. kNN stores borrowed training rows and chosen hyperparameters. Gaussian NB estimates priors, means, and variances. Both `predict` methods return a label. kNN squared distances and Gaussian `log_score` values are raw internal comparison quantities; this project exposes no probability method.

## Shapes, reductions, and code/prose checks

- Every `Point` has `features: [f64; 2]` and `label: usize`; the label never enters scaling or distance.
- `squared_distance` sums both coordinate differences with no square root. The array type makes unequal widths unrepresentable.
- `Scaler::fit` averages each feature over all training rows, uses population variance with denominator `train_data.len()`, and maps zero scale to one.
- `GaussianNb::fit` computes each prior over all training rows and each mean and population variance over the rows carrying that label. Its `1e-9` variance floor is unchanged.
- kNN still scans and fully sorts all training rows, votes among exactly `k`, and resolves ties toward the lower label. Gaussian NB still selects the greatest finite log score.
- Four `data-source` excerpts cover the shared distance primitive, kNN voting, the fit/transform/estimator pipeline, and the Rustlings solution. All match their formatted source.
- Hints, worked answers, retrieval answers, metadata outcomes/checks/limitations, and research notes were checked against the implemented names, shapes, and output meanings.
