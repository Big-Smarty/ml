# Chapter 52 consistency revision

## Changes and interface mapping

- `DualEncoder` now stores `image_weights: [[f64; 4]; 2]` and `text_weights: [[f64; 3]; 2]`; the flattened local is `parameters`, and the optimizer setting is `learning_rate`.
- Read-only methods borrow `&self`. The fixed-shape public teaching path is:
  - `similarities(&self, images: &[[f64; 4]; 3], captions: &[&str; 3]) -> Result<[[f64; 3]; 3], &'static str>`
  - `logits(&self, images: &[[f64; 4]; 3], captions: &[&str; 3], temperature: f64) -> Result<[[f64; 3]; 3], &'static str>`
  - `loss(&self, images: &[[f64; 4]; 3], captions: &[&str; 3], temperature: f64) -> Result<f64, &'static str>`
  - `train(self, images: &[[f64; 4]; 3], captions: &[&str; 3], steps: usize, learning_rate: f64, temperature: f64) -> Result<Self, &'static str>`
  - `recall_at_one(&self, images: &[[f64; 4]; 3], candidate_captions: &[&str; 3]) -> Result<f64, &'static str>`
- The executable still uses the exact three image-caption pairs, fourteen initial parameters, temperature 0.2, 300 optimizer steps, learning rate 0.03, and central differences at ±1e-5.
- A focused alternate-input test proves that supplied images change loss, supplied temperature rescales logits, and supplied tied candidates use the preserved last-maximum rule.
- Existing zero/nonfinite embedding, nonfinite pixel/feature, out-of-vocabulary caption, and learning-rate errors remain. The temperature boundary now rejects nonpositive, nonfinite, and finite-but-too-small values that produce nonfinite logits; `loss` also rejects overflow that can arise from extreme but finite logits.
- This is a standalone binary with no cross-crate callers or migration.

## Shapes, loss, and metric conventions

- Row-major image input is `[4]`; caption word-count features are `[3]`.
- Fixed `[out,in]` learned matrices are image `[2,4]` and text `[2,3]`; both towers return normalized embeddings `[2]`.
- `similarities` returns raw normalized-embedding dot products `[3,3]`. `logits` divides that matrix by positive temperature τ. Softmax normalization is internal to cross-entropy and does not turn retrieval similarities into calibrated relevance probabilities.
- `cross_entropy_from_logits(logits, target)` puts logits before the target and uses `(maximum - target_logit) + ln Σ exp(logit - maximum)`, avoiding maximum-plus-log-sum cancellation. `DualEncoder::loss` returns an error if the six-term result is nonfinite.
- Paired row i and column i both use target index i. Symmetric loss sums three row and three column cross-entropies and divides by `2N = 6`.
- `recall_at_one` ranks raw similarities. It equals HitRate@1 only because this fixture has one positive caption per query; equal similarities select the last candidate.
