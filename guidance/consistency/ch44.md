# Chapter 44 consistency revision

## Interface mapping

- Chapter 24's standalone `dot(&[f64], &[f64]) -> f64` becomes `dot(&[f32], &[f32]) -> f32` because Chapter 44's query and document embedding tables already store `f32`. The slice arguments, coordinate-wise multiplication, sum, and raw-score meaning are unchanged.
- Chapter 24's `MatrixFactorization::score(user, item)` and `ranked_candidates(user)` receive IDs and perform model lookups. Chapter 44's `DenseRetriever::scores(query)` tokenizes text, averages table rows, and calls `dot`; the Rustlings `exact_top(query, docs)` receives resolved vectors and returns one document position. The names differ because the input and output contracts differ.
- Chapter 33's stable `cross_entropy_from_logits(logits, target)` name and shifted log-sum-exp formula are reused. The ranking target is the `usize` index of the supporting document. Softmax values are named `probabilities` only before subtracting the one-hot target; the resulting p-y vector is `logit_gradients`.
- `DenseRetriever::train(train_data, steps, learning_rate)` now uses the course learning-rate name and receives its labeled pairs explicitly. One step is one optimizer update from one pair. `DenseRetriever::loss(data)` averages categorical cross-entropy over the explicitly supplied labeled pairs.
- `DenseRetriever::new` fixes the closed vocabulary from the fact corpus and declared training queries, tokenizes documents, and deterministically initializes parameters. It does not update parameters. The lesson distinguishes this bundled construction-time preprocessing from `train`; it does not introduce an unused `fit` API.
- The reference now owns the same `should_abstain(best, second, known_terms)` helper as the starter. `rag` counts known content terms and delegates to it without changing the score, margin, threshold, or NaN comparisons.
- Chapter 43's Chapter 36 `Decoder` predicts next-token logits and is absent from Chapter 44. Chapter 44's standalone dense retriever ranks facts, and its extractive answerer returns selected fact text. No decoder checkpoint, method, or generation claim carries across this boundary.
- All changed functions and fields are private to the Chapter 44 binary. No cross-crate API or caller migration is required.

## Scores, embeddings, targets, loss, and metrics

- BM25 and dense dot products are raw ranking scores, not probabilities of relevance or calibrated support confidence. The three-way softmax is a training distribution over the declared corpus candidates only.
- Each query-side or document-side table row is a learned word embedding with storage `[vocabulary, 8]`. Averaging selected rows produces one query or document embedding `[8]`; a document embedding is not a token embedding.
- A labeled training pair is `(query text, target document index)`. The target serves as the discrete class label for cross-entropy over the three documents.
- `loss(data)` is mean categorical cross-entropy over the supplied pairs. Held-out hit@1 asks whether the sole relevant document ranks first. On this one-relevant-document fixture hit@1 equals Recall@1; neither metric is the training loss.
- `rag` selects the top raw score and applies the unchanged known-term, score `0.05`, and margin `0.02` gates. These remain fixture heuristics rather than calibrated confidence.
