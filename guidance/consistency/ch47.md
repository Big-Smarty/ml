## Numerical and behavioral contracts

- Dense weights are contiguous row-major f64 `[out_features,in_features]`; input is `[in_features]`; output is `[out_features]`. Each output reduces a dot product by summing across `in_features`.
- `prune_to_density` still keeps `round(density * weights.len())` positions globally by descending absolute magnitude, breaking exact ties by original index. The deterministic 192×192 fixture, sinusoidal input, density sweep `[1.0, 0.5, 0.2, 0.05]`, and printed CLI output are unchanged.
- Sparsity is the fraction zero and equals `1 - actual_density`. Requested density is the pruning position budget; `CsrMatrix::density` reports stored nonzeros divided by all positions, so original exact zeros can make actual density lower.
- Pruning produces exact zeros and CSR omits them. This differs from Chapter 41 quantization, which keeps positions and approximates values with integer codes and scales.
- Masked dense output versus CSR output is the representation parity check, using absolute tolerance `1e-10` plus relative tolerance `1e-8`. Unpruned dense output versus pruned output is coordinate RMSE measuring the pruning-induced change for one fixed input. It is not loss or task accuracy.
- The fixture is fixed deterministic weight data, not a trained model. Chapter 47 has no training, loss, gradient, held-out task metric, or sparse retraining.
- Allocating `dense_matvec_reference` and `CsrMatrix::matvec` are used outside timing for validation. The benchmark allocates separate dense and CSR output buffers once, warms each path once, and then measures only `dense_matvec_into` and `CsrMatrix::matvec_into` for 31 samples. Pruning, CSR conversion, allocation, checking, and printing remain outside the timed intervals.
- Existing error strings and rejection behavior for empty/mismatched shapes, nonfinite weights/input, invalid densities, and mismatched CSR buffers are preserved.
