# Chapter 05 consistency revision

## Continuity and interface mapping

Chapter 05 now explicitly consumes the outputs established by Chapter 04: positive-class probabilities and discrete targets, which are the evaluation class labels. It does not define or train another model. The early `continuity` section links Chapter 04 and `/conventions.html`, explains why Chapter 04's BCE targets were `f64` while evaluation targets are `bool`, and identifies the chapter's output artifacts: a validation-selected threshold, confusion counts, and derived metrics.

The implementation and teaching interface changed as follows:

- `ScoredExample { entity, target, score }` became `EvaluationExample { entity, target, probability }`. Every fixture value, validation check, test, lesson reference, and metadata limitation uses the new names.
- Inline `example.score >= threshold` became `predict(probability, threshold) -> bool`. The reference and starter use the same argument order and return meaning.
- `evaluate(data: &[ScoredExample], threshold)` became `evaluate(data: &[EvaluationExample], threshold)`. It still rejects empty data, nonfinite/out-of-range thresholds, and nonfinite/out-of-range continuous outputs before counting.
- `choose_threshold` and `no_entity_overlap` now accept `EvaluationExample` slices. Their behavior and argument order did not change.
- The lesson now calls the fixture values probabilities rather than ambiguous scores. It distinguishes those probabilities, the `bool` class decision from `predict`, and the `bool` target used to judge that decision.
- The starter's runnable checkpoint uses `predict(probability, threshold)` and prints `probability 0.7 ... class 1`. Its precision TODO is unchanged.
- The Rustlings exercise and solution were already aligned: `recall(true_positive, false_negative)` calculates TP / (TP + FN), with zero for an empty denominator. They required no edit.

The exact `predict` plus `evaluate` excerpt in the lesson is tagged `data-source="projects/ch05/src/main.rs"` and matches the reference source after HTML decoding and whitespace normalization.

## Shapes and reductions

- One `EvaluationExample` contains one entity identifier, one `bool` target, and one `f64` positive-class probability. `VALIDATION` has shape `[EvaluationExample; 8]`; `TEST` has shape `[EvaluationExample; 10]`.
- `predict` compares one probability with one threshold and returns one `bool` class. `evaluate` sums each example into exactly one of TP, FP, TN, and FN.
- `Confusion::metrics` derives scalar ratios from counts. Accuracy divides TP + TN by all examples; precision divides TP by TP + FP; recall divides TP by TP + FN; F1 is the harmonic mean of precision and recall; balanced accuracy averages positive and negative recall. A zero denominator returns `0.0`, as stated in the lesson.
- `choose_threshold` maximizes validation F1 across the supplied candidates and preserves the first candidate on a tie. Test data does not participate in selection.
- Chapter 05 has no loss, gradient, parameter update, or averaging over a training objective. Chapter 04 owns mean BCE and training; this chapter owns held-out evaluation of supplied probabilities.
