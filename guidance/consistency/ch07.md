# Chapter 07 consistency record

## Interface mapping

- `Net::loss()` became `Net::loss(&self, data: &[Example]) -> Result<f64, _>`; it no longer captures the global XOR fixture.
- The backpropagation embedded in `step(&mut self, rate)` became `gradient(&self, data) -> Result<Gradient, _>`. `Gradient { hidden_weights, hidden_bias, output_weights, output_bias }` stores derivatives separately from `Net` parameters.
- `step(&mut self, rate) -> Result<(), _>` became `step(self, data, learning_rate) -> Result<Self, _>`. It applies the complete mean gradient simultaneously and returns the updated model.
- The free `train(steps, rate)` function became `Net::train(self, data, steps, learning_rate)`. The dataset and chosen learning rate are explicit.
- Tuple-valued `forward(x)` became `forward(features) -> Forward { hidden, logit, probability }`, naming the intermediates reused by backpropagation.
- `probability(features)` selects the continuous positive-class probability. `predict(features)` applies the documented 0.5 threshold and returns class `0` or `1`.
- Parameter and derivative fields use `hidden_weights`, `hidden_bias`, `output_weights`, and `output_bias` rather than unexplained `w1`/`b1`/`w2`/`b2` and `gw1`/`gb1`/`gw2`/`gb2` abbreviations.
- The Rustlings primitive is now `sigmoid_derivative_from_output` in both exercise and solution. The starter now carries the real 2–2–1 forward path, explicit-data mean loss, prediction operations, and matching `Gradient` shape; its single TODO is full-batch `Net::gradient`.

The lesson's early continuity section links Chapters 06 and 04 plus `/conventions.html`. It distinguishes `forward` intermediates from probability and class prediction, parameter derivatives from updated parameters, and Chapter 08 graph adjoints from this chapter's parameter `Gradient`. The tagged backpropagation excerpt matches `projects/ch07/src/main.rs` after HTML decoding and whitespace normalization.

## Loss, gradient, and shape conventions

- `Features` is `[f64; 2]`; one `Example` is `(Features, f64)` in `(features, target)` order.
- Conceptual activations are `[batch, features]`. `hidden_weights` is `[out_features, in_features] = [2, 2]`. The only output row is stored as `output_weights: [f64; 2]`, and one example produces one logit and probability.
- `binary_cross_entropy_from_logit(logit, target)` uses the stable logit expression. `loss(data)` averages it over all supplied examples; the XOR fixture has four.
- `gradient(data)` divides every parameter contribution by the same example count before returning. It uses cached hidden activations and the unchanged output weights.
- `step(data, learning_rate)` subtracts the returned mean derivative from each matching parameter. `steps` counts optimizer updates; the default demonstration uses one full-batch update per step.
- Empty data, nonfinite features or targets, targets outside `[0, 1]`, and nonpositive or nonfinite learning rates return errors.
