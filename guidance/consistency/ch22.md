# Chapter 22 consistency review

## Changes and interface mapping

- `Autoencoder::loss(inputs) -> f64` retains the shared model-loss name and evaluates coordinate reconstruction MSE. The owning model identifies the objective.
- `Autoencoder::reconstruct(features)` now returns only the four-coordinate reconstruction. `Autoencoder::forward(features) -> AutoencoderForwardCache` returns the two-coordinate code and reconstruction needed by backward. This separates a model output from cached intermediates.
- `Autoencoder::encoder_gradient(features)` remains the encoder-parameter derivative of one row's coordinate MSE and still uses the old decoder values.
- `Contrastive::loss(view_a, view_b, temperature)` retains the shared name for its documented InfoNCE objective. `loss_grad(...)` became `loss_and_gradient(...)`; the fused method still shares normalized-encoder caches and returns the same InfoNCE value plus its `[2,4]` shared-weight gradient.
- `Contrastive::raw_and_embed` became `forward`, which returns `ContrastiveForwardCache`; `embed(features)` returns only the normalized two-coordinate representation. Retrieval, rather than either of these operations, makes the task-level candidate choice.
- The contrastive field `w` became `weights`. Both trainers' `rate` argument and local uses became `learning_rate`. Algorithms, initialization, fixtures, epoch counts, update order, CLI, and numerical tolerances were preserved.
- The Rustlings primitive is now `reconstruction_mse(reconstruction, target)`, exactly matching the reference helper's arguments and output-before-target order. The starter primitive is `encode(features, encoder_weights)`; the lesson explicitly maps it to `Autoencoder::encode(&self, features)`, which reads stored weights, adds bias, and applies tanh.

These APIs are chapter-local. The consistency scout found no path dependencies for Chapter 22, and a repository caller scan found no external Rust callers.

## Shapes, objectives, and reductions

- Autoencoder inputs and reconstruction targets have shape `[N,4]`; its code is `[N,2]`. Encoder weights are `[2,4]`, decoder weights are `[4,2]`, following `[out_features,in_features]`.
- `reconstruction_mse(reconstruction, target)` divides one row's sum of squared coordinate errors by four. `Autoencoder::loss(inputs)` averages those row values, so the complete denominator is `N * 4`, with no factor one half. Online training applies one row's coordinate-MSE gradient at a time.
- Chapter 17's frozen `mean_squared_reconstruction_norm` instead sums coordinate errors within each row and divides only by `N`. The Chapter 22 lesson states why that statistic and coordinate MSE have different names and values.
- Contrastive views each have shape `[N,4]`; shared normalized embeddings have shape `[N,2]`. For each anchor, InfoNCE uses log-sum-exp over all `N` candidate logits minus its positive logit. The batch objective divides the anchor-loss sum by `N` and does not divide again by candidate count.
- `loss_and_gradient` uses the same anchor denominator in every logit derivative, differentiates normalization, and accumulates both anchor and candidate branches into one shared `[2,4]` weight gradient. Training applies one full-pair-batch update per epoch.
