# Chapter 25 consistency revision

## Interface and continuity

- Added the required early continuity section linking Chapters 9 and 24 and `/conventions.html`.
- The reference and starter now use the same dense argument order: `dense(inputs, weights, bias, batch, in_features, out_features, outputs)`.
- The logical and stored shapes remain `inputs=[batch,in_features]`, `weights=[out_features,in_features]`, `bias=[out_features]`, and `outputs=[batch,out_features]`. Both kernels still compute `outputs = inputs × weights-transpose + bias` in contiguous row-major storage.
- Chapter 25 introduces `f32` for the timed kernel. `dense_f64_reference` casts the same stored `f32` fixture values to `f64` and accumulates the same operation outside the timed interval as a numerical oracle. The absolute-plus-relative comparison is unchanged.
- This is inference-only code. It has no scalar loss, reduction, training update, backward pass, input gradient, or output gradient. The lesson, metadata, hints, and worked answers now say so directly.

## Timing and exercise mapping

- Reference samples remain `Duration` values; their debug formatting prints a unit such as `ns` or `µs`. The starter and Rustlings primitive use `median_ns(&mut [u128]) -> u128`, where every integer is explicitly a nanosecond count. Both sort an odd sample count and select its middle value.
- The starter dense call now includes the zero bias that was implicit before, uses the reference argument order, and preserves its printed outputs `[-1.5, -2.5]`.
- The Rustlings exercise retains its literal TODO and intentional failure. Its solution and lesson answer use the same `median_ns` operation.
- Two exact `data-source` excerpts cover the complete reference `dense` kernel and the solved median body. Both match their defining files after HTML decoding and whitespace normalization.

## Preserved behavior and scope

The scalar loop order, generated fixture, shape validation, tolerance, warmup and repetition counts, `--large` flag, benchmark boundary, FLOP and byte formulas, checksum, CLI error behavior, and default short demonstration are unchanged. No learner-authored Chapter 25 changes existed at baseline. No dependency, shared abstraction, long benchmark, GPU path, or training behavior was added.
