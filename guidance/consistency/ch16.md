# Chapter 16 consistency revision

## Continuity and interface mapping

The early `continuity` section now links Chapter 15 and `/conventions.html`. Chapter 15's tree classifier stores class IDs as 0 or 1; Chapter 16 explicitly converts the negative class to -1 before constructing a `Point`, because hinge loss and the subgradient multiply the signed label by the raw score. Two-feature storage remains a fixed `[f64; 2]` array.

The reference, starter, lesson, hints, and worked answers now use the same Rust vocabulary:

- `Point { x, y }` -> `Point { features, label }`.
- `LinearSvm { w, b }` -> `LinearSvm { weights, bias }`.
- `LinearSvm::fit(data, epochs, rate, lambda)` -> `LinearSvm::fit(data, epochs, learning_rate, lambda)`.
- Inspecting `LinearSvm` methods now borrow `&self`; all known Chapter 16 callers were updated.
- Mathematical `x`, `y`, `w`, `b`, and `eta` remain in equations and are mapped explicitly to `features`, `label`, `weights`, `bias`, and `learning_rate`.

No published cross-project caller or path dependency uses these private Chapter 16 types. The reference CLI command, arguments, fixtures, algorithms, and measured output values are unchanged.

## Scores, predictions, objectives, and reductions

- `LinearSvm::score(features) -> f64` returns the raw unnormalized value `weights dot features + bias`.
- `LinearSvm::predict(features) -> f64` converts the score to the signed class decision -1 or +1; a zero score maps to +1. It does not return a probability.
- `LinearSvm::objective(data, lambda)` returns mean hinge loss over points plus `lambda / 2 * ||weights||^2`. It is a regularized training objective, distinct from the raw score, class prediction, per-point hinge loss, and accuracy.
- The fixed-order trainer performs one stochastic subgradient update per point and calls one complete pass an epoch. `learning_rate` is the public hyperparameter name. The bias remains unregularized.
- `KernelClassifier::score` returns the raw alpha-weighted RBF sum; its `predict` method applies the same signed class decision rule. The nonlinear trainer remains a kernel perceptron, not a kernel SVM.
- One point has shape `[2]`. Both feature and weight arrays are contiguous. Accuracy divides correct signed class decisions by points. The reference, Rustlings exercise, and starter all use `hinge_loss(score, label)`, with the prediction score before its target label. The caller constructs the score from model parameters before evaluating this primitive.

The lesson contains six checked `data-source` excerpts: linear `score`/`predict`, the objective core, the stochastic update loop, kernel `score`, the Rustlings solution expression, and the shared hinge-loss function. All match their defining files after HTML decoding and whitespace removal.
