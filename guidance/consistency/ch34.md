# Chapter 34 consistency revision

## Interface mapping

- Chapter 33's private `Model::logits(input)`, `probabilities(input)`, `predict(input)`, `loss(data)`, and `step(data, learning_rate)` retain their classification and optimizer meanings. Chapter 34 adds no model, objective, gradient, update step, or learning rate.
- The chapter-local tokenizer estimator changed from `Bpe::train(text, merges)` to `Bpe::fit(data, max_merge_count)`. `fit` counts adjacent token-ID pairs and estimates ordered preprocessing rules; it does not run gradient updates. The maximum is an upper bound because fitting stops when no adjacent pair occurs at least twice.
- The learned field changed from `merges` to `merge_rules`. `Bpe::encode(bytes)` returns `Vec<u16>` token IDs, and `Bpe::decode(token_ids)` returns `Result<Vec<u8>, String>`. The `merge_pair` primitive now uses `token_ids` and `new_token_id` in the reference, starter, learner exercise, solution, hints, and worked answer.
- These APIs are private to the Chapter 34 binaries and standalone exercise files. Repository-wide caller search found no path-dependent or published caller. The old-to-new mapping is reported to the lead for integration visibility.

## Units, counts, and boundaries

- Bytes are `u8` values, token IDs are `u16` vocabulary indices, and Rust `chars()` counts Unicode scalar values. The lesson and starter label each unit explicitly; token boundaries may divide a multi-byte UTF-8 character.
- The base vocabulary always has 256 entries. Every learned merge rule creates one entry, so `vocab.len() == 256 + merge_rules.len()`. The unchanged default fixture supplies 36 UTF-8 bytes, requests at most 24 rules, learns 12, creates a 268-entry vocabulary, and encodes to 12 token IDs.
- `decode(encode(bytes)) == bytes` is the canonical round trip. Text conversion happens only after all decoded token bytes have been concatenated.
- `fit` treats its one `data: &[u8]` slice as one document. The lesson carries forward Chapter 33's boundary convention: a multi-document extension must keep separate token-ID sequences, aggregate counts only from windows inside each sequence, and apply replacements inside each sequence. Production pre-tokenization remains outside this checkpoint.
- The merge algorithm, lexicographic tie-break, non-overlapping left-to-right replacement, course-authored fixtures, CLI, file header and lines, safety limits, error behavior, serialized format, and printed output are preserved. Removing the one-element `words` wrapper does not change the single-sequence algorithm.
