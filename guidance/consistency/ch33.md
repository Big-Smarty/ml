# Chapter 33 consistency revision

## Interface mapping

- The chapter-local trainable type is now `Model`. `Model::loss(data)` evaluates mean next-byte cross-entropy on the supplied byte sequence, `Model::step(data, learning_rate)` performs one simultaneous full-data gradient update of that objective, and `Model::predict(input)` returns the most likely next-byte class ID without updating parameters.
- `Model::logits(input)` returns 256 unrestricted scores. `Model::probabilities(input)` applies stable softmax and returns 256 normalized probabilities. `input`, `target`, and the returned prediction are `u8` class IDs; a target ID selects the desired output class and is not a regression value or probability.
- Chapter 23's adjacent sequence examples carry forward, but its scalar next-value regression and mean squared error change here to 256-class next-byte classification and mean cross-entropy. Chapter 24 remains the glossary owner for the broad `embedding` concept; Chapter 33 links it and teaches the byte-ID lookup instance. Chapter 32's `f32` representation carries forward, while this small reference runs on CPU.
- The rename from `BigramEmbeddingLm` to private `Model` and `rate` to `learning_rate` has only chapter-local callers: the reference `main` and its four tests. No published path dependency or checkpoint format is affected.

## Shapes, reductions, and boundaries

- The embedding table is row-major `[256, width]`, the output matrix is row-major `[width, 256]`, and bias, logits, and probabilities each have shape `[256]`.
- One sequence of `data.len()` bytes produces `data.len() - 1` adjacent examples. `loss` averages cross-entropy over exactly those targets, and `step` divides every accumulated parameter gradient by the same example count before updating embeddings, output weights, and bias together.
- The lesson corrects the former claim that Chapter 37 prevents cross-document transitions. Chapter 37 cleans, deduplicates, and splits whole documents but does not build windows. A downstream consumer must call `windows(2)` separately within each document.
- Algorithms, deterministic initialization, corpus fixtures, error/assertion behavior, command lines, test tolerances, and printed reference measurements are preserved. The starter and Rustlings TODO algorithms are unchanged.
