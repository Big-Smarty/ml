# Chapter 31 consistency revision

Status: chapter interface frozen for root integration on 2026-09-08.

## Changes and interface mapping

- Replaced the captured-fixture `gpu_train(epochs, rate)` with `train_with_gpu(data, steps, learning_rate)`. It still starts from the same 17 values and runs the same default 800 full-batch updates; the data is now explicit and validated before device lookup.
- Replaced `cpu_forward(weights, input)` with `Model::forward(features)`, which returns the four hidden activations needed by backward and one logit. `Model::probability(features)` applies sigmoid for the task output.
- Replaced `cpu_loss(weights)` and `cpu_gradient(weights)` with `Model::loss(data)` and `Model::gradient(data)`. Both are scalar CPU oracles over explicit examples. `Model::step(data, learning_rate)` is the gradient-descent optimizer oracle, and `Model::train(data, steps, learning_rate)` repeats it.
- Replaced the packed `weights` name with `parameters`: offsets 0..8 are hidden input weights, 8..12 hidden biases, 12..16 output weights, and 16 the output bias. The values, order, bytes, shader binding number, and readback semantics are unchanged. `TrainingResult.weights` is now `TrainingResult.model.parameters`.
- Renamed WGSL `epoch` to `history_index`, `rate_bits` to `learning_rate_bits`, and the local update value to `learning_rate`. Shader entry points `forward`, `backward`, and `update`, all eight bindings, and all dispatch sizes remain unchanged.
- Renamed the starter and Rustlings delta argument from `prediction` to `probability`; the argument order remains probability first, target second. Their TODO behavior is unchanged.

No external chapter caller was found. Root does not need a cross-chapter source edit for this private binary API.

## Loss, shapes, and numerical conventions

- The scalar and WGSL paths implement the same `binary_cross_entropy_from_logit(logit, target)` objective introduced in Chapter 4: `max(z, 0) - z*y + log(1 + exp(-abs(z)))`.
- `Model::loss` and WGSL backward sum per-example BCE and divide by the complete example count. `Model::gradient` and WGSL backward divide every parameter derivative by the same count. There is no half factor or mismatched reduction.
- The fixed fixture is `data=[8]` examples with `features=[2]`, forward cache `hidden=[8,4]`, `logits=[8]`, `targets=[8]`, and packed `parameters=[17]`. The data values and initialization are unchanged.
- Every step consumes the complete eight-example data once, so one optimizer step is also one epoch here. The interface counts `steps` because that equality will not hold for later minibatches or accumulation.
- Chapter 4's scalar reference is `f64`; Chapter 31 deliberately uses CPU and WGSL `f32`. Central differences use epsilon `1e-3`; checked scalar derivatives and 80-step GPU parity use absolute tolerance `2e-4`. No bit-equality claim is made.
- Rust calls the desired answer `target`. WGSL uses local `label` because `target` is reserved, and the source comment maps it directly to the value read from the `targets` buffer.
