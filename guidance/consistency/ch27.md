# Chapter 27 consistency revision

## Interface mapping

- Chapter 25 remains frozen at `dense(inputs, weights, bias, batch, in_features, out_features, outputs)` with row-major `weights=[out_features,in_features]`. Chapter 27 specializes this to `out_features=1`: `Model.weights=[in_features]`, scalar `Model.bias`, `inputs=[batch,in_features]`, and flattened `predictions=[batch]`.
- `Model::predict_row(features) -> f32` became `Model::predict(features) -> f32`, the one-row regression task operation.
- `Model::infer(inputs, features)` became `Model::predict_batch(inputs, in_features)`. `Model::infer_parallel(inputs, features, threads)` became `Model::predict_batch_parallel(inputs, in_features, threads)`. Both batch wrappers return one prediction per row; inference remains the process that calls them without updating parameters.
- `gradient_parallel(model, x, y, features, threads) -> (loss, dw, db)` became `loss_and_gradient_parallel(model, inputs, targets, in_features, threads) -> (loss, Gradient)`. The new scalar counterpart is `loss_and_gradient` with the same loss and gradient meanings.
- `Gradient { weights: Vec<f64>, bias: f64 }` separates accumulated parameter derivatives from `Model`'s learned `f32` storage. `train_step` now takes `learning_rate`; its update order and arithmetic are unchanged.
- Root aligned the starter to the reference `Model` fields and exact `predict(&self,features)` implementation, with bias initialized to zero. Starter `loss` and `loss_parallel` evaluate MSE on explicit inputs/targets and retain the supplied checked shape boundary; the parallel method is the loss-only predecessor of `loss_and_gradient_parallel`. The Rustlings `reduce_gradient_sums_in_order` receives the `Gradient.weights` vectors that workers return, produces a sum, and leaves division to the caller.

## Shapes and reductions

`predict` consumes `features=[in_features]`. The batch wrappers consume contiguous row-major `inputs=[batch,in_features]` and produce `predictions=[batch]`, equivalent to flattening the one-output dense result `[batch,1]`. Training consumes numeric `targets=[batch]`.

Each call to `loss_and_gradient_sum` returns a summed squared loss and summed weight/bias derivatives for its shard. `loss_and_gradient_parallel` joins and reduces those results in shard-creation order. `mean_loss_and_gradient` then divides the complete loss and every complete parameter-gradient sum by the full batch size exactly once. The same averaging boundary serves scalar `loss_and_gradient`, so unequal chunks cannot receive equal shard weighting.
