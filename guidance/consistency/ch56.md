# Chapter 56 consistency revision

## Interface and compatibility

- Kept Chapter 56 as an independent standard-library `f64` implementation with its own `Model`, `Gradients`, and `Trainer`. It imports neither Chapter 36 code nor Chapter 36 checkpoints. The lesson explains that Chapter 36 uses `f32` for its CPU/GPU path, while this tiny model uses `f64` for tighter exhaustive finite-difference checks.
- Renamed `Model::loss_and_grad(input, targets)` to `Model::loss_and_gradient(input, targets)` in the trainer and every owned test. The fused method still returns `Gradients` for the same capped objective and does not mutate the model.
- Renamed the private flat `Model::params` field to `parameters`. Public `parameters()` and `parameters_mut()` retain their signatures and behavior.
- Renamed optimizer arguments and `TrainingIdentity::rate` to `learning_rate`. The serialized identity value remains in the same byte position and keeps the same `f64` representation. No `TrainConfig` type exists in this chapter, so none was introduced.
- Renamed the private helpers `cross_entropy` to `cross_entropy_with_gradient_from_logits` and `norm_backward` to `layer_norm_backward`. The former now matches Chapter 36's primitive role, with the documented Chapter 56 differences of `f64` and a `Result` boundary; neither change alters arithmetic.
- Preserved all public `parameter_spans()` labels, their order, and ranges. Weight labels remain singular (`qkv_weight`, `attention_output_weight`, `router_weight`, `expert.i.ff1_weight`, `expert.i.ff2_weight`, and `output_weight`). A regression test fixes the exact 21-span two-expert ABI and the tiny three-expert totals: 3,303 total parameters and 2,879 nonexpert-plus-one-expert parameters.
- Preserved the `CH56MOE2` magic, model parameter order, checkpoint field order, and HTTP response format. A fresh two-step checkpoint is byte-identical to the pre-revision artifact, and one resumed old-format step is byte-identical to a fresh three-step run.

There are no external crate callers of the renamed `loss_and_gradient` method. The Chapter 56 binary and tests were migrated together. Starter calls to `Trainer::train_step` remain source-compatible because only the argument name changed.

## Loss, routing, shapes, and updates

- `Model::forward(tokens)` maps token IDs `[T]` to contiguous logits `[T,V]` with uncapped top-1 inference. `Trainer::evaluate(data)` uses that path, reports task cross-entropy only, and weights each window mean by its actual number of targets, including the final short window.
- `Model::loss(input, targets)` uses capped training forward and returns mean next-token cross-entropy over all T targets plus `alpha * E * sum_i(f_i * P_i)`. `loss_and_gradient` returns that same scalar objective and one derivative per parameter. `apply_sgd(gradients, learning_rate)` applies one in-place update only after the full gradient is available.
- `cross_entropy_with_gradient_from_logits(logits, targets, rows, vocab)` returns mean task cross-entropy and its `[T,V]` logit gradient. Every logit derivative divides by T. It is a fused logit-level primitive, not a parameter-gradient API.
- The load-balancing loss matches Chapter 48: attempted hard count divided by T gives `f_i`; full-softmax probability sum divided by T gives `P_i`; holding counts fixed gives `alpha * E * count_i / T^2` before the softmax Jacobian. Dropped tokens remain in both attempted counts and mean probabilities.
- A dropped training token keeps the residual, contributes task cross-entropy over the same T denominator, and sends task gradients through the shared output, final normalization, attention, and embeddings. It contributes no expert task computation or expert task gradient. A focused test forces three of four tokens to drop and checks these statements, including the selected expert's exact one-token gradient scaled by `1/T`.
- Every affine matrix remains contiguous row-major `[in_features,out_features]`, as in Chapter 36: QKV `[D,3D]`, attention `[D,D]`, router `[D,E]`, experts `[D,F]` then `[F,D]`, and output `[D,V]`. T is token positions, D model width, V vocabulary size, F expert feed-forward width, and tau/`temperature` controls sampling.
- The private capacity primitive is `max(1, ceil((T/E) * factor))` after floating-point division. Reference and Rustlings checks now include `(8,3,1.25) -> 4`, which detects integer division that the existing seven-token case did not.
- Chapter 48's `Model::route(input)` accepts two features and returns the selected index plus all probabilities. The Chapter 56 starter's `route(logits)` accepts three already-computed logits and returns the selected index plus its gate. The starter now copies Chapter 48's pure stable three-way `softmax` exactly, and the lesson states the intentional interface difference.
