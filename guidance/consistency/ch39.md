## Shapes, losses, and run semantics

- Decoder input and targets are `[T]` token-ID slices; `forward` logits are row-major `[T,V]`; the configured vocabulary is `V=256` bytes.
- `Decoder::loss` is mean cross-entropy over the `T` target tokens. Held-out evaluation processes non-overlapping blocks and weights each block mean by its actual target count, including an unequal final block.
- The default configuration is context 12, width 16, two heads, one layer, feed-forward width 32, vocabulary 256, and exactly 10,896 trainable f32 parameters. Forty optimizer steps process `40 × 2 × 12 = 960` target tokens. The cursor can wrap, so the program does not claim data epochs.
- `Config::approximately_15m()` remains vocabulary 256, context 128, width 384, eight heads, eight layers, feed-forward width 1536, and exactly 14,442,496 parameters. Its published persistent byte counts remain 57,769,984 for f32 parameters and 173,309,952 for parameters plus two Adam moment buffers.
- `--resume PATH --steps N` loads the Chapter 38 trainer and performs `N` additional optimizer steps. The saved file includes model/optimizer/schedule state, step, cursor, RNG, and training-ID fingerprint. It does not include corpus bytes or paths, tokenizer identity, prompt/sampling choices, executable revision, or call-level microbatch choices.
