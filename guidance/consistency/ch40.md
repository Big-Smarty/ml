# Chapter 40 consistency revision

## Interface mapping

- Chapter 39's full-prefix generation remains the oracle: `Decoder::forward(token_ids)` returns row-major logits `[T,V]` without updating the model.
- Chapter 40 still reads Chapter 36 through `config()`, `parameters()`, and `parameter_spans()`. The published span names, ranges, order, `[in,out]` storage, and parameter bytes were not changed.
- `CachedDecoder::step(token_id)` means one decoding advancement: it stores one `[D]` key and one `[D]` value per layer at the next sequence position and returns logits `[V]`. It does not mean an optimizer step and does not mutate model parameters.
- Private teaching names now distinguish outputs and units: `sample` became `sample_token`, `run_batch` became `run_request_batch`, `position` became `next_position`, and request quotas use `remaining_tokens`. These have no external callers or serialized representation.
- `Decoder::forward` and `Decoder::trace` necessarily remain full-sequence operations. Incremental inference therefore keeps a local persistent cache and reuses Chapter 36's published parameter access instead of introducing a second model API or changing the Chapter 36 ABI.

## Shapes, probabilities, and batching

- Chapter 36 and 40 projection weights are row-major `[input features,output features]` (`[in,out]`); `matvec` indexes `weights[input * out_features + output]`. This is the storage transpose of the earlier dense-layer `[out,in]` convention and computes the same linear map.
- `Decoder::forward` produces logits `[T,V]`; `CachedDecoder::step` produces the newest logits `[V]`; `sample_token` converts retained logits to normalized sampling probabilities and returns one sampled token ID.
- Each `CachedDecoder` tracks sequence positions for one request. `run_request_batch` schedules several independent requests and advances each active request by at most one sampled token per scheduler iteration. Its scalar loop does not add a tensor batch dimension or admit late arrivals.
- This inference chapter defines no loss or optimizer update, so there is no loss reduction. Attention and sampling softmax normalize probability mass; that normalization is not a loss average.
