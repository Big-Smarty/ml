# Chapter 42 consistency revision

## Interface and terminology mapping

Chapter 42 remains a standalone CPU attention binary. A repository-wide caller search found no callers outside its reference binary, tests, starter, Rustlings exercise, solution, and lesson. The chapter-local interfaces were renamed together:

- `full_attention(q, k, v, s)` → `causal_attention_scalar(queries, keys, values, shape)`.
- `tiled_attention(q, k, v, s, tile)` → `causal_attention_tiled(queries, keys, values, shape, key_tile_width)`.
- `Shape::tokens` → `Shape::positions`; `Shape::head_dim` → `Shape::head_width`.
- Starter `online_denominator(x)` → `online_softmax_state(scores)`.
- Rustlings `update(m, l, score)` → `update_online_softmax_state(running_maximum, shifted_denominator, score)` in both exercise and solution.

These are private, chapter-local names, so no Chapter 36 API, parameter span, serialized layout, or cross-crate caller changed. The fixtures, causal rule, GQA division, function argument order, `f32` arithmetic, mixed tolerance, CLI flags, and numerical outputs are otherwise unchanged.

## Continuity, shapes, and reductions

The new early continuity section links Chapters 35, 36, and 40 plus `/conventions.html`. It distinguishes Chapter 35's direct single-head `f64` Q/K/V arrays [positions,width] from this chapter's direct `f32` grouped-query layout:

- queries and output: [positions,query_heads,head_width];
- keys and values: [positions,kv_heads,head_width];
- flat offset: `(position * heads + head) * head_width + lane`;
- causal range for `query_position`: key positions `0..=query_position`;
- GQA mapping: `kv_head = query_head / (query_heads / kv_heads)`.

The lesson now states that a query position is a sequence-row index, not a token ID, and that the direct Q/K/V inputs are projected values rather than learned projection weights. Query-key dot products are scores; shifted exponential masses are unnormalized; division by the shifted denominator produces attention probabilities. “Attention weights” is identified as an alias for those data-dependent probabilities, distinct from learned model weights.

`causal_attention_scalar` applies two-pass stable softmax to one query/head row at a time. It stores O(T) scores for that row and never allocates a complete [T,T] matrix per head. `causal_attention_tiled` retains a running maximum, shifted denominator, and shifted value numerator across key tiles, storing at most B scores plus d numerator lanes for one query/head. Both visit every causally permitted pair, use the same GQA mapping, and compute O(Hq T² d) arithmetic. Neither computes a loss, gradient, optimizer update, or training reduction.

The memory discussion now separates a hypothetical 4HqT²-byte square score tensor from the actual functions. The caller retains Q/K/V; each function allocates one THq d output plus its own temporary workspace. The 512 MiB and 2 GiB examples remain arithmetic estimates rather than measured resident memory. No speed claim is made.

## Lesson, metadata, starter, and exercises

The lesson, metadata, research note, reference, starter, hints, worked answer, exercise, and solution use the implemented names and meanings. Three `data-source` excerpts exactly match the formatted sources: `Shape`, starter `stable_softmax`, and solution `update_online_softmax_state`. The starter's `stable_softmax` remains the ordinary score-to-probability operation; its variables now name `maximum`, `denominator`, and `probabilities`. The guided TODO returns only online softmax state, and the prose explicitly says this is not an optimizer step.

The scalar and tiled paths retain the same causal mask and contiguous GQA groups. The first-position test checks both at once: query heads 0–1 read K/V head 0 and query heads 2–3 read K/V head 1. The several-tile comparison, increasing-maximum recurrence, nonfinite-input/score rejection, invalid-GQA rejection, overflow rejection, maximum tile-width check, and mixed numerical tolerance are unchanged.
