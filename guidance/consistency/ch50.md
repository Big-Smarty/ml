# Chapter 50 consistency revision

## Interface mapping

- `Model { w, b }` became `Model { weights, bias }`. The free `predict(model, x)` function became `Model::predict(&self, features)`, matching the Chapter 27 receiver and feature terminology.
- `Example { x, y }` became `Example { features, target }`.
- `Gradient { worker, dw, db, count }` became `Gradient { weights, bias, count }`. Worker identity travels beside it as `(worker, Gradient)` and controls deterministic channel-message reduction order.
- `gradient_sum(&Model, &[Example])` returns unnormalized parameter-gradient sums and an example count. `aggregate_gradient_sums` combines those sufficient statistics and is used by the reference update. The starter now uses the same four-feature types, fixture rows, prediction method, gradient fields, and aggregation interface instead of its former scalar shortcut.
- Ordinary Rust parameters named `rate` became `learning_rate`.
- `TwoLayer { w1, b1, w2, b2 }` became `TwoLayer { hidden_weights, hidden_biases, output_weights, output_bias }`.
- `serial_step`, `data_parallel_step`, and `tensor_parallel_step` retain their explicit `data: &[Example]` interfaces. `serial_pipeline_step` and `pipeline_training_step` now take `data: &[(f64, f64)]` explicitly and return `Result<TwoLayer, _>` after validating data, learning rate, and the resulting parameters.

No external Chapter 50 callers exist, so this rename did not require a cross-crate migration. The `CH50v1` record remains eight whitespace-separated fields in the original order: magic, step, cursor, four weights, bias. A literal encoding assertion protects that byte order; the release demo retained its prior numerical output and recovery result.

## Shapes and reductions

- The linear model receives one `features=[4]` array and returns one `f64` prediction. `DATA` is six `Example` rows with scalar targets.
- Each worker sums four weight derivatives and one bias derivative over its batch slice. The coordinator sums worker `Gradient` values and counts, then divides once by the total example count. This is the gradient of MSE averaged over examples; it is distinct from every worker's unnormalized sum.
- Tensor parallelism keeps the same two two-coordinate parameter shards, shared residual, single bias reduction, and explicit `data` input.
- `pipeline_losses` returns one squared error per four-feature example without reducing it.
- The two-layer pipeline consumes scalar `(input, target)` pairs, accumulates hidden/output weight and bias gradient sums, and divides by the supplied slice length. The four original fixture pairs and forward/backward channel order are unchanged. The test now also uses the first three fixture pairs and compares the update-implied gradient with finite differences, so two implementations sharing the former hard-coded denominator cannot pass together.

## Limits and unresolved issues

The threads and standard-library channels are a deterministic miniature of communication and reduction semantics. They do not test multiple hosts, GPUs, accelerator placement, network collectives, bandwidth, scheduling throughput, or failure recovery. The checkpoint still round-trips a string inside one process and does not bind data or configuration identity. No Chapter 50 consistency issues remain in the owned files.
