# Chapter 04 consistency revision

## Changes and interface mapping

Chapter 04 deliberately changes the task introduced by Chapter 03. `LinearModel::predict(&self, features) -> f64` is a regression estimate. Chapter 04 uses `LogisticModel` because it models a binary outcome and exposes three distinct values:

| Operation | Meaning |
| --- | --- |
| `logit(&self, features: [f64; 2]) -> f64` | Unbounded affine score |
| `probability(&self, features: [f64; 2]) -> f64` | Positive-class probability from sigmoid |
| `predict(&self, features: [f64; 2]) -> u8` | Class `0` or `1` at the documented 0.5 threshold |

The following reference changes make Chapter 04 follow the shared conventions:

- `DATA` became `TRAIN_DATA`, and `Features` plus `Example` aliases document the two-feature shape and `(features, target)` tuple order.
- `logit(self, x)` and `probability(self, x)` became borrowing methods with the argument name `features`.
- `predict(&self, features) -> u8` now owns the default class decision; probability is never presented as the class.
- `loss(&self, data)` and `gradient(&self, data)` expose the two results of the existing fused `loss_and_gradient` operation.
- `loss_and_gradient(self, data) -> Result<(f64, LogisticModel), _>` became `loss_and_gradient(&self, data) -> Result<(f64, Gradient), _>`. Parameter derivatives no longer masquerade as a trained model.
- `numerical_gradient` checks the same loss with central differences at `1e-5`; it is compiled for tests, where it is used.
- `step(self, data, learning_rate)` performs one update. `train(self, data, steps, learning_rate)` repeats it. The old public argument name `rate` was removed.
- The starter's `stable_bce(logit, target) -> f64` TODO became `binary_cross_entropy_from_logit(logit, target) -> Result<f64, &'static str>`, matching the reference name, argument order, and validation boundary.

The lesson, worked answers, starter output, retrieval answers, metadata, and research note now use the same names and explain these transitions before technical use. The required continuity section links Chapter 03 and `/conventions.html`.

## Loss, gradient, and shape conventions

- One example is `([f64; 2], f64)`: a two-feature vector followed by its binary target.
- `logit` is `weights dot features + bias`; it is not a probability.
- `probability` applies stable sigmoid to the logit; it is not a class.
- `predict` applies the chapter's fixed 0.5 threshold and returns a discrete `u8` class.
- Regression's ordinary mean squared error is intentionally replaced by mean binary cross-entropy because the target is binary. The loss primitive takes `(logit, target)` in that order and uses `max(z, 0) - z * y + ln(1 + exp(-abs(z)))`.
- Both loss and every parameter derivative are divided by the number of examples. The per-example logit derivative is `probability - target`, without the factor two used by the Chapter 03 MSE gradient.
- `loss_and_gradient` shares each logit and returns `(mean_bce, Gradient { weights: [f64; 2], bias })`.
