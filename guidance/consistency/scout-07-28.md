# Consistency scout: Chapters 07–28

Read-only audit for the consistency revision. No chapter files were changed. Cargo projects 07–28 have no path dependencies; cross-chapter dependencies are lesson links and starter checkpoint carryovers in `chapters/*/lesson.html`.

## Shared findings

- Every lesson in 07–28 lacks the required early `<section id="continuity">` described in [`guidance/CONSISTENCY.md`](../CONSISTENCY.md:57). Add a short continuity section at the start of each lesson.
- Training code uses `rate` in ch07, 10, 11, 15, 16, 19–24, and 27. The shared contract prefers `learning_rate` in public teaching interfaces and ordinary Rust code.
- Fused loss/derivative methods are named `loss_grad`, `loss_and_grad`, or `gradient_parallel`. The contract standard is `loss_and_gradient`, with a suffix such as `_parallel` when the backend matters.
- Use `label` for a stored discrete class field where that is natural, while `target` remains valid for a generic loss argument, including a class index in cross entropy. A numeric regression target should also be called `target`; explain the type/encoding when it differs. Mathematical `y` may remain in equations or tightly scoped formulas.
- Recommended operation roles: `forward` computes model/layer outputs and caches; `predict` returns a task prediction; `score` is a raw scalar used before a threshold or ranking; `probability` is normalized output. Explain each transition instead of treating these as synonyms.
- Recommended shapes: activations `[batch, features]`, dense weights `[out_features, in_features]`, output `[batch, out_features]`; GEMM remains `A[m,k] × B[k,n] = C[m,n]`. Existing flat/internal layouts are fine when mapped explicitly.
- Loss reductions need explicit denominators. In particular, ch09 returns gradient sums, while later trainers commonly average; ch17 and ch22 use different reconstruction-MSE denominators; ch18 reports summed inertia/likelihood.

## Chapter map

- **07** — [`projects/ch07/src/main.rs`](../../projects/ch07/src/main.rs:45) has `Net::loss()` and [`:55`](../../projects/ch07/src/main.rs:55) `step()` capturing global `XOR`, unlike the explicit-data model contract. `forward` replaces earlier `predict` without a continuity explanation. Rename `rate`; map `gw1/gb1/gw2/gb2` to parameter gradients; document mean-over-four reduction. Transition to ch08 should distinguish model gradients from graph adjoints.
- **08** — The same accumulation primitive is `add_gradient` in the exercise, `accumulate` in the starter, and `add_grad` in the reference. [`projects/ch08/src/main.rs`](../../projects/ch08/src/main.rs:18) uses `grad` for a node adjoint, which needs to be distinguished from parameter gradients introduced in ch07.
- **09** — Lesson terminology uses `in_features/out_features`, while [`Dense`](../../projects/ch09/src/main.rs:34) stores `input/output`. `backward` returns `dx,dw,db` sums ([`:82–99`](../../projects/ch09/src/main.rs:82)); the lesson states the caller owns averaging. Carry that convention into ch10 and later chapters. Prefer `dX`, `dW`, and `dbias` in prose/code mapping.
- **10** — [`Dataset`](../../projects/ch10/src/main.rs:6) uses `images/labels`, `Linear` uses `features,w,b`, and [`cross_entropy(logits,target)`](../../projects/ch10/src/main.rs:103) is a stable logits loss. Rename or explain `cross_entropy_from_logits`; clarify stored `label` versus generic loss `target`. Training averages minibatch gradients at [`:123–141`](../../projects/ch10/src/main.rs:123).
- **11** — [`Dataset { x, y }`](../../projects/ch11/src/main.rs:11) abruptly changes names from ch10. [`Mlp`](../../projects/ch11/src/main.rs:102) packs all parameters into opaque `p`; [`loss_grad`](../../projects/ch11/src/main.rs:176) returns `g`; [`Optimizer::update`](../../projects/ch11/src/main.rs:266) also has a `step` counter. Rename fused API, use `parameters`/`gradient` where readable, and show the packed offsets for W1/b1/W2/b2. Preserve the ch10 cross-entropy convention.
- **12** — Reference [`Prediction { probability, label }`](../../projects/ch12/src/main.rs:3) is coherent. The exercise instead takes separate `probabilities` and `labels` slices. Explain that Brier is mean over prediction rows and an evaluation metric, not the classifier’s training objective.
- **13** — [`Row.label`](../../projects/ch13/src/main.rs:3) and `Preprocessor::fit/transform` ([`:17–36`](../../projects/ch13/src/main.rs:17)) are good canonical forms. The exercise uses `fill_missing(value, training_median)` while the starter uses `training_median(values)`; add the mapping to fitted state and `transform`.
- **14** — [`Point { x, class }`](../../projects/ch14/src/main.rs:3) and `Scaler::transform` are reasonable. The transition from ch13’s variable `Vec<f64>` to fixed `[f64; 2]` should be explicit. Keep `class`/`label` for discrete IDs; reserve `target` as the generic desired-output name when used by a loss.
- **15** — [`Row`](../../projects/ch15/src/main.rs:3) intentionally contains both `class` and numeric `target` because the chapter compares classification trees/forests with regression boosting. State that distinction. Local `loss` names weighted Gini or residual SSE; use or explain more precise terms such as `weighted_impurity` and `residual_sse`.
- **16** — [`Point.y`](../../projects/ch16/src/main.rs:4) switches to signed labels −1/+1; `score`, `predict`, and regularized `objective` are separate ([`:29–58`](../../projects/ch16/src/main.rs:29)). Explain the encoding change and that `objective` includes L2. Rename `rate`.
- **17** — [`Pca1::transform`](../../projects/ch17/src/main.rs:110) returns a projection called `score`, reusing classifier/ranking terminology. `reconstruction_mse` ([`:121–129`](../../projects/ch17/src/main.rs:121)) averages squared Euclidean error over rows only; this differs from ch22’s row-and-coordinate MSE. State the denominator or use an explicit name.
- **18** — [`distance2`, `inertia`, `responsibilities`, and `log_likelihood`](../../projects/ch18/src/main.rs:15) are algorithm-specific and valid, but inertia and likelihood are sums. Mark them as sums or provide mean names; do not silently present them as comparable to mean losses.
- **19** — Binary classification returns to [`Row.y`](../../projects/ch19/src/main.rs:4), and `Scaler::apply` ([`:86`](../../projects/ch19/src/main.rs:86)) conflicts with ch13–14 `transform`. - **20** — CNN introduces `Forward`, `Grad`, and [`loss_and_grad`](../../projects/ch20/src/main.rs:78), while ch10/11 use inline CE. - **21** — Residual CNN uses `loss_grad`, `NetCache`, `BlockCache`, `dout`, `dinput`, and `Grad` fields without `d` prefixes ([`projects/ch21/src/main.rs:78–246`](../../projects/ch21/src/main.rs:78)). Standardize fused naming and explain `dout` propagation from block two to block one.
- **22** — Two deliberately separate models both expose `loss`: autoencoder reconstruction and contrastive InfoNCE ([`projects/ch22/src/main.rs:67`](../../projects/ch22/src/main.rs:67), [`:172`](../../projects/ch22/src/main.rs:172)).
