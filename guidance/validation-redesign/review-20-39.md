# Independent review — chapters 20–39

Date: 2026-09-09
Reviewer: systems audit agent
Scope: Sections 04–07, their twenty lessons and metadata files, `labs/s04-deep-learning`, `labs/s05-cpu`, `labs/s06-gpu`, `labs/s07-language-models`, the preserved chapter 20–39 references used by those labs, and the shared goal-delivery behavior that affects these chapters.

## Result

The redesigned chapters now form four coherent project sequences for a reader who can program in Rust but is new to machine learning. Each ordinary chapter command starts from a useful working computation. The learner then changes a central algorithm or experimental method rather than filling an isolated formula. Checks exercise the selected learner implementation, while complete solutions stay separate. The lessons introduce arithmetic, roles, shapes, and invariants before compact notation, and each session ends with a changed input, controlled comparison, source review, or explanation.

No open material defect remains in the chapter 20–39 lesson/lab scope after the resolutions below. The result does not mean that every learner has demonstrated the written explanation or hardware work: source-level and hardware claims retain explicit manual evidence requirements.

## Review method

I read every final lesson, metadata record, learner entry, solution entry, supplied lab module, package README, and Section 04–07 validation report. I traced each learner callback into the code that trains, evaluates, benchmarks, dispatches, or checks it. I inspected the mathematical updates and their independent fixtures, ran the section packages and learner/solution modes during integration, and checked the final fixes against the exact source paths. The section owners' frozen reports contain the complete command matrices and final test counts; the root integration gate separately validates metadata, lesson structure, exact goal markers, manual-review criteria, and navigation behavior.

Browser layout and the complete downloadable-archive policy are outside this file. Interactive arithmetic was reviewed through its deterministic script checks; the root task owns final viewport and accessibility inspection.

## Bundle progression

- **Chapters 20–24 — broader deep learning:** Five complete domain experiments share a baseline/change/check/report rhythm. The independent section project asks the learner to choose one image, representation, sequence, or recommendation question, which avoids forcing unrelated data types into one artificial application.
- **Chapters 25–28 — make the CPU faster:** One dense computation carries through measurement, locality, threads, and SIMD. Numerical parity brackets every optimization, and the final artifact is an evidence report rather than a predetermined speedup claim.
- **Chapters 29–32 — write GPU kernels:** One supplied wgpu host carries vector arithmetic, cooperative reduction/GEMM, resident training, and fusion/timing. CPU oracles and ownership traces make the material accessible without a device; only an actual hardware run earns hardware evidence.
- **Chapters 33–39 — train a language model:** Bytes and a count baseline lead to embeddings, BPE as a bounded comparison, attention, a decoder, corpus audit, optimizer/checkpoints, and a complete tiny byte-model capstone. The full decoder backward and serialization plumbing are supplied at the point where repeating infrastructure would obscure the intended algorithm work.

The sequences preserve all original topic groups. They also create a visible shift from closely guided numerical substitutions toward decisions about partitions, measurement plans, corpus policy, training artifacts, and reproducible capstone comparisons.

| P2 | Chapter 37's first repaired goal check compared only retained/removed counts. ## Remaining limits

The course can verify numerical outputs, selected invariants, and process status, but it cannot automatically grade explanations, experimental judgment, safety arguments around `unsafe`, or source-level cooperative structure. Those chapters use visible review criteria rather than claiming automated mastery.

Optional datasets and hardware remain real boundaries. Chapter 20 does not download MNIST implicitly. Chapters 28–32 do not claim an unsupported SIMD/GPU path ran. Chapter 37's audit does not certify legal status or semantic decontamination. Chapters 33–39 do not claim useful language quality from their tiny authored corpus. Chapter 39 uses byte IDs; integrating Chapter 34 BPE and Chapter 37's manifest is a future project rather than a hidden requirement.

Within these limits, the final design meets the requested progression: runnable work first, substantive learner-owned algorithms, immediate numerical evidence, then controlled experiments and independent projects with reproducible artifacts.
