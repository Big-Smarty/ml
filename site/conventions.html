A reference throughout the course

The same ideas, the same names.

You should be able to recognize the code you learned in an earlier chapter. This page sets out the names we carry forward and explains the changes you will encounter as the models grow.

The first two chapters share one interface

A Neuron stores weight and bias. Calling a method on that neuron keeps its parameters together. A dataset is a slice of (input, target) pairs. The order stays the same in prediction, loss calculation, and training.

let model = Neuron { weight: 0.0, bias: 0.0 };
let prediction = model.predict(0.5);
let initial_loss = model.loss(&TRAIN)?;
let model = model.train(&TRAIN, 100, 0.1)?;

This excerpt belongs inside a function that can return an error, such as the reference program's main. The question mark propagates an error; it is not part of the mathematics. predict borrows the model through &self. The early step and train methods return an updated model, which we store back in model.

Chapter 1 uses the numerical gradient inside step. Chapter 2 uses the analytical gradient there and retains the numerical calculation as a check. The model, data, loss, and prediction have the same meaning in both chapters.

Vocabulary that stays with you

Input, features, and target
An input is what the model receives. A feature vector contains several input measurements. A target is the desired output paired with an input. A class label is a target identifying a category.
Prediction, error, and loss
A prediction is the model's answer. For regression, signed error is prediction − target. A loss scores disagreement according to a chosen objective. These are different quantities: an error can be negative even though its square is positive.
Parameters and hyperparameters
Training adjusts parameters such as weights and biases. You choose hyperparameters such as the learning rate, batch size, and layer width. Rust uses learning_rate for the update multiplier; equations often use η for the same quantity.
Gradient and update
A gradient contains derivatives of the loss with respect to parameters. It is calculated at the current parameters. An update uses it to produce new parameters. Calculate all derivatives that depend on the old parameters before changing those parameters.
Batch, step, and epoch
A batch is the group processed together. An optimizer step applies one update. An epoch is a pass over the training dataset. Several batches can make one epoch; gradient accumulation can make several batches contribute to one step.
Training, inference, and evaluation
Training adjusts learned state. Inference uses learned state to make predictions. Evaluation compares predictions with a task's criteria. Validation helps choose settings; the test split is reserved for the final evaluation.

Hover or focus linked terms in lessons for a preview, or consult the glossary. The early “bias” is a learned additive offset; statistical bias and fairness concerns have different meanings and are introduced separately.

A loss name includes a mathematical promise

For the scalar regression model, loss(data) means ordinary mean squared error:

L = (1/N) Σᵢ (predictionᵢ − targetᵢ)²

N is the number of examples. There is no factor of one half. Its derivative therefore includes a factor of two. At zero weight and bias, the five examples in Chapters 1 and 2 give loss 9 and gradient (−8, −2). With learning rate 0.1, the next parameters are (0.8, 0.2).

Classification introduces a different objective: cross-entropy. A logit is a score before probability normalization; it is not a probability or a predicted class. Standalone primitives such as binary_cross_entropy_from_logit(logit, target) name the input representation explicitly. A model's loss method computes the objective defined by that chapter.

Later implementations use loss_and_gradient when the loss and its derivatives can share a computation. The longer name describes two outputs, not a new kind of loss. Every chapter specifies whether it sums or averages over examples, output elements, or tokens. The gradient uses the same reduction. A regularization penalty is stated separately from the data loss.

Each chapter starts with a short account of the code and terminology it carries forward. Classical models and preprocessing tools can use fit to estimate state from training data and transform to apply that fitted state. A tokenizer's training loop or an environment's step has a different job from a neural optimizer; the lesson identifies the object and what one step counts.

Read shapes alongside function signatures

Arrays are contiguous and stored in row-major order unless a particular layout is explicitly explained. A dense layer normally receives activations shaped [batch, in_features], stores weights as [out_features, in_features], and returns [batch, out_features]. Its operation is input × weights-transpose + bias. A general matrix multiplication instead takes A[m,k] and B[k,n] and returns C[m,n]. These are compatible descriptions once the transpose is accounted for.

Language-model formulas use T for sequence positions, D for model width, V for vocabulary size, and τ for temperature. A token ID chooses a vocabulary entry; a position says where that token occurs in a sequence. The same ID can appear at several positions.

Kernel and checkpoint layouts sometimes differ. Their chapters give the indexing and conversion so you can follow the same numbers through memory. Early numerical examples use f64; performance chapters introduce f32 and explain the associated tolerance. Faster execution can change rounding without changing the intended formula.
