Reference, when you need it

Connect the numbers to the code.

The lesson explains each idea before relying on it. Use this page to check a name, shape or mathematical convention when comparing your implementation with a worked example.

The first model has two adjustable numbers

Chapter 1 predicts a trusted sensor reading by multiplying the raw input by a weight, then adding a bias. Its lab stores these parameters in [weight, bias]. The prediction function reads that array without changing it:

pub fn predict(model: [f64; 2], x: f64) -> f64 {
    model[0] * x + model[1]
}

Changing the weight changes the input's contribution. Changing the bias adds the same offset to every prediction. Chapter 1 implements numerical gradients; Chapter 2 calculates the same slopes analytically. Keep the examples, loss convention and update rule fixed when comparing those methods. The lab supplies input validation and command handling; you implement the learning procedure in the linked chapter source.

Name the quantity before calculating it

Input and target
The input is what the model receives. The target is the desired answer paired with it. A feature vector holds several input measurements; a class label identifies a category.
Prediction, error and loss
A prediction is the model's answer. For regression, signed error is prediction minus target. A loss turns prediction quality into a number using a stated rule. Squared error is never negative, even when the signed error is.
Parameters and hyperparameters
The training algorithm changes parameters such as weights and biases. You choose settings such as the learning rate, batch size or model width; these are hyperparameters.
Gradient and update
The gradient describes how the loss changes near the current parameters. An update uses those slopes to choose new parameters. Compute all derivatives that need the old parameters before changing them.
Training, inference and evaluation
Training adjusts learned state. Inference uses that state to predict. Evaluation compares predictions with a task's criteria. Validation helps choose settings; a test set is reserved for a final assessment.
Batch, step and epoch
A batch is the group processed together. An optimizer step applies an update. An epoch is a pass through the training dataset. Several batches can form an epoch, and several batches can contribute to one accumulated update.

Linked terms lead to the glossary. Hovering or focusing them also gives a short definition. Words such as “bias” have different meanings in different settings; each lesson introduces the one it uses.

Check what the loss averages

The first regression model uses ordinary mean squared error, with no factor of one half:

L=1N∑i=1N(predictioni−targeti)2

N is the number of examples. The symbol ∑ means add the quantity for each example i. With zero weight and bias, Chapter 1's five targets are −3, −1, 1, 3 and 5. Their squared errors sum to 45, so L=455=9. At these parameters the weight slope is −8 and the bias slope is −2. A learning rate of 0.1 gives new parameters 0−0.1(−8)=0.8 and 0−0.1(−2)=0.2.

Classification introduces cross-entropy and a different prediction representation. A logit is an unnormalized score; it is neither a probability nor a chosen class. The relevant lesson explains how scores become probabilities and why stable calculations matter.

Later losses may average across examples, output elements or tokens. Read that definition before comparing a formula or learning rate. A gradient must use the same reduction as its loss. A regularization penalty is an additional term, stated separately from the data loss.

Follow the same operation as the model grows

A function called forward calculates outputs, sometimes returning intermediates needed later. A backward operation propagates loss derivatives. Optimizers use the resulting gradients after the backward calculation has finished. Names and data structures can change as the model needs more state; the chapter shows the corresponding inputs and outputs.

Classical models and preprocessing tools often use fit for estimating state from training data and transform for applying fitted state. Fitting a preprocessing rule on test data leaks information even when no neural-network weights change. A tokenizer's training loop and a reinforcement-learning environment's step do different jobs; ask which object changes and what one iteration counts.

Read array shapes alongside signatures

A row-major matrix stores the elements of each row together. In a matrix with C columns, row r and column c live at flat index r×C+c. For example, row 1, column 2 of a three-column matrix has index 1×3+2=5.

Unless a chapter says otherwise, a dense layer receives [batch, in_features], stores weights as [out_features, in_features], and produces [batch, out_features]. General matrix multiplication takes a matrix A of shape [m,k] and a matrix B of shape [k,n] to a matrix C of shape [m,n]; the shared inner dimension k counts products added for each output. The layer's stored weight layout therefore implies a transpose relative to that matrix formula. Each lab states its actual layout.

Language-model chapters use T for sequence length, D for model width and V for vocabulary size. A token ID selects a vocabulary entry; a position identifies where a token occurs. The same token can occur at many positions. The relevant chapters derive these shapes before using them.

Compare floating-point calculations with a reason

The first numerical examples use f64. Central differences use a small positive h, normally 10−5, to compare loss at a parameter plus h and minus h. Gradient checks compare small smooth examples and avoid points where a function's slope is undefined.

Floating-point results can differ slightly when a CPU instruction, thread reduction or GPU changes the order of operations. A check commonly accepts absolute error up to atol+rtol×|expected|. The absolute allowance covers values near zero; the relative allowance scales with a larger expected value. Each experiment supplies a justified tolerance. A tolerance does not excuse a wrong shape, mask or reduction.

Input parsers and checkpoints reject malformed dimensions and nonfinite values. Those guards stay in the program even when the lesson focuses on the mathematical core. The authoring numerical conventions provide the fuller reference.

Know which implementation you checked

just lab NN runs your learner source. just lab-check NN checks its learning goal. just solution NN --check checks the separate completed example. Ordinary package tests verify the shipped baseline and supporting algorithms. These commands answer different questions; a successful solution run does not certify your implementation.

The source viewer and complete download let you inspect the checks. A passing check establishes behavior on those inputs. Your explanation and an unfamiliar variation test a different part of understanding. Keep both the numerical evidence and the reasoning in your learning notes.
