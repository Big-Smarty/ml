Before Chapter 1

A workspace for learning.

Read a little, write a little, then check what you think you know. This course works best with the website beside your editor.

Get ready

You need a stable Rust toolchain and Python 3 to serve these local pages. Python assembles the website and prepares optional downloads; the ML code you learn is Rust. The included toolchain file chooses stable Rust.

rustup toolchain install stable --component rustfmt --component clippy
cargo install rustlings --version 6.5.0 --locked
python3 tools/serve.py

Run commands from the course folder. Open http://127.0.0.1:8000 in your browser. If the port is already in use, run python3 tools/serve.py --port 8001 and open that port instead.

If you do not yet have Rust, follow the official Rust installation guide. Toolchain and dependency installation require an internet connection. The first chapter needs no ML dependencies.

Short commands for everyday work

The root justfile collects the course commands. If just is installed, run it from this folder or one of its subfolders. Chapter numbers can be written as 1 or 01.

just                 # list the available tasks
just serve           # build and serve the website
just run 1           # run the Chapter 1 reference
just test 1          # test the Chapter 1 reference
just starter 1       # run your starting checkpoint
just starter-test 1  # test your work; initially fails at the TODO
just exercises       # open the Rustlings exercise runner
just verify 1        # audit the chapter, reference, starter, and exercise

just verify without chapter numbers checks the whole course, including whether learner TODOs still fail as intended; use just starter-test and Rustlings to check your own completed work. See the official just installation instructions if needed. The underlying Cargo and Python commands in every lesson remain available.

Before your first exercise, follow the Git guide to save a baseline, record learning checkpoints, and push your history to GitHub.

A useful study session

  1. Answer the previous chapter’s review questions without opening its code.
  2. Read one lesson and calculate its numerical example with a pencil.
  3. Predict what the program will print, then run it.
  4. Complete the small exercise before revealing a hint.
  5. Extend the project and explain one failure you encountered.

A lesson may fit into an hour; a project can take several sessions. There is no race. Revisit difficult ideas the next day and after several days. If a word interrupts your reading, hover or focus its link for a definition, or open the glossary explanation.

Small exercises, then real projects

cd exercises/cpu
rustlings

If this workspace already contains .tools/bin/rustlings, use ../../.tools/bin/rustlings from exercises/cpu without reinstalling it. Rustlings watches your edited exercise, reruns its test, and offers a hint with h. The exercise list lets you return to earlier work. Starting exercises intentionally contain unfinished code. They are not supposed to pass before you solve them.

For each larger project, the src/ directory is the complete reference checkpoint. The starter/ directory contains the learner version. Start here:

cargo test --manifest-path projects/ch01/starter/Cargo.toml
cargo test --manifest-path projects/ch01/Cargo.toml
cargo run --manifest-path projects/ch01/Cargo.toml

Run these Cargo commands from the course root (return there with cd ../.. after the Rustlings session). The first command initially fails because the starter needs your implementation. The reference tests should pass. Later lessons explain the exact commands and data for their projects. Do not copy a complete answer until you have tried the exercise and used the hints.

Keep the course offline

The reading site uses local styles, scripts, diagrams and glossary entries. It does not load fonts, libraries or analytics from a CDN. External source links are optional further reading. The website is intended to be served locally rather than opened directly with a file URL.

Rust examples using only the standard library can run offline once Rust is installed. GPU or optional integration projects need their dependencies fetched once. Fetch from the particular project directory with cargo fetch --manifest-path projects/ch29/Cargo.toml when online; afterward use Cargo’s --offline option. Dataset downloads are explicit. Tiny course-authored fixtures keep the default demonstrations independent of external data.

The browser’s completion checkboxes record your reading progress locally. They do not read your editor files or claim that you passed the Rust exercises. Clearing browser storage removes that reading progress.

Prepare real digit data when you reach Chapter 10

The default projects run on tiny fixtures. For handwritten digits, this explicit command downloads about 12 MB, checks the published archive fingerprints, and writes a fixed 55,000-row training subset plus 5,000 validation rows. The official 10,000-row test set stays separate.

python3 tools/prepare_mnist.py --download

Files live in datasets/downloads/mnist/. During development use the fit-* and validation-* pairs described in Chapter 10. Save the t10k-* pair for final evaluation. A local provenance manifest records source links, checksums, and every selected validation row. After this preparation the digit projects need no network. The downloader uses the OSSCI mirror listed in the official torchvision implementation; it does not install or use PyTorch.

When you reach the GPU

Chapters 1–28 use the CPU. GPU chapters use Rust with wgpu and hand-written WGSL compute shaders. Start by checking that your operating system exposes a hardware adapter. The course kernels have run successfully on the Radeon RX 6950 XT, including tiled matrix products, reductions, training, and optional half precision. Sandboxed processes may still lack device access. Consult the validation record for the actual status of kernel checks.

A small language model teaches the complete training process. It does not become a general-purpose assistant merely by using the same architecture. Larger configurations have explicit data, memory and runtime requirements; they never launch automatically.
