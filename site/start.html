Before Chapter 1

Set up, then try one experiment.

You need a browser, Python 3, Rust, the just command runner and a folder where you can change the code. You already know enough programming to begin; the lessons introduce the mathematics when it becomes useful.

Get a working copy

If you already have the course repository, use the codex/ml-learning-redesign branch. Otherwise, download the course sources and extract the archive. Open a terminal in the first-principles folder, where justfile, labs and course.json live.

Install Rust with the official Rust installer if needed. Install the just command runner with the package instructions for your system. Then run the first experiment from the course root:

just --version
just lab 01

You should see calibration pairs, a prediction rule and a mean squared error of 0.75. That is a useful, working starting point. You have not trained the model yet; Chapter 1 explains how to replace the supplied candidate comparison with a learning algorithm.

If Cargo cannot be found after installation, open a fresh terminal and check the installer's PATH instructions. Work from the folder containing labs; a “manifest does not exist” message usually means you are in a different folder.

Learn in a working experiment

Each of the nine course sections has one Cargo package. Each chapter has a named experiment inside it. You change the chapter's learner source; the package supplies small datasets, input checks and incidental plumbing so your attention can stay on the algorithm.

Chapter 1's learner file is labs/s01-foundations/src/ch01.rs. Read the concrete goal in the lesson, make a prediction, run the baseline, then implement the requested change. Check its behavior on the supplied and unfamiliar inputs:

just lab-check 01

The learning-goal check can fail before you have implemented the algorithm. Read its numerical evidence and compare it with your prediction. This is different from just lab-test 01, which checks the package as supplied and should pass immediately.

Hints, solutions and what counts as evidence

The lesson's hints gradually reveal the reasoning. After attempting the work, compare it with the separate src/solutions/ch01.rs implementation. just solution 01 --check checks that completed example. It does not check your implementation. A successful numerical check is evidence about the tested behavior; explain why it succeeds and try the chapter's changed input to test your understanding.

Use these four commands throughout the course:

just lab 01
just lab-check 01
just lab-test 01
just solution 01 --check

Both 1 and 01 work. Later chapters show their package and exact experiment arguments. just lab uses Cargo offline: run just deps NN while online before your first run if a section's README names external dependencies (for example, just deps 29). Early labs use only Rust's standard library.

A session has one visible result

Allow roughly 30–45 minutes for a session, then adjust to the idea and your energy. A chapter can take several sessions. The reader shows one coherent step at a time, with Back and Next controls and a Full chapter view whenever you want the surrounding argument.

  1. Recall the earlier idea the session needs. Try answering before opening its explanation.
  2. Follow a worked calculation and predict a result before changing a control or running code.
  3. Run the working baseline and implement the meaningful algorithm change.
  4. Compare your evidence, explain a mistake and try a changed case.

When you stop, leave a sentence about what you understood and what you want to check next. On a later day, try the recall question again before looking at your notes. Needing a hint is useful information about what to revisit.

Your place and your practice are different records

The homepage's Continue action returns to your latest reading step. The practice card lets you record an implementation attempt, successful Rust goal checks and an explanation or new case. These records stay in this browser. The site cannot inspect the code on your computer, so Rust results are explicitly self-reported.

Browser activity does not unlock chapters or prove mastery. You can move freely through the course, read a solution or return to an earlier explanation. The new course starts a fresh progress record. For durable source changes and notes across devices, use your own files and the Git guide.

Open the learner source in your editor

Open the editor from the course root. For Helix, run helix labs/s01-foundations/src/ch01.rs (or hx if that is your executable name). The supplied .helix/languages.toml connects rust-analyzer to the nine labs and their preserved reference libraries. Reopen the editor if it was already running when the configuration changed.

The complete solutions live in a separate source directory so you can compare them deliberately. projects/ contains preserved reference implementations; those are supporting material. The new lab entry point is always linked from the chapter's practice card.

Use the guide offline

Before disconnecting, install Python 3 and the requested Rust toolchain, download the course, and fetch any section dependencies described in its README. The download does not include compilers or Cargo's dependency cache. In the downloaded course folder, run:

just serve

Open localhost:8000. The generator writes only dist/; it never resets your learner files. Serve the pages through this local server so search and glossary data can load. The complete chapter text remains readable without JavaScript; interactive figures have worked text or tables alongside them.

Default datasets are bundled, tiny and course-authored unless a lesson identifies a different source. Larger datasets, longer training and GPU execution require explicit commands. Browser figures illustrate computations; GPU timing comes only from actual hardware runs. Follow the GPU section's device setup when you reach it.
